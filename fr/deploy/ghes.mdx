Ce guide vous accompagne pas à pas dans la configuration de l&#39;application GitHub de Mintlify sur votre installation GitHub Enterprise Server (GHES). Pour connecter une instance GHES à Mintlify, vous devez créer, dans votre environnement auto‑hébergé, une version locale de notre application qui communique avec notre serveur distant.

Si vous utilisez une instance GitHub hébergée dans le cloud, consultez la page [GitHub](/fr/deploy/github) pour les instructions de configuration.

<div id="prerequisites">
  ## Prérequis
</div>

* Droits d’administrateur sur l’organisation GitHub Enterprise Server où vous souhaitez installer l’application
* Accès aux dépôts de votre organisation où vous souhaitez installer l’application
* Connectivité réseau pour communiquer avec nos services externes (voir la section [Exigences réseau](#network-requirements) ci-dessous)

<div id="network-requirements">
  ### Configuration réseau requise
</div>

<div id="outbound-connectivity">
  #### Connectivité sortante
</div>

Votre instance GitHub Enterprise Server doit pouvoir accéder :

* aux points de terminaison de l’API Mintlify (https://leaves.mintlify.com)
* aux récepteurs de webhooks (port 443)

<div id="firewall-configuration">
  #### Configuration du pare-feu
</div>

Les connexions sortantes suivantes doivent être autorisées :

* Connexions depuis l’adresse IP statique de Mintlify : `54.242.90.151`
* HTTPS (port 443) vers les domaines de service de Mintlify
* Résolution DNS des domaines de service de Mintlify

<div id="step-1-register-the-github-app">
  ## Étape 1 : Enregistrer l’application GitHub
</div>

Consultez la page [Enregistrement d’une application GitHub](https://docs.github.com/en/enterprise-server@3.18/apps/creating-github-apps/registering-a-github-app/registering-a-github-app) dans la documentation GitHub pour obtenir des instructions détaillées.

<Steps>
  <Step title="Accédez aux paramètres de votre organisation">
    1. Dans l’angle supérieur droit de n’importe quelle page GitHub, cliquez sur votre photo de profil.
    2. Cliquez sur **Your organizations**.
    3. Cliquez sur **Settings** à côté de l’organisation pour laquelle vous souhaitez créer l’application.
  </Step>

  <Step title="Créer une nouvelle application GitHub">
    1. Dans la barre latérale gauche, cliquez sur **Developer settings**.
    2. Cliquez sur **GitHub Apps**.
    3. Cliquez sur **New GitHub App**.
  </Step>

  <Step title="Configurer les informations de base de l’application">
    Définissez les éléments suivants :

    * **GitHub App name :** `Mintlify`
    * **Description :** `Integration with Mintlify services`
    * **Homepage URL :** `https://mintlify.com`
    * **User authorization callback URL :** `https://your-github-server.com/` (remplacez par votre domaine GHES réel)
  </Step>
</Steps>

<div id="step-2-configure-app-permissions">
  ## Étape 2 : Configurer les autorisations de l’application
</div>

<Steps>
  <Step title="Définir les autorisations du dépôt">
    Définissez les autorisations suivantes pour l’application. Aucune autorisation au niveau de l’organisation, du compte ou de l’entreprise n’est requise :

    * **Checks :** lecture et écriture
    * **Contents :** lecture et écriture
    * **Deployments :** lecture et écriture
    * **Metadata :** lecture seule
    * **Pull Requests :** lecture et écriture
  </Step>

  <Step title="S’abonner aux événements">
    Sélectionnez les événements de webhook suivants :

    * Installation
    * Installation Target
    * Create
    * Delete
    * Public
    * Pull Request
    * Push
    * Repository
  </Step>
</Steps>

<div id="step-3-generate-and-secure-credentials">
  ## Étape 3 : Générer et sécuriser les identifiants
</div>

<Steps>
  <Step title="Créer l'application">
    Cliquez sur **Create GitHub App**.

    Vous serez redirigé vers la page des paramètres de l&#39;application.
  </Step>

  <Step title="Générer la clé privée">
    1. Faites défiler la page jusqu&#39;à la section **Private keys**.
    2. Cliquez sur **Generate a private key**.
    3. Téléchargez le fichier `.pem` et conservez-le en lieu sûr.
  </Step>

  <Step title="Noter les identifiants de l'application">
    Notez les éléments suivants :

    * **App ID** (visible en haut de la page des paramètres)
    * **Client ID** (dans la section « About »)
    * **Client Secret** (générez-le, puis enregistrez-le en lieu sûr)
  </Step>
</Steps>

<div id="step-4-install-the-app">
  ## Étape 4 : Installer l’application
</div>

<Steps>
  <Step title="Accéder à l’installation de l’application">
    1. Depuis la page des paramètres de l’application, cliquez sur **Install App** dans la barre latérale gauche.
    2. Sélectionnez votre organisation dans la liste.
  </Step>

  <Step title="Choisir le périmètre de l’installation">
    Sélectionnez l’une des options suivantes :

    * **All repositories** (pour un accès à tous les dépôts de l’organisation)
    * **Only select repositories** (pour choisir des dépôts spécifiques)

    <Tip>
      Nous recommandons de sélectionner « Only select repositories » et de limiter l’application uniquement aux dépôts où se trouve votre documentation.
    </Tip>
  </Step>

  <Step title="Terminer l’installation">
    1. Cliquez sur **Install**.
    2. Relevez l’ID d’installation dans l’URL. Par exemple, dans `https://your-github-server.com/settings/installations/12345`, la chaîne `12345` correspond à l’ID d’installation.
  </Step>
</Steps>

<div id="step-5-configure-webhook-url">
  ## Étape 5 : Configurer l’URL du webhook
</div>

<Steps>
  <Step title="Revenir aux paramètres de l’application">
    1. Revenez à la page des paramètres de votre application.
    2. Faites défiler jusqu’à la section **Webhook**.
  </Step>

  <Step title="Définir l’URL du webhook">
    Configurez les éléments suivants :

    * **Webhook URL :** `https://leaves.mintlify.com/github-enterprise/:subdomain` (remplacez `:subdomain` par l’URL que nous vous communiquerons)
    * **Webhook secret :** Générez une chaîne aléatoire (32 caractères ou plus) et conservez-la en lieu sûr. Mintlify peut également la générer pour vous et vous la fournir.
  </Step>
</Steps>

<div id="required-credentials">

<div id="mintlify-connection">
  ## Connexion à Mintlify
</div>

Nous utilisons les identifiants que vous nous fournissez et les stockons, chiffrés, dans un emplacement sécurisé. Ensuite, nous collaborons avec vous pour :

* Intégrer votre environnement GHES à un déploiement Mintlify existant.
* Intégrer votre environnement GHES à un nouveau déploiement Mintlify que nous mettons à votre disposition.

Une fois que votre environnement GHES est intégré à un déploiement Mintlify, vous pouvez activer les webhooks pour votre application GitHub.

<Note>
  L’URL du webhook peut changer en fonction de notre configuration. Nous testons l’intégration et vous fournissons la nouvelle URL.
</Note>

<div id="test-the-integration">
  ## Tester l’intégration
</div>

<Steps>
  <Step title="Vérifier la livraison du webhook">
    1. Allez dans les paramètres de votre application GitHub.
    2. Cliquez sur l’onglet **Advanced**.
    3. Vérifiez les « Recent Deliveries » pour confirmer la réussite des livraisons de webhooks.
    4. Recherchez des réponses HTTP 200.
  </Step>

  <Step title="Tester l’accès au dépôt">
    1. Créez une issue de test ou une pull request dans un dépôt où l’application est installée.
    2. Vérifiez que Mintlify réagit correctement.
  </Step>
</Steps>

<div id="faq-and-troubleshooting">
  ## FAQ et dépannage
</div>

<AccordionGroup>
  <Accordion title="L'installation de l'application échoue avec des erreurs de permissions.">
    Assurez-vous de disposer :

    * Des privilèges d’administrateur du site pour la création d’applications
    * Des droits de propriétaire ou d’administrateur de l’organisation pour l’installation de l’application.
    * Des permissions de dépôt appropriées si vous l’installez sur des dépôts spécifiques.
  </Accordion>

  <Accordion title="Les webhooks ne sont pas livrés">
    * Vérifiez que l’URL du webhook est correcte et accessible.
    * Assurez-vous que votre pare-feu autorise les connexions HTTPS sortantes.
    * Vérifiez que le secret du webhook correspond à ce qui a été configuré.
    * Consultez les journaux de livraison des webhooks dans l’onglet &quot;Advanced&quot; des paramètres de votre GitHub App.
  </Accordion>

  <Accordion title="Je reçois des erreurs de certificat SSL/TLS">
    Il est possible que votre GHES utilise des certificats auto-signés. Nos services ne peuvent pas vérifier le certificat de votre serveur.

    **Solution :** assurez-vous que votre GHES dispose d’un certificat SSL valide.
  </Accordion>

  <Accordion title="L’application s’installe, mais ne réagit pas aux événements.">
    * Assurez-vous que les webhooks sont bien livrés et que notre serveur en accuse réception avec un code de réponse 200.
    * Vérifiez que les permissions requises ont été accordées lors de l’installation.
  </Accordion>

  <Accordion title="Puis-je limiter les dépôts auxquels l’application accède ?">
    Oui, lors de l’installation, vous pouvez sélectionner &quot;Only select repositories&quot; et choisir des dépôts spécifiques. Vous pouvez modifier ce paramètre plus tard dans les paramètres des applications installées de votre organisation. C’est le mode d’installation recommandé.
  </Accordion>

  <Accordion title="Comment mettre à jour les permissions de l’application plus tard ?">
    * Accédez aux paramètres de l’application en tant qu’administrateur du site.
    * Modifiez les permissions selon vos besoins.
    * L’application devra être à nouveau approuvée par les propriétaires de l’organisation.
    * Informez-nous de tout changement de permissions, car cela peut affecter les fonctionnalités.
  </Accordion>

  <Accordion title="Notre GHES est derrière un pare-feu d’entreprise, un proxy nginx ou une configuration similaire.">
    Vous devez :

    * Ajouter nos domaines de service à la liste d’autorisation de votre pare-feu.
    * Assurer la connectivité HTTPS sortante (port 443).
    * Si l’accès direct à Internet n’est pas autorisé, configurez un proxy.
  </Accordion>

  <Accordion title="Cela peut-il fonctionner avec un GHES dans un environnement isolé (air-gapped) ?">
    Non, votre GHES doit pouvoir communiquer avec notre serveur hébergé dans le cloud.
  </Accordion>

  <Accordion title="Qui dois-je contacter si j’ai besoin d’aide ?">
    Veuillez contacter votre interlocuteur Customer Success avec qui vous avez échangé chez Mintlify, ou notre équipe d’assistance à l’adresse <a href="mailto:support@mintlify.com">support@mintlify.com</a> avec :

    * Votre version de GitHub Enterprise Server.
    * Les messages d’erreur spécifiques.
    * Des captures d’écran de tout problème.
    * Les détails de configuration réseau/pare-feu (le cas échéant).
  </Accordion>
</AccordionGroup>
