Si vous utilisez un proxy externe comme Cloudflare ou AWS CloudFront en amont de votre déploiement Vercel, vous devez le configurer correctement afin d’éviter tout conflit avec la vérification de domaine et l’émission de certificats SSL par Vercel.

Une mauvaise configuration du proxy peut empêcher Vercel d’émettre des certificats SSL Let's Encrypt et entraîner des échecs de vérification de domaine.

Consultez la liste des [fournisseurs pris en charge](https://vercel.com/guides/how-to-setup-verified-proxy#supported-providers-verified-proxy-lite) dans la documentation Vercel.

<div id="required-path-allowlist">
  ## Liste d’autorisation de chemins obligatoire
</div>

Votre proxy externe doit autoriser le trafic vers ces chemins spécifiques sans le bloquer, le rediriger ni le mettre en cache de manière agressive :

- `/.well-known/acme-challenge/*` - Requis pour la vérification des certificats Let's Encrypt
- `/.well-known/vercel/*` - Requis pour la vérification des domaines Vercel
- `/mintlify-assets/_next/static/*` - Requis pour les ressources statiques

Ces chemins doivent être acheminés directement vers votre déploiement Vercel sans modification.

<div id="header-forwarding-requirements">
  ## Exigences relatives au transfert des en-têtes
</div>

Assurez-vous que votre proxy transmet correctement l’en-tête `HOST`. Sans un transfert correct des en-têtes, les requêtes de vérification échoueront.

<div id="testing-your-proxy-setup">
  ## Tester la configuration de votre proxy
</div>

Pour vérifier que votre proxy est correctement configuré :

1. Vérifiez que `https://[yourdomain].com/.well-known/vercel/` renvoie bien une réponse.
2. Assurez-vous que les certificats SSL sont correctement provisionnés dans votre tableau de bord Vercel.
3. Vérifiez que la vérification du domaine s’effectue correctement.
