Hébergez votre documentation sur un sous-chemin tel que `your-domain.com/docs` afin de la conserver sur votre domaine principal, de la rendre plus facile à trouver et d’offrir à vos utilisateurs une expérience de marque cohérente.

<div id="set-up-by-hosting-provider">
  ## Configuration selon le fournisseur d’hébergement
</div>

La configuration d’un sous-chemin `/docs` varie selon votre fournisseur d’hébergement. Choisissez le vôtre et suivez les instructions correspondantes.

* [Cloudflare](/fr/deploy/cloudflare): Configurez Cloudflare Workers pour votre domaine afin de diffuser votre documentation sur le sous-chemin `/docs`.
* [AWS Route 53 et CloudFront](/fr/deploy/route53-cloudfront): Déployez votre documentation sur le sous-chemin `/docs` à l’aide d’AWS, avec le DNS Route 53 et le CDN CloudFront.
* [Vercel](/fr/deploy/vercel#host-from-docs) - Utilisez des réécritures pour déployer votre documentation sur le sous-chemin `/docs`.
* [Proxy inverse personnalisé](/fr/deploy/reverse-proxy) - Pour les autres plateformes d’hébergement, configurez un proxy inverse afin de déployer votre documentation sur le sous-chemin `/docs`.

<div id="additional-configuration-for-strict-security-policies">
  ### Configuration supplémentaire pour les politiques de sécurité strictes
</div>

Si vous faites transiter tout le trafic sur votre domaine personnalisé via un proxy, vous devrez peut-être configurer votre proxy ou vos règles de pare-feu pour ajouter les [en-têtes](/fr/deploy/csp-configuration) appropriés afin que votre documentation s’affiche correctement.
