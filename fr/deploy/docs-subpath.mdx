Hébergez votre documentation sur un sous-chemin tel que `your-domain.com/docs`, afin de la conserver sur votre domaine principal, ce qui la rend plus facile à trouver et garantit une expérience de marque cohérente pour vos utilisateurs.

<div id="set-up-by-hosting-provider">
  ## Configuration selon le fournisseur d’hébergement
</div>

La configuration d’un sous-chemin `/docs` varie en fonction de votre fournisseur d’hébergement. Sélectionnez votre fournisseur et suivez les instructions correspondantes.

* [Cloudflare](/fr/deploy/cloudflare) : Configurez Cloudflare Workers pour votre domaine afin de diffuser votre documentation sur le sous-chemin `/docs`.
* [AWS Route 53 and CloudFront](/fr/deploy/route53-cloudfront) : Déployez votre documentation sur le sous-chemin `/docs` en utilisant AWS avec Route 53 comme DNS et CloudFront comme CDN.
* [Vercel](/fr/deploy/vercel#host-from-docs) - Utilisez des règles de réécriture pour déployer votre documentation sur le sous-chemin `/docs`.
* [Custom reverse proxy](/fr/deploy/reverse-proxy) - Pour d’autres plateformes d’hébergement, configurez un proxy inverse pour déployer votre documentation sur le sous-chemin `/docs`.

<div id="additional-configuration-for-strict-security-policies">
  ### Configuration supplémentaire pour des politiques de sécurité strictes
</div>

Si vous faites transiter tout le trafic de votre domaine personnalisé par un proxy, il peut être nécessaire de configurer ce proxy ou vos règles de pare-feu afin d’ajouter les [en-têtes](/fr/deploy/csp-configuration) appropriés pour que votre documentation s’affiche correctement.
