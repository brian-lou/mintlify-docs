Configurez votre fichier `vercel.json` pour rediriger les requêtes de votre domaine principal vers votre documentation dans un sous-chemin.


<div id="verceljson-file">
  ## Fichier `vercel.json`
</div>

Le fichier `vercel.json` définit la façon dont votre projet est compilé et déployé. Il se trouve à la racine de votre projet et contrôle différents aspects du déploiement, notamment le routage, les redirections, les en-têtes et les paramètres de build.

Nous utilisons la configuration `rewrites` dans votre fichier `vercel.json` pour acheminer les requêtes de votre domaine principal vers votre documentation.

Les `rewrites` associent les requêtes entrantes à d&#39;autres destinations sans modifier l&#39;URL affichée dans le navigateur. Lorsqu&#39;une personne visite `yoursite.com/docs`, Vercel récupère en interne le contenu depuis `your-subdomain.mintlify.dev/docs`, mais l&#39;utilisateur voit toujours `yoursite.com/docs` dans son navigateur. Cela diffère des redirections, qui envoient les utilisateurs vers une autre URL.

<div id="configuration">
  ## Configuration
</div>

<div id="host-at-docs-subpath">
  ### Héberger sur le sous-chemin `/docs`
</div>

1. Accédez à [la configuration du domaine personnalisé](https://dashboard.mintlify.com/settings/deployment/custom-domain) dans votre tableau de bord.
2. Activez le bouton bascule **Host at `/docs`**.
   <Frame>
     <img alt="Capture d’écran de la page de configuration du domaine personnalisé. Le bouton bascule Host at `/docs` est activé et mis en évidence par un rectangle orange." src="/images/subpath/toggle-light.png" className="block dark:hidden" />

     <img alt="Capture d’écran de la page de configuration du domaine personnalisé. Le bouton bascule Host at `/docs` est activé et mis en évidence par un rectangle orange." src="/images/subpath/toggle-dark.png" className="hidden dark:block" />
   </Frame>
3. Saisissez votre domaine.
4. Sélectionnez **Add domain**.
5. Ajoutez les rewrites suivantes à votre fichier `vercel.json`. Remplacez `[subdomain]` par votre sous-domaine, que vous trouverez à la fin de l’URL de votre tableau de bord. Par exemple, `dashboard.mintlify.com/your-organization/your-subdomain` a pour identifiant de domaine `your-subdomain`.

   ```json
   {
     "rewrites": [
       {
         "source": "/docs",
         "destination": "https://[subdomain].mintlify.dev/docs"
       },
       {
         "source": "/docs/:match*",
         "destination": "https://[subdomain].mintlify.dev/docs/:match*"
       }
     ]
   }
   ```

La configuration `rewrites` associe le sous-chemin `/docs` de votre domaine au sous-chemin `/docs` de votre documentation.

* **`source`** : le modèle de chemin sur votre domaine qui déclenche le rewrite.
* **`destination`** : la destination vers laquelle la requête est transmise.
* **`:match*`** : un caractère générique qui capture tous les segments de chemin après votre sous-chemin.

Pour en savoir plus, consultez [Configuring projects with vercel.json: Rewrites](https://vercel.com/docs/projects/project-configuration#rewrites) dans la documentation Vercel.

<div id="host-at-custom-subpath">
  ### Héberger sur un sous-chemin personnalisé
</div>

Pour utiliser un sous-chemin personnalisé (n’importe quel chemin autre que `/docs`), vous devez organiser les fichiers de votre documentation dans votre dépôt pour qu’ils correspondent à la structure de ce sous-chemin. Par exemple, si votre documentation est hébergée sur `yoursite.com/help`, ses fichiers doivent se trouver dans un répertoire `help/`.
