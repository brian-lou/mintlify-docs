Utilisez les vérifications CI pour détecter les erreurs dans votre documentation et afficher des avertissements avant le déploiement. Les vérifications CI de Mintlify s’exécutent sur les pull requests par rapport à une branche de déploiement configurée.

<div id="installation">
  ## Installation
</div>

Pour commencer, suivez les étapes de la page [GitHub](/fr/deploy/github).

<Tip>
  Seul l’accès au dépôt contenant votre documentation est nécessaire. Il est donc fortement recommandé de n’accorder l’accès qu’à ce dépôt.
</Tip>

## Configuration

Configurez les vérifications CI activées pour un déploiement en accédant à la page [Add-ons](https://dashboard.mintlify.com/products/addons) de votre tableau de bord. Activez les vérifications que vous souhaitez exécuter.

Lorsque vous activez des vérifications, vous pouvez choisir de les exécuter au niveau `Warning` ou `Blocking`.

* Une vérification de niveau `Warning` ne renverra jamais un statut d’échec, même en cas d’erreur ou de suggestions.
* Une vérification de niveau `Blocking` renverra un statut d’échec en cas d’erreur ou de suggestions.

<div id="available-ci-checks">
  ## Vérifications CI disponibles
</div>

<div id="broken-links">
  ### Liens rompus
</div>

À l’instar du [vérificateur de liens CLI](/fr/installation#find-broken-links) sur votre machine locale, la
vérification CI des liens rompus recherche automatiquement les liens internes rompus dans le contenu de votre documentation.

Pour consulter les résultats de cette vérification, accédez à la page des résultats des vérifications GitHub pour un commit donné.

<div id="vale">
  ### Vale
</div>

[Vale](https://vale.sh/) est un linter de prose open source basé sur des règles, compatible avec plusieurs types de documents, dont Markdown et MDX. Utilisez Vale pour vérifier la cohérence du style et du ton de votre documentation.

Mintlify permet d’exécuter automatiquement Vale dans une vérification CI et d’afficher les résultats sous forme de statut de vérification.

<div id="configuration">
  #### Configuration
</div>

Si vous avez un fichier `.vale.ini` dans le répertoire racine du contenu de votre déploiement, la vérification Vale CI utilise ce fichier de configuration ainsi que tous les fichiers de configuration du `stylesPath` spécifié.

Si vous n&#39;avez pas de fichier de configuration Vale, la configuration par défaut se charge automatiquement.

```mdx Default vale.ini configuration expandable
# Styles de niveau supérieur
StylesPath = /app/styles
MinAlertLevel = suggestion
# Balises HTML en ligne à ignorer (code/tt pour les extraits de code, img/url pour les liens/images, a pour les balises d'ancrage)
IgnoredScopes = code, tt, img, url, a
SkippedScopes = script, style, pre, figure

# Vocabulaires
Vocab = Mintlify

# Paquets
Packages = MDX

# Correspondre uniquement aux fichiers MDX
[*.mdx]
BasedOnStyles = Vale
Vale.Terms = NO # Applique des règles de capitalisation très strictes, à laisser désactivé

# Ignorer les motifs de syntaxe spécifiques à JSX/MDX
# `import ...`, `export ...`
# `<Component ... />`
# `<Component>...</Component>`
# `{ ... }`
TokenIgnores = (?sm)((?:import|export) .+?$), \
(?<!`)(<\w+ ?.+ ?\/>)(?!`), \
(<[A-Z]\w+>.+?<\/[A-Z]\w+>)

# Exclure les JSX multilignes et les accolades
# `<Component \n ... />`
BlockIgnores = (?sm)^(<\w+\n .*\s\/>)$, \
(?sm)^({.+.*})
```

Pour ajouter votre propre vocabulaire à la configuration par défaut, créez un répertoire `styles/config/vocabularies/Mintlify` avec les fichiers `accept.txt` et `reject.txt`.

* `accept.txt` : Mots qui doivent être ignorés par le linter Vale. Par exemple, les noms de produits ou les termes peu courants.
* `reject.txt` : Mots qui doivent être considérés comme des erreurs. Par exemple, le jargon ou les mots qui ne conviennent pas au ton de votre documentation.

```text Example Vale file structure
/your-project
  |- docs.json
  |- .vale.ini
  |- styles/
    |- config/
      |- vocabularies/
        |- Mintlify/
          |- accept.txt
          |- reject.txt
  |- example-page.mdx
```

```text Example monorepo Vale file structure
/your-monorepo
  |- main.ts
  |- docs/
    |- docs.json
    |- .vale.ini
    |- styles/
      |- config/
      |- vocabularies/
        |- Mintlify/
          |- accept.txt
          |- reject.txt
    |- example-page.mdx
  |- test/
```

<Note>
  Pour des raisons de sécurité, les `stylesPath` absolus ou les `stylesPath` contenant des valeurs `..` ne sont pas pris en charge.

  Utilisez des chemins relatifs et veillez à inclure le `stylesPath` dans votre dépôt.
</Note>

<div id="packages">
  #### Packages
</div>

Vale prend en charge un large éventail de [packages](https://vale.sh/docs/keys/packages), qui peuvent être utilisés pour détecter les fautes d’orthographe et les erreurs de style. Tous les packages que vous incluez dans votre dépôt sous le bon `stylesPath` sont automatiquement installés et utilisés dans votre configuration Vale.

Pour les packages qui ne sont pas inclus dans votre dépôt, vous pouvez spécifier n’importe quel package du [registre de packages Vale](https://vale.sh/explorer) ; ils seront automatiquement téléchargés et utilisés dans votre configuration Vale.

<Note>
  Pour des raisons de sécurité, le téléchargement automatique de packages qui ne proviennent pas du [registre de packages Vale](https://vale.sh/explorer) n’est **pas** pris en charge.
</Note>

<div id="vale-with-mdx">
  #### Vale avec `MDX`
</div>

<Note>
  La prise en charge native de MDX nécessite Vale 3.10.0 ou version ultérieure. Vérifiez votre version de Vale avec `vale --version`.
</Note>

Pour utiliser les commentaires intégrés au document de Vale dans des fichiers MDX, utilisez des commentaires au format MDX `{/* ... */}` :

```mdx
{/* vale off */}

This text is ignored by Vale

{/* vale on */}
```

Vale reconnaît et prend automatiquement en compte ces commentaires dans les fichiers MDX, sans configuration supplémentaire. Utilisez des commentaires pour exclure les lignes ou sections qui doivent être ignorées par le linter.
