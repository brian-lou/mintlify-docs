Utilisez les vérifications CI pour analyser votre documentation à la recherche d’erreurs et fournir des avertissements avant le déploiement. Les vérifications CI Mintlify s’exécutent sur les pull requests visant une branche de déploiement configurée.

<div id="installation">
  ## Installation
</div>

Pour commencer, suivez les étapes indiquées sur la page [GitHub](/fr/deploy/github).

<Tip>
  Seul l&#39;accès au dépôt où se trouve le contenu de votre documentation est nécessaire. Il est donc fortement recommandé de n&#39;accorder l&#39;accès qu&#39;à ce dépôt.
</Tip>

## Configuration

Configurez les vérifications CI à exécuter lors d’un déploiement en vous rendant sur la page [Add-ons](https://dashboard.mintlify.com/products/addons) de votre tableau de bord. Activez les vérifications que vous souhaitez exécuter.

Lors de l’activation des vérifications, vous pouvez choisir de les exécuter au niveau `Warning` ou `Blocking`.

* Une vérification de niveau `Warning` n’indiquera jamais un statut d’échec, même en cas d’erreur ou de suggestions.
* Une vérification de niveau `Blocking` indiquera un statut d’échec en cas d’erreur ou de suggestions.

<div id="available-ci-checks">
  ## Contrôles CI disponibles
</div>

<div id="broken-links">
  ### Liens cassés
</div>

De la même manière que l&#39;[outil de vérification de liens en ligne de commande](/fr/installation#find-broken-links) fonctionne sur votre machine locale, le contrôle CI des liens cassés recherche automatiquement les liens internes brisés dans votre documentation.

Pour voir les résultats de ce contrôle, rendez-vous sur la page des résultats des contrôles GitHub pour un commit donné.

<div id="vale">
  ### Vale
</div>

[Vale](https://vale.sh/) est un linter de prose open source, basé sur des règles, qui prend en charge un large éventail de types de documents, y compris Markdown et MDX. Utilisez Vale pour vérifier la cohérence du style et du ton de votre documentation.

Mintlify permet d’exécuter automatiquement Vale dans un contrôle CI et d’afficher les résultats en tant que statut de vérification.

<div id="configuration">
  #### Configuration
</div>

Si vous avez un fichier `.vale.ini` dans le répertoire racine de contenu de votre déploiement, le contrôle CI Vale utilise ce fichier de configuration ainsi que tous les fichiers de configuration situés dans le `stylesPath` que vous avez spécifié.

Si vous n’avez pas de fichier de configuration Vale, la configuration par défaut est automatiquement chargée.

```mdx Default vale.ini configuration expandable
# Styles de niveau supérieur
StylesPath = /app/styles
MinAlertLevel = suggestion
# Balises HTML en ligne à ignorer (code/tt pour les extraits de code, img/url pour les liens/images, a pour les balises d'ancrage)
IgnoredScopes = code, tt, img, url, a
SkippedScopes = script, style, pre, figure

# Vocabulaires
Vocab = Mintlify

# Paquets
Packages = MDX

# Correspondre uniquement aux fichiers MDX
[*.mdx]
BasedOnStyles = Vale
Vale.Terms = NO # Applique des règles de capitalisation très strictes, à désactiver

# Ignorer les motifs de syntaxe spécifiques à JSX/MDX
# `import ...`, `export ...`
# `<Component ... />`
# `<Component>...</Component>`
# `{ ... }`
TokenIgnores = (?sm)((?:import|export) .+?$), \
(?<!`)(<\w+ ?.+ ?\/>)(?!`), \
(<[A-Z]\w+>.+?<\/[A-Z]\w+>)

# Exclure les JSX multilignes et les accolades
# `<Component \n ... />`
BlockIgnores = (?sm)^(<\w+\n .*\s\/>)$, \
(?sm)^({.+.*})
```

Pour ajouter votre propre vocabulaire pour la configuration par défaut, créez un répertoire `styles/config/vocabularies/Mintlify` contenant les fichiers `accept.txt` et `reject.txt`.

* `accept.txt` : Mots qui doivent être ignorés par l’outil de vérification Vale, par exemple des noms de produits ou des termes peu courants.
* `reject.txt` : Mots qui doivent être signalés comme des erreurs, par exemple du jargon ou des mots qui ne sont pas appropriés au ton de votre documentation.

```text Example Vale file structure
/your-project
  |- docs.json
  |- .vale.ini
  |- styles/
    |- config/
      |- vocabularies/
        |- Mintlify/
          |- accept.txt
          |- reject.txt
  |- example-page.mdx
```

```text Example monorepo Vale file structure
/your-monorepo
  |- main.ts
  |- docs/
    |- docs.json
    |- .vale.ini
    |- styles/
      |- config/
      |- vocabularies/
        |- Mintlify/
          |- accept.txt
          |- reject.txt
    |- example-page.mdx
  |- test/
```

<Note>
  Pour des raisons de sécurité, les `stylesPath` absolus, ou les `stylesPath` contenant `..`, ne sont pas pris en charge.

  Utilisez des chemins relatifs et incluez le `stylesPath` dans votre dépôt.
</Note>

<div id="packages">
  #### Paquets
</div>

Vale prend en charge une gamme de [paquets](https://vale.sh/docs/keys/packages) qui peuvent être utilisés pour détecter les fautes d’orthographe et les erreurs de style. Tous les paquets que vous incluez dans votre dépôt sous le `stylesPath` approprié sont automatiquement installés et utilisés dans votre configuration Vale.

Pour les paquets qui ne sont pas inclus dans votre dépôt, vous pouvez spécifier n’importe quel paquet issu du [registre de paquets Vale](https://vale.sh/explorer) ; ils sont alors automatiquement téléchargés et utilisés dans votre configuration Vale.

<Note>
  Pour des raisons de sécurité, le téléchargement automatique de paquets qui ne proviennent pas du [registre de paquets Vale](https://vale.sh/explorer) n’est **pas** pris en charge.
</Note>

<div id="vale-with-mdx">
  #### Vale avec `MDX`
</div>

<Note>
  La prise en charge native de MDX nécessite Vale 3.10.0 ou une version ultérieure. Vérifiez votre version de Vale avec `vale --version`.
</Note>

Pour utiliser les commentaires intégrés de Vale dans les fichiers MDX, utilisez les commentaires au format MDX `{/* ... */}` :

```mdx
{/* vale off */}

This text is ignored by Vale

{/* vale on */}
```

Vale reconnaît et respecte automatiquement ces commentaires dans les fichiers MDX sans configuration supplémentaire. Utilisez les commentaires pour ignorer les lignes ou sections qui doivent être ignorées par le linter.
