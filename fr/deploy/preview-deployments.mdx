<Info>
  Les déploiements de prévisualisation sont disponibles avec les [offres Pro et Enterprise](https://mintlify.com/pricing?ref=preview-deployments).
</Info>

Les déploiements de prévisualisation vous permettent de voir à quoi ressembleront les modifications apportées à votre documentation avant leur mise en production. Chaque prévisualisation crée une URL partageable qui se met automatiquement à jour lorsque vous poussez de nouvelles modifications.

Les URL de prévisualisation sont visibles publiquement par défaut. Partagez un lien de prévisualisation avec toute personne qui doit examiner vos modifications.

<div id="create-preview-deployments">
  ## Créer des déploiements de prévisualisation
</div>

Les déploiements de prévisualisation sont créés automatiquement à partir de pull requests ou manuellement depuis votre tableau de bord.

<div id="automatic-previews">
  ### Aperçus automatiques
</div>

<Note>
  Des aperçus automatiques ne sont créés que pour les pull requests ciblant votre [branche de déploiement](/fr/guides/git-concepts#deployment-branch).
</Note>

Lorsque vous créez une pull request, le bot Mintlify ajoute automatiquement un lien pour afficher le déploiement de prévisualisation dans votre pull request. L’aperçu est mis à jour à chaque fois que vous poussez de nouveaux commits vers la branche.

<div id="manual-previews">
  ### Aperçus manuels
</div>

Vous pouvez créer manuellement un aperçu pour n&#39;importe quelle branche.

1. Accédez à votre [tableau de bord](https://dashboard.mintlify.com/).
2. Sélectionnez **Previews**.
3. Sélectionnez **Create custom preview**.
4. Saisissez le nom de la branche pour laquelle vous souhaitez générer un aperçu.
5. Sélectionnez **Create deployment**.

<div id="redeploy-a-preview">
  ## Redéployer un aperçu
</div>

Redéployez un aperçu pour actualiser le contenu ou réessayer après un échec de déploiement.

1. Sélectionnez l’aperçu dans votre [dashboard](https://dashboard.mintlify.com/).
2. Cliquez sur **Redeploy**.

<div id="preview-widget">
  ## Widget de prévisualisation
</div>

Le widget de prévisualisation apparaît sur les déploiements de prévisualisation pour vous aider à parcourir et à examiner les pages mises à jour. Le widget se présente sous la forme d’un bouton flottant dans le coin inférieur droit de votre déploiement de prévisualisation.

<Frame>
  <img src="/images/previews/widget-light.png" alt="Widget de prévisualisation déployé affichant la liste des fichiers modifiés." className="block dark:hidden" />

  <img src="/images/previews/widget-dark.png" alt="Widget de prévisualisation déployé affichant la liste des fichiers modifiés." className="hidden dark:block" />
</Frame>

1. Cliquez sur le widget pour afficher tous les fichiers ajoutés, modifiés ou supprimés dans la prévisualisation.
2. Cliquez sur un fichier pour afficher les modifications sur la page correspondante.
3. Utilisez la barre de recherche pour filtrer la liste des fichiers modifiés.

Le widget apparaît uniquement sur les déploiements de prévisualisation, et non sur votre site en production ou dans les prévisualisations locales.

<div id="restrict-access-to-preview-deployments">
  ## Restreindre l&#39;accès aux déploiements de prévisualisation
</div>

Par défaut, les déploiements de prévisualisation sont accessibles publiquement à toute personne disposant du lien. Vous pouvez en restreindre l’accès aux membres authentifiés de votre organisation Mintlify.

1. Accédez à la section **Previews** dans la page [Add-ons](https://dashboard.mintlify.com/products/addons) de votre tableau de bord.
2. Cliquez sur le bouton bascule **Preview authentication** pour activer ou désactiver l’authentification pour les aperçus.

<div id="troubleshooting-preview-deployments">
  ## Dépannage des déploiements de prévisualisation
</div>

Si votre déploiement de prévisualisation échoue, essayez les étapes de dépannage suivantes.

* **Consulter les journaux de build** : Dans votre [dashboard](https://dashboard.mintlify.com/), allez dans **Previews** et cliquez sur la prévisualisation ayant échoué. Les journaux de déploiement affichent les erreurs à l’origine de l’échec.
* **Vérifier votre configuration** :
  * Syntaxe `docs.json` non valide
  * Chemins de fichiers manquants ou incorrects référencés dans votre navigation
  * Frontmatter non valide dans les fichiers MDX
  * Liens d’images brisés ou fichiers d’images manquants
* **Valider en local** : Exécutez `mint dev` en local pour détecter les erreurs de build avant de pousser vers le dépôt.
* **Vérifier les modifications récentes** : Passez en revue les commits les plus récents de votre branche pour identifier les modifications ayant provoqué l’échec du build.
