Pour héberger votre documentation sur un domaine personnalisé :

1. Ajoutez votre domaine dans votre dashboard.
2. Configurez les paramètres DNS chez votre fournisseur de domaine.
3. Laissez le temps à la propagation DNS de s’effectuer et aux certificats TLS d’être provisionnés automatiquement.

<Info>
  Vous souhaitez configurer un sous-chemin comme `example.com/docs` ? Consultez [/docs subpath](/fr/deploy/docs-subpath).
</Info>

<div id="add-your-custom-domain">
  ## Ajoutez votre domaine personnalisé
</div>

1. Accédez à la page [Configuration du domaine personnalisé](https://dashboard.mintlify.com/settings/deployment/custom-domain) dans votre dashboard.
2. Saisissez votre nom de domaine. Par exemple, `docs.example.com` ou `www.example.com`.
3. Cliquez sur **Add domain**.

<div id="configure-your-dns">
  ## Configurez votre DNS
</div>

1. Sur le site web de votre fournisseur de domaine, accédez aux paramètres DNS de votre domaine.
2. Créez un nouvel enregistrement DNS avec les valeurs suivantes :

```text
CNAME | docs | cname.mintlify-dns.com.
```

<Tip>
  Chaque fournisseur de domaine a sa propre méthode pour ajouter des enregistrements DNS. Consultez la documentation de votre fournisseur de domaine pour obtenir des instructions précises.
</Tip>

<div id="dns-propagation">
  ### Propagation DNS
</div>

Les modifications DNS prennent généralement entre 1 et 24 heures pour se propager dans le monde entier, mais cela peut aller jusqu’à 48 heures dans certains cas. Vous pouvez vérifier que votre configuration DNS est correcte à l’aide de [DNSChecker](https://dnschecker.org).

Une fois vos enregistrements DNS actifs, votre documentation est d’abord accessible en HTTP. Le HTTPS est disponible une fois que Vercel a provisionné votre certificat TLS.

<div id="automatic-tls-provisioning">
  ### Provisionnement TLS automatique
</div>

Une fois vos enregistrements DNS propagés et correctement résolus, Vercel provisionne automatiquement un certificat SSL/TLS gratuit pour votre domaine via Let&#39;s Encrypt.

Cette opération s’effectue généralement dans les heures qui suivent la propagation des enregistrements DNS, bien qu’elle puisse prendre jusqu’à 24 heures dans de rares cas. Les certificats sont automatiquement renouvelés avant leur expiration.

<div id="caa-records">
  ### Enregistrements CAA
</div>

Si votre domaine utilise des enregistrements CAA (Certification Authority Authorization), vous devez autoriser Let&#39;s Encrypt à émettre des certificats pour ce domaine. Ajoutez l’enregistrement CAA suivant à vos paramètres DNS :

```text
0 issue "letsencrypt.org"
```

<div id="reserved-paths">
  ### Chemins réservés
</div>

Le chemin `/.well-known/acme-challenge` est réservé à la validation des certificats et ne peut faire l’objet ni d’une redirection ni d’une réécriture. Si vous avez configuré des redirections ou des réécritures pour ce chemin, le provisionnement des certificats échouera.

<div id="provider-specific-settings">
  ### Paramètres spécifiques au fournisseur
</div>

<AccordionGroup>
  <Accordion title="Vérification Vercel">
    Si Vercel est votre fournisseur de domaine, vous devez ajouter un enregistrement `TXT` de vérification. Ces informations apparaissent dans votre dashboard après l’ajout de votre domaine personnalisé et vous sont également envoyées par e-mail.
  </Accordion>

  <Accordion title="Mode de chiffrement de Cloudflare">
    Si Cloudflare est votre fournisseur DNS, vous devez activer le mode « Full (strict) » dans les paramètres de chiffrement SSL/TLS. Désactivez également « Always Use HTTPS » dans vos paramètres Edge Certificates. La redirection HTTPS de Cloudflare empêchera Let’s Encrypt de valider votre domaine pendant le provisionnement des certificats.
  </Accordion>
</AccordionGroup>

<div id="set-a-canonical-url">
  ## Définir une URL canonique
</div>

Après avoir configuré votre DNS, définissez une URL canonique afin que les moteurs de recherche indexent le domaine de votre choix. Une URL canonique indique aux moteurs de recherche quelle version de votre documentation doit être considérée comme principale. Cela améliore le SEO lorsque votre documentation est accessible depuis plusieurs URL et évite les problèmes de contenu dupliqué.

Ajoutez la balise méta `canonical` à votre `docs.json` :

```json
"seo": {
    "metatags": {
        "canonical": "https://www.your-custom-domain-here.com"
    }
}
```

Remplacez `https://www.your-custom-domain-here.com` par votre véritable domaine personnalisé. Par exemple, si votre domaine personnalisé est `docs.mintlify.com`, vous utiliserez :

```json
"seo": {
    "metatags": {
        "canonical": "https://docs.mintlify.com"
    }
}
```
