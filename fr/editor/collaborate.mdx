Collaborez avec votre équipe sur la documentation à l’aide de workflows basés sur des branches, de pull requests et de déploiements de prévisualisation.

Si vous n’êtes pas à l’aise avec Git, consultez la page [Concepts Git](/fr/guides/git-concepts).

<div id="branch-based-collaboration">
  ## Collaboration basée sur les branches
</div>

Utilisez des branches pour travailler sur des mises à jour de la documentation en parallèle, sans affecter votre site en production.

<div id="why-use-branches">
  ### Pourquoi utiliser des branches
</div>

* **Isoler les modifications** : Travaillez sur des mises à jour sans impacter votre documentation publiée.
* **Relire avant de publier** : Obtenez des retours de l’équipe avant que les modifications ne soient mises en ligne.
* **Travail en parallèle** : Plusieurs membres de l’équipe peuvent travailler simultanément sur différentes branches.

<div id="recommended-workflow">
  ## Workflow recommandé
</div>

Utilisez des pull requests pour proposer des modifications et collaborer avec votre équipe avant de fusionner dans votre documentation en production. Ce workflow garantit que votre équipe passe en revue les modifications avant la publication et permet de conserver un historique clair des mises à jour.

<Steps>
  <Step title="Créer une pull request">
    Créez une pull request depuis l&#39;éditeur lorsque vous êtes prêt à publier vos modifications. Consultez <a href="/fr/editor/publish">Publier des modifications dans l’éditeur web</a> pour plus d&#39;informations sur l&#39;utilisation des pull requests.
  </Step>

  <Step title="Examiner les pull requests">
    Examinez les pull requests dans votre plateforme Git, comme GitHub ou GitLab.
  </Step>

  <Step title="Répondre aux retours">
    Lorsque les relecteurs demandent des modifications, effectuez les changements demandés et enregistrez vos modifications. Les changements supplémentaires sont automatiquement envoyés vers la pull request existante.
  </Step>

  <Step title="Fusionner les pull requests">
    Fusionnez votre pull request une fois que vous avez traité toutes les modifications demandées, que les relecteurs requis ont approuvé la pull request et que tous les contrôles automatisés ont abouti.
  </Step>
</Steps>

<div id="preview-deployments">
  ## Déploiements de prévisualisation
</div>

Les déploiements de prévisualisation créent des URL temporaires où vous pouvez voir le rendu de vos modifications avant leur mise en production. Utilisez les déploiements de prévisualisation pour recueillir des commentaires sur vos modifications.

<div id="access-preview-deployments">
  ### Accéder aux déploiements de prévisualisation
</div>

1. Cliquez sur **Share** dans la barre d’outils de l’éditeur.
2. Cliquez sur **Preview** pour ouvrir le déploiement de prévisualisation dans un nouvel onglet.
3. L’URL de prévisualisation affiche votre documentation avec toutes les modifications enregistrées.

<div id="share-previews">
  ### Partager des aperçus
</div>

Partagez l’URL du déploiement de prévisualisation avec les membres de votre équipe pour recueillir des retours. Les aperçus sont automatiquement mis à jour lorsque vous enregistrez de nouvelles modifications.

<div id="preview-authentication">
  ### Authentification des aperçus
</div>

Les URL d’aperçu sont accessibles publiquement par défaut. Activez l’authentification des aperçus sur la page [Add-ons](https://dashboard.mintlify.com/products/addons) de votre tableau de bord afin de restreindre l’accès aux membres authentifiés de votre organisation.

<div id="share-editor-links">
  ## Partager des liens de l’éditeur
</div>

Partagez un lien direct vers une page spécifique de l’éditeur avec vos collègues. Utilisez les liens de l’éditeur pour collaborer aux mises à jour et apporter des modifications aux pages.

Quand vous ouvrez une page, l’éditeur enregistre le chemin de la page dans l’URL. Copiez l’URL à partir de la barre d’adresse de votre navigateur pour la partager avec les collègues qui ont accès à l’éditeur.

Le format de l’URL est :

```
https://dashboard.mintlify.com/{org}/{project}/editor/{branch}?file={filepath}
```

Par exemple, `https://dashboard.mintlify.com/acme/docs/editor/main?file=guides/quickstart.mdx` ouvre `quickstart.mdx` sur la branche `main`.

Toute personne ayant accès à votre organisation Mintlify peut utiliser ce lien pour ouvrir le fichier directement dans l&#39;éditeur.

<Tip>
  Lorsque vous partagez une page, précisez sur quelle branche vous travaillez afin qu&#39;elles puissent vérifier qu&#39;elles consultent la bonne version.
</Tip>
