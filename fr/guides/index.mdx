Les guides de cette section proposent des conseils pour créer une documentation qui aide vos utilisateurs à atteindre leurs objectifs. Que vous partiez de zéro ou que vous amélioriez une documentation existante, ces guides vous aident à planifier, rédiger et maintenir votre documentation.

Avant tout, tenez compte des besoins et des objectifs de vos utilisateurs. Documentez ce qui les aide à utiliser votre produit et à reprendre leurs tâches.

<div id="topics">
  ## Thèmes
</div>

<div id="ai-tools">
  ### Outils d’IA
</div>

Utilisez des outils d’IA pour accélérer la création de votre documentation.

* [Automate documentation updates](/fr/guides/automate-agent) : tutoriel qui vous apprend à configurer des mises à jour automatisées de la documentation à l’aide de l’agent.
* [Build an in-app assistant](/fr/guides/assistant-embed) : tutoriel qui vous apprend à ajouter un chatbot d’IA dans une application React pour aider les utilisateurs à trouver des réponses dans votre documentation.
* [Claude Code](/fr/guides/claude-code), [Cursor](/fr/guides/cursor), [Windsurf](/fr/guides/windsurf) : guides pour utiliser des assistants de développement basés sur l’IA afin de maintenir votre documentation.
* [GEO](/fr/guides/geo) : bonnes pratiques pour optimiser votre documentation pour les moteurs de recherche et de réponse propulsés par l’IA.

<div id="api-documentation">
  ### Documentation d’API
</div>

Créez une documentation d’API qui permet aux utilisateurs de tester et d’apprendre à utiliser votre API, tout en restant facile à maintenir.

* [Migrer de MDX vers OAS](/fr/guides/migrating-from-mdx): Faites passer votre documentation d’API de pages MDX distinctes à des pages générées automatiquement à partir d’une spécification OpenAPI.

<div id="best-practices">
  ### Bonnes pratiques
</div>

Faites de votre documentation une référence.

* [Accessibilité](/fr/guides/accessibility) : Rendez votre documentation accessible au plus grand nombre d’utilisateurs possible.
* [Types de contenu](/fr/guides/content-types) : Choisissez le bon format pour les tutoriels, guides pratiques, références et explications.
* [Modèles de contenu](/fr/guides/content-templates) : Copiez et modifiez des modèles pour chaque type de contenu.
* [Améliorer votre documentation](/fr/guides/improving-docs) : Utilisez les données et les retours pour améliorer en continu votre documentation.
* [Internationalisation](/fr/guides/internationalization) : Configurez une documentation multilingue pour toucher un public international.
* [Liens](/fr/guides/linking) : Créez des liens internes, référencez des endpoints d’API et maintenez l’intégrité des liens dans l’ensemble de votre documentation.
* [Maintenance](/fr/guides/maintenance) : Gardez votre documentation fiable et à jour.
* [Médias](/fr/guides/media) : Ajoutez efficacement des images, des vidéos et d’autres médias tout en maîtrisant la charge de maintenance.
* [Organisation de la navigation](/fr/guides/navigation) : Concevez une architecture de l’information adaptée à vos utilisateurs.
* [SEO](/fr/guides/seo) : Optimisez votre documentation pour les moteurs de recherche.
* [Style et ton](/fr/guides/style-and-tone) : Rédigez avec un ton cohérent.
* [Comprendre votre audience](/fr/guides/understand-your-audience) : Analysez et prenez en compte les besoins et objectifs de vos utilisateurs.

<div id="git-workflows">
  ### Flux de travail Git
</div>

Comprenez Git pour tirer le meilleur parti de Mintlify et d’une approche « docs-as-code » de la documentation.

* [Concepts de Git](/fr/guides/git-concepts) : Apprenez les bases de Git pour la documentation.
* [Branches](/fr/guides/branches) : Utilisez les branches pour gérer les modifications de la documentation.

<div id="use-cases">
  ### Cas d’utilisation
</div>

Découvrez comment Mintlify prend en charge différents cas d’utilisation et trouvez une solution qui vous convient.

* [Créer une documentation pour développeurs](/fr/guides/developer-documentation) : Aidez vos utilisateurs à tirer le meilleur parti de votre produit ou de votre API grâce à une documentation pour développeurs qui répond aux questions et leur permet de se remettre rapidement à leurs tâches principales.
* [Créer une base de connaissances](/fr/guides/knowledge-base) : Mettez en place une base de connaissances interne pour centraliser les informations de votre équipe, améliorer la recherche et réduire la charge de maintenance.
* [Créer un centre d’assistance](/fr/guides/support-center) : Créez un centre d’assistance en libre-service qui aide les clients à trouver des réponses, réduit le volume de tickets et améliore la satisfaction client.
