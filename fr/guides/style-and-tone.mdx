<Tip>
  Cette page explique les choix stylistiques, les erreurs courantes et donne des conseils pratiques pour rédiger une documentation technique.
</Tip>

<div id="writing-principles">
  ## Principes de rédaction
</div>

* **Soyez concis.** Les gens lisent la documentation pour atteindre un objectif. Allez vite à l’essentiel.
* **Privilégiez la clarté à l’effet de style.** Soyez simple, direct, et évitez le jargon ou les structures de phrases complexes.
* **Utilisez la voix active.** Au lieu de dire « A configuration file should be created », utilisez « Create a configuration file. »
* **Rendez le texte facile à parcourir.** Utilisez des titres pour orienter les lecteurs. Divisez les paragraphes trop denses. Utilisez des puces et des listes pour faciliter la lecture en diagonale.
* **Rédigez à la deuxième personne.** Le fait de s’adresser directement au lecteur facilite le suivi des instructions et rend la documentation plus personnelle.

<div id="common-writing-mistakes">
  ## Erreurs d’écriture courantes
</div>

* **Fautes d’orthographe et de grammaire.** Même quelques fautes d’orthographe et de grammaire dans votre documentation peuvent suffire à la rendre moins crédible et plus difficile à lire.
* **Terminologie incohérente.** Utiliser le terme « API key » dans un paragraphe puis « API token » dans le suivant rend la lecture difficile pour les utilisateurs.
* **Terminologie centrée sur le produit.** Vos utilisateurs n’ont pas la même connaissance de votre produit que vous. Utilisez un langage qui leur est familier.
* **Colloquialismes.** En particulier pour la localisation, les tournures trop familières nuisent à la clarté.

<div id="tips-for-enforcing-style">
  ## Conseils pour faire respecter le style
</div>

Utilisez des guides de style existants pour standardiser votre documentation :

* [Microsoft Style Guide](https://learn.microsoft.com/en-us/style-guide/welcome/)
* [Splunk Style Guide](https://docs.splunk.com/Documentation/StyleGuide/current/StyleGuide/Howtouse)
* [Google Developer Documentation Style Guide](https://developers.google.com/style)

Une fois que vous avez défini les principes rédactionnels que vous voulez appliquer, automatisez autant que possible. Vous pouvez utiliser des [contrôles CI](/fr/deploy/ci) ou des linters comme [Vale](https://vale.sh).
