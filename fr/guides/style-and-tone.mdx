</Tip>

<div id="writing-principles">
  ## Principes de rédaction
</div>

* **Soyez concis.** Les lecteurs consultent la documentation pour atteindre un objectif. Allez rapidement à l’essentiel.
* **Privilégiez la clarté à l’ingéniosité.** Soyez simple, direct et évitez le jargon ou les tournures de phrase complexes.
* **Utilisez la voix active.** Au lieu de dire « Un fichier de configuration doit être créé », utilisez « Créez un fichier de configuration. »
* **Facilitez la lecture en diagonale.** Utilisez des titres pour orienter les lecteurs. Aérez les paragraphes trop denses. Utilisez des puces et des listes pour rendre les informations plus faciles à parcourir.
* **Écrivez à la deuxième personne.** En vous adressant directement à votre lecteur, vous facilitez le suivi des instructions et rendez la documentation plus personnelle.

<div id="common-writing-mistakes">
  ## Erreurs de rédaction courantes
</div>

* **Fautes d’orthographe et de grammaire.** Même quelques fautes d’orthographe et de grammaire dans votre documentation la rendent moins crédible et plus difficile à lire.
* **Terminologie incohérente.** Appeler un élément « clé API » dans un paragraphe puis « jeton API » dans le suivant complique la compréhension pour les utilisateurs.
* **Terminologie centrée sur le produit.** Vos utilisateurs n’ont pas tout le contexte de votre produit. Utilisez un langage qui leur est familier.
* **Expressions familières.** En particulier dans le cadre de la localisation, les expressions familières nuisent à la clarté.

<div id="tips-for-enforcing-style">
  ## Conseils pour faire respecter le style
</div>

Appuyez-vous sur des guides de style existants pour harmoniser votre documentation :

* [Microsoft Style Guide](https://learn.microsoft.com/en-us/style-guide/welcome/)
* [Splunk Style Guide](https://docs.splunk.com/Documentation/StyleGuide/current/StyleGuide/Howtouse)
* [Google Developer Documentation Style Guide](https://developers.google.com/style)

Une fois que vous avez défini les principes de rédaction à appliquer, automatisez autant que possible. Vous pouvez utiliser des [contrôles CI](/fr/deploy/ci) ou des linters comme [Vale](https://vale.sh).
