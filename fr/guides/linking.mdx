Des liens bien conçus créent une expérience de documentation cohérente qui aide les utilisateurs à découvrir du contenu associé et à naviguer efficacement. Trop de liens ou des liens brisés peuvent dérouter les utilisateurs et rendre votre documentation moins efficace. Ce guide explique comment créer et maintenir des liens tout au long de votre documentation.

<div id="internal-links">
  ## Liens internes
</div>

Créez des liens vers d&#39;autres pages de votre documentation en utilisant des chemins relatifs à la racine. Ces chemins commencent à la racine de votre répertoire de documentation et fonctionnent de manière cohérente, quel que soit l&#39;emplacement de la page qui contient le lien.

```mdx
* [Quickstart guide](/quickstart)
* [API overview](/api-playground/overview)
* [Custom components](/customize/react-components)
```

* [Guide de démarrage rapide](/fr/quickstart)
* [Aperçu de l’API](/fr/api-playground/overview)
* [Composants personnalisés](/fr/customize/react-components)

<div id="anchor-links">
  ## Liens d’ancrage
</div>

Les liens d’ancrage vous permettent de créer un lien directement vers des sections précises d’une page. Chaque en‑tête génère automatiquement un lien d’ancrage à partir de son texte.

<div id="link-to-headers-on-the-same-page">
  ### Lien vers des en-têtes sur la même page
</div>

Référez-vous aux en-têtes de la page actuelle en utilisant le symbole # :

```mdx
[Jump to best practices](#best-practices)
```

[Accéder aux bonnes pratiques](#best-practices)

<div id="link-to-headers-on-other-pages">
  ### Créer des liens vers les en-têtes d&#39;autres pages
</div>

Combinez les chemins de page avec des liens d&#39;ancrage.

```mdx
* [Customize your playground](/api-playground/overview#customize-your-playground)
* [Cards properties](/components/cards#properties)
```

* [Personnaliser votre bac à sable](/fr/api-playground/overview#customize-your-playground)
* [Propriétés des cartes](/fr/components/cards#properties)

<div id="how-anchor-links-are-generated">
  ### Comment sont générés les liens d’ancrage
</div>

Les liens d’ancrage sont automatiquement générés à partir du texte des titres.

* Convertir en minuscules
* Remplacer les espaces par des tirets
* Supprimer les caractères spéciaux
* Conserver les chiffres et les lettres

| Texte du titre | Lien d’ancrage |
|-------------|-------------|
| `## Getting Started` | `#getting-started` |
| `### API Authentication` | `#api-authentication` |
| `#### Step 1: Install` | `#step-1-install` |

<Note>
  Les titres avec la prop `noAnchor` ne génèrent pas de liens d’ancrage. Voir [Format text](/fr/create/text#disabling-anchor-links) pour plus de détails.
</Note>

<div id="link-to-api-endpoints">
  ## Créer des liens vers des endpoints d’API
</div>

Lorsque vous documentez des API, vous pouvez créer des liens vers des endpoints spécifiques depuis n’importe où dans votre documentation.

Créez des liens vers les pages d’endpoints d’API à l’aide de leur chemin dans la navigation.

<div id="link-to-external-pages">
  ## Liens vers des pages externes
</div>

Lorsque vous créez un lien vers des ressources externes, indiquez clairement que ce lien mène en dehors de votre documentation.

```mdx
Learn more about [Markdown syntax](https://www.markdownguide.org/) (external link).

See the [OpenAPI specification](https://swagger.io/specification/) in the Swagger documentation for details.
```

<div id="best-practices">
  ## Bonnes pratiques
</div>

<div id="write-descriptive-link-text">
  ### Rédigez un texte de lien descriptif
</div>

Utilisez un texte clair et descriptif qui indique ce que les utilisateurs trouveront lorsqu&#39;ils cliqueront dessus.

<CodeGroup>
  ```mdx Bons exemples
  Voir [Pages masquées](/organize/hidden-pages) pour plus d’informations.
  [Configurer des domaines personnalisés](/customize/custom-domain)
  ```

  ```mdx À éviter
  [Cliquez ici](/api-playground/overview)
  [En savoir plus](/deploy/deployments)
  [Voir cette page](/customize/custom-domain)
  ```
</CodeGroup>

<div id="create-topic-clusters">
  ### Créer des groupes thématiques
</div>

Reliez entre eux les contenus liés pour aider les utilisateurs à découvrir des informations pertinentes.

```mdx
## Related topics

- [API authentication](/api-playground/overview#authentication)
- [Adding SDK examples](/api-playground/adding-sdk-examples)
- [Managing page visibility](/api-playground/managing-page-visibility)
```

<div id="use-contextual-links">
  ### Utiliser des liens contextuels
</div>

Ajoutez des liens au fil du contenu lorsqu’ils apportent une réelle valeur.

```mdx
To customize your documentation appearance, configure [themes](/customize/themes) 
and [fonts](/customize/fonts) in your settings. You can also add 
[custom scripts](/customize/custom-scripts) for advanced functionality.
```

<div id="link-to-prerequisites">
  ### Lien vers les prérequis
</div>

Aidez les utilisateurs à se préparer en ajoutant des liens vers le contenu prérequis :

```mdx
## Prerequisites

Before deploying your documentation, ensure you have:

- Completed the [quickstart guide](/quickstart)
- Configured your [custom domain](/customize/custom-domain)
- Set up [authentication](/deploy/authentication-setup) if needed
```

<div id="avoid-circular-links">
  ### Évitez les liens circulaires
</div>

Ne créez pas de liens qui renvoient les utilisateurs sans cesse entre les mêmes pages.

<div id="check-for-broken-links">
  ### Vérifiez les liens rompus
</div>

Utilisez la CLI Mintlify pour identifier les liens rompus dans votre documentation.

```bash
mint broken-links
```

<div id="update-links-when-reorganizing">
  ### Mettre à jour les liens lors de la réorganisation
</div>

Lorsque vous déplacez ou renommez des pages :

1. Mettez à jour le chemin de la page dans votre configuration de navigation.
2. Configurez des redirections de l’ancien chemin vers le nouveau.
3. Recherchez dans votre documentation les références à l’ancien chemin.
4. Mettez à jour tous les liens internes pour utiliser le nouveau chemin.
5. Exécutez `mint broken-links` pour vérifier que tous les liens fonctionnent.

<div id="use-redirects-for-moved-content">
  ### Utilisez des redirections pour le contenu déplacé
</div>

Lorsque vous déplacez définitivement du contenu, ajoutez des redirections pour éviter les liens brisés.

```json
{
  "redirects": [
    {
      "source": "/old-path",
      "destination": "/new-path"
    }
  ]
}
```

Consultez [Redirects](/fr/create/redirects) pour plus d’informations.
