Des liens bien conçus offrent une expérience documentaire cohérente, qui aide les utilisateurs à découvrir du contenu connexe et à naviguer facilement. À l’inverse, un trop grand nombre de liens ou des liens rompus peut les dérouter et réduire l’efficacité de votre documentation. Ce guide explique comment créer et maintenir des liens dans l’ensemble de votre documentation.

<div id="internal-links">
  ## Liens internes
</div>

Créez des liens vers d’autres pages de votre documentation à l’aide de chemins relatifs à la racine. Ces chemins commencent à la racine de votre répertoire de documentation et fonctionnent de manière cohérente, quel que soit l’emplacement de la page contenant le lien.

```mdx
* [Quickstart guide](/quickstart)
* [API overview](/api-playground/overview)
* [Custom components](/customize/react-components)
```

* [Guide de démarrage rapide](/fr/quickstart)
* [Vue d’ensemble de l’API](/fr/api-playground/overview)
* [Composants personnalisés](/fr/customize/react-components)

<div id="anchor-links">
  ## Liens d’ancrage
</div>

Les liens d’ancrage vous permettent de créer des liens directs vers des sections spécifiques d’une page. Chaque titre génère automatiquement un lien d’ancrage à partir de son texte.

<div id="link-to-headers-on-the-same-page">
  ### Lien vers les titres de la même page
</div>

Créez un lien vers les titres de la page actuelle à l’aide du symbole dièse :

```mdx
[Jump to best practices](#best-practices)
```

[Voir les bonnes pratiques](#best-practices)

<div id="link-to-headers-on-other-pages">
  ### Créer des liens vers des titres sur d&#39;autres pages
</div>

Combinez les chemins de page avec des liens d’ancrage.

```mdx
* [Customize your playground](/api-playground/overview#customize-your-playground)
* [Cards properties](/components/cards#properties)
```

* [Personnaliser votre playground](/fr/api-playground/overview#customize-your-playground)
* [Propriétés des cartes](/fr/components/cards#properties)

<div id="how-anchor-links-are-generated">
  ### Comment les liens d’ancrage sont générés
</div>

Les liens d’ancrage sont automatiquement créés à partir du texte des titres.

* Convertir en minuscules
* Remplacer les espaces par des tirets
* Supprimer les caractères spéciaux
* Conserver les chiffres et les lettres

| Texte du titre           | Lien d’ancrage        |
| ------------------------ | --------------------- |
| `## Getting Started`     | `#getting-started`    |
| `### API Authentication` | `#api-authentication` |
| `#### Step 1: Install`   | `#step-1-install`     |

<Note>
  Les titres avec la propriété `noAnchor` ne génèrent pas de liens d’ancrage. Consultez [Mettre en forme le texte](/fr/create/text#disabling-anchor-links) pour en savoir plus.
</Note>

<div id="link-to-api-endpoints">
  ## Lier des endpoints d’API
</div>

Lorsque vous documentez des API, vous pouvez créer des liens vers des endpoints spécifiques depuis n’importe où dans votre documentation.

Créez des liens vers les pages d’endpoint d’API à l’aide de leur chemin dans la navigation.

<div id="link-to-external-pages">
  ## Créer un lien vers des pages externes
</div>

Lorsque vous créez des liens vers des ressources externes, indiquez clairement qu’ils renvoient hors de votre documentation.

```mdx
Learn more about [Markdown syntax](https://www.markdownguide.org/) (external link).

See the [OpenAPI specification](https://swagger.io/specification/) in the Swagger documentation for details.
```

<div id="best-practices">
  ## Bonnes pratiques
</div>

<div id="write-descriptive-link-text">
  ### Rédigez un texte de lien descriptif
</div>

Utilisez un texte clair et descriptif qui indique ce que les utilisateurs trouveront en cliquant.

<CodeGroup>
  ```mdx Bons exemples
  Consultez [Pages masquées](/organize/hidden-pages) pour en savoir plus.
  [Configurer des domaines personnalisés](/customize/custom-domain)
  ```

  ```mdx À éviter
  [Cliquez ici](/api-playground/overview)
  [En savoir plus](/deploy/deployments)
  [Voir cette page](/customize/custom-domain)
  ```
</CodeGroup>

<div id="create-topic-clusters">
  ### Créez des ensembles thématiques
</div>

Reliez les contenus associés entre eux pour aider les utilisateurs à découvrir des informations pertinentes.

```mdx
## Sujets connexes

- [Authentification API](/api-playground/overview#authentication)
- [Ajouter des exemples SDK](/api-playground/adding-sdk-examples)
- [Gérer la visibilité des pages](/api-playground/managing-page-visibility)
```

<div id="use-contextual-links">
  ### Utiliser des liens contextuels
</div>

Ajoutez des liens de manière naturelle dans le contenu lorsqu’ils apportent une réelle valeur.

```mdx
To customize your documentation appearance, configure [themes](/customize/themes) 
and [fonts](/customize/fonts) in your settings. You can also add 
[custom scripts](/customize/custom-scripts) for advanced functionality.
```

<div id="link-to-prerequisites">
  ### Lien vers les prérequis
</div>

Aidez les utilisateurs à se préparer en ajoutant des liens vers le contenu prérequis :

```mdx
## Prerequisites

Before deploying your documentation, ensure you have:

- Completed the [quickstart guide](/quickstart)
- Configured your [custom domain](/customize/custom-domain)
- Set up [authentication](/deploy/authentication-setup) if needed
```

<div id="avoid-circular-links">
  ### Évitez les liens circulaires
</div>

Ne créez pas de liens qui renvoient les utilisateurs en boucle entre les mêmes pages.

<div id="check-for-broken-links">
  ### Vérifiez les liens rompus
</div>

Utilisez la CLI Mintlify pour repérer les liens rompus dans votre documentation.

```bash
mint broken-links
```

<div id="update-links-when-reorganizing">
  ### Mettre à jour les liens en cas de réorganisation
</div>

Lorsque vous déplacez ou renommez des pages :

1. Mettez à jour le chemin de la page dans votre configuration de navigation.
2. Mettez en place des redirections de l’ancien chemin vers le nouveau.
3. Recherchez dans votre documentation les références à l’ancien chemin.
4. Mettez à jour tous les liens internes pour utiliser le nouveau chemin.
5. Exécutez `mint broken-links` pour vérifier que tous les liens fonctionnent.

<div id="use-redirects-for-moved-content">
  ### Utiliser des redirections pour le contenu déplacé
</div>

Lorsque vous déplacez définitivement du contenu, ajoutez des redirections pour éviter les liens rompus.

```json
{
  "redirects": [
    {
      "source": "/old-path",
      "destination": "/new-path"
    }
  ]
}
```

Consultez [Redirections](/fr/create/redirects) pour plus d’informations.
