L’internationalisation (i18n) consiste à concevoir un logiciel ou un contenu pour qu’il fonctionne dans différentes langues et différents paramètres régionaux. Ce guide explique comment structurer les fichiers, configurer la navigation et gérer efficacement les traductions afin d’aider les utilisateurs à consulter votre documentation dans la langue de leur choix et d’élargir votre portée à l’international.

<div id="file-structure">
  ## Structure des fichiers
</div>

Organisez le contenu traduit dans des répertoires spécifiques à chaque langue afin de faciliter la maintenance de votre documentation et d’organiser votre navigation par langue.

Créez un répertoire distinct pour chaque langue à l’aide des [codes de langue ISO 639-1](https://en.wikipedia.org/wiki/List_of_ISO_639-1_codes). Placez les fichiers traduits dans ces répertoires en conservant la même structure que pour la langue par défaut.

<Expandable title="codes de langue pris en charge">
  * `ar` - Arabe
  * `cs` - Tchèque
  * `cn` ou `zh-Hans` - Chinois (simplifié)
  * `zh-Hant` - Chinois (traditionnel)
  * `de` - Allemand
  * `en` - Anglais
  * `es` - Espagnol
  * `fr` - Français
  * `he` - Hébreu
  * `hi` - Hindi
  * `id` - Indonésien
  * `it` - Italien
  * `jp` - Japonais
  * `ko` - Coréen
  * `lv` - Letton
  * `nl` - Néerlandais
  * `no` - Norvégien
  * `pl` - Polonais
  * `pt` ou `pt-BR` - Portugais
  * `ro` - Roumain
  * `ru` - Russe
  * `sv` - Suédois
  * `tr` - Turc
  * `ua` - Ukrainien
  * `uz` - Ouzbek
  * `vi` - Vietnamien
</Expandable>

```text Example file structure
docs/
├── index.mdx                    # Anglais (par défaut)
├── quickstart.mdx
├── fr/
│   ├── index.mdx               # Français
│   ├── quickstart.mdx
├── es/
│   ├── index.mdx               # Espagnol
│   ├── quickstart.mdx
└── zh/
    ├── index.mdx               # Chinois
    └── quickstart.mdx
```

<Tip>
  Conservez les mêmes noms de fichiers et la même structure de répertoires dans toutes les langues. Cela facilite la gestion des traductions et le repérage du contenu manquant.
</Tip>


<div id="configure-the-language-switcher">
  ## Configurer le sélecteur de langue
</div>

Pour ajouter un sélecteur de langue à votre documentation, configurez le tableau `languages` dans la section de navigation de votre `docs.json`.

```json docs.json
{
  "navigation": {
    "languages": [
      {
        "language": "en",
        "groups": [
          {
            "group": "Getting started",
            "pages": ["index", "quickstart"]
          }
        ]
      },
      {
        "language": "es",
        "groups": [
          {
            "group": "Comenzando",
            "pages": ["es/index", "es/quickstart"]
          }
        ]
      }
    ]
  }
}
```

Chaque entrée de langue dans le tableau `languages` requiert :

* `language` : code de langue ISO 639-1
* Structure de navigation complète
* Chemins vers les fichiers traduits

La structure de navigation peut varier selon la langue afin de s’adapter aux besoins de contenu propres à chacune.


<div id="set-default-language">
  ### Définir la langue par défaut
</div>

La première langue du tableau `languages` est automatiquement définie comme langue par défaut. Pour en utiliser une autre par défaut, réorganisez le tableau ou ajoutez la propriété `default` :

```json docs.json
{
  "navigation": {
    "languages": [
      {
        "language": "es",
        "groups": [...]
      },
      {
        "language": "en",
        "groups": [...]
      }
    ]
  }
}
```

Sinon, utilisez la propriété `default` pour redéfinir l’ordre :

```json docs.json
{
  "navigation": {
    "languages": [
      {
        "language": "en",
        "groups": [...]
      },
      {
        "language": "es",
        "default": true,
        "groups": [...]
      }
    ]
  }
}
```


<div id="single-language-documentation">
  ### Documentation en une seule langue
</div>

Si vous souhaitez proposer une seule langue sans sélecteur de langue, supprimez le champ `languages` de votre configuration de navigation. Définissez plutôt directement la structure de navigation :

```json docs.json
{
  "navigation": {
    "tabs": [
      {
        "tab": "Documentation",
        "groups": [
          {
            "group": "Getting started",
            "pages": ["index", "quickstart"]
          }
        ]
      }
    ]
  }
}
```

Cela affiche votre documentation dans une seule langue, sans l’interface de sélection de la langue.

<Tip>
  Traduisez les libellés de navigation, comme les noms de groupes ou d’onglets, pour qu’ils correspondent à la langue du contenu. Vous offrirez ainsi une expérience entièrement localisée à vos utilisateurs.
</Tip>


<div id="global-navigation">
  ### Navigation globale
</div>

Pour ajouter des éléments de navigation communs à toutes les langues, configurez l’objet `global` dans la navigation de votre `docs.json`.

```json docs.json
{
  "navigation": {
    "global": {
      "anchors": [
        {
          "anchor": "Documentation",
          "href": "https://example.com/docs"
        },
        {
          "anchor": "Blog",
          "href": "https://example.com/blog"
        }
      ]
    },
    "languages": [
      // Navigation spécifique à la langue
    ]
  }
}
```


<div id="maintain-translations">
  ## Maintenir les traductions
</div>

Veillez à ce que les traductions restent exactes et synchronisées avec votre contenu source.

<div id="translation-workflow">
  ### Processus de traduction
</div>

1. Mettez à jour le contenu source dans votre langue principale.
2. Repérez le contenu modifié.
3. Traduisez le contenu modifié.
4. Vérifiez l’exactitude des traductions.
5. Mettez à jour les fichiers traduits.
6. Vérifiez que la navigation et les liens fonctionnent.

<div id="images-and-media">
  ### Images et médias
</div>

Stockez les images traduites dans des répertoires propres à chaque langue.

```
images/
├── dashboard.png          # Version anglaise
├── fr/
│   └── dashboard.png     # Version française
└── es/
    └── dashboard.png     # Version espagnole
```

Utilisez des chemins relatifs pour référencer les images dans votre contenu traduit.

```mdx es/index.mdx
![Captura de pantalla del panel de control](/images/es/dashboard.png)
```

</div>

<div id="best-practices">
  ## Bonnes pratiques
</div>

<div id="date-and-number-formats">
  ### Formats de date et de nombre
</div>

Tenez compte des formats propres à chaque langue pour les dates et les nombres.

* Formats de date : MM/DD/YYYY vs DD/MM/YYYY
* Formats de nombre : 1,000.00 vs 1.000,00
* Symboles monétaires : $100.00 vs 100,00€

Incluez des exemples au format approprié pour chaque langue, ou utilisez des formats compréhensibles par tous.

<div id="maintain-consistency">
  ### Assurer la cohérence
</div>

* Veillez à maintenir la même couverture de contenu dans toutes les langues afin que chaque utilisateur bénéficie de la même qualité d&#39;information.
* Créez un glossaire de traduction pour les termes techniques.
* Conservez la même structure de contenu dans toutes les langues.
* Respectez le ton et le style de votre contenu source.
* Utilisez des branches Git pour gérer le travail de traduction séparément des mises à jour du contenu principal.

<div id="layout-differences">
  ### Différences de mise en page
</div>

Certaines langues prennent plus ou moins de place que l’anglais. Testez votre contenu traduit sur différentes tailles d’écran pour vous assurer que :

* La navigation s’affiche correctement.
* Les blocs de code ne débordent pas.
* Les tableaux et autres contenus mis en forme restent lisibles.
* Les images s’adaptent correctement.

<div id="character-encoding">
  ### Encodage des caractères
</div>

Assurez-vous que votre environnement de développement et votre pipeline de déploiement prennent en charge l’encodage UTF-8 pour afficher correctement tous les caractères dans les langues utilisant différents alphabets et caractères spéciaux.
