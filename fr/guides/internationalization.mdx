L’internationalisation (i18n) est le processus de conception de logiciels ou de contenus pour qu’ils prennent en charge différentes langues et différents paramètres régionaux. Ce guide explique comment structurer les fichiers, configurer la navigation et maintenir efficacement les traductions afin d’aider vos utilisateurs à accéder à votre documentation dans la langue de leur choix et d’améliorer votre portée mondiale.

<div id="file-structure">
  ## Structure des fichiers
</div>

Organisez le contenu traduit dans des répertoires spécifiques à chaque langue pour que votre documentation reste facile à maintenir et pour structurer votre navigation par langue.

Créez un répertoire séparé pour chaque langue en utilisant les [codes de langue ISO 639-1](https://en.wikipedia.org/wiki/List_of_ISO_639-1_codes). Placez les fichiers traduits dans ces répertoires en conservant la même structure que pour votre langue par défaut.

<Expandable title="codes de langue pris en charge">
  * `ar` - Arabe
  * `cs` - Tchèque
  * `cn` or `zh-Hans` - Chinois (simplifié)
  * `zh-Hant` - Chinois (traditionnel)
  * `de` - Allemand
  * `en` - Anglais
  * `es` - Espagnol
  * `fr` - Français
  * `he` - Hébreu
  * `hi` - Hindi
  * `id` - Indonésien
  * `it` - Italien
  * `jp` - Japonais
  * `ko` - Coréen
  * `lv` - Letton
  * `nl` - Néerlandais
  * `no` - Norvégien
  * `pl` - Polonais
  * `pt` or `pt-BR` - Portugais
  * `ro` - Roumain
  * `ru` - Russe
  * `sv` - Suédois
  * `tr` - Turc
  * `ua` - Ukrainien
  * `uz` - Ouzbek
  * `vi` - Vietnamien
</Expandable>

```text Example file structure
docs/
├── index.mdx                    # Anglais (par défaut)
├── quickstart.mdx
├── fr/
│   ├── index.mdx               # Français
│   ├── quickstart.mdx
├── es/
│   ├── index.mdx               # Espagnol
│   ├── quickstart.mdx
└── zh/
    ├── index.mdx               # Chinois
    └── quickstart.mdx
```

<Tip>
  Conservez les mêmes noms de fichiers et la même structure de répertoires pour toutes les langues. Cela facilite la maintenance des traductions et l’identification du contenu manquant.
</Tip>


<div id="configure-the-language-switcher">
  ## Configurer le sélecteur de langue
</div>

Pour ajouter un sélecteur de langue à votre documentation, configurez le tableau `languages` dans la navigation de votre fichier `docs.json`.

```json docs.json
{
  "navigation": {
    "languages": [
      {
        "language": "en",
        "groups": [
          {
            "group": "Getting started",
            "pages": ["index", "quickstart"]
          }
        ]
      },
      {
        "language": "es",
        "groups": [
          {
            "group": "Comenzando",
            "pages": ["es/index", "es/quickstart"]
          }
        ]
      }
    ]
  }
}
```

Chaque entrée dans le tableau `languages` doit inclure :

* `language` : code de langue au format ISO 639-1
* Structure de navigation complète
* Chemins vers les fichiers traduits

La structure de navigation peut varier d’une langue à l’autre afin de tenir compte des besoins spécifiques de contenu propres à chaque langue.


<div id="set-default-language">
  ### Définir la langue par défaut
</div>

La première langue du tableau `languages` est automatiquement utilisée comme langue par défaut. Pour définir une autre langue par défaut, réordonnez le tableau ou ajoutez la propriété `default` :

```json docs.json
{
  "navigation": {
    "languages": [
      {
        "language": "es",
        "groups": [...]
      },
      {
        "language": "en",
        "groups": [...]
      }
    ]
  }
}
```

Vous pouvez également utiliser la propriété `default` pour modifier l&#39;ordre :

```json docs.json
{
  "navigation": {
    "languages": [
      {
        "language": "en",
        "groups": [...]
      },
      {
        "language": "es",
        "default": true,
        "groups": [...]
      }
    ]
  }
}
```


<div id="single-language-documentation">
  ### Documentation dans une seule langue
</div>

Si vous souhaitez ne proposer qu’une seule langue, sans sélecteur de langue, supprimez le champ `languages` de la configuration de navigation. Définissez alors directement la structure de navigation :

```json docs.json
{
  "navigation": {
    "tabs": [
      {
        "tab": "Documentation",
        "groups": [
          {
            "group": "Getting started",
            "pages": ["index", "quickstart"]
          }
        ]
      }
    ]
  }
}
```

Cela affiche votre documentation dans une seule langue, sans le sélecteur de langue.

<Tip>
  Traduisez les libellés de navigation, comme les noms de groupes ou d’onglets, pour qu’ils correspondent à la langue du contenu. Vous offrirez ainsi à vos utilisateurs une expérience entièrement localisée.
</Tip>


<div id="global-navigation">
  ### Navigation globale
</div>

Pour ajouter des éléments de navigation globaux qui apparaissent pour toutes les langues, configurez l&#39;objet `global` dans la navigation de votre `docs.json`.

```json docs.json
{
  "navigation": {
    "global": {
      "anchors": [
        {
          "anchor": "Documentation",
          "href": "https://example.com/docs"
        },
        {
          "anchor": "Blog",
          "href": "https://example.com/blog"
        }
      ]
    },
    "languages": [
      // Navigation spécifique à la langue
    ]
  }
}
```


<div id="maintain-translations">
  ## Maintenir les traductions
</div>

Maintenez des traductions fidèles et synchronisées avec votre contenu source.

<div id="translation-workflow">
  ### Processus de traduction
</div>

1. Mettez à jour le contenu source dans votre langue principale.
2. Identifiez le contenu modifié.
3. Traduisez le contenu modifié.
4. Relisez les traductions pour en vérifier l’exactitude.
5. Mettez à jour les fichiers traduits.
6. Vérifiez que la navigation et les liens fonctionnent.

<div id="images-and-media">
  ### Images et médias
</div>

Stockez les images traduites dans des répertoires propres à chaque langue.

```
images/
├── dashboard.png          # Version anglaise
├── fr/
│   └── dashboard.png     # Version française
└── es/
    └── dashboard.png     # Version espagnole
```

Référencez les images à l&#39;aide de chemins relatifs dans votre contenu traduit.

```mdx es/index.mdx
![Captura de pantalla del panel de control](/images/es/dashboard.png)
```


<div id="seo-for-multi-language-sites">
  ## SEO pour les sites multilingues
</div>

Optimisez chaque version du site dans chaque langue pour les moteurs de recherche.

<div id="page-metadata">
  ### Métadonnées de page
</div>

Incluez les métadonnées traduites dans le frontmatter de chaque fichier :

```mdx fr/index.mdx
---
title: "Commencer"
description: "Apprenez à commencer avec notre produit."
keywords: ["démarrage", "tutoriel", "guide"]
---
```


<div id="best-practices">
  ## Bonnes pratiques
</div>

<div id="date-and-number-formats">
  ### Formats de dates et de nombres
</div>

Tenez compte du formatage spécifique à la langue et à la région pour les dates et les nombres.

- Formats de date : MM/DD/YYYY vs DD/MM/YYYY
- Formats de nombre : 1,000.00 vs 1.000,00
- Symboles monétaires : $100.00 vs 100,00€

Incluez des exemples dans le format approprié pour chaque langue ou utilisez des formats universellement compris.

<div id="maintain-consistency">
  ### Maintenir la cohérence
</div>

- Assurez l’équivalence du contenu dans toutes les langues afin que chaque utilisateur bénéficie de la même qualité d’information.
- Créez un glossaire de traduction pour les termes techniques.
- Conservez la même structure de contenu d’une langue à l’autre.
- Adaptez le ton et le style à ceux de votre contenu source.
- Utilisez des branches Git pour gérer le travail de traduction séparément des mises à jour du contenu principal.

<div id="layout-differences">
  ### Différences de mise en page
</div>

Certaines langues prennent plus ou moins de place que l’anglais. Testez votre contenu traduit sur différentes tailles d’écran afin de vérifier :

- La navigation tient correctement à l’écran.
- Les blocs de code ne débordent pas.
- Les tableaux et autres textes mis en forme restent faciles à lire.
- Les images s’adaptent correctement.

<div id="character-encoding">
  ### Encodage des caractères
</div>

Assurez-vous que votre environnement de développement et votre pipeline de déploiement prennent en charge l'encodage UTF-8 afin d'afficher correctement tous les caractères pour les langues qui utilisent différents alphabets et des caractères spéciaux.
