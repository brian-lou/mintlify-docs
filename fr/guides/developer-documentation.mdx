La documentation développeur aide à comprendre votre produit et à l’intégrer. Une bonne documentation permet d’en faire plus avec votre produit, réduit la charge de travail du support, accélère l’adoption et améliore l’expérience développeur.

Mintlify fournit une infrastructure conçue pour la documentation développeur.

* **Génération de références API** : Générez des [références API](/fr/api-playground/overview) interactives à partir de spécifications OpenAPI, afin que les développeurs puissent tester des endpoints directement dans votre documentation.
* **Blocs de code avec explications** : L’[assistant](/fr/ai/assistant) explique les exemples de code dans leur contexte, ce qui aide les développeurs à comprendre les détails d’implémentation.
* **Synchronisation Git** : Gardez la documentation synchronisée avec votre base de code grâce à [GitHub](/fr/deploy/github) ou [GitLab](/fr/deploy/gitlab).
* **Versionnement** : Maintenez une documentation pour plusieurs [versions](/fr/organize/navigation#versions) afin que les développeurs qui utilisent d’anciennes versions puissent toujours trouver des informations exactes.

<div id="prerequisites">
  ## Prérequis
</div>

Si vous n&#39;avez pas encore créé de projet Mintlify, consultez le [guide de démarrage rapide](/fr/quickstart) pour déployer votre site.

* Votre spécification API au format OpenAPI (si vous documentez une API)
* Un dépôt Git pour votre documentation
* Un accès administrateur à votre organisation Mintlify

<div id="migrate-existing-documentation">
  ## Migrer une documentation existante
</div>

Si vous créez une documentation à partir de zéro, passez à [Planifiez la structure de votre documentation](#plan-your-documentation-structure).

<div id="audit-existing-content">
  ### Auditer le contenu existant
</div>

Passez en revue votre documentation actuelle pour comprendre ce que vous avez et ce que vous devez migrer.

* **Référence API** : est-elle générée à partir d’une spécification ou rédigée manuellement ? Quels endpoints documentez-vous ?
* **Guides et tutoriels** : quels guides d’intégration existent ? Sont-ils à jour ?
* **Exemples de code** : quels langages et frameworks utilisez-vous ?
* **Documentation des SDK** : avez-vous une documentation distincte pour chaque SDK ?
* **Journal des modifications** : tenez-vous un journal des modifications ou des notes de version ?
* **Métadonnées** : avez-vous des métadonnées pour votre contenu, comme des dates, des auteurs et des tags ?

<div id="export-your-existing-content">
  ### Exportez votre contenu existant
</div>

* Exportez au format **Markdown** pour migrer plus facilement vers Mintlify.
* Exportez les **spécifications OpenAPI** pour le contenu de référence API.
* Exportez au format **HTML** si Markdown n’est pas disponible, puis convertissez-le en Markdown.

<div id="plan-your-documentation-structure">
  ## Planifiez la structure de votre documentation
</div>

La documentation développeur comprend généralement plusieurs types de contenu. Structurez votre navigation selon la manière dont vos utilisateurs appréhendent votre produit.

```json docs.json example
{
  "navigation": {
    "groups": [
      {
        "group": "Get Started",
        "pages": [
          "introduction",
          "quickstart",
          "authentication"
        ]
      },
      {
        "group": "Guides",
        "pages": [
          "guides/webhooks",
          "guides/error-handling",
          "guides/rate-limits",
          "guides/pagination"
        ]
      },
      {
        "group": "API Reference",
        "pages": [
          "api-reference/overview",
          "api-reference/users",
          "api-reference/orders",
          "api-reference/products"
        ]
      },
      {
        "group": "SDKs",
        "pages": [
          "sdks/javascript",
          "sdks/python",
          "sdks/go"
        ]
      }
    ]
  }
}
```

Consultez [Navigation](/fr/organize/navigation) pour découvrir d’autres options de configuration.

<div id="set-up-your-api-reference">
  ## Configurez votre référence API
</div>

Si vous avez une API, générez une référence interactive à partir de votre spécification OpenAPI.

<Steps>
  <Step title="Ajoutez votre spécification OpenAPI">
    Ajoutez votre fichier de spécification OpenAPI à votre projet. Vous pouvez utiliser le format YAML ou JSON.

    ```text
    your-project/
    ├── docs.json
    ├── openapi.yaml
    └── api-reference/
        └── overview.mdx
    ```
  </Step>

  <Step title="Configurez la spécification dans docs.json">
    Indiquez votre fichier OpenAPI dans votre configuration `docs.json`.

    ```json Exemple de configuration
    {
      "openapi": "openapi.yaml"
    }
    ```
  </Step>

  <Step title="Ajoutez les endpoints à la navigation">
    Ajoutez les endpoints à la navigation dans votre `docs.json`. Consultez [la configuration OpenAPI](/fr/api-playground/openapi-setup) pour voir les options de configuration.

    ```json Exemple de navigation
    {
      "group": "API Reference",
      "pages": [
        "api-reference/overview",
        "api-reference/users/list-users",
        "api-reference/users/get-user",
        "api-reference/users/create-user"
      ]
    }
    ```
  </Step>
</Steps>

<div id="set-up-the-assistant">
  ## Configurer l’assistant
</div>

L’assistant aide les développeurs à trouver des réponses et à comprendre les exemples de code. Configurez-le depuis votre [tableau de bord](https://dashboard.mintlify.com/products/assistant/settings).

* **Exemples de questions** : ajoutez des questions destinées aux développeurs, comme « Comment authentifier des requêtes API ? » ou « Comment gérer les webhooks ? »
* **Explications de code** : l’assistant peut expliquer des blocs de code en contexte lorsque les développeurs posent des questions sur des exemples précis.

<div id="set-up-versioning">
  ## Configurer le versionnement
</div>

Si vous gérez plusieurs versions d’API, configurez le versionnement pour que les développeurs trouvent la documentation correspondant à leur version.

```json Versioning example
{
  "versions": ["v2", "v1"],
  "navigation": {
    "groups": [
      {
        "group": "API Reference",
        "version": "v2",
        "pages": ["v2/api-reference/users"]
      },
      {
        "group": "API Reference",
        "version": "v1",
        "pages": ["v1/api-reference/users"]
      }
    ]
  }
}
```

Consultez [Versions](/fr/organize/navigation#versions) pour en savoir plus.

<div id="connect-to-your-repository">
  ## Connectez votre dépôt
</div>

Installez l’[application GitHub](/fr/deploy/github) de Mintlify pour que votre documentation reste synchronisée avec votre base de code et pour faciliter les contributions.

<Steps>
  <Step title="Connectez votre dépôt">
    Connectez votre dépôt GitHub dans le [tableau de bord](https://dashboard.mintlify.com). Cela active les déploiements automatiques lorsque vous apportez des modifications.
  </Step>

  <Step title="Configurez les paramètres de branche">
    Définissez votre branche de production et activez les déploiements d’aperçu pour les pull requests. Cela vous permet de vérifier les modifications de la documentation avant leur mise en ligne.
  </Step>
</Steps>

<Note>
  Si vous utilisez GitLab, consultez [GitLab](/fr/deploy/gitlab) pour les instructions de configuration.
</Note>

<div id="maintain-your-documentation">
  ## Maintenez votre documentation
</div>

La documentation développeur doit être mise à jour régulièrement afin que les informations restent exactes et utiles.

<Steps>
  <Step title="Gardez la référence API à jour">
    Mettez à jour votre spécification OpenAPI chaque fois que vous publiez des changements. Si votre spécification est générée à partir du code, automatisez cette étape dans votre processus de publication.
  </Step>

  <Step title="Mettez à jour les exemples de code">
    Passez en revue les exemples de code lorsque vous publiez de nouvelles versions de SDK ou des mises à jour produit. Des exemples obsolètes entraînent des échecs d’intégration et des demandes d’assistance.
  </Step>

  <Step title="Tenez un journal des modifications">
    Documentez les changements incompatibles, les nouvelles fonctionnalités et les dépréciations. Les développeurs s’appuient sur les journaux des modifications pour comprendre ce qui a changé entre les versions. Consultez [Changelogs](/fr/create/changelogs) pour plus d’informations.
  </Step>

  <Step title="Surveillez les retours">
    Examinez les conversations avec l’assistant et les statistiques de recherche pour identifier les lacunes de votre documentation. Si les développeurs posent à plusieurs reprises des questions sur le même sujet, améliorez cette section. Consultez [Maintenance](/fr/guides/maintenance) pour plus d’informations.
  </Step>
</Steps>

<div id="next-steps">
  ## Prochaines étapes
</div>

Votre documentation développeur est prête à être publiée. Après le déploiement :

1. Annoncez la documentation à votre communauté de développeurs.
2. Surveillez les recherches et les échanges avec l’assistant afin de repérer les lacunes.
3. Mettez en place un processus de mise à jour de la documentation à chaque nouvelle version de l’API.
4. Recueillez les retours des développeurs pour améliorer le contenu au fil du temps.
