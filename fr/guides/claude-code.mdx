Claude Code est un outil de ligne de commande agentique qui peut vous aider à maintenir votre documentation. Il peut rédiger de nouveaux contenus, relire des pages existantes et garder votre documentation à jour.

Vous pouvez entraîner Claude Code à comprendre les normes et les flux de travail de votre documentation en ajoutant un fichier `CLAUDE.md` à votre projet, puis en l&#39;affinant au fil du temps.

<div id="getting-started">
  ## Prise en main
</div>

**Prérequis :**

* Un abonnement Claude actif (Pro, Max ou accès à l’API)

**Configuration :**

1. Installez Claude Code :

```bash
  npm install -g @anthropic-ai/claude-code
```

2. Accédez à votre répertoire de documentation.
3. (Facultatif) Ajoutez le fichier `CLAUDE.md` ci-dessous à votre projet.
4. Exécutez `claude` pour démarrer.


<div id="claudemd-template">
  ## Modèle CLAUDE.md
</div>

Enregistrez un fichier `CLAUDE.md` à la racine de votre répertoire de documentation pour aider Claude Code à comprendre votre projet. Ce fichier permet à Claude Code d’assimiler vos normes de documentation, vos préférences et vos flux de travail. Consultez [Gérer la mémoire de Claude](https://docs.anthropic.com/en/docs/claude-code/memory) dans la documentation Anthropic pour plus d’informations.

Copiez cet exemple de modèle ou adaptez-le aux spécifications de votre documentation :

```mdx
# Documentation Mintlify

## Relation de travail
- Tu peux remettre en question les idées — cela peut mener à une meilleure documentation. Cite tes sources et explique ton raisonnement lorsque tu le fais
- TOUJOURS demander des clarifications plutôt que de faire des suppositions
- NE JAMAIS mentir, deviner ou inventer quoi que ce soit

## Contexte du projet
- Format : fichiers MDX avec Frontmatter YAML
- Config : docs.json pour la navigation, le thème, les paramètres
- Composants : Composants Mintlify

## Stratégie de contenu
- Documenter juste ce qu'il faut pour la réussite de l'utilisateur — ni trop, ni trop peu
- Privilégier l'exactitude et la facilité d'utilisation
- Rendre le contenu pérenne dans la mesure du possible
- Rechercher le contenu existant avant d'en ajouter. Éviter les doublons sauf si cela répond à un objectif stratégique
- Vérifier les modèles existants pour assurer la cohérence
- Commencer par les modifications les plus petites et raisonnables

## docs.json

- Se référer au [schéma docs.json](https://mintlify.com/docs.json) lors de la construction du fichier docs.json et de la navigation du site

## Exigences du Frontmatter pour les pages
- title : Titre de page clair et descriptif
- description : Résumé concis pour le référencement/la navigation

## Normes rédactionnelles
- Voix à la deuxième personne (« vous »)
- Prérequis au début du contenu procédural
- Tester tous les exemples de code avant publication
- Respecter le style et la mise en forme des pages existantes
- Inclure des cas d'utilisation basiques et avancés
- Balises de langue sur tous les blocs de code
- Texte alternatif sur toutes les images
- Chemins relatifs pour les liens internes

## Workflow Git
- NE JAMAIS utiliser --no-verify lors des commits
- Demander comment gérer les modifications non validées avant de commencer
- Créer une nouvelle branche lorsqu'aucune branche existante ne correspond aux modifications
- Effectuer des commits fréquemment tout au long du développement
- NE JAMAIS ignorer ou désactiver les hooks de pré-commit

## À ne pas faire
- Omettre le Frontmatter dans un fichier MDX
- Utiliser des URL absolues pour les liens internes
- Inclure des exemples de code non testés
- Faire des suppositions — toujours demander des clarifications
```


<div id="sample-prompts">
  ## Exemples de prompts
</div>

Une fois Claude Code configuré, essayez ces prompts pour voir comment il peut vous aider dans les tâches courantes de rédaction de documentation. Vous pouvez copier-coller directement ces exemples ou les adapter à vos besoins spécifiques.

<div id="convert-notes-to-polished-docs">
  ### Convertir des notes en documentation aboutie
</div>

Transformez des brouillons en pages Markdown structurées avec des composants et du Frontmatter.

**Exemple de prompt :**

```text wrap
Convertis ce texte en une page MDX correctement formatée : [colle ton texte ici]
```


<div id="review-docs-for-consistency">
  ### Vérifiez la cohérence de la documentation
</div>

Obtenez des suggestions pour améliorer le style, la mise en forme et l’utilisation des composants.

**Exemple de prompt :**

```text wrap
Review the files in docs/ and suggest improvements for consistency and clarity
```


<div id="update-docs-when-features-change">
  ### Mettez à jour la documentation quand les fonctionnalités évoluent
</div>

Gardez la documentation à jour à mesure que votre produit évolue.

**Exemple de prompt :**

```text wrap
Notre API nécessite désormais un paramètre de version. Mettez à jour notre documentation pour inclure version=2024-01 dans tous les exemples
```


<div id="generate-comprehensive-code-examples">
  ### Générer des exemples de code complets
</div>

Créez des exemples en plusieurs langages avec gestion des erreurs.

**Exemple de prompt :**

```text wrap
Create code examples for [your API endpoint] in JavaScript, Python, and cURL with error handling
```


<div id="extending-claude-code">
  ## Aller plus loin avec Claude Code
</div>

En plus de l’utiliser manuellement avec des prompts, vous pouvez l’intégrer à vos flux de travail existants.

<div id="automation-with-github-actions">
  ### Automatisation avec GitHub Actions
</div>

Exécutez automatiquement Claude Code lorsque le code évolue afin de maintenir la documentation à jour. Vous pouvez déclencher des revues de documentation sur les pull requests ou mettre à jour les exemples lorsque des changements apportés à l’API sont détectés.

<div id="multi-instance-workflows">
  ### Flux de travail multi-instances
</div>

Utilisez des sessions Claude Code distinctes pour des tâches différentes - l’une pour rédiger du nouveau contenu, l’autre pour la relecture et l’assurance qualité. Vous gagnerez ainsi en cohérence et repérerez des problèmes qu’une seule session pourrait laisser passer.

<div id="team-collaboration">
  ### Collaboration en équipe
</div>

Partagez votre fichier `CLAUDE.md` peaufiné avec votre équipe afin de garantir des normes de documentation cohérentes pour tous les contributeurs. Les équipes développent souvent des prompts et des flux de travail propres au projet qui deviennent partie intégrante de leur processus de documentation.

<div id="custom-commands">
  ### Commandes personnalisées
</div>

Créez des commandes slash réutilisables dans `.claude/commands/` pour les tâches de documentation courantes propres à votre projet ou à votre équipe.
