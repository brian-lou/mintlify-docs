Claude Code est un outil en ligne de commande, basé sur des agents, qui peut vous aider à maintenir votre documentation. Il peut rédiger de nouveaux contenus, relire des pages existantes et garder votre documentation à jour.

Vous pouvez entraîner Claude Code à comprendre vos normes et vos flux de travail en matière de documentation en ajoutant un fichier `CLAUDE.md` à votre projet et en le peaufinant au fil du temps.

<div id="getting-started">
  ## Pour commencer
</div>

**Prérequis :**

* Abonnement Claude actif (Pro, Max ou accès API)

**Installation :**

1. Installez Claude Code :

```bash
  npm install -g @anthropic-ai/claude-code
```

2. Accédez à votre répertoire `docs`.
3. (Facultatif) Ajoutez le fichier `CLAUDE.md` ci-dessous à votre projet.
4. Exécutez `claude` pour le lancer.


<div id="claudemd-template">
  ## Modèle CLAUDE.md
</div>

Enregistrez un fichier `CLAUDE.md` à la racine de votre dossier de documentation pour aider Claude Code à comprendre votre projet. Ce fichier sert à entraîner Claude Code sur vos normes de documentation, vos préférences et vos processus de travail. Pour plus d&#39;informations, consultez [Gérer la mémoire de Claude](https://docs.anthropic.com/en/docs/claude-code/memory) dans la documentation Anthropic.

Copiez cet exemple de modèle ou adaptez-le aux spécifications de votre documentation :

```mdx
# Mintlify documentation

## Working relationship
- You can push back on ideas-this can lead to better documentation. Cite sources and explain your reasoning when you do so
- ALWAYS ask for clarification rather than making assumptions
- NEVER lie, guess, or make up anything

## Project context
- Format: MDX files with YAML frontmatter
- Config: docs.json for navigation, theme, settings
- Components: Mintlify components

## Content strategy
- Document just enough for user success - not too much, not too little
- Prioritize accuracy and usability
- Make content evergreen when possible
- Search for existing content before adding anything new. Avoid duplication unless it is done for a strategic reason
- Check existing patterns for consistency
- Start by making the smallest reasonable changes

## docs.json

- Refer to the [docs.json schema](https://mintlify.com/docs.json) when building the docs.json file and site navigation

## Frontmatter requirements for pages
- title: Clear, descriptive page title
- description: Concise summary for SEO/navigation

## Writing standards
- Second-person voice ("you")
- Prerequisites at start of procedural content
- Test all code examples before publishing
- Match style and formatting of existing pages
- Include both basic and advanced use cases
- Language tags on all code blocks
- Alt text on all images
- Relative paths for internal links

## Git workflow
- NEVER use --no-verify when committing
- Ask how to handle uncommitted changes before starting
- Create a new branch when no clear branch exists for changes
- Commit frequently throughout development
- NEVER skip or disable pre-commit hooks

## Do not
- Skip frontmatter on any MDX file
- Use absolute URLs for internal links
- Include untested code examples
- Make assumptions - always ask for clarification
```


<div id="sample-prompts">
  ## Exemples de prompts
</div>

Une fois Claude Code configuré, essayez ces prompts pour voir comment il peut vous aider dans les tâches de documentation courantes. Vous pouvez copier-coller ces exemples tels quels ou les adapter à vos besoins spécifiques.

<div id="convert-notes-to-polished-docs">
  ### Convertir des notes en documents soignés
</div>

Transformez des brouillons en véritables pages Markdown avec des composants et du frontmatter.

**Exemple de prompt :**

```text wrap
Convert this text into a properly formatted MDX page: [paste your text here]
```


<div id="review-docs-for-consistency">
  ### Vérifier la cohérence de la documentation
</div>

Obtenez des suggestions pour améliorer le style, la mise en forme et l&#39;utilisation des composants.

**Exemple de demande :**

```text wrap
Review the files in docs/ and suggest improvements for consistency and clarity
```


<div id="update-docs-when-features-change">
  ### Mettez à jour la documentation lorsque les fonctionnalités évoluent
</div>

Veillez à ce que la documentation reste à jour lorsque votre produit évolue.

**Exemple de prompt :**

```text wrap
Our API now requires a version parameter. Update our docs to include version=2024-01 in all examples
```


<div id="generate-comprehensive-code-examples">
  ### Générer des exemples de code détaillés
</div>

Générez des exemples multilingues avec gestion des erreurs.

**Exemple d’invite :**

```text wrap
Create code examples for [your API endpoint] in JavaScript, Python, and cURL with error handling
```


<div id="extending-claude-code">
  ## Aller plus loin avec Claude Code
</div>

Au-delà des invites manuelles adressées à Claude Code, vous pouvez l'intégrer à vos flux de travail existants.

<div id="automation-with-github-actions">
  ### Automatisation avec GitHub Actions
</div>

Exécutez Claude Code automatiquement lorsque le code est modifié afin de maintenir la documentation à jour. Vous pouvez déclencher des revues de documentation sur les pull requests ou mettre à jour les exemples lorsque des modifications de l'API sont détectées.

<div id="multi-instance-workflows">
  ### Flux de travail multi‑instances
</div>

Utilisez des sessions Claude Code distinctes pour différentes tâches : l’une dédiée à la rédaction de nouveaux contenus et une autre à la relecture et à l’assurance qualité. Cela permet de maintenir la cohérence et de détecter des problèmes qu’une seule session pourrait ne pas repérer.

<div id="team-collaboration">
  ### Collaboration en équipe
</div>

Partagez votre fichier `CLAUDE.md` amélioré avec votre équipe afin de garantir des standards de documentation cohérents pour l'ensemble des contributeurs. Les équipes développent souvent des prompts et des flux de travail spécifiques au projet qui finissent par faire partie intégrante de leur processus de documentation.

<div id="custom-commands">
  ### Commandes personnalisées
</div>

Créez des commandes slash réutilisables dans `.claude/commands/` pour les tâches de documentation spécifiques à votre projet ou à votre équipe que vous effectuez fréquemment.
