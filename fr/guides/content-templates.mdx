Utilisez ces modèles comme points de départ pour créer votre documentation. Adaptez-les à votre contenu et à votre public.

1. Copiez le modèle correspondant à votre type de contenu.
2. Remplacez les espaces réservés et le contenu d’exemple par votre contenu.
3. Ajustez les sections selon vos besoins.
4. Supprimez les sections qui ne s’appliquent pas.

<Tip>
  Vous ne savez pas quel modèle utiliser ? Consultez les [types de contenu](/fr/guides/content-types) pour savoir quand utiliser chacun d’eux.
</Tip>

<div id="how-to-guide-template">
  ## Modèle de guide pratique
</div>

Utilisez les guides pratiques lorsque les utilisateurs doivent accomplir une tâche précise et ont déjà une certaine familiarité avec votre produit. Les guides pratiques sont axés sur un objectif et vont droit au but.

````mdx How-to guide template
---
title: "[Titles should start with a verb]"
description: "[Do specific task] to [achieve outcome]."
---

Start with a brief statement of what this guide helps users accomplish.

## Prerequisites (optional)

List only what's necessary:

- Required setup or configuration
- Permissions needed
- Related features that should be configured first

## [Action-oriented heading describing the task]

Provide direct instructions focused on achieving the goal.

1. Ouvrez [emplacement] et accédez à [endroit précis]
2. Cliquez sur [bouton ou option]
3. Saisissez [informations requises]
4. Cliquez sur [bouton de confirmation]

```language
// Include code examples that users can copy and modify
```

<Tip>
  Include practical tips that help users avoid common mistakes or work more efficiently.
</Tip>

## Verify the result (optional)

If success is ambiguous, explain how users can confirm they completed the task successfully.

## Troubleshooting (optional)

Address common issues users might encounter:

- **Problem description**: Solution or workaround
- **Another common issue**: How to resolve it

## Related tasks

Link to related how-to guides or next steps.
````

<div id="tutorial-template">
  ## Modèle de tutoriel
</div>

Utilisez des tutoriels lorsque vous souhaitez aider de nouveaux utilisateurs à apprendre par la pratique. Les tutoriels accompagnent les utilisateurs, étape par étape, dans un parcours d’apprentissage complet avec un objectif clair.

````mdx Tutorial template
---
title: "[Verbe d'action] [résultat spécifique]"
description: "Apprenez à [résultat spécifique] en [méthode ou approche]."
---

Utilisez un paragraphe d'introduction pour expliquer ce que les utilisateurs apprendront et ce qu'ils seront capables de faire après avoir terminé ce tutoriel.

## Prérequis

Listez ce dont les utilisateurs ont besoin avant de commencer :

- Connaissances ou compétences requises
- Outils, comptes ou autorisations
- Temps estimé (facultatif)

## Étape 1 : [Première action]

Fournissez des instructions claires et précises pour la première étape.

```language
// Incluez des exemples de code là où c'est utile
```

Expliquez ce que cette étape accomplit et pourquoi elle est importante.

## Étape 2 : [Deuxième action]

Poursuivez avec des étapes séquentielles qui s'appuient sur le travail précédent.

Signalez les jalons et les indicateurs de progression pour que les utilisateurs sachent qu'ils avancent dans la bonne direction.

## Étape 3 : [Troisième action]

Concentrez les étapes sur des actions concrètes plutôt que sur la théorie.

Limitez au maximum les choix que les utilisateurs doivent faire.

## Étapes suivantes

Résumez ce que les utilisateurs ont appris et suggérez des étapes suivantes logiques :

- Tutoriels connexes à explorer
- Guides pratiques pour les tâches courantes
- Ressources supplémentaires pour approfondir les connaissances
````

<div id="explanation-template">
  ## Modèle d’explication
</div>

Utilisez des explications lorsque les utilisateurs ont besoin de comprendre des concepts, des choix de conception ou le fonctionnement de fonctionnalités complexes. Les explications apportent du contexte et permettent d’approfondir la compréhension plutôt que de fournir des instructions étape par étape.

```mdx Explanation template
---
title: "À propos de [concept ou fonctionnalité]"
description: "Comprendre [concept] et son fonctionnement dans [produit ou contexte]."
---

Commencez par une présentation claire de ce que couvre cette explication et de l'importance de la comprendre.

Définissez le concept en termes simples. Expliquez ce que c'est, ce que cela fait et pourquoi cela existe.

Utilisez des analogies ou des comparaisons avec des concepts familiers si cela aide à la compréhension.

## Fonctionnement de [concept]

Expliquez les mécanismes sous-jacents, l'architecture ou le processus.

<Frame>
  <img src="/path/to/diagram.png" alt="Diagramme illustrant le fonctionnement de [concept]" />
</Frame>

Décomposez les idées complexes en sections accessibles.

## Pourquoi [décision de conception ou approche]

Expliquez pourquoi les choses fonctionnent de cette façon.

Abordez les compromis, les alternatives envisagées ou les contraintes qui ont influencé la conception.

## Quand utiliser [concept]

Aidez les utilisateurs à identifier les situations où ce concept ou cette approche est le plus adapté.

- **Cas d'usage 1** : Quand cette approche est pertinente
- **Cas d'usage 2** : Un autre scénario où c'est le bon choix
- **Déconseillé pour** : Les situations où des alternatives sont préférables

## Relation avec d'autres fonctionnalités

Établissez des liens avec les concepts ou fonctionnalités connexes de votre produit.

Expliquez comment ce concept s'intègre dans le système ou le flux de travail global.

## Idées reçues courantes

Corrigez les malentendus ou clarifiez les distinctions subtiles.

## Pour aller plus loin

Ajoutez des liens vers des explications connexes, des tutoriels ou de la documentation de référence.
```
