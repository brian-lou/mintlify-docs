<Note>
  La personnalisation nécessite une [authentification](/fr/deploy/authentication-setup) configurée avec OAuth ou JWT.
</Note>

Personnalisez le contenu pour vos utilisateurs lorsqu’ils se connectent à votre site de documentation. Vous pouvez préremplir automatiquement des clés d’API, afficher du contenu propre au plan ou au rôle d’un utilisateur, et filtrer la référence d’API en fonction de l’appartenance à des groupes.

<div id="api-key-prefilling">
  ## Préremplissage de la clé API
</div>

Renseignez automatiquement les champs de l’espace de test de l’API avec des valeurs propres à chaque utilisateur en renvoyant des noms de champs correspondants dans vos données utilisateur. Incluez ces valeurs dans le champ `apiPlaygroundInputs` de vos [données utilisateur](/fr/deploy/authentication-setup#user-data-format).

```json
{
  "apiPlaygroundInputs": {
    "header": { "X-API-Key": "user_api_key_123" },
    "server": { "subdomain": "acme" }
  }
}
```

Les noms des champs doivent correspondre aux noms définis dans votre spécification OpenAPI. Seules les valeurs correspondant au schéma de sécurité de l’endpoint actuel sont prises en compte.

<div id="dynamic-mdx-content">
  ## Contenu MDX dynamique
</div>

Affichez du contenu en fonction d’informations sur l’utilisateur, comme le nom, l’abonnement ou l’organisation, grâce à la variable `user` dans vos pages MDX. Incluez des données personnalisées dans le champ `content` de vos [données utilisateur](/fr/deploy/authentication-setup#user-data-format).

```json
{
  "content": {
    "firstName": "Jane",
    "company": "Acme Corp",
    "plan": "Enterprise"
  }
}
```

Utilisez ces valeurs dans votre MDX.

```mdx
Welcome back, {user.firstName}! Your {user.plan} plan includes 100 seats for members in your {user.company} organization.
```

Pour effectuer un rendu conditionnel en fonction des données de l’utilisateur, utilisez la variable `user` dans les composants JSX.

```jsx
{
  user.plan === 'enterprise'
    ? <>Contact your admin to enable this feature.</>
    : <>See <a href="https://yoursite.com/pricing">pricing</a> for information about upgrading.</>
}
```

<Note>
  La variable `user` est un objet vide pour les utilisateurs déconnectés. Utilisez l&#39;opérateur d&#39;enchaînement optionnel sur toutes les propriétés de `user` afin d&#39;éviter les erreurs. Par exemple, `{user.org?.plan}` au lieu de `{user.org.plan}`.
</Note>

<div id="page-visibility">
  ## Visibilité des pages
</div>

Limitez l’accès à certaines pages à des groupes d’utilisateurs spécifiques en ajoutant `groups` au frontmatter de la page. Les utilisateurs doivent appartenir à au moins un des groupes indiqués pour accéder à la page.

```mdx
---
title: "Admin settings"
groups: ["admin"]
---
```

Pour plus de détails sur la manière dont les groupes interagissent avec les pages publiques, consultez [Contrôler l’accès à l’aide de groupes](/fr/deploy/authentication-setup#control-access-with-groups).

<div id="openapi-content-filtering">
  ## Filtrage du contenu OpenAPI
</div>

Filtrez le contenu de la référence d’API par groupes d’utilisateurs à l’aide de l’extension `x-mint` dans votre spécification OpenAPI. Vous pouvez filtrer des endpoints entiers, des propriétés individuelles du schéma, des variantes `oneOf` et des valeurs d’énumération.

<div id="filter-endpoints">
  ### Filtrer les endpoints
</div>

Ajoutez `x-mint.groups` à une opération ou à un chemin pour restreindre l’accès à la page de l’endpoint à certains groupes d’utilisateurs. Les utilisateurs qui ne font pas partie des groupes indiqués ne verront pas l’endpoint dans la navigation et ne pourront pas accéder à sa page.

<CodeGroup>
  ```json {6-8} Opération restreinte
  {
    "paths": {
      "/billing": {
        "get": {
          "summary": "Récupérer les détails de facturation",
          "x-mint": {
            "groups": ["admin", "billing"]
          },
          "responses": {
            "200": {
              "description": "Détails de facturation"
            }
          }
        }
      }
    }
  }
  ```

  ```json {3-5} Chemin restreint
  {
    "paths": {
      "x-mint": {
        "groups": ["admin", "billing"]
      },
      "/billing": {
        "get": {
          "summary": "Récupérer les détails de facturation",
        }
      },
      "/users": {
        "get": {
          "summary": "Récupérer les détails de l’utilisateur",
        }
      }
    }
  }
  ```
</CodeGroup>

<div id="filter-schema-properties">
  ### Filtrer les propriétés du schéma
</div>

Ajoutez `x-mint.groups` à chaque propriété des corps de requête, des paramètres ou des réponses. Les propriétés sans `x-mint.groups` restent visibles pour tous les utilisateurs.

```json {11-13} Restricted property
{
  "components": {
    "schemas": {
      "User": {
        "type": "object",
        "properties": {
          "name": {
            "type": "string"
          },
          "internal_id": {
            "type": "string",
            "x-mint": {
              "groups": ["admin"]
            }
          }
        }
      }
    }
  }
}
```

Dans cet exemple, tous les utilisateurs voient la propriété `name`. Seuls les utilisateurs qui appartiennent au groupe `admin` voient la propriété `internal_id`.

<div id="filter-oneof-variants">
  ### Filtrer les variantes de oneOf
</div>

Ajoutez `x-mint.groups` aux différentes options de `oneOf` pour restreindre les variantes de schéma qu’un utilisateur est autorisé à voir.

```json {7-9} Restricted oneOf variant
{
  "schema": {
    "oneOf": [
      {
        "title": "Enterprise config",
        "type": "object",
        "x-mint": {
          "groups": ["enterprise"]
        },
        "properties": {
          "sso_enabled": { "type": "boolean" }
        }
      },
      {
        "title": "Standard config",
        "type": "object",
        "properties": {
          "notifications": { "type": "boolean" }
        }
      }
    ]
  }
}
```

<div id="filter-enum-values">
  ### Filtrer les valeurs d’énumération
</div>

Utilisez l’extension `x-mint-enum` pour restreindre certaines valeurs d’énumération par groupe. Indiquez chaque valeur restreinte en tant que clé, avec ses groupes autorisés comme valeur. Les valeurs d’énumération qui ne sont pas répertoriées dans `x-mint-enum` sont visibles par tous les utilisateurs.

```json {4-7} Restricted enum values
{
  "type": "string",
  "enum": ["free", "pro", "enterprise"],
  "x-mint-enum": {
    "pro": ["pro", "enterprise"],
    "enterprise": ["enterprise"]
  }
}
```

Dans cet exemple, tous les utilisateurs voient `free`. Les utilisateurs des groupes `pro` ou `enterprise` voient `pro`. Seuls les utilisateurs du groupe `enterprise` voient `enterprise`.

<Note>
  `x-mint-enum` est une extension distincte de premier niveau de l&#39;objet de schéma, et non imbriquée sous `x-mint`.
</Note>

<div id="user-data-format">
  ## Format des données utilisateur
</div>

Votre système d&#39;authentification retourne des données utilisateur qui servent à la personnalisation. Les champs `groups`, `content` et `apiPlaygroundInputs` décrits sur cette page font tous partie de l&#39;objet de données utilisateur.

Pour connaître le format complet des données utilisateur et la référence de leurs champs, voir [Format des données utilisateur](/fr/deploy/authentication-setup#user-data-format).

<div id="logout-behavior">
  ## Comportement de déconnexion
</div>

La déconnexion se fait côté client. Lorsque les utilisateurs cliquent sur le bouton de déconnexion, Mintlify efface les données de session stockées dans leur navigateur.

Pour limiter la durée de conservation des données de personnalisation, définissez le champ `expiresAt` dans vos données utilisateur.
