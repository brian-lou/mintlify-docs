Créez un fichier `AGENTS.md` dans votre dépôt pour personnaliser le comportement de l&#39;agent (`Agents.md` est également accepté). L&#39;agent lit ce fichier et suit toutes les instructions que vous lui fournissez.

Vous pouvez aussi utiliser CLAUDE.md

L&#39;agent recherche des fichiers `AGENTS.md` à deux endroits. Il vérifie d&#39;abord le répertoire de documentation, puis la racine du dépôt. Si vous avez des fichiers `AGENTS.md` aux deux emplacements, l&#39;agent utilise celui qui se trouve dans votre répertoire de documentation.

Ajoutez toutes les instructions que vous souhaitez voir l&#39;agent suivre. L&#39;agent les ajoute à son prompt système ; elles s&#39;appliquent donc à toutes les tâches, que vous utilisiez l&#39;agent dans votre tableau de bord, sur Slack ou via l&#39;API.

<div id="what-to-include-in-agentsmd">
  ## Que faut-il inclure dans AGENTS.md
</div>

Pensez à ajouter des consignes sur :

* **Préférences de style** : style rédactionnel, ton, mise en forme et terminologie propres à votre documentation.
* **Normes de code** : langages de programmation, frameworks et conventions de codage à utiliser dans les exemples.
* **Exigences de contenu** : sections ou informations à inclure selon les types de pages.
* **Contexte du projet** : détails propres à votre produit, à votre architecture ou à votre base d’utilisateurs qui guident les choix de documentation.

<div id="example-agentsmd-file">
  ## Exemple de fichier AGENTS.md
</div>

```markdown AGENTS.md
# Documentation agent instructions

## Code examples
- Use TypeScript for all code examples. Our users are primarily TypeScript developers.
- Always include error handling in API call examples.
- Show both success and error response examples for all endpoints.
- Include import statements at the top of code examples.

## API documentation standards
- Every endpoint must document: authentication requirements, rate limits, and common error codes.
- Use real-world parameter values in examples (not foo/bar placeholders).
- Include a complete request/response cycle for each endpoint.

## Style and formatting
- Write for developers with 2-5 years of experience. Don't oversimplify, but explain non-obvious concepts.
- Use active voice and second person ("you").
- Date format: ISO 8601 (YYYY-MM-DD).
- When referencing UI elements, use bold: **Settings** button.

## What to include
- Add prerequisite sections to guides when users need API keys, environment setup, or dependencies.
- Include "Next steps" sections linking to related documentation.
- Add troubleshooting sections for common issues we see in support tickets.
```
