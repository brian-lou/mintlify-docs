---
title: "Créer manuellement des pages d’API"
description: "Documentez manuellement des points de terminaison d’API dans des fichiers MDX."
keywords: ["documentation API", "documentation des points de terminaison"]
---

Vous pouvez définir manuellement des points de terminaison d’API sur des pages MDX distinctes. Cette approche est utile pour les petites API ou pour le prototypage.

<div id="setup">
  ## Configuration
</div>

<Steps>
  <Step title="Configurez les paramètres de votre API">
    Dans votre fichier `docs.json`, définissez votre URL de base et votre méthode d’authentification.

    ```json Example docs.json
    "api": {
      "mdx": {
        "server": "https://api.acme.com/",
        "auth": {
          "method": "key",
          "name": "x-api-key"
        }
      }
    }
    ```

    Si vous souhaitez masquer le Bac à sable API, définissez le champ `display` sur `none`. Vous n&#39;avez pas besoin d&#39;inclure de méthode d&#39;authentification si vous masquez le bac à sable.

    ```json
    "api": {
      "playground": {
        "display": "none"
      }
    }
    ```

    Retrouvez la liste complète des configurations de l’API dans [Settings](/fr/organize/settings#api-configurations).
  </Step>

  <Step title="Créez les pages de vos endpoints">
    Créez un fichier MDX pour chaque point de terminaison. Définissez `title` et `api` dans le Frontmatter :

    ```mdx
    ---
    title: 'Create new user'
    api: 'POST /v1/users'
    ---
    ```

    Le champ `api` du Frontmatter accepte soit une URL complète, soit un chemin relatif :

    * **URL complète** comme `POST https://api.acme.com/v1/users`. Le champ `server` dans `docs.json` est ignoré pour cet endpoint.
    * **Chemin relatif** comme `POST /v1/users`. Nécessite un champ `server` dans `docs.json`. L’URL du serveur est ajoutée au chemin.

    Spécifiez les paramètres de chemin en les entourant de `{}` :

    ```bash
    https://api.example.com/v1/endpoint/{userId}
    ```

    Pour remplacer le mode d’affichage global du `playground` sur une page spécifique, ajoutez `playground` au frontmatter :

    ```mdx
    ---
    title: 'Create new user'
    api: 'POST https://api.mintlify.com/user'
    playground: 'none'
    ---
    ```

    Options :

    * `playground: 'interactive'` - Affiche le playground interactif (par défaut)
    * `playground: 'simple'` - Affiche un endpoint copiable, sans playground
    * `playground: 'none'` - Masque entièrement le playground
  </Step>

  <Step title="Ajouter des paramètres et des réponses">
    Utilisez les [champs de paramètres et de réponse](/fr/components/fields) pour documenter les paramètres de votre point de terminaison et les valeurs qu’il renvoie.

    ```mdx
    <ParamField path="userId" type="string" required>
      Unique identifier for the user
    </ParamField>

    <ParamField body="email" type="string" required>
      User's email address
    </ParamField>

    <ResponseField name="id" type="string" required>
      Unique identifier for the newly created user
    </ResponseField>

    <ResponseField name="email" type="string" required>
      User's email address
    </ResponseField>
    ```
  </Step>

  <Step title="Ajoutez vos endpoints à votre documentation">
    Ajoutez les pages de vos endpoints à la navigation en mettant à jour le champ `pages` de votre `docs.json` :

    ```json docs.json
    "navigation": {
      "tabs": [
        {
          "tab": "API Reference",
          "groups": [
            {
              "group": "Users",
              "pages": [
                "api-reference/users/create-user",
                "api-reference/users/get-user",
                "api-reference/users/update-user"
              ]
            },
            {
              "group": "Orders",
              "pages": [
                "api-reference/orders/create-order",
                "api-reference/orders/list-orders"
              ]
            }
          ]
        }
      ]
    }
    ```

    Chaque chemin de page correspond à un fichier MDX dans votre dépôt de documentation. Par exemple, `api-reference/users/create-user.mdx`. Pour en savoir plus sur l&#39;organisation de votre documentation, consultez [Navigation](/fr/organize/navigation).

    ### Utiliser des endpoints OpenAPI dans la navigation

    Si vous disposez d&#39;une spécification OpenAPI, vous pouvez faire référence directement à des endpoints dans votre navigation sans créer de fichiers MDX individuels. Pour faire référence à des endpoints spécifiques, incluez le chemin du fichier OpenAPI et l&#39;endpoint :

    ```json docs.json
    "navigation": {
      "pages": [
        "introduction",
        "/path/to/users-openapi.json POST /users",
        "/path/to/orders-openapi.json GET /orders"
      ]
    }
    ```

    Vous pouvez également définir une spécification OpenAPI par défaut pour un groupe de navigation et référencer les endpoints par méthode et chemin :

    ```json docs.json
    {
      "group": "API reference",
      "openapi": "/path/to/openapi-v1.json",
      "pages": [
        "overview",
        "authentication",
        "GET /users",
        "POST /users",
        {
          "group": "Orders",
          "openapi": "/path/to/openapi-v2.json",
          "pages": [
            "GET /orders",
            "POST /orders"
          ]
        }
      ]
    }
    ```

    Pour en savoir plus sur l’intégration d’OpenAPI, consultez [la configuration d’OpenAPI](/fr/api-playground/openapi-setup).
  </Step>
</Steps>

<div id="enable-authentication">
  ## Activer l’authentification
</div>

Vous pouvez définir l’authentification globalement dans `docs.json` ou la redéfinir sur des pages individuelles à l’aide du champ `authMethod` dans le Frontmatter. Une méthode définie pour une page spécifique remplace le paramètre global.

<div id="bearer-token">
  ### Jeton d’authentification Bearer
</div>

<CodeGroup>
  ```json docs.json
  "api": {
    "mdx": {
      "auth": {
        "method": "bearer"
      }
    }
  }
  ```

  ```mdx Page Metadata
  ---
  title: "Titre de votre page"
  authMethod: "bearer"
  ---
  ```
</CodeGroup>

<div id="none">
  ### Aucun
</div>

Pour désactiver l’authentification sur une page spécifique, définissez `authMethod` sur `none` :

```mdx Page Metadata
---
title: "Your page title"
authMethod: "none"
---
```
