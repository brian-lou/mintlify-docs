---
title: "Créer manuellement des pages d’API"
description: "Documentez manuellement les endpoints d’API avec des fichiers MDX."
keywords: ["API documentation", "endpoint documentation"]
---

Vous pouvez définir manuellement des endpoints d’API dans des pages MDX distinctes. Cette approche est utile pour les petites API ou pour le prototypage.

<div id="setup">
  ## Configuration
</div>

<Steps>
  <Step title="Configurez vos paramètres d’API">
    Dans votre fichier `docs.json`, définissez l’URL de base et la méthode d’authentification.

    ```json Example docs.json
    "api": {
      "mdx": {
        "server": "https://api.acme.com/",
        "auth": {
          "method": "key",
          "name": "x-api-key"
        }
      }
    }
    ```

    Si vous souhaitez masquer l&#39;espace de test de l&#39;API, définissez le champ `display` sur `none`. Il n&#39;est pas nécessaire d&#39;inclure de méthode d&#39;authentification si vous masquez l&#39;espace de test.

    ```json
    "api": {
      "playground": {
        "display": "none"
      }
    }
    ```

    Consultez la liste complète des configurations d’API dans [Settings](/fr/organize/settings#api-configurations).
  </Step>

  <Step title="Créez les pages de vos points de terminaison">
    Créez un fichier MDX pour chaque endpoint. Renseignez les champs `title` et `api` dans le frontmatter :

    ```mdx
    ---
    title: 'Create new user'
    api: 'POST /v1/users'
    ---
    ```

    Le champ frontmatter `api` accepte soit une URL complète, soit un chemin relatif :

    * **URL complète** comme `POST https://api.acme.com/v1/users`. Le champ `server` dans `docs.json` est ignoré pour cet endpoint.
    * **Chemin relatif** comme `POST /v1/users`. Nécessite un champ `server` dans `docs.json`. L’URL du serveur est ajoutée devant le chemin.

    Spécifiez les paramètres de chemin en les encadrant de `{}` :

    ```bash
    https://api.example.com/v1/endpoint/{userId}
    ```

    Pour remplacer le mode d’affichage global du playground pour une page donnée, ajoutez `playground` au frontmatter :

    ```mdx
    ---
    title: 'Create new user'
    api: 'POST https://api.mintlify.com/user'
    playground: 'none'
    ---
    ```

    Options :

    * `playground: 'interactive'` - Afficher le playground interactif (par défaut)
    * `playground: 'simple'` - Afficher un endpoint à copier, sans playground
    * `playground: 'none'` - Masquer complètement le playground
  </Step>

  <Step title="Ajouter des paramètres et des réponses">
    Utilisez les [champs de paramètres et de réponse](/fr/components/fields) pour documenter les paramètres et les valeurs renvoyées par votre endpoint.

    ```mdx
    <ParamField path="userId" type="string" required>
      Identifiant unique de l’utilisateur
    </ParamField>

    <ParamField body="email" type="string" required>
      Adresse e-mail de l’utilisateur
    </ParamField>

    <ResponseField name="id" type="string" required>
      Identifiant unique de l’utilisateur nouvellement créé
    </ResponseField>

    <ResponseField name="email" type="string" required>
      Adresse e-mail de l’utilisateur
    </ResponseField>
    ```
  </Step>

  <Step title="Ajoutez vos endpoints à votre documentation">
    Ajoutez les pages de vos points de terminaison à la navigation en mettant à jour le champ `pages` dans votre `docs.json` :

    ```json docs.json
    "navigation": {
      "tabs": [
        {
          "tab": "API Reference",
          "groups": [
            {
              "group": "Users",
              "pages": [
                "api-reference/users/create-user",
                "api-reference/users/get-user",
                "api-reference/users/update-user"
              ]
            },
            {
              "group": "Orders",
              "pages": [
                "api-reference/orders/create-order",
                "api-reference/orders/list-orders"
              ]
            }
          ]
        }
      ]
    }
    ```

    Chaque chemin de page correspond à un fichier MDX dans votre dépôt de documentation. Par exemple, `api-reference/users/create-user.mdx`. Pour en savoir plus sur la structuration de votre documentation, consultez [Navigation](/fr/organize/navigation).

    ### Utilisation des endpoints OpenAPI dans la navigation

    Si vous avez une spécification OpenAPI, vous pouvez référencer des endpoints directement dans votre navigation, sans créer de fichiers MDX individuels. Pour référencer des endpoints spécifiques, incluez le chemin du fichier OpenAPI ainsi que l’endpoint :

    ```json docs.json
    "navigation": {
      "pages": [
        "introduction",
        "/path/to/users-openapi.json POST /users",
        "/path/to/orders-openapi.json GET /orders"
      ]
    }
    ```

    Vous pouvez également définir une spécification OpenAPI par défaut pour un groupe de navigation, puis référencer les endpoints par méthode et chemin :

    ```json docs.json
    {
      "group": "API reference",
      "openapi": "/path/to/openapi-v1.json",
      "pages": [
        "overview",
        "authentication",
        "GET /users",
        "POST /users",
        {
          "group": "Orders",
          "openapi": "/path/to/openapi-v2.json",
          "pages": [
            "GET /orders",
            "POST /orders"
          ]
        }
      ]
    }
    ```

    Pour plus de détails sur l&#39;intégration d&#39;OpenAPI, consultez [Configuration d&#39;OpenAPI](/fr/api-playground/openapi-setup).
  </Step>
</Steps>

<div id="enable-authentication">
  ## Activer l’authentification
</div>

Vous pouvez configurer l’authentification globalement dans `docs.json` ou la remplacer pour des pages spécifiques à l’aide du champ `authMethod` dans le frontmatter. Une méthode définie pour une page précise a priorité sur le paramètre global.

<div id="bearer-token">
  ### Jeton d’accès Bearer
</div>

<CodeGroup>
  ```json docs.json
  "api": {
    "mdx": {
      "auth": {
        "method": "bearer"
      }
    }
  }
  ```

  ```mdx Page Metadata
  ---
  title: "Titre de votre page"
  authMethod: "bearer"
  ---
  ```
</CodeGroup>

<div id="none">
  ### Aucun
</div>

Pour désactiver l’authentification pour une page donnée, définissez `authMethod` sur `none` :

```mdx Page Metadata
---
title: "Your page title"
authMethod: "none"
---
```
