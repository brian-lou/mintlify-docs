Le bac à sable API est un environnement interactif qui permet aux utilisateurs de tester et d’explorer les points de terminaison de votre API. Les développeurs peuvent créer des requêtes API, les envoyer et consulter les réponses sans quitter votre documentation.

Consultez [Déclencher une mise à jour](/fr/api/update/trigger) pour voir un exemple du bac à sable API en action.

Le bac à sable génère des pages interactives pour vos points de terminaison à partir de votre spécification OpenAPI ou de votre schéma AsyncAPI. Si vous modifiez votre API, il met automatiquement à jour les pages concernées.

Nous vous recommandons de générer votre bac à sable API à partir d’une spécification OpenAPI. Vous pouvez toutefois créer manuellement des pages de référence d’API après avoir défini une URL de base et une méthode d’authentification dans votre `docs.json`.

<div id="get-started">
  ## Pour commencer
</div>

<Steps>
  <Step title="Ajoutez votre fichier de spécification OpenAPI.">
    <Tip>
      Validez votre fichier de spécification OpenAPI avec le [Swagger Editor](https://editor.swagger.io/) ou la commande [Mint CLI](https://www.npmjs.com/package/mint) `mint openapi-check <filename>`.
    </Tip>

    ```bash {3}
    /your-project
      |- docs.json
      |- openapi.json
    ```
  </Step>

  <Step title="Générez les pages des points de terminaison.">
    Mettez à jour votre `docs.json` pour y référencer votre spécification OpenAPI.

    **Pour générer automatiquement des pages pour tous les points de terminaison de votre spécification OpenAPI**, ajoutez une propriété `openapi` à n’importe quel élément de navigation.

    Cet exemple génère une page pour chaque point de terminaison défini dans `openapi.json` et organise les pages dans le groupe « API reference ».

    ```json Générer toutes les pages de point de terminaison
    "navigation": {
      "groups": [
        {
          "group": "API reference",
          "openapi": "openapi.json"
        }
      ]
    }
    ```

    **Pour générer des pages uniquement pour certains points de terminaison**, listez les points de terminaison dans la propriété `pages` de l’élément de navigation.

    Cet exemple génère des pages uniquement pour les points de terminaison `GET /users` et `POST /users`. Pour générer d’autres pages de point de terminaison, ajoutez des points de terminaison supplémentaires au tableau `pages`.

    ```json Générer des pages de point de terminaison spécifiques
    "navigation": {
      "groups": [
          {
            "group": "API reference",
            "openapi": "openapi.json",
            "pages": [
              "GET /users",
              "POST /users"
            ]
          }
      ]
    }
    ```
  </Step>
</Steps>

<div id="customize-your-playground">
  ## Personnalisez votre bac à sable
</div>

Personnalisez votre Bac à sable API en définissant les propriétés suivantes dans votre `docs.json`.

<ResponseField name="playground" type="object">
  Configuration du Bac à sable API.

  <Expandable title="playground" defaultOpen="True">
    <ResponseField name="display" type="&#x22;interactive&#x22; | &#x22;simple&#x22; | &#x22;none&#x22; | &#x22;auth&#x22;">
      Le mode d’affichage du Bac à sable API.

      * `"interactive"`: Affiche le bac à sable interactif.
      * `"simple"`: Affiche un endpoint copiable sans bac à sable.
      * `"none"`: N’affiche rien.
      * `"auth"`: Affiche le bac à sable interactif uniquement pour les utilisateurs authentifiés. Les utilisateurs non authentifiés ou qui ne font pas partie des groupes requis ne voient aucun bac à sable.

      La valeur par défaut est `interactive`.
    </ResponseField>

    <ResponseField name="proxy" type="boolean" defaultOpen="True">
      Indique si les requêtes API doivent passer par un serveur proxy. La valeur par défaut est `true`.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="examples" type="object">
  Configuration des exemples d’API générés automatiquement.

  <Expandable title="examples" defaultOpen="True">
    <ResponseField name="languages" type="array of string">
      Langues des extraits d’API générés automatiquement.

      Les langues s’affichent dans l’ordre indiqué.
    </ResponseField>

    <ResponseField name="defaults" type="&#x22;required&#x22; | &#x22;all&#x22;">
      Indique s’il faut afficher les paramètres facultatifs dans les exemples d’API. La valeur par défaut est `all`.
    </ResponseField>

    <ResponseField name="prefill" type="boolean">
      Indique s’il faut préremplir le Bac à sable API avec les données issues des exemples de schéma. Lorsqu’elle est activée, cette option renseigne automatiquement les champs de requête du bac à sable avec les valeurs d’exemple de votre spécification OpenAPI. La valeur par défaut est `false`.
    </ResponseField>

    <ResponseField name="autogenerate" type="boolean">
      Indique s’il faut générer des exemples de code pour les points de terminaison à partir des spécifications d’API. La valeur par défaut est `true`. Lorsqu’elle est définie sur `false`, seuls les exemples de code rédigés manuellement (issus de `x-codeSamples` dans les spécifications OpenAPI ou des composants `<RequestExample>` en MDX) apparaissent dans le Bac à sable API.
    </ResponseField>
  </Expandable>
</ResponseField>

<div id="example-configuration">
  ### Exemple de configuration
</div>

Cet exemple configure le Bac à sable API en mode interactif, avec des extraits de code d’exemple pour cURL, Python et JavaScript. Seuls les paramètres obligatoires sont affichés dans les extraits de code, et le bac à sable préremplit le corps de la requête avec des valeurs d’exemple.

```json
{
 "api": {
   "playground": {
     "display": "interactive"
   },
   "examples": {
     "languages": ["curl", "python", "javascript"],
     "defaults": "required",
     "prefill": true
   }
 }
}
```

<div id="auth-based-playground-display">
  ### Affichage du Bac à sable API selon l&#39;authentification
</div>

Utilisez le mode d&#39;affichage `auth` pour afficher le Bac à sable API interactif uniquement aux utilisateurs authentifiés. C&#39;est utile lorsque vous souhaitez permettre aux utilisateurs de consulter publiquement la documentation de votre API tout en réservant l&#39;accès au Bac à sable API aux utilisateurs connectés.

Lorsque `display` est défini sur `auth` :

* Les utilisateurs authentifiés voient le Bac à sable API interactif.
* Les utilisateurs non authentifiés ne voient pas de Bac à sable API (équivalent à `none`).

Vous pouvez également combiner `auth` avec la propriété `groups` dans le Frontmatter de la page pour limiter l&#39;accès au Bac à sable API à des groupes d&#39;utilisateurs spécifiques.

```mdx Page with group-restricted playground
---
title: "Create user"
openapi: POST /users
playground: auth
groups: ["admin", "developer"]
public: true
---
```

Dans cet exemple :

* La page est visible publiquement (n’importe qui peut consulter la documentation).
* Seuls les utilisateurs authentifiés appartenant aux groupes `admin` ou `developer` voient le Bac à sable API interactif.
* Les utilisateurs qui n’appartiennent pas à ces groupes ne voient pas le Bac à sable API.

Si la page n’a pas de propriété `groups`, tous les utilisateurs authentifiés voient le Bac à sable API interactif.

<Note>
  Le mode d’affichage `auth` nécessite que l’[authentification](/fr/deploy/authentication-setup) soit configurée pour votre documentation.
</Note>

<div id="custom-endpoint-pages">
  ### Pages de point de terminaison personnalisées
</div>

Lorsque vous avez besoin de davantage de contrôle sur votre documentation d’API, utilisez l’extension `x-mint` dans votre spécification OpenAPI ou créez des pages MDX distinctes pour vos points de terminaison.

Les deux options vous permettent de :

* Personnaliser les métadonnées de la page
* Ajouter du contenu supplémentaire, comme des exemples
* Contrôler le comportement du Bac à sable API pour chaque page

L’extension `x-mint` est recommandée afin que toute votre documentation d’API soit générée automatiquement à partir de votre spécification OpenAPI et centralisée dans un seul fichier.

Les pages MDX distinctes sont recommandées pour les petites API ou lorsque vous souhaitez tester des modifications page par page.
