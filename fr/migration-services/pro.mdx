Votre offre Pro comprend des services de migration pour transférer votre documentation vers Mintlify. Ce guide présente le processus de migration, les délais de livraison et notre approche de l’assurance qualité.

<div id="what-to-expect-for-your-migration">
  ## À quoi vous attendre pour votre migration
</div>

Une migration est un transfert ponctuel de votre documentation qui nécessite un gel du code. Nous migrons votre documentation, votre image de marque (logos, couleurs et polices), vos pages de référence d’API et la structure de navigation.

Votre migration inclut un lien de préproduction pour suivre l’avancement, ainsi qu’une période de 3 jours après la livraison pour nous faire part de vos retours sur tout problème lié au contenu, aux ressources ou à l’image de marque.

<Info>
  Les services de migration **n’incluent pas** :

  * La synchronisation dynamique de votre documentation
  * Le conseil en design ou en architecture de l’information
  * Le développement de composants personnalisés (pages d’accueil, intégrations personnalisées, etc.)
  * La configuration des redirections
  * La configuration des outils d’analyse
</Info>

<div id="migration-process">
  ## Processus de migration
</div>

<Steps>
  <Step title="Soumettre le formulaire de migration">
    Soumettez le [formulaire de migration](https://mintlify.typeform.com/pro-migrations).

    Fournissez la source de votre documentation, vos éléments de marque (logos, codes couleur, polices), vos spécifications OpenAPI, votre date de mise en ligne et votre mode de livraison préféré (PR GitHub ou fichier zip).
  </Step>

  <Step title="Recevoir le cadrage et le calendrier (1 à 2 jours ouvrés)">
    Nous examinons votre demande et vous communiquons un délai de livraison estimé sous 24 à 48 heures. Nous signalons tout composant personnalisé ou toute partie de la migration nécessitant une discussion.
  </Step>

  <Step title="Suivre l'avancement pendant la migration">
    Nous lançons la migration et partageons un lien de préproduction afin que vous puissiez suivre l&#39;avancement en temps réel.
  </Step>

  <Step title="Recevoir la livraison finale">
    Nous livrons votre migration via une PR GitHub ou un fichier zip, selon votre préférence.
  </Step>

  <Step title="Délai de retour (trois jours ouvrés)">
    Faites part de vos retours sur le contenu, les ressources ou l&#39;image de marque. Nous traitons tous les problèmes relevant du périmètre dans ce même délai.
  </Step>

  <Step title="Assistance à la mise en ligne">
    Nous fournissons la documentation et les conseils nécessaires pour connecter votre dépôt, configurer les redirections et paramétrer votre domaine personnalisé.
  </Step>
</Steps>

<div id="quality-assurance">
  ## Assurance qualité
</div>

Nous travaillons avec des prestataires tiers sélectionnés avec soin et effectuons un audit qualité interne avant la livraison. Voici ce que nous vérifions :

<Card title="Exhaustivité du contenu" icon="file-check">
  * Toute la documentation issue de votre source a été migrée.
  * Le contenu est correctement mis en forme avec les composants Mintlify.
  * La structure de navigation correspond à vos spécifications.

<Card title="Éléments visuels" icon="palette">

<Card title="Fonctionnement" icon="rocket">

</Card>

<div id="after-your-migration">
  ## Après votre migration
</div>

Une fois que nous aurons livré votre migration, vous devrez suivre les étapes ci-dessous pour mettre votre documentation en ligne :

1. [Connecter votre dépôt GitHub et finaliser la configuration](https://www.mintlify.com/docs/quickstart#install-the-github-app).
2. [Configurer les redirections si nécessaire](https://www.mintlify.com/docs/create/redirects).
3. [Configurer votre domaine personnalisé](https://www.mintlify.com/docs/customize/custom-domain).
4. **Testez avant la mise en ligne** - Avant de basculer depuis votre ancienne documentation :
   * Passez en revue toutes les pages sur votre lien de préproduction.
   * Testez la navigation et la fonction de recherche.
   * Vérifiez que toutes les images et vidéos se chargent correctement.
   * Vérifiez que les blocs de code s’affichent correctement.
   * Testez sur mobile et sur ordinateur.
5. **Mettez en ligne !** Votre documentation est prête à être publiée !

<Note>
  **Besoin d’aide ?** Notre équipe d’assistance est disponible pour vous accompagner à chaque étape. Contactez-nous à [support@mintlify.com](mailto:support@mintlify.com).
</Note>

<div id="frequently-asked-questions">
  ## Questions fréquentes
</div>

<AccordionGroup>
  <Accordion title="Combien de temps dure une migration ?">
    Nous livrons généralement les migrations sous 10 jours ouvrés, selon leur complexité. Vous recevrez un calendrier précis dans les 24 à 48 heures suivant l’envoi de votre formulaire de migration.
  </Accordion>

  <Accordion title="Puis-je demander des modifications après la livraison ?">
    Oui. Vous disposez d’une période de 3 jours après la livraison pour demander des modifications du contenu, des éléments graphiques ou de l’image de marque. Nous traitons tous les retours inclus dans le périmètre dans ce même délai.
  </Accordion>

  <Accordion title="Que dois-je faire une fois la migration terminée ?">
    La migration transfère votre contenu, mais vous devrez :

    * Connecter votre dépôt de documentation à votre dashboard Mintlify.
    * Mettre en place des redirections depuis vos anciennes URL de documentation.
    * Configurer votre domaine personnalisé.

    Nous fournissons une documentation pas à pas et une assistance pour chacune de ces étapes.
  </Accordion>

  <Accordion title="Puis-je personnaliser la structure de navigation ?">
    Oui. Vous pouvez fournir une architecture de l’information personnalisée dans le formulaire de migration, et nous la mettrons en place. Toutefois, le développement de composants personnalisés (comme des pages d’accueil sur mesure) n’est pas inclus dans le service de migration.
  </Accordion>

  <Accordion title="Que se passe-t-il si ma documentation change pendant la migration ?">
    Comme les migrations nécessitent un gel du code, toute modification apportée à votre documentation source après l’envoi ne sera pas incluse. Nous vous recommandons de finaliser toutes les mises à jour avant de lancer la migration.
  </Accordion>
</AccordionGroup>
