Le fichier `docs.json` vous permet de transformer une collection de fichiers Markdown en un site de documentation navigable et personnalisé. Ce fichier de configuration obligatoire contrôle les styles, la navigation, les intégrations et bien plus encore. Considérez-le comme le plan de votre documentation.

Les paramètres définis dans `docs.json` s&#39;appliquent à l&#39;ensemble des pages.

<div id="setting-up-your-docsjson">
  ## Configuration de votre `docs.json`
</div>

Pour commencer, vous n&#39;avez besoin que de définir `theme`, `name`, `colors.primary` et `navigation`. Les autres champs sont facultatifs et vous pourrez les ajouter au fur et à mesure que votre documentation se développe.

Pour une expérience d’édition optimale, incluez la référence du schéma en haut de votre fichier `docs.json`. Cela active l’autocomplétion, la validation et des info-bulles utiles dans la plupart des éditeurs de code :

```json
{
  "$schema": "https://mintlify.com/docs.json",
  "theme": "mint",
  "name": "Your Docs",
  "colors": {
    "primary": "#ff0000"
  },
  "navigation": {
    // Votre structure de navigation
  }
  // Le reste de votre configuration
}
```

<ResponseField name="theme" required>
  Le thème de mise en page de votre site.

  L&#39;un des suivants : `mint`, `maple`, `palm`, `willow`, `linden`, `almond`, `aspen`.

  Voir [Thèmes](/fr/customize/themes) pour plus d&#39;informations.
</ResponseField>

<ResponseField name="name" type="string" required>
  Le nom de votre projet, de votre organisation ou de votre produit.
</ResponseField>

<ResponseField name="colors" type="object" required>
  Les couleurs utilisées dans votre documentation. Les couleurs sont appliquées différemment selon les thèmes. Si vous ne fournissez qu&#39;une couleur principale, elle s&#39;applique à tous les éléments de couleur.

  <Expandable title="Couleurs">
    <ResponseField name="primary" type="string matching ^#([a-fA-F0-9]{6}|[a-fA-F0-9]{3})$" required>
      La couleur principale de votre documentation. Généralement utilisée pour la mise en avant en mode clair, avec quelques variations selon le thème.

      Doit être un code hexadécimal commençant par `#`.
    </ResponseField>

    <ResponseField name="light" type="string matching ^#([a-fA-F0-9]{6}|[a-fA-F0-9]{3})$">
      La couleur utilisée pour la mise en avant en mode sombre.

      Doit être un code hexadécimal commençant par `#`.
    </ResponseField>

    <ResponseField name="dark" type="string matching ^#([a-fA-F0-9]{6}|[a-fA-F0-9]{3})$">
      La couleur utilisée pour les boutons et les états de survol en modes clair et sombre, avec quelques variations selon le thème.

      Doit être un code hexadécimal commençant par `#`.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="styling" type="object">
  Paramètres de style visuel.

  <Expandable title="Style">
    <ResponseField name="eyebrows" type="&#x22;section&#x22; | &#x22;breadcrumbs&#x22;">
      Le style de l’« eyebrow » de la page. Choisissez `section` pour afficher le nom de la section ou `breadcrumbs` pour afficher le chemin de navigation complet. La valeur par défaut est `section`.
    </ResponseField>

    <ResponseField name="latex" type="boolean">
      Contrôle l’inclusion des feuilles de style LaTeX, en remplaçant la détection automatique. Par défaut, Mintlify détecte automatiquement l’utilisation de LaTeX dans votre contenu et charge les feuilles de style nécessaires.

      * Réglez sur `true` pour forcer le chargement des feuilles de style LaTeX lorsque la détection automatique ne reconnaît pas vos expressions mathématiques.
      * Réglez sur `false` pour empêcher le chargement des feuilles de style LaTeX afin d’améliorer les performances si vous n’utilisez pas d’expressions mathématiques mais que vous avez du contenu qui déclenche une détection faussement positive.
    </ResponseField>

    <ResponseField name="codeblocks" type="&#x22;system&#x22; | &#x22;dark&#x22; | string | object">
      Configuration du thème des blocs de code. La valeur par défaut est `"system"`.

      **Configuration simple :**

      * `"system"` : correspond au mode actuel du site (clair ou sombre)
      * `"dark"` : utilise toujours le mode sombre

      **Configuration de thème personnalisée :**

      * Utilisez une chaîne pour spécifier un seul [thème Shiki](https://shiki.style/themes) pour tous les blocs de code
      * Utilisez un objet pour spécifier des [thèmes Shiki](https://shiki.style/themes) distincts pour les modes clair et sombre

      <ResponseField name="theme" type="string">
        Un unique nom de thème Shiki à utiliser pour les modes clair et sombre.

        ```json
        "styling": {
          "codeblocks": {
            "theme": "dracula"
          }
        }
        ```
      </ResponseField>

      <ResponseField name="theme" type="object">
        Thèmes distincts pour les modes clair et sombre.

        <Expandable title="theme">
          <ResponseField name="light" type="string" required>
            Un nom de thème Shiki pour le mode clair.
          </ResponseField>

          <ResponseField name="dark" type="string" required>
            Un nom de thème Shiki pour le mode sombre.
          </ResponseField>

          ```json
          "styling": {
            "codeblocks": {
              "theme": {
                "light": "github-light",
                "dark": "github-dark"
              }
            }
          }
          ```
        </Expandable>
      </ResponseField>

      <ResponseField name="languages" type="object">
        Configuration personnalisée des langages pour les blocs de code.

        <Expandable title="languages">
          <ResponseField name="custom" type="array of string">
            Chemins vers les fichiers JSON décrivant des langages Shiki personnalisés. Utilisez cette option pour ajouter la coloration syntaxique pour des langages qui ne sont pas inclus dans l’ensemble par défaut de Shiki.

            Le fichier JSON doit suivre le [format de grammaire TextMate](https://macromates.com/manual/en/language_grammars) utilisé par Shiki.

            ```json
            "styling": {
              "codeblocks": {
                "languages": {
                  "custom": ["/languages/my-custom-language.json"]
                }
              }
            }
            ```
          </ResponseField>
        </Expandable>
      </ResponseField>
    </ResponseField>
  </Expandable>
</ResponseField>

<div id="upgrading-from-mintjson">
  ## Migration depuis `mint.json`
</div>

Si votre projet de documentation utilise le fichier déprécié `mint.json`, suivez ces étapes pour passer à `docs.json`.

<Steps>
  <Step title="Installer ou mettre à jour le CLI">
    Si vous n&#39;avez pas encore installé le [CLI](/fr/installation), installez-le maintenant :

    <CodeGroup>
      ```bash npm
      npm i -g mint
      ```

      ```bash yarn
      yarn global add mint
      ```

      ```bash pnpm
      pnpm add -g mint
      ```
    </CodeGroup>

    Si vous avez déjà installé le CLI, assurez-vous qu&#39;il est à jour :

    ```bash
    mint update
    ```
  </Step>

  <Step title="Créer votre fichier docs.json">
    Dans le dépôt de votre documentation, exécutez :

    ```bash
    mint upgrade
    ```

    Cette commande crée un fichier `docs.json` à partir de votre `mint.json` existant. Passez en revue le fichier généré pour vous assurer que tous les paramètres sont corrects.
  </Step>

  <Step title="Supprimer votre fichier mint.json">
    Après avoir vérifié que votre `docs.json` est correctement configuré, vous pouvez supprimer sans risque votre ancien fichier `mint.json`.
  </Step>
</Steps>
