Le fichier `docs.json` vous permet de transformer un ensemble de fichiers Markdown en un site de documentation personnalisé, facile à parcourir. Ce fichier de configuration obligatoire contrôle le style, la navigation, les intégrations, et plus encore. Considérez-le comme le plan de votre documentation.

Les paramètres définis dans `docs.json` s’appliquent globalement à toutes les pages.

<div id="setting-up-your-docsjson">
  ## Configurer votre `docs.json`
</div>

Pour commencer, il vous suffit d’indiquer `theme`, `name`, `colors.primary` et `navigation`. Les autres champs sont facultatifs, et vous pourrez les ajouter à mesure que les besoins de votre documentation évoluent.

Pour une meilleure expérience d’édition, ajoutez la référence du schéma en haut de votre fichier `docs.json`. Cela active l’autocomplétion, la validation et des infobulles utiles dans la plupart des éditeurs de code :

```json
{
  "$schema": "https://mintlify.com/docs.json",
  "theme": "mint",
  "name": "Your Docs",
  "colors": {
    "primary": "#ff0000"
  },
  "navigation": {
    // Votre structure de navigation
  }
  // Le reste de votre configuration
}
```

<ResponseField name="theme" required>
  Le thème de mise en page de votre site.

  Une des valeurs suivantes : `mint`, `maple`, `palm`, `willow`, `linden`, `almond`, `aspen`.

  Consultez [Themes](/fr/customize/themes) pour en savoir plus.
</ResponseField>

<ResponseField name="name" type="string" required>
  Le nom de votre projet, de votre organisation ou de votre produit.
</ResponseField>

<ResponseField name="colors" type="object" required>
  Les couleurs utilisées dans votre documentation. Elles s’appliquent différemment selon le thème. Si vous fournissez uniquement une couleur principale, elle sera utilisée pour tous les éléments colorés.

  <Expandable title="Couleurs">
    <ResponseField name="primary" type="string matching ^#([a-fA-F0-9]{6}|[a-fA-F0-9]{3})$" required>
      La couleur principale de votre documentation. Elle est généralement utilisée pour les mises en valeur en mode clair, avec quelques variations selon le thème.

      Doit être un code hexadécimal commençant par `#`.
    </ResponseField>

    <ResponseField name="light" type="string matching ^#([a-fA-F0-9]{6}|[a-fA-F0-9]{3})$">
      La couleur utilisée pour les mises en valeur en mode sombre.

      Doit être un code hexadécimal commençant par `#`.
    </ResponseField>

    <ResponseField name="dark" type="string matching ^#([a-fA-F0-9]{6}|[a-fA-F0-9]{3})$">
      La couleur utilisée pour les boutons et les états de survol, en modes clair et sombre, avec quelques variations selon le thème.

      Doit être un code hexadécimal commençant par `#`.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="description" type="string">
  Description de votre site pour le référencement et l’indexation par l’IA.
</ResponseField>

<ResponseField name="logo" type="string or object">
  Définissez votre logo pour les modes clair et sombre.

    <ResponseField name="dark" type="string" required>

  </Expandable>
</ResponseField>

<ResponseField name="thumbnails" type="object">

<ResponseField name="styling" type="object">
  Configurations de style visuel.

  <Expandable title="Style">
    <ResponseField name="eyebrows" type="&#x22;section&#x22; | &#x22;breadcrumbs&#x22;">
      Définit le style du surtitre de la page. Choisissez `section` pour afficher le nom de la section ou `breadcrumbs` pour afficher le chemin de navigation complet. La valeur par défaut est `section`.
    </ResponseField>

    <ResponseField name="latex" type="boolean">
      Détermine si les feuilles de style LaTeX sont incluses, en remplaçant la détection automatique. Par défaut, Mintlify détecte automatiquement l’utilisation de LaTeX dans votre contenu et charge les feuilles de style nécessaires.

      * Définissez cette option sur `true` pour forcer le chargement des feuilles de style LaTeX lorsque la détection automatique ne reconnaît pas vos expressions mathématiques.
      * Définissez cette option sur `false` pour empêcher le chargement des feuilles de style LaTeX et améliorer les performances si vous n’utilisez pas d’expressions mathématiques, mais que votre contenu déclenche de faux positifs.
    </ResponseField>

    <ResponseField name="codeblocks" type="&#x22;system&#x22; | &#x22;dark&#x22; | string | object">
      Configuration du thème des blocs de code. La valeur par défaut est `"system"`.

      **Configuration simple :**

      * `"system"` : suit le mode actuel du site (clair ou sombre)
      * `"dark"` : utilise toujours le mode sombre

      **Configuration de thème personnalisée :**

      * Utilisez une chaîne pour indiquer un seul [thème Shiki](https://shiki.style/themes) pour tous les blocs de code
      * Utilisez un objet pour indiquer des [thèmes Shiki](https://shiki.style/themes) distincts pour les modes clair et sombre

      <ResponseField name="theme" type="string">
        Nom d’un thème Shiki unique à utiliser pour les modes clair et sombre.

        ```json
        "styling": {
          "codeblocks": {
            "theme": "dracula"
          }
        }
        ```
      </ResponseField>

      <ResponseField name="theme" type="object">
        Thèmes distincts pour les modes clair et sombre.

        <Expandable title="theme">
          <ResponseField name="light" type="string" required>
            Nom d’un thème Shiki pour le mode clair.
          </ResponseField>

          <ResponseField name="dark" type="string" required>
            Nom d’un thème Shiki pour le mode sombre.
          </ResponseField>

          ```json
          "styling": {
            "codeblocks": {
              "theme": {
                "light": "github-light",
                "dark": "github-dark"
              }
            }
          }
          ```
        </Expandable>
      </ResponseField>

      <ResponseField name="languages" type="object">
        Configuration personnalisée des langages pour les blocs de code.

        <Expandable title="languages">
          <ResponseField name="custom" type="array of string">
            Chemins vers des fichiers JSON décrivant des langages Shiki personnalisés. Utilisez cette option pour ajouter la coloration syntaxique de langages qui ne font pas partie de l’ensemble par défaut de Shiki.

            Le fichier JSON doit respecter le [format de grammaire TextMate](https://macromates.com/manual/en/language_grammars) utilisé par Shiki.

            ```json
            "styling": {
              "codeblocks": {
                "languages": {
                  "custom": ["/languages/my-custom-language.json"]
                }
              }
            }
            ```
          </ResponseField>
        </Expandable>
      </ResponseField>
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="icons" type="object">
  Paramètres de la bibliothèque d’icônes.

  <Expandable title="Icônes">
    <ResponseField name="library" type="&#x22;fontawesome&#x22; | &#x22;lucide&#x22;" required>
      Bibliothèque d’icônes à utiliser dans toute votre documentation. La valeur par défaut est `fontawesome`.

      Vous ne pouvez utiliser qu’une seule bibliothèque d’icônes pour votre projet. Tous les noms d’icônes de votre documentation doivent provenir de la même bibliothèque.

      <Note>
        Vous pouvez indiquer l’URL d’une icône hébergée en externe ou le chemin vers un fichier d’icône dans votre projet pour n’importe quelle icône, quel que soit le paramètre de bibliothèque.

    </ResponseField>
  </Expandable>
</ResponseField>

<div id="upgrading-from-mintjson">
  ## Migrer depuis `mint.json`
</div>

Si votre projet de documentation utilise le fichier `mint.json`, désormais obsolète, suivez ces étapes pour migrer vers `docs.json`.

<Steps>
  <Step title="Installer ou mettre à jour le CLI">
    Si vous n&#39;avez pas encore installé le [CLI](/fr/installation), faites-le maintenant :

    <CodeGroup>
      ```bash npm
      npm i -g mint
      ```

      ```bash yarn
      yarn global add mint
      ```

      ```bash pnpm
      pnpm add -g mint
      ```
    </CodeGroup>

    Si le CLI est déjà installé, vérifiez qu&#39;il est à jour :

    ```bash
    mint update
    ```
  </Step>

  <Step title="Créer votre fichier docs.json">
    Dans votre dépôt de documentation, exécutez :

    ```bash
    mint upgrade
    ```

    Cette commande crée un fichier `docs.json` à partir de votre `mint.json` existant. Vérifiez le fichier généré pour vous assurer que tous les paramètres sont corrects.
  </Step>

  <Step title="Supprimer votre fichier mint.json">
    Après avoir vérifié que votre `docs.json` est correctement configuré, vous pouvez supprimer votre ancien fichier `mint.json` en toute sécurité.
  </Step>
</Steps>
