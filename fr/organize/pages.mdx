Chaque page est un fichier Markdown. Les deux types de fichiers, `.mdx` et `.md`, sont pris en charge. Nous recommandons d&#39;utiliser MDX, qui combine Markdown et des composants React pour créer une documentation riche et interactive. Le Markdown simple (`.md`) est pris en charge pour faciliter la migration depuis d&#39;autres plateformes, mais il est recommandé de le convertir en MDX afin de bénéficier de l&#39;ensemble des fonctionnalités.

<div id="page-metadata">
  ## Métadonnées de page
</div>

Chaque page commence par un frontmatter, les métadonnées YAML délimitées par `---` au début d&#39;un fichier. Ces métadonnées définissent l&#39;apparence et le comportement de votre page.

Utilisez le frontmatter pour contrôler :

* Les titres et descriptions de page
* Les titres, icônes et tags de la barre latérale
* La mise en page des pages
* Les balises meta pour le SEO
* Les métadonnées personnalisées

<ResponseField name="title" type="string" required>
  Le titre de votre page qui apparaît dans la navigation et les onglets du navigateur.
</ResponseField>

<ResponseField name="description" type="string">
  Une brève description de ce que contient cette page. Apparaît sous le titre et améliore le référencement (SEO).
</ResponseField>

<ResponseField name="sidebarTitle" type="string">
  Un titre court qui s&#39;affiche dans la navigation de la barre latérale.
</ResponseField>

<ResponseField name="icon" type="string">
  L&#39;icône à afficher.

  Options :

  * Nom de l&#39;icône [Font Awesome](https://fontawesome.com/icons)
  * Nom de l&#39;icône [Lucide](https://lucide.dev/icons)
  * URL vers une icône hébergée en externe
  * Chemin vers un fichier d&#39;icône dans votre projet
</ResponseField>

<ResponseField name="iconType" type="string">
  Le style d&#39;icône [Font Awesome](https://fontawesome.com/icons). Utilisé uniquement avec les icônes Font Awesome.

  Options : `regular`, `solid`, `light`, `thin`, `sharp-solid`, `duotone`, `brands`.
</ResponseField>

<ResponseField name="tag" type="string">
  Un tag qui apparaît à côté du titre de votre page dans la barre latérale.
</ResponseField>

<ResponseField name="<custom>" type="string">
  Tout frontmatter YAML valide. Par exemple, `product: "API"` ou `version: "1.0.0"`.
</ResponseField>

```yaml Example YAML frontmatter wrap
---
title: "About frontmatter"
description: "Frontmatter is the metadata that controls how your page appears and behaves"
sidebarTitle: "Frontmatter"
icon: "book"
tag: "NEW"
---
```

<div id="page-mode">
  ## Mode de page
</div>

Contrôlez la façon dont votre page s’affiche grâce au paramètre `mode`.

<div id="default">
  ### Par défaut
</div>

Si aucun mode n’est défini, la page utilise une mise en page standard avec une barre latérale de navigation et une table des matières.

```yaml
---
title: "Default page title"
---
```

<div id="wide">
  ### Large
</div>

Le mode large masque la table des matières. Ce mode est utile pour les pages qui n’ont pas de titres ou si vous préférez profiter de l’espace horizontal supplémentaire. Le mode large est disponible pour tous les thèmes.

```yaml
---
title: "Wide page title"
mode: "wide"
---
```

<div id="custom">
  ### Personnalisé
</div>

Le mode personnalisé offre une mise en page minimaliste qui supprime tous les éléments à l’exception de la barre de navigation supérieure. C’est une toile vierge pour créer des pages de destination ou toute autre mise en page unique pour laquelle vous souhaitez réduire au minimum les éléments de navigation. Le mode personnalisé est disponible pour tous les thèmes.

```yaml
---
title: "Custom page title"
mode: "custom"
---
```

<Warning>
  L’utilisation de la propriété `style` sur les pages en mode personnalisé peut provoquer un décalage de la mise en page au chargement de la page. Utilisez plutôt [Tailwind CSS ou du CSS personnalisé](/fr/customize/custom-scripts) pour éviter ce problème.
</Warning>

<div id="frame">
  ### Frame
</div>

Le mode Frame propose une mise en page similaire au mode personnalisé, tout en conservant la barre latérale de navigation. Ce mode de page permet d’utiliser du HTML et des composants personnalisés tout en préservant l’expérience de navigation par défaut. Le mode Frame est uniquement disponible pour les thèmes Aspen et Almond.

```yaml
---
title: "Frame page title"
mode: "frame"
---
```

<div id="center">
  ### Mode centré
</div>

Le mode centré supprime la barre latérale et la table des matières pour placer le contenu au centre. Il est utile pour les journaux de modifications ou d’autres pages où vous souhaitez mettre l’accent sur le contenu. Le mode centré est disponible pour les thèmes Mint et Linden.

```yaml
---
title: "Center page title"
mode: "center"
---
```

<div id="api-pages">
  ## Pages d’API
</div>

Créez des environnements de test d’API interactifs en ajoutant une spécification d’API dans votre frontmatter, via `api` ou `openapi`.

```yaml
---
openapi: "GET /endpoint"
---
```

En savoir plus sur la création de [documentation d’API](/fr/api-playground/overview).

<div id="external-links">
  ## Liens externes
</div>

Ajoutez des liens vers des sites externes directement depuis votre navigation à l’aide de la métadonnée `url`.

```yaml
---
title: "npm Package"
url: "https://www.npmjs.com/package/mint"
---
```

<div id="search-engine-optimization">
  ## Optimisation pour les moteurs de recherche
</div>

La plupart des balises méta SEO sont générées automatiquement. Vous pouvez définir manuellement des balises méta SEO pour améliorer le référencement de votre site, le partage sur les réseaux sociaux et la compatibilité avec les navigateurs.

<Note>
  Les balises méta contenant des deux-points doivent être entourées de guillemets.
</Note>

```yaml
---
"twitter:image": "/images/social-preview.jpg"
---
```

Consultez [SEO](/fr/optimize/seo) pour l’ensemble des options complètes de métadonnées SEO.

<div id="internal-search-keywords">
  ## Mots-clés de recherche internes
</div>

Améliorez la visibilité d’une page spécifique dans la recherche interne en ajoutant des `keywords` dans vos métadonnées. Ces mots-clés n’apparaîtront ni dans le contenu de la page ni dans les résultats de recherche, mais les utilisateurs qui les saisiront verront la page s’afficher dans les résultats.

```yaml
---
keywords: ['configuration', 'setup', 'getting started']
---
```

<div id="last-modified-timestamp">
  ## Horodatage de la dernière modification
</div>

Ajoutez la mention &quot;Dernière modification le [date]&quot; à toutes les pages en activant `metadata.timestamp` dans vos [paramètres globaux](/fr/organize/settings#metadata).

```json docs.json
"metadata": {
  "timestamp": true
}
```

Remplacez le paramètre global d’horodatage pour des pages individuelles à l’aide du champ `timestamp` dans le frontmatter. Utilisez ce champ pour afficher ou masquer sélectivement les horodatages sur certaines pages.

```yaml
---
title: "Page title"
timestamp: false
---
```

Lorsque ce paramètre est défini sur `true`, l’horodatage s’affiche même si le paramètre global est défini sur `false`. Lorsqu’il est défini sur `false`, l’horodatage est masqué même si le paramètre global est défini sur `true`.
