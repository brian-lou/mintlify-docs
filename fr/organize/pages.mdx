Chaque page est un fichier Markdown. Les formats de fichier `.mdx` et `.md` sont tous deux pris en charge. Nous vous recommandons d’utiliser MDX, qui combine Markdown et des composants React pour créer une documentation riche et interactive. Le Markdown simple (`.md`) est pris en charge pour faciliter la migration depuis d’autres plateformes, mais il doit être converti en MDX pour bénéficier de toutes les fonctionnalités.

<div id="page-metadata">
  ## Métadonnées de la page
</div>

Chaque page commence par un Frontmatter, c’est-à-dire le bloc de métadonnées YAML délimité par `---` au début du fichier. Ces métadonnées définissent l’apparence et le comportement de votre page.

Utilisez le Frontmatter pour définir :

* Les titres et descriptions des pages
* Les titres, icônes et tags de la barre latérale
* Les mises en page
* Les balises méta SEO
* Les métadonnées personnalisées

<ResponseField name="title" type="string" required>
  Le titre de votre page, affiché dans la navigation et dans les onglets du navigateur.
</ResponseField>

<ResponseField name="description" type="string">
  Une brève description du contenu de cette page. Elle apparaît sous le titre et améliore le SEO.
</ResponseField>

<ResponseField name="sidebarTitle" type="string">
  Un titre court qui s’affiche dans la navigation de la barre latérale.
</ResponseField>

<ResponseField name="icon" type="string">
  L’icône à afficher.

  Options :

  * Nom d’une icône [Font Awesome](https://fontawesome.com/icons)
  * Nom d’une icône [Lucide](https://lucide.dev/icons)
  * URL d’une icône hébergée à l’extérieur
  * Chemin vers un fichier d’icône dans votre projet
</ResponseField>

<ResponseField name="iconType" type="string">
  Le style de l’icône [Font Awesome](https://fontawesome.com/icons). Utilisé uniquement avec les icônes Font Awesome.

  Options : `regular`, `solid`, `light`, `thin`, `sharp-solid`, `duotone`, `brands`.
</ResponseField>

<ResponseField name="tag" type="string">
  Un tag qui apparaît à côté du titre de votre page dans la barre latérale.
</ResponseField>

<ResponseField name="<custom>" type="string">
  N’importe quel Frontmatter YAML valide. Par exemple, `product: "API"` ou `version: "1.0.0"`.
</ResponseField>

```yaml Example YAML frontmatter wrap
---
title: "À propos du Frontmatter"
description: "Frontmatter is the metadata that controls how your page appears and behaves"
sidebarTitle: "Frontmatter"
icon: "book"
tag: "NEW"
---
```

<div id="page-mode">
  ## Mode d’affichage de la page
</div>

Contrôlez l’affichage de votre page avec le paramètre `mode`.

<div id="default">
  ### Par défaut
</div>

Si aucun mode n’est défini, une mise en page standard est utilisée par défaut, avec une barre latérale de navigation et une table des matières.

```yaml
---
title: "Default page title"
---
```

<div id="wide">
  ### Large
</div>

Le mode large masque la table des matières. C’est utile pour les pages qui n’ont pas de titres, ou si vous préférez profiter de l’espace horizontal supplémentaire. Le mode large est disponible pour tous les thèmes.

```yaml
---
title: "Wide page title"
mode: "wide"
---
```

<div id="custom">
  ### Personnalisé
</div>

Le mode personnalisé propose une mise en page minimaliste qui supprime tous les éléments, à l’exception de la barre de navigation supérieure. C’est une toile vierge pour créer des pages d’accueil ou toute autre mise en page unique nécessitant un minimum d’éléments de navigation. Le mode personnalisé est disponible pour tous les thèmes.

```yaml
---
title: "Custom page title"
mode: "custom"
---
```

<Warning>
  L’utilisation de la propriété `style` sur les pages en mode personnalisé peut provoquer un décalage de mise en page au chargement. Utilisez plutôt [Tailwind CSS ou du CSS personnalisé](/fr/customize/custom-scripts) pour éviter ce problème.
</Warning>

<div id="frame">
  ### Frame
</div>

Le mode Frame propose une mise en page similaire au mode personnalisé, tout en conservant la navigation dans la barre latérale. Ce mode de page permet d’utiliser du HTML personnalisé et des composants, tout en préservant l’expérience de navigation par défaut. Le mode Frame est disponible uniquement avec les thèmes Aspen et Almond.

```yaml
---
title: "Frame page title"
mode: "frame"
---
```

<div id="center">
  ### Centré
</div>

Le mode centré supprime la barre latérale et la table des matières afin de centrer le contenu. C’est utile pour les changelogs ou d’autres pages où vous souhaitez mettre l’accent sur le contenu. Le mode centré est disponible pour les thèmes Mint et Linden.

```yaml
---
title: "Center page title"
mode: "center"
---
```

<div id="api-pages">
  ## Pages d’API
</div>

Créez des bacs à sable API interactifs en ajoutant une spécification API à votre frontmatter, `api` ou `openapi`.

```yaml
---
openapi: "GET /endpoint"
---
```

En savoir plus sur la création d’une [documentation d’API](/fr/api-playground/overview).

<div id="external-links">
  ## Liens externes
</div>

Ajoutez des liens directs vers des sites externes dans votre navigation à l’aide des métadonnées `url`.

```yaml
---
title: "npm Package"
url: "https://www.npmjs.com/package/mint"
---
```

<div id="search-engine-optimization">
  ## Référencement naturel
</div>

La plupart des balises méta SEO sont générées automatiquement. Vous pouvez définir manuellement les balises méta SEO pour améliorer le référencement de votre site, le partage sur les réseaux sociaux et la compatibilité avec les navigateurs.

<Note>
  Les balises méta contenant des deux-points doivent être placées entre guillemets.
</Note>

```yaml
---
"twitter:image": "/images/social-preview.jpg"
---
```

Consultez [SEO](/fr/optimize/seo) pour connaître toutes les options de métadonnées SEO.

<div id="internal-search-keywords">
  ## Mots-clés de recherche internes
</div>

Améliorez la visibilité d’une page précise dans la recherche intégrée en ajoutant des `keywords` à vos métadonnées. Ces mots-clés n’apparaîtront ni dans le contenu de la page ni dans les résultats de recherche, mais les utilisateurs qui les saisissent verront la page dans les résultats.

```yaml
---
keywords: ['configuration', 'setup', 'getting started']
---
```

<div id="last-modified-timestamp">
  ## Date de dernière modification
</div>

Ajoutez la mention &quot;Dernière modification le [date]&quot; à toutes les pages en activant `metadata.timestamp` dans vos [paramètres globaux](/fr/organize/settings#metadata).

```json docs.json
"metadata": {
  "timestamp": true
}
```

Remplacez le paramètre global d’horodatage sur certaines pages à l’aide du champ de Frontmatter `timestamp`. Utilisez ce champ pour afficher ou masquer sélectivement les horodatages sur des pages spécifiques.

```yaml
---
title: "Page title"
timestamp: false
---
```

Lorsqu’il est défini sur `true`, l’horodatage s’affiche même si le paramètre global est `false`. Lorsqu’il est défini sur `false`, l’horodatage est masqué même si le paramètre global est `true`.
