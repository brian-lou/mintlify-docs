La propriété [navigation](/fr/organize/settings#param-navigation) du fichier `docs.json` contrôle la structure et la hiérarchie de l’information de votre documentation.

Avec une configuration de navigation adaptée, vous pouvez organiser votre contenu de manière à ce que les utilisateurs puissent trouver exactement ce qu’ils recherchent.

Choisissez un schéma d’organisation principal à la racine de votre navigation. Une fois votre schéma principal choisi, vous pouvez imbriquer d’autres éléments de navigation en son sein.

<div id="pages">
  ## Pages
</div>

Les pages sont le composant de navigation le plus élémentaire. Chaque page est un fichier MDX dans votre dépôt de documentation.

<img className="block dark:hidden pointer-events-none" src="/images/navigation/pages-light.png" alt="Graphique décoratif représentant des pages." />

<img className="hidden dark:block pointer-events-none" src="/images/navigation/pages-dark.png" alt="Graphique décoratif représentant des pages." />

Dans l&#39;objet `navigation`, `pages` est un tableau dont chaque entrée doit indiquer le chemin vers un [fichier de page](/fr/organize/pages).

```json
{
  "navigation": {
    "pages": [
      "settings",
      "pages",
      "navigation",
      "themes",
      "custom-domain"
    ]
  }
}
```

<div id="groups">
  ## Groupes
</div>

Utilisez des groupes pour organiser la navigation de votre barre latérale en sections. Les groupes peuvent être imbriqués les uns dans les autres, étiquetés avec des tags et associés à des icônes.

<img className="block dark:hidden pointer-events-none" src="/images/navigation/groups-light.png" alt="Graphique décoratif de groupes." />

<img className="hidden dark:block pointer-events-none" src="/images/navigation/groups-dark.png" alt="Graphique décoratif de groupes." />

Dans l&#39;objet `navigation`, `groups` est un tableau où chaque entrée est un objet qui requiert un champ `group` et un champ `pages`. Les champs `icon`, `tag` et `expanded` sont facultatifs.

```json
{
  "navigation": {
    "groups": [
      {
        "group": "Getting started",
        "icon": "play",
        "pages": [
          "quickstart",
          {
            "group": "Editing",
            "expanded": false,
            "icon": "pencil",
            "pages": [
              "installation",
              "editor"
            ]
          }
        ]
      },
      {
        "group": "Writing content",
        "icon": "notebook-text",
        "tag": "NEW",
        "pages": [
          "writing-content/page",
          "writing-content/text"
        ]
      }
    ]
  }
}
```

<div id="default-expanded-state">
  ### État développé par défaut
</div>

Utilisez la propriété `expanded` pour contrôler l&#39;état par défaut d&#39;un groupe imbriqué dans la barre latérale de navigation.

* `expanded: true` : le groupe est développé par défaut.
* `expanded: false` ou non définie : le groupe est replié par défaut.

<Note>
  La propriété `expanded` affecte uniquement les groupes imbriqués — les groupes à l&#39;intérieur d&#39;autres groupes. Les groupes de niveau supérieur sont toujours développés et ne peuvent pas être repliés.
</Note>

```json
{
  "group": "Getting started",
  "pages": [
    "quickstart",
    {
      "group": "Advanced",
      "expanded": false,
      "pages": ["installation", "configuration"]
    }
  ]
}
```

<div id="tabs">
  ## Onglets
</div>

Les onglets créent des sections distinctes dans votre documentation, chacune avec son propre chemin d’URL. Ils génèrent une barre de navigation horizontale en haut de votre documentation qui permet aux utilisateurs de passer d’une section à l’autre.

<img className="block dark:hidden pointer-events-none" src="/images/navigation/tabs-light.png" alt="Graphique décoratif représentant une navigation par onglets." />

<img className="hidden dark:block pointer-events-none" src="/images/navigation/tabs-dark.png" alt="Graphique décoratif représentant une navigation par onglets." />

Dans l’objet `navigation`, `tabs` est un tableau dont chaque entrée est un objet qui nécessite un champ `tab` et peut contenir d’autres champs de navigation tels que des groupes, des pages, des icônes ou des liens vers des pages externes.

```json
{
  "navigation": {
    "tabs": [
      {
        "tab": "API reference",
        "icon": "square-terminal",
        "pages": [
          "api-reference/get",
          "api-reference/post",
          "api-reference/delete"
        ]
      },
      {
        "tab": "SDKs",
        "icon": "code",
        "pages": [
          "sdk/fetch",
          "sdk/create",
          "sdk/delete"
        ]
      },
      {
        "tab": "Blog",
        "icon": "newspaper",
        "href": "https://external-link.com/blog"
      }
    ]
  }
}
```

<div id="menus">
  ### Menus
</div>

Les menus ajoutent des éléments de navigation déroulants à un onglet. Utilisez-les pour aider les utilisateurs à accéder directement à des pages spécifiques au sein d&#39;un onglet.

Dans l’objet `navigation`, `menu` est un tableau où chaque entrée est un objet qui requiert un champ `item` et peut contenir d’autres champs de navigation tels que des groupes, des pages, des icônes ou des liens vers des pages externes.

Les éléments de menu peuvent uniquement contenir des groupes, des pages et des liens externes.

```json
{
  "navigation": {
    "tabs": [
      {
        "tab": "Developer tools",
        "icon": "square-terminal",
        "menu": [
          {
            "item": "API reference",
            "icon": "rocket",
            "groups": [
              {
                "group": "Core endpoints",
                "icon": "square-terminal",
                "pages": [
                  "api-reference/get",
                  "api-reference/post",
                  "api-reference/delete"
                ]
              }
            ]
          },
          {
            "item": "SDKs",
            "icon": "code",
            "description": "SDKs are used to interact with the API.",
            "pages": [
              "sdk/fetch",
              "sdk/create",
              "sdk/delete"
            ]
          }
        ]
      }
    ]
  }
}
```

<div id="anchors">
  ## Ancres
</div>

Les ancres ajoutent des éléments de navigation permanents en haut de votre barre latérale. Utilisez-les pour structurer votre contenu, offrir un accès rapide à des ressources externes ou créer des appels à l&#39;action bien visibles.

<img className="block dark:hidden pointer-events-none" src="/images/navigation/anchors-light.png" alt="Illustration décorative d'une navigation avec ancres." />

<img className="hidden dark:block pointer-events-none" src="/images/navigation/anchors-dark.png" alt="Illustration décorative d'une navigation avec ancres." />

Dans l&#39;objet `navigation`, `anchors` est un tableau dont chaque entrée est un objet qui doit comporter un champ `anchor` et peut contenir d&#39;autres champs de navigation tels que des groupes, des pages, des icônes ou des liens vers des pages externes.

```json
{
  "navigation": {
    "anchors": [
      {
        "anchor": "Documentation",
        "icon": "book-open",
        "pages": [
          "quickstart",
          "development",
          "navigation"
        ]
      },
      {
        "anchor": "API reference",
        "icon": "square-terminal",
        "pages": [
          "api-reference/get",
          "api-reference/post",
          "api-reference/delete"
        ]
      },
      {
        "anchor": "Blog",
        "href": "https://external-link.com/blog"
      }
    ]
  }
}
```

<div id="global-anchors">
  ### Ancres globales
</div>

Utilisez des ancres globales pour les liens qui doivent apparaître sur toutes les pages, quelle que soit la section de votre navigation que l’utilisateur consulte. Les ancres globales sont particulièrement utiles pour créer des liens vers des ressources en dehors de votre documentation (comme un blog, un forum communautaire ou un portail d’assistance) ou pour fournir un accès constant à des pages internes importantes (comme un changelog ou une page d’état).

Les ancres globales prennent en charge aussi bien les URL externes que les chemins relatifs vers les pages de votre documentation.

```json
{
  "navigation": {
    "global":  {
      "anchors": [
        {
          "anchor": "Changelog",
          "icon": "list",
          "href": "/changelog"
        },
        {
          "anchor": "Blog",
          "icon": "pencil",
          "href": "https://mintlify.com/blog"
        }
      ]
    },
    "tabs": /*...*/
  }
}
```

<div id="dropdowns">
  ## Menus déroulants
</div>

Les menus déroulants sont regroupés dans un menu repliable en haut de la barre de navigation latérale. Chaque élément d’un menu déroulant mène à une section de votre documentation.

Dans l’objet `navigation`, `dropdowns` est un tableau où chaque entrée est un objet qui nécessite un champ `dropdown` et peut contenir d’autres champs de navigation comme des groupes, des pages, des icônes ou des liens vers des pages externes.

```json
      {
        "dropdown": "Documentation",
        "icon": "book-open",
        "pages": [
          "quickstart",
          "development",
          "navigation"
        ]
      },
      {
        "dropdown": "API reference",
        "icon": "square-terminal",
        "pages": [
          "api-reference/get",
          "api-reference/post",
          "api-reference/delete"
        ]
      },
      {
        "dropdown": "Blog",
        "href": "https://external-link.com/blog"

  }
```


<div id="openapi">
  ## OpenAPI
</div>

Intégrez des spécifications OpenAPI directement dans votre structure de navigation pour générer automatiquement la documentation de votre API. Créez des sections d’API dédiées ou placez les pages de points de terminaison (endpoints) au sein d’autres composants de navigation.

Définissez une spécification OpenAPI par défaut à n’importe quel niveau de votre hiérarchie de navigation. Les éléments enfants hériteront de cette spécification, sauf s’ils définissent leur propre spécification.

<Note>
  Lorsque vous ajoutez la propriété `openapi` à un élément de navigation (comme une ancre, un onglet ou un groupe) sans spécifier de pages, Mintlify génère automatiquement des pages pour **tous les endpoints** définis dans votre spécification OpenAPI.

  Pour contrôler les endpoints qui apparaissent, listez explicitement les endpoints souhaités dans un tableau `pages`.
</Note>

Pour plus d’informations sur la manière de référencer des endpoints OpenAPI dans votre documentation, consultez la page [Configuration d’OpenAPI](/fr/api-playground/openapi-setup).

```json
{
  "navigation": {
    "groups": [
      {
        "group": "API reference",
        "openapi": "/path/to/openapi-v1.json",
        "pages": [
          "overview",
          "authentication",
          "GET /users",
          "POST /users",
          {
            "group": "Products",
            "openapi": "/path/to/openapi-v2.json",
            "pages": [
              "GET /products",
              "POST /products"
            ]
          }
        ]
      }
    ]
  }
}
```

<div id="nesting">
  ## Imbrication
</div>

Les éléments de navigation peuvent être imbriqués les uns dans les autres pour créer des hiérarchies complexes. Vous devez avoir un élément de navigation parent au niveau racine, comme des onglets, des groupes ou un menu déroulant. Vous pouvez imbriquer d’autres types d’éléments de navigation au sein de votre structure de navigation principale.

Chaque élément de navigation peut contenir un seul type d’élément enfant à chaque niveau de votre hiérarchie de navigation. Par exemple, un onglet peut contenir des ancres qui contiennent des groupes, mais un onglet ne peut pas contenir à la fois des ancres et des groupes au même niveau.

<div id="breadcrumbs">
  ## Fils d’Ariane
</div>

Les fils d’Ariane affichent le chemin de navigation complet en haut de la page. Certains thèmes ont les fils d’Ariane activés par défaut, et d’autres non. Vous pouvez contrôler leur activation pour votre site à l’aide de la propriété `styling` dans votre fichier `docs.json`.

<CodeGroup>
  ```json Afficher le fil d’Ariane complet
  "styling": {
    "eyebrows": "breadcrumbs"
  }
  ```

  ```json Afficher uniquement la section parente
  "styling": {
    "eyebrows": "section"
  }
  ```
</CodeGroup>

<div id="interaction-configuration">
  ## Configuration des interactions
</div>

Configurez la façon dont les utilisateurs interagissent avec les éléments de navigation à l’aide de la propriété `interaction` dans le fichier `docs.json`.

<div id="enable-auto-navigation-for-groups">
  ### Activer la navigation automatique pour les groupes
</div>

Lorsqu’un utilisateur déploie un groupe de navigation, certains thèmes ouvrent automatiquement la première page du groupe. Vous pouvez remplacer le comportement par défaut d’un thème à l’aide de l’option `drilldown`.

* Définissez la valeur sur `true` pour forcer la navigation automatique vers la première page lorsqu’un groupe de navigation est sélectionné.
* Définissez la valeur sur `false` pour empêcher la navigation et uniquement déployer ou replier le groupe lorsqu’il est sélectionné.
* Laissez cette option non définie pour utiliser le comportement par défaut du thème.

<CodeGroup>
  ```json Navigation forcée
  "interaction": {
    "drilldown": true  // Forcer la navigation vers la première page lorsqu’un utilisateur déploie un menu déroulant
  }
  ```

  ```json Empêcher la navigation
  "interaction": {
    "drilldown": false // Ne jamais naviguer, uniquement déployer ou replier le groupe
  }
  ```
</CodeGroup>
