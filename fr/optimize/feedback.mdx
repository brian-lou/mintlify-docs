<div id="feedback-types">
  ## Types de retours
</div>

<Note>
  Les retours contextuels et sur les extraits de code sont en version bêta. Pour les activer sur votre site de documentation, [contactez notre équipe commerciale](mailto:hahnbee@mintlify.com).
</Note>

L’onglet des retours affiche des informations selon les [modules complémentaires de retour](https://dashboard.mintlify.com/products/addons) que vous activez.

<Frame>
  <img className="block dark:hidden" src="/images/analytics/feedback-addons-light.png" alt="Options de retours sur la page des modules complémentaires." />

  <img className="hidden dark:block" src="/images/analytics/feedback-addons-dark.png" alt="Options de retours sur la page des modules complémentaires." />

* **Évaluation par pouces** : vote simple par pouce levé/pouce baissé pour mesurer la satisfaction globale vis-à-vis des pages.
* **Retours contextuels** : retours en texte libre sur le contenu d’une page.
* **Retours sur les extraits de code** : retours portant spécifiquement sur les extraits de code.
* **Suggestions de modification** : permet aux utilisateurs de suggérer des modifications à votre documentation. Disponible uniquement pour les dépôts GitHub publics.
* **Signaler des problèmes** : permet aux utilisateurs de créer des issues GitHub directement depuis votre documentation. Disponible uniquement pour les dépôts GitHub publics.

<Note>
  Si vous désactivez la télémétrie dans votre fichier `docs.json`, les fonctionnalités de retour ne sont pas disponibles sur vos pages de documentation.
</Note>

<div id="manage-feedback">
  ## Gérer les retours
</div>

Pour les retours contextuels et sur les extraits de code, vous pouvez définir l’état d’un retour et ajouter des notes internes pour suivre la résolution des retours des utilisateurs.

<div id="change-feedback-status">
  ### Modifier le statut d’un retour
</div>

Sélectionnez le statut à côté d’un retour pour le marquer comme **En attente**, **En cours**, **Résolu** ou **Écarté**.

Bonnes pratiques pour définir les statuts des retours :

* **En attente** : Le retour est en attente d’examen.
* **En cours** : Le retour a été validé et est en cours de traitement.
* **Résolu** : Le retour a été résolu.
* **Écarté** : Le retour a été écarté, car il n’est pas exploitable, n’est pas pertinent ou est inexact.

<div id="filter-by-status">
  ### Filtrer par statut
</div>

Utilisez le filtre de statut pour choisir quels retours afficher. Désactivez un statut pour masquer tous les retours correspondants. Par défaut, tous les retours sont affichés.

<div id="add-internal-notes">
  ### Ajouter des notes internes
</div>

Cliquez sur un retour pour ajouter une note interne. Ces notes sont visibles uniquement par les personnes ayant accès à votre tableau de bord.

Utilisez les notes pour faciliter la collaboration, associer des tickets pertinents du support ou de l’ingénierie, ou consigner toute autre information utile.

<div id="use-feedback-data">
  ## Utiliser les données de retour
</div>

Examinez vos données de retour pour :

* **Identifier les contenus efficaces** : les pages qui reçoivent le plus de retours positifs montrent ce qui fonctionne bien dans votre documentation.
* **Prioriser les améliorations** : les pages qui reçoivent le plus de retours négatifs indiquent quels contenus nécessitent peut-être une attention particulière.
* **Passer à l&#39;action** : mettez à jour la documentation en vous appuyant sur les retours directs des utilisateurs.
