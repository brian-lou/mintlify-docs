</Info>

L'onglet [Feedback](https://dashboard.mintlify.com/products/analytics/v2/feedback) affiche le nombre de votes positifs (pouce levé) et négatifs (pouce baissé) reçus par votre documentation, ainsi que tous les commentaires qualitatifs laissés par les utilisateurs. Utilisez ces informations pour évaluer la qualité de votre documentation et l’améliorer.

Consultez les commentaires sur la page Analytics de votre tableau de bord.

- **Évaluation par pouces** : Vote simple pouce levé/pouce baissé pour mesurer la satisfaction générale vis‑à‑vis des pages.
- **Commentaires contextuels** : Commentaires libres sur le contenu d’une page.
- **Commentaires sur les extraits de code** : Commentaires spécifiquement sur les extraits de code.
- **Suggestions de modification** : Permettez aux utilisateurs de suggérer des modifications à votre documentation. Disponible uniquement pour les dépôts GitHub publics.
- **Signalement de problèmes** : Permettez aux utilisateurs de créer des issues GitHub directement depuis votre documentation. Disponible uniquement pour les dépôts GitHub publics.

<Note>
  Si vous désactivez la télémétrie dans votre fichier `docs.json`, les fonctionnalités de commentaires ne sont pas disponibles sur vos pages de documentation.
</Note>

<div id="manage-feedback">
  ## Gérer les retours
</div>

Pour les retours contextuels et ceux portant sur des extraits de code, vous pouvez définir le statut d’un retour et ajouter des notes internes pour suivre l’avancement de la prise en compte des retours utilisateurs.

<div id="change-feedback-status">
  ### Modifier le statut d’un retour
</div>

Sélectionnez le statut à côté d’un retour pour le marquer comme **En attente**, **En cours**, **Résolu** ou **Rejeté**.

Bonnes pratiques pour définir les statuts des retours :

- **En attente** : le retour est en attente d’examen.
- **En cours** : le retour a été validé et est en cours de traitement.
- **Résolu** : le retour a été résolu.
- **Rejeté** : le retour a été rejeté car non exploitable, non pertinent ou inexact.

<div id="filter-by-status">
  ### Filtrer par statut
</div>

Utilisez le filtre par statut pour choisir quels commentaires afficher. Décochez un statut pour masquer tous les commentaires ayant ce statut. Par défaut, tous les commentaires sont affichés.

<div id="add-internal-notes">
  ### Ajouter des notes internes
</div>

Cliquez sur un commentaire pour ajouter une note interne. Ces notes sont uniquement visibles par les personnes qui ont accès à votre tableau de bord.

Utilisez les notes pour ajouter des informations afin de faciliter la collaboration, associer des tickets de support ou d’ingénierie pertinents, ou vous rappeler toute autre information utile.

<div id="use-feedback-data">
  ## Utiliser les données issues des retours d’expérience
</div>

Examinez vos données de retour d’expérience pour :

- **Identifier le contenu efficace** : les pages qui reçoivent le plus de retours positifs indiquent ce qui fonctionne bien dans votre documentation.
- **Prioriser les améliorations** : les pages qui reçoivent le plus de retours négatifs signalent le contenu qui pourrait nécessiter une attention particulière.
- **Passer à l’action** : mettez votre documentation à jour en fonction des retours directs des utilisateurs.
