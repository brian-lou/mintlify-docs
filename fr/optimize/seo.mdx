Mintlify gère automatiquement de nombreuses bonnes pratiques SEO, notamment :

* Génération de balises meta
* Génération du fichier sitemap et de `robots.txt`
* Structure HTML sémantique
* Optimisation pour mobile

Vous pouvez entièrement personnaliser les balises meta de votre site en ajoutant le champ `metatags` à votre `docs.json` ou au frontmatter d&#39;une page.

<div id="automatically-generated-meta-tags">
  ## Balises meta générées automatiquement
</div>

Mintlify génère les balises meta suivantes pour chaque page. Vous pouvez remplacer ces balises meta en les spécifiant dans votre `docs.json` ou dans le frontmatter d&#39;une page.

**Métadonnées de base :**

* `charset: utf-8` - Encodage des caractères
* `og:type: website` - Type Open Graph
* `og:site_name` - Nom de votre site de documentation
* `twitter:card: summary_large_image` - Type de carte Twitter

**Métadonnées spécifiques à la page :**

* `title` - Titre de la page, au format « Titre de la page - Nom du site »
* `og:title` - Titre Open Graph, identique au titre de la page
* `twitter:title` - Titre Twitter, identique au titre de la page
* `description` - Description de la page
* `og:description` - Description Open Graph, identique à la description de la page
* `twitter:description` - Description Twitter, identique à la description de la page

**URL et balise canonique :**

* `canonical` - Générée automatiquement à partir de l’URL de la page
* `og:url` - Définie sur l’URL canonique

**SEO et indexation :**

* `robots` - Générée à partir des métadonnées de la page
* `noindex` - Générée à partir des métadonnées de la page
* `keywords` - Générée à partir des métadonnées de la page

**Images :**

* `og:image` - Image Open Graph, `og:image:width` définie sur 1200 et `og:image:height` sur 630
* `twitter:image` - Image Twitter, `twitter:image:width` définie sur 1200 et `twitter:image:height` sur 630

**Métadonnées du navigateur et de l’application :**

* `applicationName` - Nom de votre site de documentation
* `generator: Mintlify` - Indique que le générateur du site est Mintlify
* `apple-mobile-web-app-title` - Nom de l’application sur l’écran d’accueil iOS
* `msapplication-TileColor` - Couleur de la tuile Windows
* Favicons et icônes provenant de votre configuration
* Lien vers le sitemap

Toutes les balises meta définies dans la configuration `docs.json` `seo.metatags` sont également automatiquement injectées dans chaque page, comme `google-site-verification` pour la validation via la Search Console.

<div id="global-meta-tags">
  ## Balises méta globales
</div>

Pour définir des balises méta par défaut pour toutes les pages, ajoutez le champ `metatags` dans votre fichier `docs.json`.

```json
"seo": {
    "metatags": {
        "og:image": "link to your default meta tag image"
    }
}
```

<div id="set-a-canonical-url">
  ### Définir une URL canonique
</div>

Si vous utilisez un domaine personnalisé, définissez la balise meta `canonical` pour vous assurer que les moteurs de recherche indexent votre domaine préféré. Une URL canonique indique aux moteurs de recherche quelle version de votre documentation est la principale. Cela améliore le référencement lorsque votre documentation est accessible depuis plusieurs URL et évite les problèmes de contenu dupliqué.

```json
"seo": {
    "metatags": {
        "canonical": "https://www.your-custom-domain-here.com"
    }
}
```

<div id="page-specific-meta-tags">
  ## Balises meta spécifiques à la page
</div>

Pour définir des balises meta spécifiques à une page, ajoutez-les au frontmatter de la page.

Les balises meta suivantes sont prises en charge au niveau de la page :

* `title` - Titre de la page
* `description` - La description de la page apparaît sous le titre sur la page et dans certains résultats de moteurs de recherche
* `keywords` - Mots-clés séparés par des virgules
* `og:title` - Titre Open Graph pour le partage sur les réseaux sociaux
* `og:description` - Description Open Graph
* `og:image` - URL de l&#39;image Open Graph
* `og:url` - URL Open Graph
* `og:type` - Type Open Graph comme &quot;article&quot; ou &quot;website&quot;
* `og:image:width` - Largeur de l&#39;image Open Graph
* `og:image:height` - Hauteur de l&#39;image Open Graph
* `twitter:title` - Titre de la carte Twitter
* `twitter:description` - Description de la carte Twitter
* `twitter:image` - Image de la carte Twitter
* `twitter:card` - Type de carte Twitter comme &quot;summary&quot; ou &quot;summary&#95;large&#95;image&quot;
* `twitter:site` - Compte Twitter du site
* `twitter:image:width` - Largeur de l&#39;image Twitter
* `twitter:image:height` - Hauteur de l&#39;image Twitter
* `noindex` - Mettre à `true` pour empêcher l&#39;indexation par les moteurs de recherche
* `robots` - Valeur de la balise meta robots

```mdx
---
title: "Your example page title"
description: "Page-specific description"
"og:image": "link to your meta tag image"
"og:title": "Social media title"
keywords: ["keyword1", "keyword2"]
---
```

<Note>
  Les balises meta comportant des deux-points doivent être placées entre guillemets. Le champ `keywords` doit être formaté sous forme de tableau YAML.
</Note>

<div id="sitemaps-and-robotstxt-files">
  ## Fichiers sitemap et robots.txt
</div>

Mintlify génère automatiquement les fichiers `sitemap.xml` et `robots.txt`. Vous pouvez consulter votre sitemap en ajoutant `/sitemap.xml` à l’URL de votre site de documentation.

Seules les pages présentes dans votre fichier `docs.json` sont incluses par défaut. Pour inclure des liens masqués, ajoutez `seo.indexing` à votre `docs.json` :

```json
"seo": {
    "indexing": "all"
}
```

<div id="custom-sitemaps-and-robotstxt-files">
  ### Sitemaps personnalisés et fichiers robots.txt
</div>

Pour ajouter un fichier `sitemap.xml` ou `robots.txt` personnalisé, créez un fichier `sitemap.xml` ou `robots.txt` à la racine de votre projet. L’ajout d’un fichier personnalisé remplacera le fichier généré automatiquement portant le même nom. Si vous supprimez un fichier personnalisé, le fichier par défaut sera de nouveau utilisé.

<div id="disabling-indexing">
  ## Désactiver l’indexation
</div>

Si vous souhaitez empêcher une page d’être indexée par les moteurs de recherche, vous pouvez inclure ce qui suit dans le [frontmatter](/fr/organize/pages) de votre page :

```
---
noindex: true
---
```

Vous pouvez également spécifier `noindex` pour l’ensemble des pages de votre documentation en définissant le champ `metatags.robots` sur `"noindex"` dans votre `docs.json` :

```json
"seo": {
    "metatags": {
      "robots": "noindex"
    }
  }
```

<div id="seo-best-practices">
  ## Bonnes pratiques SEO
</div>

<AccordionGroup>
  <Accordion title="Rédiger des titres et descriptions explicites">
    * Utiliser des titres de page clairs et descriptifs (50-60 caractères)
    * Rédiger des descriptions convaincantes (150-160 caractères)
    * Inclure des mots-clés pertinents
    * Veiller à ce que chaque titre de page et chaque description soient uniques
  </Accordion>

  <Accordion title="Optimiser la structure de votre contenu">
    * Utiliser une hiérarchie de titres appropriée (H1 → H2 → H3)
    * Écrire d’abord pour les humains, ensuite pour les moteurs de recherche
    * Inclure des mots-clés pertinents dans les titres et le contenu
    * Garder des URL courtes, descriptives et organisées de façon hiérarchique
    * Scinder le contenu long avec des sous-titres et des listes
  </Accordion>

  <Accordion title="Stratégie de maillage interne">
    * Créer des liens vers des pages liées au sein de votre documentation
    * Utiliser un texte d’ancrage descriptif plutôt que « cliquez ici »
    * Créer des grappes thématiques en liant les concepts associés
    * Utiliser les fonctionnalités de renvoi automatique
  </Accordion>

  <Accordion title="SEO pour les images">
    * Utiliser des noms de fichier descriptifs pour les images
    * Toujours inclure un texte alternatif pour l’accessibilité et le SEO
    * Optimiser la taille des fichiers image pour un chargement plus rapide
    * Utiliser des images pertinentes qui soutiennent votre contenu
  </Accordion>
</AccordionGroup>
