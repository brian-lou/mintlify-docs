<Note>
  La personalización requiere que la [autenticación](/es/deploy/authentication-setup) esté configurada con OAuth o JWT.
</Note>

Personaliza el contenido para tus usuarios cuando inicien sesión en tu sitio de documentación. Puedes rellenar previamente las claves de API, mostrar contenido específico para el plan o el rol de un usuario y filtrar el contenido de referencia de la API según la pertenencia a grupos.

<div id="api-key-prefilling">
  ## Relleno previo de claves de API
</div>

Rellena automáticamente los campos del playground de la API con valores específicos de cada usuario devolviendo nombres de campos que coincidan en los datos del usuario. Incluye esos valores en el campo `apiPlaygroundInputs` de tus [datos de usuario](/es/deploy/authentication-setup#user-data-format).

```json
{
  "apiPlaygroundInputs": {
    "header": { "X-API-Key": "user_api_key_123" },
    "server": { "subdomain": "acme" }
  }
}
```

Los nombres de los campos deben coincidir con los nombres definidos en tu especificación de OpenAPI. Solo se aplican aquellos valores que coincidan con el esquema de seguridad del endpoint actual.

<div id="dynamic-mdx-content">
  ## Contenido MDX dinámico
</div>

Muestra contenido según la información del usuario, como su nombre, plan u organización, con la variable `user` en tus páginas MDX. Incluye datos personalizados en el campo `content` de tus [datos de usuario](/es/deploy/authentication-setup#user-data-format).

```json
{
  "content": {
    "firstName": "Jane",
    "company": "Acme Corp",
    "plan": "Enterprise"
  }
}
```

Utiliza estos valores en tu MDX.

```mdx
Welcome back, {user.firstName}! Your {user.plan} plan includes 100 seats for members in your {user.company} organization.
```

Para el renderizado condicional basado en datos del usuario, utiliza la variable `user` en los componentes JSX.

```jsx
{
  user.plan === 'enterprise'
    ? <>Contact your admin to enable this feature.</>
    : <>See <a href="https://yoursite.com/pricing">pricing</a> for information about upgrading.</>
}
```

<Note>
  La variable `user` es un objeto vacío para los usuarios que no han iniciado sesión. Utiliza encadenamiento opcional en todos los campos de `user` para evitar errores. Por ejemplo, `{user.org?.plan}` en lugar de `{user.org.plan}`.
</Note>

<div id="page-visibility">
  ## Visibilidad de la página
</div>

Restringe el acceso a páginas a grupos de usuarios específicos añadiendo `groups` al frontmatter de la página. Los usuarios deben pertenecer a al menos uno de los grupos indicados para poder acceder a la página.

```mdx
---
title: "Admin settings"
groups: ["admin"]
---
```

Para obtener más información sobre cómo los grupos interactúan con las páginas públicas, consulta [Controlar el acceso con grupos](/es/deploy/authentication-setup#control-access-with-groups).

<div id="openapi-content-filtering">
  ## Filtrado de contenido de OpenAPI
</div>

Filtra el contenido de referencia de la API en función de los grupos de usuarios con la extensión `x-mint` en tu especificación OpenAPI. Puedes filtrar endpoints completos, propiedades individuales de esquemas, variantes de `oneOf` y valores de enum.

<div id="filter-endpoints">
  ### Filtrar endpoints
</div>

Añade `x-mint.groups` a una operación o ruta para restringir la página del endpoint a grupos de usuarios específicos. Los usuarios que no pertenezcan a los grupos indicados no verán el endpoint en la navegación ni podrán acceder a su página.

<CodeGroup>
  ```json {6-8} Operación restringida
  {
    "paths": {
      "/billing": {
        "get": {
          "summary": "Get billing details",
          "x-mint": {
            "groups": ["admin", "billing"]
          },
          "responses": {
            "200": {
              "description": "Billing details"
            }
          }
        }
      }
    }
  }
  ```

  ```json {3-5} Ruta restringida
  {
    "paths": {
      "x-mint": {
        "groups": ["admin", "billing"]
      },
      "/billing": {
        "get": {
          "summary": "Get billing details",
        }
      },
      "/users": {
        "get": {
          "summary": "Get user details",
        }
      }
    }
  }
  ```
</CodeGroup>

<div id="filter-schema-properties">
  ### Filtrar propiedades del esquema
</div>

Agrega `x-mint.groups` a propiedades individuales dentro de los cuerpos de la solicitud, parámetros o respuestas. Las propiedades sin `x-mint.groups` permanecen visibles para todos los usuarios.

```json {11-13} Restricted property
{
  "components": {
    "schemas": {
      "User": {
        "type": "object",
        "properties": {
          "name": {
            "type": "string"
          },
          "internal_id": {
            "type": "string",
            "x-mint": {
              "groups": ["admin"]
            }
          }
        }
      }
    }
  }
}
```

En este ejemplo, todos los usuarios pueden ver la propiedad `name`. Solo los usuarios del grupo `admin` pueden ver la propiedad `internal_id`.

<div id="filter-oneof-variants">
  ### Filtrar variantes de oneOf
</div>

Añade `x-mint.groups` a las opciones individuales de `oneOf` para restringir qué variantes de esquema puede ver un usuario.

```json {7-9} Restricted oneOf variant
{
  "schema": {
    "oneOf": [
      {
        "title": "Enterprise config",
        "type": "object",
        "x-mint": {
          "groups": ["enterprise"]
        },
        "properties": {
          "sso_enabled": { "type": "boolean" }
        }
      },
      {
        "title": "Standard config",
        "type": "object",
        "properties": {
          "notifications": { "type": "boolean" }
        }
      }
    ]
  }
}
```

<div id="filter-enum-values">
  ### Filtrar valores de enumeración
</div>

Usa la extensión `x-mint-enum` para restringir, por grupo, valores individuales de una enumeración. Enumera cada valor restringido como una clave, con sus grupos permitidos como valor. Los valores de enumeración que no se incluyan en `x-mint-enum` serán visibles para todos los usuarios.

```json {4-7} Restricted enum values
{
  "type": "string",
  "enum": ["free", "pro", "enterprise"],
  "x-mint-enum": {
    "pro": ["pro", "enterprise"],
    "enterprise": ["enterprise"]
  }
}
```

En este ejemplo, todos los usuarios ven `free`. Los usuarios de los grupos `pro` o `enterprise` ven `pro`. Solo los usuarios del grupo `enterprise` ven `enterprise`.

<Note>
  `x-mint-enum` es una extensión independiente de nivel superior en el objeto de esquema, no está anidada dentro de `x-mint`.
</Note>

<div id="user-data-format">
  ## Formato de datos de usuario
</div>

Tu sistema de autenticación devuelve datos de usuario que controlan la personalización. Los campos `groups`, `content` y `apiPlaygroundInputs` descritos en esta página forman parte del objeto de datos de usuario.

Para ver el formato completo de los datos de usuario y la referencia de campos, consulta [Formato de datos de usuario](/es/deploy/authentication-setup#user-data-format).

<div id="logout-behavior">
  ## Comportamiento de cierre de sesión
</div>

El cierre de sesión ocurre en el cliente. Cuando los usuarios hacen clic en el botón de cierre de sesión, Mintlify borra los datos de sesión almacenados en el navegador.

Para limitar el tiempo durante el cual persisten los datos de personalización, establece el campo `expiresAt` en los datos del usuario.
