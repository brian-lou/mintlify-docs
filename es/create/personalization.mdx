<Note>
  La personalización requiere [autenticación](/es/deploy/authentication-setup) configurada con OAuth o JWT.
</Note>

Personaliza el contenido para tus usuarios cuando inicien sesión en tu sitio de documentación. Puedes precompletar claves de API, mostrar contenido específico según el plan o el rol del usuario y filtrar el contenido de referencia de la API según su pertenencia a grupos.

<div id="api-key-prefilling">
  ## Autocompletado de claves de API
</div>

Rellena automáticamente los campos del Área de pruebas de API con valores específicos de cada usuario si devuelves nombres de campo coincidentes en tus datos de usuario. Incluye los valores en el campo `apiPlaygroundInputs` de tus [datos de usuario](/es/deploy/authentication-setup#user-data-format).

```json
{
  "apiPlaygroundInputs": {
    "header": { "X-API-Key": "user_api_key_123" },
    "server": { "subdomain": "acme" }
  }
}
```

Los nombres de los campos deben coincidir con los definidos en tu especificación de OpenAPI. Solo se aplican los valores que coinciden con el esquema de seguridad del endpoint actual.

<div id="dynamic-mdx-content">
  ## Contenido dinámico en MDX
</div>

Muestra contenido en función de la información del usuario, como el nombre, el plan o la organización, con la variable `user` en tus páginas de MDX. Incluye datos personalizados en el campo `content` de tus [datos de usuario](/es/deploy/authentication-setup#user-data-format).

```json
{
  "content": {
    "firstName": "Jane",
    "company": "Acme Corp",
    "plan": "Enterprise"
  }
}
```

Haz referencia a estos valores en tu MDX.

```mdx
Welcome back, {user.firstName}! Your {user.plan} plan includes 100 seats for members in your {user.company} organization.
```

Para el renderizado condicional en función de los datos del usuario, usa la variable `user` en los componentes JSX.

```jsx
{
  user.plan === 'enterprise'
    ? <>Contacta a tu administrador para habilitar esta función.</>
    : <>See <a href="https://yoursite.com/pricing">pricing</a> para obtener información sobre cómo actualizar tu plan.</>
}
```

<Note>
  La variable `user` es un objeto vacío cuando el usuario no ha iniciado sesión. Usa el encadenamiento opcional en todos los campos de `user` para evitar errores. Por ejemplo, `{user.org?.plan}` en lugar de `{user.org.plan}`.
</Note>

<div id="page-visibility">
  ## Visibilidad de la página
</div>

Restringe el acceso a páginas a grupos de usuarios específicos añadiendo `groups` al Frontmatter de la página. Los usuarios deben pertenecer al menos a uno de los grupos indicados para poder acceder a la página.

```mdx
---
title: "Admin settings"
groups: ["admin"]
---
```

Para más detalles sobre cómo interactúan los grupos con las páginas públicas, consulta [Controlar el acceso con grupos](/es/deploy/authentication-setup#control-access-with-groups).

<div id="openapi-content-filtering">
  ## Filtrado de contenido en OpenAPI
</div>

Filtra el contenido de referencia de la API según los grupos de usuarios mediante la extensión `x-mint` en tu especificación de OpenAPI. Puedes filtrar endpoints completos, propiedades concretas del esquema, variantes de `oneOf` y valores de enumeración.

<div id="filter-endpoints">
  ### Filtrar endpoints
</div>

Agrega `x-mint.groups` a una operación o ruta para restringir la visibilidad de la página del endpoint a grupos de usuarios específicos. Los usuarios que no pertenezcan a los grupos indicados no verán el endpoint en la navegación ni podrán acceder a su página.

<CodeGroup>
  ```json {6-8} Operación restringida
  {
    "paths": {
      "/billing": {
        "get": {
          "summary": "Get billing details",
          "x-mint": {
            "groups": ["admin", "billing"]
          },
          "responses": {
            "200": {
              "description": "Billing details"
            }
          }
        }
      }
    }
  }
  ```

  ```json {3-5} Ruta restringida
  {
    "paths": {
      "x-mint": {
        "groups": ["admin", "billing"]
      },
      "/billing": {
        "get": {
          "summary": "Get billing details",
        }
      },
      "/users": {
        "get": {
          "summary": "Get user details",
        }
      }
    }
  }
  ```
</CodeGroup>

<div id="filter-schema-properties">
  ### Filtra las propiedades del esquema
</div>

Agrega `x-mint.groups` a propiedades individuales en cuerpos de solicitud, parámetros o respuestas. Las propiedades sin `x-mint.groups` siguen siendo visibles para todos los usuarios.

```json {11-13} Restricted property
{
  "components": {
    "schemas": {
      "User": {
        "type": "object",
        "properties": {
          "name": {
            "type": "string"
          },
          "internal_id": {
            "type": "string",
            "x-mint": {
              "groups": ["admin"]
            }
          }
        }
      }
    }
  }
}
```

En este ejemplo, todos los usuarios ven la propiedad `name`. Solo los usuarios del grupo `admin` ven la propiedad `internal_id`.

<div id="filter-oneof-variants">
  ### Filtra variantes de `oneOf`
</div>

Agrega `x-mint.groups` a opciones individuales de `oneOf` para restringir qué variantes del esquema pueden ver los usuarios.

```json {7-9} Restricted oneOf variant
{
  "schema": {
    "oneOf": [
      {
        "title": "Enterprise config",
        "type": "object",
        "x-mint": {
          "groups": ["enterprise"]
        },
        "properties": {
          "sso_enabled": { "type": "boolean" }
        }
      },
      {
        "title": "Standard config",
        "type": "object",
        "properties": {
          "notifications": { "type": "boolean" }
        }
      }
    ]
  }
}
```

<div id="filter-enum-values">
  ### Filtrar valores de enumeración
</div>

Usa la extensión `x-mint-enum` para restringir valores individuales de enumeración por grupo. Enumera cada valor restringido como una clave y sus grupos permitidos como valor. Los valores de enumeración que no se incluyan en `x-mint-enum` serán visibles para todos los usuarios.

```json {4-7} Restricted enum values
{
  "type": "string",
  "enum": ["free", "pro", "enterprise"],
  "x-mint-enum": {
    "pro": ["pro", "enterprise"],
    "enterprise": ["enterprise"]
  }
}
```

En este ejemplo, todos los usuarios ven `free`. Los usuarios de los grupos `pro` o `enterprise` ven `pro`. Solo los usuarios del grupo `enterprise` ven `enterprise`.

<Note>
  `x-mint-enum` es una extensión independiente de nivel superior del objeto de esquema; no está anidada dentro de `x-mint`.
</Note>

<div id="user-data-format">
  ## Formato de los datos de usuario
</div>

Tu sistema de autenticación devuelve datos de usuario que determinan la personalización. Los campos `groups`, `content` y `apiPlaygroundInputs` descritos en esta página forman parte del objeto de datos de usuario.

Para consultar el formato completo de los datos de usuario y la referencia de los campos, consulta [Formato de los datos de usuario](/es/deploy/authentication-setup#user-data-format).

<div id="logout-behavior">
  ## Comportamiento del cierre de sesión
</div>

El cierre de sesión se produce del lado del cliente. Cuando los usuarios hacen clic en el botón de cierre de sesión, Mintlify borra del navegador los datos de sesión almacenados.

Para limitar durante cuánto tiempo se conservan los datos de personalización, establece el campo `expiresAt` en los datos del usuario.
