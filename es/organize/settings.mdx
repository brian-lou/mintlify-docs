El archivo `docs.json` te permite convertir una colección de archivos Markdown en un sitio de documentación navegable y personalizado. Este archivo de configuración obligatorio controla el estilo, la navegación, las integraciones y más. Piensa en él como el plano de tu documentación.

La configuración de `docs.json` se aplica globalmente a todas las páginas.

<div id="setting-up-your-docsjson">
  ## Configuración de tu `docs.json`
</div>

Para empezar, solo necesitas especificar `theme`, `name`, `colors.primary` y `navigation`. Los demás campos son opcionales y puedes agregarlos a medida que crezcan las necesidades de tu documentación.

Para disfrutar de la mejor experiencia de edición, incluye la referencia de esquema en la parte superior de tu archivo `docs.json`. Esto habilita el autocompletado, la validación y cuadros de información emergentes útiles en la mayoría de los editores de código:

```json
{
  "$schema": "https://mintlify.com/docs.json",
  "theme": "mint",
  "name": "Your Docs",
  "colors": {
    "primary": "#ff0000"
  },
  "navigation": {
    // Tu estructura de navegación
  }
  // El resto de tu configuración
}
```

<ResponseField name="theme" required>
  El tema de diseño de tu sitio.

  Uno de los siguientes: `mint`, `maple`, `palm`, `willow`, `linden`, `almond`, `aspen`.

  Consulta [Themes](/es/customize/themes) para obtener más información.
</ResponseField>

<ResponseField name="name" type="string" required>
  El nombre de tu proyecto, organización o producto.
</ResponseField>

<ResponseField name="colors" type="object" required>
  Los colores que se usan en tu documentación. Los colores se aplican de forma diferente según el tema. Si solo proporcionas un color primario, se aplica a todos los elementos de color.

  <Expandable title="Colores">
    <ResponseField name="primary" type="string matching ^#([a-fA-F0-9]{6}|[a-fA-F0-9]{3})$" required>
      El color primario de tu documentación. Generalmente se usa para énfasis en el modo claro, con algunas variaciones según el tema.

      Debe ser un código hexadecimal que comience con `#`.
    </ResponseField>

    <ResponseField name="light" type="string matching ^#([a-fA-F0-9]{6}|[a-fA-F0-9]{3})$">
      El color que se usa para énfasis en el modo oscuro.

      Debe ser un código hexadecimal que comience con `#`.
    </ResponseField>

    <ResponseField name="dark" type="string matching ^#([a-fA-F0-9]{6}|[a-fA-F0-9]{3})$">
      El color que se usa para botones y estados al pasar el cursor tanto en modo claro como oscuro, con algunas variaciones según el tema.

      Debe ser un código hexadecimal que comience con `#`.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="styling" type="object">
  Configuración del estilo visual.

  <Expandable title="Styling">
    <ResponseField name="eyebrows" type="&#x22;section&#x22; | &#x22;breadcrumbs&#x22;">
      El estilo del eyebrow (franja superior) de la página. Elige `section` para mostrar el nombre de la sección o `breadcrumbs` para mostrar la ruta de navegación completa. El valor predeterminado es `section`.
    </ResponseField>

    <ResponseField name="latex" type="boolean">
      Controla si se incluyen las hojas de estilo de LaTeX, anulando la detección automática. De forma predeterminada, Mintlify detecta automáticamente el uso de LaTeX en tu contenido y carga las hojas de estilo necesarias.

      * Establécelo en `true` para forzar la carga de las hojas de estilo de LaTeX cuando la detección automática no reconozca tus expresiones matemáticas.
      * Establécelo en `false` para evitar la carga de las hojas de estilo de LaTeX y mejorar el rendimiento si no usas expresiones matemáticas pero tienes contenido que provoca falsos positivos en la detección.
    </ResponseField>

    <ResponseField name="codeblocks" type="&#x22;system&#x22; | &#x22;dark&#x22; | string | object">
      Configuración del tema de los bloques de código. El valor predeterminado es `"system"`.

      **Configuración simple:**

      * `"system"`: Igualar el modo actual del sitio (claro u oscuro)
      * `"dark"`: Usar siempre el modo oscuro

      **Configuración de tema personalizada:**

      * Usa una cadena para especificar un único [tema de Shiki](https://shiki.style/themes) para todos los bloques de código
      * Usa un objeto para especificar [temas de Shiki](https://shiki.style/themes) diferentes para los modos claro y oscuro

      <ResponseField name="theme" type="string">
        Un único nombre de tema de Shiki para usar tanto en modo claro como en modo oscuro.

        ```json
        "styling": {
          "codeblocks": {
            "theme": "dracula"
          }
        }
        ```
      </ResponseField>

      <ResponseField name="theme" type="object">
        Temas separados para los modos claro y oscuro.

        <Expandable title="theme">
          <ResponseField name="light" type="string" required>
            Un nombre de tema de Shiki para el modo claro.
          </ResponseField>

          <ResponseField name="dark" type="string" required>
            Un nombre de tema de Shiki para el modo oscuro.
          </ResponseField>

          ```json
          "styling": {
            "codeblocks": {
              "theme": {
                "light": "github-light",
                "dark": "github-dark"
              }
            }
          }
          ```
        </Expandable>
      </ResponseField>

      <ResponseField name="languages" type="object">
        Configuración de idiomas personalizada para los bloques de código.

        <Expandable title="languages">
          <ResponseField name="custom" type="array of string">
            Rutas a archivos JSON que describen lenguajes personalizados de Shiki. Usa esto para añadir resaltado de sintaxis para lenguajes que no están incluidos en el conjunto predeterminado de Shiki.

            El archivo JSON debe seguir el [formato de gramática de TextMate](https://macromates.com/manual/en/language_grammars) usado por Shiki.

            ```json
            "styling": {
              "codeblocks": {
                "languages": {
                  "custom": ["/languages/my-custom-language.json"]
                }
              }
            }
            ```
          </ResponseField>
        </Expandable>
      </ResponseField>
    </ResponseField>
  </Expandable>
</ResponseField>

<div id="upgrading-from-mintjson">
  ## Actualizar desde `mint.json`
</div>

Si tu proyecto de documentación usa el archivo obsoleto `mint.json`, sigue estos pasos para actualizar a `docs.json`.

<Steps>
  <Step title="Instala o actualiza la CLI">
    Si no has instalado la [CLI](/es/installation), instálala ahora:

    <CodeGroup>
      ```bash npm
      npm i -g mint
      ```

      ```bash yarn
      yarn global add mint
      ```

      ```bash pnpm
      pnpm add -g mint
      ```
    </CodeGroup>

    Si ya tienes instalada la CLI, asegúrate de que esté actualizada:

    ```bash
    mint update
    ```
  </Step>

  <Step title="Crea tu archivo docs.json">
    En tu repositorio de documentación, ejecuta:

    ```bash
    mint upgrade
    ```

    Este comando crea un archivo `docs.json` a partir de tu `mint.json` existente. Revisa el archivo generado para asegurarte de que toda la configuración sea correcta.
  </Step>

  <Step title="Elimina tu archivo mint.json">
    Después de verificar que tu `docs.json` esté configurado correctamente, puedes eliminar con seguridad tu antiguo archivo `mint.json`.
  </Step>
</Steps>
