Cada página es un archivo Markdown. Se admiten los tipos de archivo `.mdx` y `.md`. Recomendamos usar MDX, que combina Markdown con componentes de React para crear documentación más completa e interactiva. El Markdown simple (`.md`) se admite para facilitar la migración desde otras plataformas, pero debería actualizarse a MDX para disponer de todas las funcionalidades.

<div id="page-metadata">
  ## Metadatos de la página
</div>

Cada página comienza con frontmatter, los metadatos YAML delimitados por `---` al inicio de un archivo. Estos metadatos definen cómo aparece y se comporta tu página.

Usa el frontmatter para controlar:

* Títulos y descripciones de la página
* Títulos, iconos y etiquetas de la barra lateral
* Diseños de página
* Metaetiquetas de SEO
* Metadatos personalizados

<ResponseField name="title" type="string" required>
  El título de tu página que aparece en la navegación y en las pestañas del navegador.
</ResponseField>

<ResponseField name="description" type="string">
  Una breve descripción de lo que trata esta página. Aparece debajo del título y mejora el SEO.
</ResponseField>

<ResponseField name="sidebarTitle" type="string">
  Un título corto que se muestra en la navegación lateral.
</ResponseField>

<ResponseField name="icon" type="string">
  El icono que se va a mostrar.

  Opciones:

  * Nombre del icono de [Font Awesome](https://fontawesome.com/icons)
  * Nombre del icono de [Lucide](https://lucide.dev/icons)
  * URL de un icono alojado externamente
  * Ruta a un archivo de icono en tu proyecto
</ResponseField>

<ResponseField name="iconType" type="string">
  El estilo del icono de [Font Awesome](https://fontawesome.com/icons). Solo se usa con iconos de Font Awesome.

  Opciones: `regular`, `solid`, `light`, `thin`, `sharp-solid`, `duotone`, `brands`.
</ResponseField>

<ResponseField name="tag" type="string">
  Una etiqueta que aparece junto al título de tu página en la barra lateral.
</ResponseField>

<ResponseField name="<custom>" type="string">
  Cualquier frontmatter YAML válido. Por ejemplo, `product: "API"` o `version: "1.0.0"`.
</ResponseField>

```yaml Example YAML frontmatter wrap
---
title: "About frontmatter"
description: "Frontmatter is the metadata that controls how your page appears and behaves"
sidebarTitle: "Frontmatter"
icon: "book"
tag: "NEW"
---
```

<div id="page-mode">
  ## Modo de página
</div>

Controla cómo se muestra la página mediante el ajuste `mode`.

<div id="default">
  ### Predeterminado
</div>

Si no se define ningún modo, se utiliza un diseño estándar con una barra lateral de navegación y una tabla de contenidos.

```yaml
---
title: "Default page title"
---
```

<div id="wide">
  ### Wide
</div>

El modo ancho oculta la tabla de contenido. Es útil para páginas sin encabezados o si prefieres aprovechar el espacio horizontal adicional. El modo ancho está disponible para todos los temas.

```yaml
---
title: "Wide page title"
mode: "wide"
---
```

<div id="custom">
  ### Personalizado
</div>

El modo personalizado proporciona un diseño minimalista que elimina todos los elementos excepto la barra de navegación superior. El modo personalizado es un lienzo en blanco para crear páginas de destino u otros diseños únicos en los que quieras que haya una navegación mínima. El modo personalizado está disponible para todos los temas.

```yaml
---
title: "Custom page title"
mode: "custom"
---
```

<Warning>
  Usar la propiedad `style` en páginas con modo personalizado puede causar un desplazamiento del diseño al cargar la página. Usa [Tailwind CSS o CSS personalizado](/es/customize/custom-scripts) en su lugar para evitar este problema.
</Warning>

<div id="frame">
  ### Frame
</div>

El modo Frame ofrece un diseño similar al modo Custom, pero conserva la navegación lateral. Este modo de página permite usar HTML y componentes personalizados, manteniendo la experiencia de navegación predeterminada. El modo Frame solo está disponible para los temas Aspen y Almond.

```yaml
---
title: "Frame page title"
mode: "frame"
---
```

<div id="center">
  ### Centrado
</div>

El modo centrado elimina la barra lateral y la tabla de contenidos, y sitúa el contenido en el centro. Es útil para registros de cambios u otras páginas en las que se desea destacar el contenido. El modo centrado está disponible para los temas Mint y Linden.

```yaml
---
title: "Center page title"
mode: "center"
---
```

<div id="api-pages">
  ## Páginas de API
</div>

Crea entornos de prueba interactivos para APIs añadiendo una especificación de API a tu frontmatter, `api` u `openapi`.

```yaml
---
openapi: "GET /endpoint"
---
```

Obtén más información sobre cómo crear [documentación de API](/es/api-playground/overview).

<div id="external-links">
  ## Enlaces externos
</div>

Enlaza a sitios externos directamente desde tu navegación mediante el metadato `url`.

```yaml
---
title: "npm Package"
url: "https://www.npmjs.com/package/mint"
---
```

<div id="search-engine-optimization">
  ## Optimización para motores de búsqueda
</div>

La mayoría de las metaetiquetas de SEO se generan automáticamente. Puedes definir metaetiquetas de SEO manualmente para mejorar el SEO de tu sitio, su difusión en redes sociales y la compatibilidad con los navegadores.

<Note>
  Las metaetiquetas con dos puntos deben ir entre comillas.
</Note>

```yaml
---
"twitter:image": "/images/social-preview.jpg"
---
```

Consulta [SEO](/es/optimize/seo) para ver todas las opciones disponibles de metadatos de SEO.

<div id="internal-search-keywords">
  ## Palabras clave internas de búsqueda
</div>

Mejora la visibilidad de una página específica en la búsqueda interna proporcionando `keywords` en tus metadatos. Estas palabras clave no aparecerán como parte del contenido de la página ni en los resultados de búsqueda, pero los usuarios que las busquen verán la página entre los resultados.

```yaml
---
keywords: ['configuration', 'setup', 'getting started']
---
```

<div id="last-modified-timestamp">
  ## Marca de tiempo de última modificación
</div>

Añade la marca de tiempo de &quot;Última modificación el [date]&quot; a todas las páginas habilitando `metadata.timestamp` en la [configuración global](/es/organize/settings#metadata).

```json docs.json
"metadata": {
  "timestamp": true
}
```

Sobrescribe la configuración global de la marca de tiempo en páginas individuales con el campo `timestamp` del frontmatter. Usa este campo para mostrar u ocultar selectivamente la marca de tiempo en páginas específicas.

```yaml
---
title: "Page title"
timestamp: false
---
```

Si se establece en `true`, la marca de tiempo se muestra incluso si la configuración global está en `false`. Si se establece en `false`, la marca de tiempo se oculta incluso si la configuración global está en `true`.
