Si tus páginas de API no se muestran correctamente, revisa estos problemas de configuración frecuentes.

<AccordionGroup>
  <Accordion title="Todas mis páginas de OpenAPI aparecen completamente en blanco">
    En este escenario, es probable que Mintlify no pueda encontrar tu documento OpenAPI,
    o que tu documento OpenAPI no sea válido.

    Ejecutar `mint dev` localmente debería revelar algunos de estos problemas.

    Para comprobar que tu documento OpenAPI pasará la validación:

    1. Visita [este validador](https://editor.swagger.io/)
    2. Cambia a la pestaña &quot;Validate text&quot;
    3. Pega tu documento OpenAPI
    4. Haz clic en &quot;Validate it!&quot;

    Si el cuadro de texto que aparece debajo tiene un borde verde, tu documento ha pasado la validación.
    Este es exactamente el mismo paquete de validación que Mintlify utiliza para validar documentos OpenAPI, así que, si tu documento
    pasa la validación aquí, es muy probable que el problema esté en otra parte.

    Además, Mintlify no es compatible con OpenAPI 2.0. Si tu documento usa esta versión de la especificación,
    podrías encontrarte con este problema. Puedes convertir tu documento en [editor.swagger.io](https://editor.swagger.io/) (en Edit &gt; Convert to OpenAPI 3):

    <Frame>
      ![Captura de pantalla de Swagger Editor con el menú Edit expandido y el elemento de menú "Convert to OpenAPI 3" resaltado.](/images/convert-oas-3.png)
    </Frame>
  </Accordion>

  <Accordion title="Una de mis páginas de OpenAPI aparece completamente en blanco">
    Esto suele deberse a un campo `openapi` mal escrito en los metadatos de la página. Asegúrate de que
    el método y la ruta HTTP coincidan exactamente con el método y la ruta HTTP del documento OpenAPI.

    Aquí tienes un ejemplo de cómo las cosas pueden salir mal:

    ```mdx get-user.mdx
    ---
    openapi: "GET /users/{id}/"
    ---
    ```

    ```yaml openapi.yaml
    paths:
      "/users/{id}":
        get: ...
    ```

    Ten en cuenta que la ruta en el campo `openapi` tiene una barra diagonal al final, mientras que la ruta en el documento OpenAPI no la tiene.

    Otro problema común es un nombre de archivo mal escrito. Si estás especificando un documento OpenAPI en particular en el campo `openapi`, asegúrate de que el nombre del archivo sea correcto. Por ejemplo, si tienes dos documentos OpenAPI `openapi/v1.json` y `openapi/v2.json`, tus metadatos podrían verse así:

    ```mdx api-reference/v1/users/get-user.mdx
    ---
    openapi: "v1 GET /users/{id}"
    ---
    ```
  </Accordion>

  <Accordion title="Las solicitudes del API Playground no funcionan">
    Si tienes un dominio personalizado configurado, esto podría ser un problema con tu proxy inverso. De forma predeterminada, las solicitudes realizadas a través de API Playground comienzan con una solicitud `POST` a la ruta `/_mintlify/api/request` en el sitio de documentación. Si tu proxy inverso está configurado para permitir solo solicitudes `GET`, entonces todas estas solicitudes fallarán. Para solucionarlo, configura tu proxy inverso para permitir solicitudes `POST` a la ruta `/_mintlify/api/request`.

    Como alternativa, si tu proxy inverso no te permite aceptar solicitudes `POST`, puedes configurar Mintlify para enviar solicitudes directamente a tu backend con la opción `api.playground.proxy` en `docs.json`, como se describe en la [documentación de configuración](/es/organize/settings#param-proxy). Cuando uses esta configuración, tendrás que configurar CORS en tu servidor, ya que las solicitudes llegarán directamente desde los navegadores de los usuarios en lugar de pasar por tu proxy.
  </Accordion>

  <Accordion title="Las entradas de navegación de OpenAPI no generan páginas">
    Si estás utilizando una configuración de navegación de OpenAPI, pero las páginas no se están generando, revisa estos problemas comunes:

    1. **Falta la especificación OpenAPI predeterminada**: Asegúrate de tener configurado un campo `openapi` para el elemento de navegación:

    ```json {5}
    "navigation": {
      "groups": [
        {
          "group": "API reference",
          "openapi": "/path/to/openapi.json",
          "pages": [
            "GET /users",
            "POST /users"
          ]
        }
      ]
    }
    ```

    2. **Herencia de especificaciones OpenAPI**: Si utilizas navegación anidada, asegúrate de que los subgrupos hereden la especificación OpenAPI correcta o definan la suya propia.

    3. **Problemas de validación**: Usa `mint openapi-check <path-to-openapi-file>` para comprobar que tu archivo OpenAPI sea válido.
  </Accordion>

  <Accordion title="Algunas operaciones de OpenAPI aparecen en la navegación, pero otras no aparecen">
    1. **Operaciones ocultas**: Las operaciones marcadas con `x-hidden: true` en tu especificación de OpenAPI no aparecerán en la navegación generada automáticamente.
    2. **Operaciones no válidas**: Es posible que se omitan las operaciones con errores de validación en la especificación de OpenAPI. Revisa tu documento de OpenAPI para comprobar si hay errores de sintaxis.
    3. **Inclusión manual vs automática**: Si haces referencia a cualquier endpoint desde una especificación de OpenAPI, solo las operaciones referenciadas explícitamente aparecerán en la navegación. No se añadirá ninguna otra página automáticamente. Esto incluye las operaciones que se referencian en elementos de navegación descendientes.
  </Accordion>

  <Accordion title="La navegación combinada (páginas OpenAPI y MDX) no funciona correctamente">
    Al combinar operaciones de OpenAPI con páginas de documentación normales en la navegación:

    1. **Conflictos de archivos**: No puedes tener al mismo tiempo un archivo `MDX` y una entrada de navegación para la misma operación. Por ejemplo, si tienes `get-users.mdx`, no incluyas también `"GET /users"` en tu navegación. Si necesitas tener un archivo que comparta nombre con una operación, usa la extensión `x-mint` para el endpoint para que el `href` apunte a una ubicación diferente.
    2. **Resolución de rutas**: Las entradas de navegación que no coincidan con operaciones de OpenAPI se interpretarán como rutas de archivo. Asegúrate de que tus archivos `MDX` existan en las ubicaciones esperadas.
    3. **Sensibilidad a mayúsculas y minúsculas**: La coincidencia de operaciones de OpenAPI es sensible a mayúsculas y minúsculas. Asegúrate de que los métodos HTTP estén en mayúsculas en las entradas de navegación.
  </Accordion>
</AccordionGroup>
