Si tus páginas de la API no se muestran correctamente, revisa estos problemas comunes de configuración.

<AccordionGroup>
  <Accordion title="Todas mis páginas de OpenAPI aparecen completamente en blanco">
    En este caso, es probable que Mintlify no pueda encontrar tu documento OpenAPI
    o que tu documento OpenAPI no sea válido.

    Ejecutar `mint dev` localmente debería sacar a la luz algunos de estos problemas.

    Para verificar que tu documento OpenAPI pase la validación:

    1. Visita [este validador](https://editor.swagger.io/)
    2. Ve a la pestaña &quot;Validate text&quot;
    3. Pega tu documento OpenAPI
    4. Haz clic en &quot;Validate it!&quot;

    Si el cuadro de texto que aparece debajo tiene un borde verde, tu documento ha pasado la validación.
    Este es exactamente el paquete de validación que Mintlify usa para validar documentos OpenAPI, así que, si tu documento
    la supera aquí, es muy probable que el problema esté en otro lugar.

    Además, Mintlify no es compatible con OpenAPI 2.0. Si tu documento usa esta versión de la especificación,
    puedes encontrarte con este problema. Puedes convertir tu documento en [editor.swagger.io](https://editor.swagger.io/) (en Edit &gt; Convert to OpenAPI 3):

    <Frame>
      ![Captura de pantalla del Swagger Editor con el menú Edit desplegado y la opción de menú "Convert to OpenAPI 3" resaltada.](/images/convert-oas-3.png)
    </Frame>
  </Accordion>

  <Accordion title="Una de mis páginas de OpenAPI aparece completamente en blanco">
    Esto suele deberse a que el campo `openapi` está mal escrito en los metadatos de la página. Asegúrate de que
    el método HTTP y la ruta coincidan exactamente con el método HTTP y la ruta del documento OpenAPI.

    Aquí tienes un ejemplo de cómo esto puede salir mal:

    ```mdx get-user.mdx
    ---
    openapi: "GET /users/{id}/"
    ---
    ```

    ```yaml openapi.yaml
    paths:
      "/users/{id}":
        get: ...
    ```

    Ten en cuenta que la ruta del campo `openapi` termina con una barra diagonal, mientras que la ruta del documento OpenAPI
    no.

    Otro problema habitual es que el nombre del archivo esté mal escrito. Si estás especificando un documento OpenAPI concreto
    en el campo `openapi`, asegúrate de que el nombre del archivo sea correcto. Por ejemplo, si tienes dos documentos OpenAPI
    `openapi/v1.json` y `openapi/v2.json`, tus metadatos podrían verse así:

    ```mdx api-reference/v1/users/get-user.mdx
    ---
    openapi: "v1 GET /users/{id}"
    ---
    ```
  </Accordion>

  <Accordion title="Las solicitudes del Área de pruebas de API no funcionan">
    Si tienes un dominio personalizado configurado, esto podría deberse a un problema con tu proxy inverso. De
    forma predeterminada, las solicitudes realizadas a través del Área de pruebas de API comienzan con una solicitud `POST` a la
    ruta `/_mintlify/api/request` del sitio de documentación. Si tu proxy inverso está configurado para permitir solo solicitudes `GET`,
    todas estas solicitudes fallarán. Para solucionarlo, configura tu proxy inverso para
    permitir solicitudes `POST` a la ruta `/_mintlify/api/request`.

    Como alternativa, si tu proxy inverso no te permite aceptar solicitudes `POST`, puedes configurar Mintlify para enviar solicitudes directamente a tu backend con el ajuste `api.playground.proxy` en `docs.json`, como se describe en la [documentación de configuración](/es/organize/settings#param-proxy). Al usar esta configuración, tendrás que configurar CORS en tu servidor, ya que las solicitudes vendrán directamente de los navegadores de los usuarios en lugar de pasar por tu proxy.
  </Accordion>

  <Accordion title="Las entradas de navegación de OpenAPI no generan páginas">
    Si estás usando una configuración de navegación con OpenAPI, pero no se generan las páginas, revisa estos problemas comunes:

    1. **Falta la especificación de OpenAPI predeterminada**: Asegúrate de que el elemento de navegación tenga definido un campo `openapi`:

    ```json {5}
    "navigation": {
      "groups": [
        {
          "group": "API reference",
          "openapi": "/path/to/openapi.json",
          "pages": [
            "GET /users",
            "POST /users"
          ]
        }
      ]
    }
    ```

    2. **Herencia de la especificación OpenAPI**: Si usas navegación anidada, asegúrate de que los grupos secundarios hereden la especificación OpenAPI correcta o que especifiquen la suya.

    3. **Problemas de validación**: Usa `mint openapi-check <path-to-openapi-file>` para comprobar que tu documento OpenAPI sea válido.
  </Accordion>

  <Accordion title="Algunas operaciones de OpenAPI aparecen en la navegación, pero otras no">
    1. **Operaciones ocultas**: Las operaciones marcadas con `x-hidden: true` en tu especificación OpenAPI no aparecerán en la navegación generada automáticamente.
    2. **Operaciones no válidas**: Las operaciones con errores de validación en la especificación OpenAPI pueden omitirse. Revisa tu documento OpenAPI para detectar errores de sintaxis.
    3. **Inclusión manual vs. automática**: Si haces referencia a algún endpoint de una especificación OpenAPI, en la navegación solo aparecerán las operaciones a las que se haga referencia explícitamente. No se añadirá automáticamente ninguna otra página. Esto incluye las operaciones a las que se hace referencia en elementos hijo de navegación.
  </Accordion>

  <Accordion title="La navegación mixta (páginas de OpenAPI y de MDX) no funciona correctamente">
    Al combinar operaciones de OpenAPI con páginas de documentación normales en la navegación:

    1. **Conflictos de archivos**: No puedes tener a la vez un archivo `MDX` y una entrada de navegación para la misma operación. Por ejemplo, si tienes `get-users.mdx`, no incluyas también `"GET /users"` en la navegación. Si necesitas tener un archivo que comparta nombre con una operación, usa la extensión `x-mint` en el endpoint para que el `href` apunte a una ubicación distinta.
    2. **Resolución de rutas**: Las entradas de navegación que no coincidan con operaciones de OpenAPI se tratarán como rutas de archivo. Asegúrate de que tus archivos `MDX` existan en las ubicaciones esperadas.
    3. **Distinción entre mayúsculas y minúsculas**: La coincidencia de operaciones de OpenAPI distingue entre mayúsculas y minúsculas. Asegúrate de que los métodos HTTP estén en mayúsculas en las entradas de navegación.
  </Accordion>
</AccordionGroup>
