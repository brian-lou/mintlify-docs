---

Puedes definir manualmente los endpoints de la API en páginas MDX individuales. Este enfoque es útil para APIs pequeñas o para prototipado.

<div id="setup">
  ## Configuración
</div>

<Steps>
  <Step title="Configura los ajustes de tu API">
    En tu archivo `docs.json`, define la URL base y el método de autenticación.

    ```json Example docs.json
    "api": {
      "mdx": {
        "server": "https://api.acme.com/",
        "auth": {
          "method": "key",
          "name": "x-api-key"
        }
      }
    }
    ```

    Si quieres ocultar el entorno de pruebas de la API, establece el campo `display` en `none`. No necesitas incluir un método de autenticación si ocultas el entorno de pruebas.

    ```json
    "api": {
      "playground": {
        "display": "none"
      }
    }
    ```

    Puedes encontrar una lista completa de configuraciones de la API en [Settings](/es/organize/settings#api-configurations).
  </Step>

  <Step title="Crea las páginas de tus endpoints">
    Crea un archivo MDX para cada endpoint. Define `title` y `api` en el frontmatter:

    ```mdx
    ---
    title: 'Crear nuevo usuario'
    api: 'POST /v1/users'
    ---
    ```

    El campo `api` del frontmatter acepta una URL completa o una ruta relativa:

    * **URL completa** como `POST https://api.acme.com/v1/users`. El campo `server` en `docs.json` se ignora para ese endpoint.
    * **Ruta relativa** como `POST /v1/users`. Requiere un campo `server` en `docs.json`. La URL del servidor se antepone a la ruta.

    Especifica los parámetros de ruta envolviéndolos en `{}`:

    ```bash
    https://api.example.com/v1/endpoint/{userId}
    ```

    Para anular el modo de visualización global del playground en una página específica, agrega `playground` al frontmatter:

    ```mdx
    ---
    title: 'Crear nuevo usuario'
    api: 'POST https://api.mintlify.com/user'
    playground: 'none'
    ---
    ```

    Opciones:

    * `playground: 'interactive'` - Mostrar el playground interactivo (predeterminado)
    * `playground: 'simple'` - Mostrar un endpoint que se pueda copiar, sin playground
    * `playground: 'none'` - Ocultar el playground por completo
  </Step>

  <Step title="Añadir parámetros y respuestas">
    Utiliza [campos de parámetros y de respuesta](/es/components/fields) para documentar los parámetros y los valores que devuelve tu endpoint.

    ```mdx
    <ParamField path="userId" type="string" required>
      Identificador único del usuario
    </ParamField>

    <ParamField body="email" type="string" required>
      Dirección de correo electrónico del usuario
    </ParamField>

    <ResponseField name="id" type="string" required>
      Identificador único del usuario recién creado
    </ResponseField>

    <ResponseField name="email" type="string" required>
      Dirección de correo electrónico del usuario
    </ResponseField>
    ```
  </Step>

  <Step title="Añade tus endpoints a la documentación">
    Añade las páginas de tus endpoints a la navegación actualizando el campo `pages` en tu `docs.json`:

    ```json docs.json
    "navigation": {
      "tabs": [
        {
          "tab": "API Reference",
          "groups": [
            {
              "group": "Users",
              "pages": [
                "api-reference/users/create-user",
                "api-reference/users/get-user",
                "api-reference/users/update-user"
              ]
            },
            {
              "group": "Orders",
              "pages": [
                "api-reference/orders/create-order",
                "api-reference/orders/list-orders"
              ]
            }
          ]
        }
      ]
    }
    ```

    Cada ruta de página se corresponde con un archivo MDX en tu repositorio de documentación. Por ejemplo, `api-reference/users/create-user.mdx`. Obtén más información sobre cómo estructurar tu documentación en [Navigation](/es/organize/navigation).

    ### Uso de endpoints de OpenAPI en la navegación

    Si tienes una especificación de OpenAPI, puedes referenciar endpoints directamente en la navegación sin crear archivos MDX individuales. Para referenciar endpoints específicos, incluye la ruta del archivo OpenAPI y el endpoint:

    ```json docs.json
    "navigation": {
      "pages": [
        "introduction",
        "/path/to/users-openapi.json POST /users",
        "/path/to/orders-openapi.json GET /orders"
      ]
    }
    ```

    También puedes configurar una especificación de OpenAPI predeterminada para un grupo de navegación y hacer referencia a los endpoints por método y path:

    ```json docs.json
    {
      "group": "API reference",
      "openapi": "/path/to/openapi-v1.json",
      "pages": [
        "overview",
        "authentication",
        "GET /users",
        "POST /users",
        {
          "group": "Orders",
          "openapi": "/path/to/openapi-v2.json",
          "pages": [
            "GET /orders",
            "POST /orders"
          ]
        }
      ]
    }
    ```

    Para obtener más información sobre la integración con OpenAPI, consulta [Configuración de OpenAPI](/es/api-playground/openapi-setup).
  </Step>
</Steps>

<div id="enable-authentication">
  ## Habilitar la autenticación
</div>

Puedes establecer la autenticación de forma global en `docs.json` o sobrescribirla en páginas individuales mediante el campo `authMethod` en el frontmatter. Un método definido específicamente para una página sobrescribe la configuración global.

<div id="bearer-token">
  ### Token de portador
</div>

<CodeGroup>
  ```json docs.json
  "api": {
    "mdx": {
      "auth": {
        "method": "bearer"
      }
    }
  }
  ```

  ```mdx Page Metadata
  ---
  title: "Título de tu página"
  authMethod: "bearer"
  ---
  ```
</CodeGroup>

<div id="api-key">
  ### Clave de API
</div>

<CodeGroup>
  ```json docs.json
  "api": {
    "mdx": {
      "auth": {
        "method": "key",
        "name": "x-api-key"
      }

  ```

  ```mdx Page Metadata
  ---
  title: "Título de la página"

  ---
  ```
</CodeGroup>

<div id="none">
  ### Ninguno
</div>

Para deshabilitar la autenticación en una página específica, configura `authMethod` como `none`:

```mdx Page Metadata
---
title: "Your page title"
authMethod: "none"
---
```
