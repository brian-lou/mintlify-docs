Cuando creas documentación accesible, priorizas un diseño de contenido que hace que tu documentación sea usable por la mayor cantidad posible de personas, sin importar cómo acceden e interactúan con ella.

La documentación accesible mejora la experiencia de usuario para todas las personas. Tu contenido es más claro, está mejor estructurado y es más fácil de navegar.

Esta guía ofrece algunas buenas prácticas para crear documentación accesible, pero no es exhaustiva. Debes considerar la accesibilidad como un proceso continuo. Las tecnologías y los estándares cambian con el tiempo, lo que brinda nuevas oportunidades para mejorar la documentación.

<div id="what-is-accessibility">
  ## ¿Qué es la accesibilidad?
</div>

La accesibilidad (a veces abreviada como a11y por el número de letras entre la primera y la última de "accessibility") consiste en diseñar y crear de forma intencionada sitios web y herramientas que puedan ser utilizados por la mayor cantidad posible de personas. Las personas con discapacidades, tanto temporales como permanentes, deberían tener el mismo nivel de acceso a las tecnologías digitales. Además, diseñar pensando en la accesibilidad beneficia a todo el mundo, incluidas las personas que acceden a tu sitio web desde dispositivos móviles o redes lentas.

La documentación accesible sigue los estándares de accesibilidad web, principalmente las [Pautas de Accesibilidad para el Contenido Web (WCAG)](https://www.w3.org/WAI/WCAG22/quickref/). Estas pautas ayudan a garantizar que tu contenido sea perceptible, operable, comprensible y robusto.

<div id="getting-started-with-accessibility">
  ## Introducción a la accesibilidad
</div>

Hacer que tu documentación sea accesible es un proceso. No tienes que corregirlo todo de una sola vez ni puedes hacerlo solo una vez. 

Si apenas estás comenzando a implementar prácticas de accesibilidad en tu documentación, considera un enfoque por fases en el que empieces con cambios de alto impacto y avances a partir de ahí.

<div id="first-steps">
  ### Primeros pasos
</div>

Aquí tienes tres cosas que puedes hacer ahora mismo para mejorar la accesibilidad de tu documentación:

1. **Ejecuta `mint a11y`** para identificar problemas de accesibilidad en tu contenido.
2. **Añade texto alternativo (alt text)** a todas las imágenes.
3. **Revisa la jerarquía de tus encabezados** para garantizar que haya un solo H1 por página y que los encabezados sigan un orden secuencial.

<div id="plan-your-accessibility-work">
  ### Planifica tu trabajo de accesibilidad
</div>

El mejor flujo de trabajo es el que funciona para tu equipo. Aquí tienes una forma de abordar el trabajo de accesibilidad:

**Fase 1: Imágenes y estructura**

- Revisa todas las imágenes para asegurarte de que tengan texto alternativo descriptivo.
- Revisa el texto de los enlaces y reemplaza frases genéricas como "haz clic aquí".
- Corrige problemas de jerarquía de encabezados en toda tu documentación.

**Fase 2: Navegación y contenido multimedia**

- Prueba la navegación con el teclado en tu documentación.
- Prueba el funcionamiento con lectores de pantalla.
- Añade subtítulos y transcripciones a los videos integrados.
- Revisa el contraste de color.

**Fase 3: Incorpóralo en tu flujo de trabajo**

- Ejecuta `mint a11y` antes de publicar contenido nuevo.
- Incluye comprobaciones de accesibilidad en tu proceso de revisión de contenido.
- Prueba la navegación con el teclado al añadir funciones interactivas.
- Verifica que los nuevos enlaces externos y contenidos integrados incluyan títulos y descripciones adecuados.

Empezar poco a poco e incorporar la accesibilidad en tu flujo de trabajo habitual la hace sostenible. Cada mejora ayuda a que más personas puedan acceder a tu documentación con éxito.

<div id="structure-your-content">
  ## Estructura tu contenido
</div>

El contenido bien estructurado es más fácil de explorar y comprender, especialmente para las personas que usan lectores de pantalla y dependen de los encabezados para moverse por las páginas, así como para quienes utilizan la navegación por teclado.

<div id="use-proper-heading-hierarchy">
  ### Usa una jerarquía de encabezados adecuada
</div>

Cada página debe tener un único encabezado H1, que se define mediante la propiedad `title:` en el frontmatter de la página. Usa los siguientes encabezados en orden, sin saltarte niveles. Por ejemplo, no pases directamente de H2 a H4.

```mdx
<!-- Correcto -->
# Page title (H1)

## Main section (H2)

### Subsection (H3)

### Another subsection (H3)

## Another main section (H2)

<!-- Incorrecto -->
# Page title (H1)

## Main section (H2)

#### Subsection (H4)

### Another subsection (H3)
```

Los encabezados del mismo nivel deben tener nombres únicos.

```mdx
<!-- Correcto -->
## Accessibility tips (H2)

### Write effective alt text (H3)

### Use proper color contrast (H3)

<!-- Incorrecto -->
## Accessibility tips (H2)

### Tip (H3)

### Tip (H3)
```


<div id="write-descriptive-link-text">
  ### Utiliza texto de enlace descriptivo
</div>

El texto de los enlaces debe ser significativo y estar relacionado con el destino. Evita expresiones vagas como &quot;haz clic aquí&quot; o &quot;leer más.&quot;

```mdx
<!-- Bien -->
Learn how to [configure your navigation](/organize/navigation).

<!-- Relación poco clara entre el texto del enlace y el destino -->
[Learn more](/organize/navigation).
```


<div id="keep-content-scannable">
  ### Facilita la exploración del contenido
</div>

- Divide los párrafos largos.
- Usa listas para pasos y opciones.
- Destaca la información con recuadros informativos.

<div id="use-proper-table-structure">
  ### Utiliza una estructura de tabla adecuada
</div>

Usa las tablas con moderación y solo para datos tabulares cuyo significado se derive de los encabezados de columna y de fila.

Al usar tablas, incluye encabezados para que los lectores de pantalla puedan asociar los datos con la columna correcta:

```mdx
| Feature | Status |
| ------- | ------ |
| Search  | Active |
| Analytics | Active |
```


<div id="write-descriptive-alt-text">
  ## Escribe texto alternativo descriptivo
</div>

El texto alternativo hace que las imágenes sean accesibles para las personas que usan lectores de pantalla y aparece cuando las imágenes no se cargan. Las imágenes de tu documentación deben tener texto alternativo que describa la imagen y deje claro por qué se ha incluido. Incluso con texto alternativo, no debes depender solo de las imágenes para transmitir información. Asegúrate de que tu contenido describa lo que comunica la imagen.

<div id="write-effective-alt-text">
  ### Escribe texto alternativo efectivo
</div>

* **Sé específico**: Describe lo que muestra la imagen, no solo que es una imagen.
* **Sé conciso**: Procura usar una o dos frases.
* **Evita la redundancia**: No empieces con &quot;Imagen de&quot; porque los lectores de pantalla ya saben que el texto alternativo está asociado con una imagen. Sin embargo, debes incluir descripciones como &quot;Captura de pantalla de&quot; o &quot;Diagrama de&quot; si ese contexto es importante para la imagen.

```mdx
<!-- Bueno -->
![Screenshot of the dashboard showing three active projects and two pending invitations](/images/dashboard.png)

<!-- No es útil -->
![Dashboard screenshot](/images/dashboard.png)
```


<div id="add-alt-text-to-images">
  ### Añade texto alternativo a las imágenes
</div>

Para las imágenes en Markdown, incluye el texto alternativo entre corchetes:

```mdx
![Description of the image](/path/to/image.png)
```

En las imágenes HTML, usa el atributo `alt`:

```html
<img
  src="/images/screenshot.png"
  alt="Settings panel with accessibility options enabled. The options are emphasized with an orange rectangle."
/>
```


<div id="add-titles-to-embedded-content">
  ### Añade títulos al contenido incrustado
</div>

Los iframes y los vídeos incrustados deben tener títulos descriptivos:

```html
<iframe
  src="https://www.youtube.com/embed/example"
  title="Tutorial: Configuración de tu primer sitio de documentación"
></iframe>
```


<div id="design-for-readability">
  ## Diseño para mejorar la legibilidad
</div>

Las decisiones de diseño visual influyen en el nivel de accesibilidad de tu documentación para las personas con visión reducida, daltonismo u otras discapacidades visuales.

<div id="ensure-sufficient-color-contrast">
  ### Asegúrate de tener suficiente contraste de color
</div>

Si personalizas los colores de tu tema, comprueba que las relaciones de contraste cumplan los requisitos de las WCAG:

- Texto principal: relación de contraste mínima de 4.5:1
- Texto grande: relación de contraste mínima de 3:1
- Elementos interactivos: relación de contraste mínima de 3:1

Prueba tanto el modo claro como el oscuro. El comando `mint a11y` comprueba el contraste de color.

<div id="dont-rely-on-color-alone">
  ### No te bases únicamente en el color
</div>

Si usas el color para transmitir información, incluye también una etiqueta de texto o un icono. Por ejemplo, no marques los errores solo con texto rojo. Incluye un icono de error o la palabra "Error".

<div id="use-clear-concise-language">
  ### Usa un lenguaje claro y conciso
</div>

- Escribe con un lenguaje claro y sencillo.
- Define los términos técnicos la primera vez que los uses.
- Evita las oraciones demasiado largas.
- Usa la voz activa.

<div id="make-code-examples-accessible">
  ## Hacer que los ejemplos de código sean accesibles
</div>

Los bloques de código son una parte fundamental de la documentación técnica, pero requieren consideraciones de accesibilidad específicas para garantizar que las personas que usan lectores de pantalla puedan entenderlos. En general, sigue estas pautas:

- Divide los ejemplos de código largos en fragmentos más pequeños y lógicos.
- Comenta la lógica compleja dentro del código.
- Considera proporcionar una descripción en texto para algoritmos complejos.
- Al mostrar la estructura de archivos, usa bloques de código reales con etiquetas de lenguaje de programación en lugar de diagramas ASCII.

<div id="specify-the-programming-language">
  ### Especifica el lenguaje de programación
</div>

Declara siempre el lenguaje para el resaltado de la sintaxis. Esto ayuda a que los lectores de pantalla indiquen el contexto del código a los usuarios:

````mdx
```javascript
function getUserData(id) {
  return fetch(`/api/users/${id}`);
}
```
````


<div id="provide-context-around-code">
  ### Proporcione contexto para el código
</div>

Proporcione un contexto claro para los bloques de código:

````mdx
La siguiente función obtiene datos del usuario desde la API:

```javascript
function getUserData(id) {
  return fetch(`/api/users/${id}`);
}
```

Esto devuelve una promesa que se resuelve en el objeto de usuario.
````


<div id="video-and-multimedia-accessibility">
  ## Accesibilidad de los vídeos y del contenido multimedia
</div>

Los vídeos, las animaciones y otros contenidos multimedia necesitan alternativas de texto para que todas las personas puedan acceder a la información que contienen.

<div id="add-captions-to-videos">
  ### Añade subtítulos a los videos
</div>

Los subtítulos hacen que el contenido en video sea accesible para usuarios sordos o con problemas de audición. También ayudan a usuarios en entornos sensibles al sonido y a personas que no son hablantes nativos:

- Usa subtítulos para todo el contenido hablado en los videos.
- Incluye efectos de sonido relevantes en los subtítulos.
- Asegúrate de que los subtítulos estén sincronizados con el audio.
- Usa una puntuación adecuada e identifica a los hablantes cuando hablen varias personas.

La mayoría de las plataformas de alojamiento de video permiten añadir subtítulos. Sube archivos de subtítulos o usa subtítulos generados automáticamente como punto de partida y luego revísalos para garantizar su precisión.

<div id="provide-transcripts">
  ### Proporciona transcripciones
</div>

Las transcripciones ofrecen una forma alternativa de acceder al contenido de vídeo. Se pueden buscar, son más fáciles de consultar y accesibles para los lectores de pantalla:

```mdx
<iframe
  src="https://www.youtube.com/embed/example"
  title="Tutorial: Setting up authentication"
></iframe>

<Accordion title="Video transcript">
In this tutorial, we'll walk through setting up authentication...
</Accordion>
```

Coloca las transcripciones junto al vídeo o proporciona un enlace claro para acceder a ellas.


<div id="consider-alternatives-to-video-only-content">
  ### Considera alternativas al contenido exclusivamente en video
</div>

Si la información crítica solo aparece en un video:

- Proporciona la misma información en formato de texto.
- Incluye capturas de pantalla clave con texto alternativo descriptivo.
- Crea un tutorial escrito que cubra el mismo material.

Esto garantiza que las personas que no pueden acceder al contenido en video también puedan completar su tarea.

<div id="test-your-documentation">
  ## Pon a prueba tu documentación
</div>

Las pruebas periódicas te ayudan a detectar problemas de accesibilidad antes de que los usuarios los experimenten.

<div id="check-for-accessibility-issues-with-mint-a11y">
  ### Comprueba problemas de accesibilidad con `mint a11y`
</div>

Usa el comando CLI `mint a11y` para analizar automáticamente tu documentación y detectar problemas de accesibilidad comunes:

```bash
mint a11y
```

El comando comprueba:

* Imágenes y videos sin texto alternativo.
* Contraste de color insuficiente.

Cuando termine el análisis, revisa los problemas detectados y corrígelos en tu contenido. Vuelve a ejecutar el comando para verificar tus correcciones.

Usa flags para comprobar problemas de accesibilidad específicos.

```bash
# Verificar solo el texto alternativo faltante
mint a11y --skip-contrast

# Verificar solo los problemas de contraste de color
mint a11y --skip-alt-text
```


<div id="basic-keyboard-navigation-test">
  ### Prueba básica de navegación con teclado
</div>

Navega por tu documentación utilizando solo el teclado:

1. Pulsa <kbd>Tab</kbd> para desplazarte hacia adelante por los elementos interactivos.
2. Pulsa <kbd>Shift</kbd> + <kbd>Tab</kbd> para desplazarte hacia atrás.
3. Pulsa <kbd>Enter</kbd> para activar enlaces y botones.
4. Comprueba que todos los elementos interactivos se puedan alcanzar y tengan un indicador de foco visible.

<div id="go-deeper-with-accessibility-testing">
  ### Profundiza en las pruebas de accesibilidad
</div>

Para realizar pruebas más completas:

- **Lectores de pantalla**: Prueba con [NVDA (Windows)](https://www.nvaccess.org/) o [VoiceOver (Mac)](https://www.apple.com/accessibility/voiceover/).
- **Extensiones del navegador**: Instala [axe DevTools](https://www.deque.com/axe/browser-extensions/) o [WAVE](https://wave.webaim.org/extension/) para analizar páginas y detectar problemas.
- **Pautas WCAG**: Revisa las [Pautas de Accesibilidad para el Contenido Web](https://www.w3.org/WAI/WCAG22/quickref/) para conocer en detalle los estándares.
