Cuando creas documentación accesible, priorizas un diseño de contenido que permite que el mayor número posible de personas pueda usar tu documentación, independientemente de cómo accedan a ella o interactúen con ella.

La documentación accesible mejora la experiencia de usuario de todas las personas. Tu contenido es más claro, está mejor estructurado y es más fácil de recorrer.

Esta guía ofrece algunas prácticas recomendadas para crear documentación accesible, pero no es exhaustiva. Debes considerar la accesibilidad como un proceso continuo. Las tecnologías y los estándares cambian con el tiempo, lo que abre nuevas oportunidades para mejorar la documentación.

<div id="what-is-accessibility">
  ## ¿Qué es la accesibilidad?
</div>

La accesibilidad (a veces abreviada como a11y por la cantidad de letras entre la primera y la última letra de &quot;accessibility&quot;) consiste en diseñar y crear intencionalmente sitios web y herramientas que pueda usar el mayor número posible de personas. Las personas con discapacidades temporales o permanentes deben tener el mismo nivel de acceso a las tecnologías digitales. Además, diseñar pensando en la accesibilidad beneficia a todo el mundo, incluidas las personas que acceden a tu sitio web desde dispositivos móviles o redes lentas.

La documentación accesible sigue los estándares de accesibilidad web, principalmente las [Pautas de Accesibilidad para el Contenido Web (WCAG)](https://www.w3.org/WAI/WCAG22/quickref/). Estas pautas ayudan a garantizar que tu contenido sea perceptible, operable, comprensible y robusto.

<div id="getting-started-with-accessibility">
  ## Primeros pasos con la accesibilidad
</div>

Lograr que tu documentación sea accesible es un proceso. No tienes que corregirlo todo de una sola vez, ni basta con hacerlo una sola vez.

Si estás empezando a implementar prácticas de accesibilidad en tu documentación, considera un enfoque por fases: empieza con cambios de alto impacto y avanza a partir de ahí.

<div id="first-steps">
  ### Primeros pasos
</div>

Aquí tienes tres cosas que puedes hacer ahora mismo para mejorar la accesibilidad de tu documentación:

1. **Ejecuta `mint a11y`** para identificar problemas de accesibilidad en tu contenido.
2. **Añade texto alternativo** a todas las imágenes.
3. **Comprueba la jerarquía de encabezados** para asegurarte de que haya un único H1 por página y de que los encabezados sigan un orden secuencial.

<div id="plan-your-accessibility-work">
  ### Planifica el trabajo de accesibilidad
</div>

El mejor flujo de trabajo es el que mejor se adapta a tu equipo. Aquí tienes una forma de abordar la accesibilidad:

**Fase 1: Imágenes y estructura**

* Revisa que todas las imágenes tengan un texto alternativo descriptivo.
* Revisa el texto de los enlaces y sustituye frases genéricas como &quot;haz clic aquí&quot;.
* Corrige los problemas de jerarquía de encabezados en toda la documentación.

**Fase 2: Navegación y contenido multimedia**

* Comprueba la navegación con teclado en tu documentación.
* Comprueba la compatibilidad con lectores de pantalla.
* Añade subtítulos y transcripciones a los vídeos incrustados.
* Revisa el contraste de color.

**Fase 3: Intégralo en tu flujo de trabajo**

* Ejecuta `mint a11y` antes de publicar contenido nuevo.
* Incluye comprobaciones de accesibilidad en tu proceso de revisión de contenido.
* Comprueba la navegación con teclado al añadir funciones interactivas.
* Verifica que los nuevos enlaces externos y los elementos incrustados incluyan títulos y descripciones adecuados.

Empezar poco a poco e integrar la accesibilidad en tu flujo de trabajo habitual hace que sea sostenible. Cada mejora ayuda a que más usuarios puedan acceder a tu documentación correctamente.

<div id="structure-your-content">
  ## Estructura tu contenido
</div>

Un contenido bien estructurado es más fácil de recorrer y comprender, especialmente para las personas que usan lectores de pantalla y dependen de los encabezados para desplazarse por las páginas, así como para quienes navegan con el teclado.

<div id="use-proper-heading-hierarchy">
  ### Usa una jerarquía adecuada de encabezados
</div>

Cada página debe tener un único encabezado H1, que se define mediante la propiedad `title:` en el Frontmatter de la página. Usa los encabezados siguientes en orden, sin saltarte ninguno. Por ejemplo, no pases de H2 a H4.

```mdx
<!-- Correcto -->
# Título de página (H1)

## Sección principal (H2)

### Subsección (H3)

### Otra subsección (H3)

## Otra sección principal (H2)

<!-- Incorrecto -->
# Título de página (H1)

## Sección principal (H2)

#### Subsección (H4)

### Otra subsección (H3)
```

Los encabezados de un mismo nivel deben tener nombres únicos.

```mdx
<!-- Correcto -->
## Accessibility tips (H2)

### Write effective alt text (H3)

### Use proper color contrast (H3)

<!-- Incorrecto -->
## Accessibility tips (H2)

### Tip (H3)

### Tip (H3)
```


<div id="write-descriptive-link-text">
  ### Escribe texto descriptivo para los enlaces
</div>

El texto del enlace debe ser claro y estar relacionado con el destino. Evita frases vagas como &quot;haz clic aquí&quot; o &quot;leer más.&quot;

```mdx
<!-- Correcto -->
Learn how to [configure your navigation](/organize/navigation).

<!-- Relación poco clara entre el texto del enlace y el destino -->
[Learn more](/organize/navigation).
```


<div id="keep-content-scannable">
  ### Haz que el contenido sea fácil de escanear
</div>

* Divide los párrafos largos.
* Usa listas para los pasos y las opciones.
* Destaca la información con avisos.

<div id="use-proper-table-structure">
  ### Usa la estructura adecuada para las tablas
</div>

Usa las tablas con moderación y solo para datos tabulares cuyo significado dependa de los encabezados de las columnas y las filas.

Cuando uses tablas, incluye encabezados para que los lectores de pantalla puedan asociar los datos con la columna correspondiente:

```mdx
| Feature | Status |
| ------- | ------ |
| Search  | Active |
| Analytics | Active |
```


<div id="write-descriptive-alt-text">
  ## Escribe un texto alternativo descriptivo
</div>

El texto alternativo hace que las imágenes sean accesibles para las personas que usan lectores de pantalla y aparece cuando no se cargan. Las imágenes de tu documentación deben incluir un texto alternativo que las describa y deje claro por qué se han incluido. Incluso con texto alternativo, no debes depender únicamente de las imágenes para transmitir información. Asegúrate de que tu contenido describa lo que comunica la imagen.

<div id="write-effective-alt-text">
  ### Escribe un texto alternativo eficaz
</div>

* **Sé específico**: Describe lo que muestra la imagen, no te limites a decir que es una imagen.
* **Sé conciso**: Intenta que tenga una o dos frases.
* **Evita la redundancia**: No empieces con &quot;Imagen de&quot;, porque los lectores de pantalla ya saben que el texto alternativo está asociado a una imagen. Sin embargo, sí debes incluir descripciones como &quot;Captura de pantalla de&quot; o &quot;Diagrama de&quot; si ese contexto es importante para la imagen.

```mdx
<!-- Correcto -->
![Screenshot of the dashboard showing three active projects and two pending invitations](/images/dashboard.png)

<!-- No es útil -->
![Dashboard screenshot](/images/dashboard.png)
```


<div id="add-alt-text-to-images">
  ### Añade texto alternativo a las imágenes
</div>

En las imágenes de Markdown, incluye el texto alternativo entre corchetes:

```mdx
![Description of the image](/path/to/image.png)
```

Para las imágenes en HTML, usa el atributo `alt`:

```html
<img
  src="/images/screenshot.png"
  alt="Settings panel with accessibility options enabled. The options are emphasized with an orange rectangle."
/>
```


<div id="add-titles-to-embedded-content">
  ### Añade títulos al contenido incrustado
</div>

Los iframes y los vídeos incrustados requieren títulos descriptivos:

```html
<iframe
  src="https://www.youtube.com/embed/example"
  title="Tutorial: Setting up your first documentation site"
></iframe>
```


<div id="design-for-readability">
  ## Diseña para que sea fácil de leer
</div>

Las decisiones de diseño visual afectan a la accesibilidad de tu documentación para las personas con baja visión, daltonismo u otras discapacidades visuales.

<div id="ensure-sufficient-color-contrast">
  ### Asegura un contraste de color suficiente
</div>

Si personalizas los colores de tu tema, verifica que las relaciones de contraste cumplan los requisitos de WCAG:

* Texto principal: relación de contraste mínima de 4.5:1
* Texto grande: relación de contraste mínima de 3:1
* Elementos interactivos: relación de contraste mínima de 3:1

Prueba tanto el modo claro como el oscuro. El comando `mint a11y` verifica el contraste de color.

<div id="dont-rely-on-color-alone">
  ### No te bases solo en el color
</div>

Si usas el color para transmitir información, incluye también una etiqueta de texto o un icono. Por ejemplo, no marques los errores solo con texto en rojo. Incluye un icono de error o la palabra &quot;Error&quot;.

<div id="use-clear-concise-language">
  ### Usa un lenguaje claro y conciso
</div>

* Escribe en un lenguaje sencillo.
* Define los términos técnicos cuando se usen por primera vez.
* Evita las oraciones demasiado largas.
* Usa la voz activa.

<div id="make-code-examples-accessible">
  ## Haz accesibles los ejemplos de código
</div>

Los bloques de código son una parte fundamental de la documentación técnica, pero requieren consideraciones específicas de accesibilidad para garantizar que las personas que usan lectores de pantalla puedan entenderlos. En general, sigue estas pautas:

* Divide los ejemplos de código largos en fragmentos más pequeños y coherentes.
* Añade comentarios a la lógica compleja dentro del código.
* Considera incluir una descripción textual de los algoritmos complejos.
* Al mostrar la estructura de archivos, usa bloques de código reales con etiquetas de lenguaje en lugar de arte ASCII.

<div id="specify-the-programming-language">
  ### Especifica el lenguaje de programación
</div>

Indica siempre el lenguaje para el resaltado de sintaxis. Esto ayuda a los lectores de pantalla a transmitir a los usuarios el contexto del código:

````mdx
```javascript
function getUserData(id) {
  return fetch(`/api/users/${id}`);
}
```
````


<div id="provide-context-around-code">
  ### Proporciona contexto para el código
</div>

Proporciona un contexto claro para los bloques de código:

````mdx
La siguiente función obtiene datos del usuario desde la API:

```javascript
function getUserData(id) {
  return fetch(`/api/users/${id}`);
}
```

Esto devuelve una promesa que se resuelve en el objeto de usuario.
````


<div id="video-and-multimedia-accessibility">
  ## Accesibilidad de videos y contenido multimedia
</div>

Los videos, las animaciones y otros contenidos multimedia necesitan alternativas textuales para que todos los usuarios puedan acceder a la información que contienen.

<div id="add-captions-to-videos">
  ### Añade subtítulos a los videos
</div>

Los subtítulos hacen que el contenido en video sea accesible para las personas sordas o con dificultades auditivas. También ayudan a quienes están en entornos donde el sonido debe mantenerse bajo y a quienes no tienen el idioma como lengua materna:

* Usa subtítulos para todo el contenido hablado en los videos.
* Incluye en los subtítulos los efectos de sonido relevantes.
* Asegúrate de que los subtítulos estén sincronizados con el audio.
* Usa una puntuación adecuada e identifica a cada hablante cuando intervengan varias personas.

La mayoría de las plataformas de alojamiento de video permiten añadir subtítulos. Sube archivos de subtítulos o usa subtítulos generados automáticamente como punto de partida y, después, revísalos para comprobar su precisión.

<div id="provide-transcripts">
  ### Incluye transcripciones
</div>

Las transcripciones ofrecen una forma alternativa de acceder al contenido de video. Se pueden buscar, son más fáciles de consultar y son accesibles para los lectores de pantalla:

```mdx
<iframe
  src="https://www.youtube.com/embed/example"
  title="Tutorial: Setting up authentication"
></iframe>

<Accordion title="Video transcript">
In this tutorial, we'll walk through setting up authentication...
</Accordion>
```

Coloca las transcripciones junto al video o proporciona un enlace claro para acceder a ellas.


<div id="consider-alternatives-to-video-only-content">
  ### Considera alternativas al contenido exclusivamente en video
</div>

Si la información crítica solo aparece en un video:

* Proporciona la misma información en formato de texto.
* Incluye capturas de pantalla clave con texto alternativo descriptivo.
* Crea un tutorial escrito que abarque el mismo contenido.

Así, quienes no puedan acceder al contenido en video también podrán completar la tarea.

<div id="test-your-documentation">
  ## Prueba tu documentación
</div>

Las pruebas periódicas te ayudan a detectar problemas de accesibilidad antes de que los usuarios los encuentren.

<div id="check-for-accessibility-issues-with-mint-a11y">
  ### Comprueba si hay problemas de accesibilidad con `mint a11y`
</div>

Usa el comando de la CLI `mint a11y` para analizar automáticamente tu documentación en busca de problemas de accesibilidad comunes:

```bash
mint a11y
```

El comando comprueba lo siguiente:

* Falta de texto alternativo en imágenes y videos.
* Contraste de color insuficiente.

Cuando finalice el análisis, revisa los problemas detectados y corrígelos en el contenido. Vuelve a ejecutar el comando para verificar las correcciones.

Usa opciones para comprobar problemas de accesibilidad específicos.

```bash
# Verificar solo el texto alternativo faltante
mint a11y --skip-contrast

# Verificar solo los problemas de contraste de color
mint a11y --skip-alt-text
```


<div id="basic-keyboard-navigation-test">
  ### Prueba básica de navegación con teclado
</div>

Navega por tu documentación usando solo el teclado:

1. Presiona <kbd>Tab</kbd> para avanzar entre los elementos interactivos.
2. Presiona <kbd>Shift</kbd> + <kbd>Tab</kbd> para retroceder.
3. Presiona <kbd>Enter</kbd> para activar enlaces y botones.
4. Verifica que se pueda acceder a todos los elementos interactivos y que tengan indicadores de enfoque visibles.

<div id="go-deeper-with-accessibility-testing">
  ### Profundiza en las pruebas de accesibilidad
</div>

Para realizar pruebas más exhaustivas:

* **Lectores de pantalla**: Prueba con [NVDA (Windows)](https://www.nvaccess.org/) o [VoiceOver (Mac)](https://www.apple.com/accessibility/voiceover/).
* **Extensiones del navegador**: Instala [axe DevTools](https://www.deque.com/axe/browser-extensions/) o [WAVE](https://wave.webaim.org/extension/) para analizar páginas y detectar problemas.
* **Pautas WCAG**: Consulta las [Pautas de Accesibilidad para el Contenido Web](https://www.w3.org/WAI/WCAG22/quickref/) para ver los estándares en detalle.
