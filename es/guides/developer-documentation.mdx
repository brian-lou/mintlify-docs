La documentación para desarrolladores ayuda a entender e integrar tu producto. Una buena documentación permite sacar más partido a tu producto, reduce la carga de soporte, acelera la adopción y mejora la experiencia de los desarrolladores.

Mintlify proporciona una infraestructura diseñada para la documentación para desarrolladores.

* **Generación de referencias de API**: Genera [referencias de API](/es/api-playground/overview) interactivas a partir de especificaciones OpenAPI para que los desarrolladores prueben endpoints directamente en tu documentación.
* **Bloques de código con explicaciones**: El [asistente](/es/ai/assistant) explica ejemplos de código en contexto, lo que ayuda a los desarrolladores a comprender los detalles de implementación.
* **Sincronización con Git**: Mantén la documentación sincronizada con tu base de código mediante [GitHub](/es/deploy/github) o [GitLab](/es/deploy/gitlab).
* **Control de versiones**: Mantén documentación para varias [versiones](/es/organize/navigation#versions) para que los desarrolladores que usan versiones anteriores sigan encontrando información precisa.

<div id="prerequisites">
  ## Requisitos previos
</div>

Si aún no has creado un proyecto de Mintlify, consulta la [Guía de inicio rápido](/es/quickstart) para desplegar tu sitio.

* La especificación de tu API en formato OpenAPI (si vas a documentar una API)
* Un repositorio de Git para tu documentación
* Acceso de administrador a tu organización de Mintlify

<div id="migrate-existing-documentation">
  ## Migra la documentación existente
</div>

Si vas a crear la documentación desde cero, pasa a [Planifica la estructura de tu documentación](#plan-your-documentation-structure).

<div id="audit-existing-content">
  ### Revisa el contenido existente
</div>

Revisa tu documentación actual para entender qué tienes y qué necesitas migrar.

* **Referencia de la API**: ¿Se genera a partir de una especificación o está escrita manualmente? ¿Qué endpoints documentas?
* **Guías y tutoriales**: ¿Qué guías de integración existen? ¿Están actualizadas?
* **Ejemplos de código**: ¿Qué lenguajes y frameworks utilizas?
* **Documentación del SDK**: ¿Tienes documentación independiente para cada SDK?
* **Registro de cambios**: ¿Mantienes un registro de cambios o notas de la versión?
* **Metadatos**: ¿Tu contenido tiene metadatos, como fechas, autores y etiquetas?

<div id="export-your-existing-content">
  ### Exporta tu contenido actual
</div>

* Exporta a **Markdown** para que la migración a Mintlify sea lo más sencilla posible.
* Exporta las **especificaciones de OpenAPI** para el contenido de referencia de la API.
* Exporta a **HTML** si Markdown no está disponible y luego conviértelo a Markdown.

<div id="plan-your-documentation-structure">
  ## Planifica la estructura de tu documentación
</div>

La documentación para desarrolladores suele incluir varios tipos de contenido. Organiza la navegación en función de cómo tus usuarios entienden tu producto.

```json docs.json example
{
  "navigation": {
    "groups": [
      {
        "group": "Get Started",
        "pages": [
          "introduction",
          "quickstart",
          "authentication"
        ]
      },
      {
        "group": "Guides",
        "pages": [
          "guides/webhooks",
          "guides/error-handling",
          "guides/rate-limits",
          "guides/pagination"
        ]
      },
      {
        "group": "API Reference",
        "pages": [
          "api-reference/overview",
          "api-reference/users",
          "api-reference/orders",
          "api-reference/products"
        ]
      },
      {
        "group": "SDKs",
        "pages": [
          "sdks/javascript",
          "sdks/python",
          "sdks/go"
        ]
      }
    ]
  }
}
```

Consulta [Navigation](/es/organize/navigation) para conocer otras opciones de configuración.

<div id="set-up-your-api-reference">
  ## Configura la referencia de la API
</div>

Si tienes una API, genera una referencia interactiva a partir de tu especificación OpenAPI.

<Steps>
  <Step title="Añade tu especificación OpenAPI">
    Añade el archivo de especificación OpenAPI a tu proyecto. Puedes usar formato YAML o JSON.

    ```text
    your-project/
    ├── docs.json
    ├── openapi.yaml
    └── api-reference/
        └── overview.mdx
    ```
  </Step>

  <Step title="Configura la especificación en docs.json">
    Haz referencia a tu archivo OpenAPI en la configuración de `docs.json`.

    ```json Ejemplo de configuración
    {
      "openapi": "openapi.yaml"
    }
    ```
  </Step>

  <Step title="Añade los endpoints a la navegación">
    Añade los endpoints a la navegación de `docs.json`. Consulta [la configuración de OpenAPI](/es/api-playground/openapi-setup) para ver las opciones de configuración.

    ```json Ejemplo de navegación
    {
      "group": "API Reference",
      "pages": [
        "api-reference/overview",
        "api-reference/users/list-users",
        "api-reference/users/get-user",
        "api-reference/users/create-user"
      ]
    }
    ```
  </Step>
</Steps>

<div id="set-up-the-assistant">
  ## Configura el asistente
</div>

El asistente ayuda a los desarrolladores a encontrar respuestas y entender ejemplos de código. Configúralo desde tu [panel de control](https://dashboard.mintlify.com/products/assistant/settings).

* **Preguntas de ejemplo**: Añade preguntas orientadas a desarrolladores, como &quot;¿Cómo autentico las solicitudes de API?&quot; o &quot;Muéstrame cómo gestionar webhooks&quot;.
* **Explicaciones de código**: El asistente puede explicar bloques de código según el contexto cuando los desarrolladores hacen preguntas sobre ejemplos específicos.

<div id="set-up-versioning">
  ## Configura el versionado
</div>

Si mantienes varias versiones de la API, configura el versionado para que los desarrolladores encuentren la documentación de la versión que usan.

```json Versioning example
{
  "versions": ["v2", "v1"],
  "navigation": {
    "groups": [
      {
        "group": "API Reference",
        "version": "v2",
        "pages": ["v2/api-reference/users"]
      },
      {
        "group": "API Reference",
        "version": "v1",
        "pages": ["v1/api-reference/users"]
      }
    ]
  }
}
```

Para obtener más información, consulta [Versions](/es/organize/navigation#versions).

<div id="connect-to-your-repository">
  ## Conecta tu repositorio
</div>

Instala la [GitHub App](/es/deploy/github) de Mintlify para mantener la documentación sincronizada con tu código y permitir contribuciones.

<Steps>
  <Step title="Conecta tu repositorio">
    Vincula tu repositorio de GitHub en el [panel de control](https://dashboard.mintlify.com). Esto habilita despliegues automáticos cuando haces push de cambios.
  </Step>

  <Step title="Configura los ajustes de la rama">
    Define tu rama de producción y habilita despliegues de vista previa para los pull requests. Esto te permite revisar los cambios en la documentación antes de publicarlos.
  </Step>
</Steps>

<Note>
  Si usas GitLab, consulta [GitLab](/es/deploy/gitlab) para ver las instrucciones de configuración.
</Note>

<div id="maintain-your-documentation">
  ## Mantén tu documentación
</div>

La documentación para desarrolladores debe actualizarse con regularidad para que la información sea precisa y útil.

<Steps>
  <Step title="Mantén actualizada la referencia de la API">
    Actualiza tu especificación OpenAPI cada vez que publiques cambios. Si tu especificación se genera a partir del código, automatiza este paso en tu proceso de lanzamiento.
  </Step>

  <Step title="Actualiza los ejemplos de código">
    Revisa los ejemplos de código cuando publiques nuevas versiones del SDK o actualizaciones del producto. Los ejemplos desactualizados provocan fallos de integración y solicitudes de soporte.
  </Step>

  <Step title="Mantén un registro de cambios">
    Documenta los cambios importantes, las nuevas funciones y las deprecaciones. Los desarrolladores dependen de los registros de cambios para entender qué cambió entre versiones. Consulta [Changelogs](/es/create/changelogs) para obtener más información.
  </Step>

  <Step title="Supervisa los comentarios">
    Revisa las conversaciones con el asistente y las analíticas de búsqueda para identificar vacíos en tu documentación. Si los desarrolladores preguntan repetidamente sobre el mismo tema, mejora esa sección. Consulta [Maintenance](/es/guides/maintenance) para obtener más información.
  </Step>
</Steps>

<div id="next-steps">
  ## Próximos pasos
</div>

Tu documentación para desarrolladores está lista para publicarse. Después de publicarla:

1. Anuncia la documentación a tu comunidad de desarrolladores.
2. Supervisa los patrones de búsqueda y la conversación con el asistente para detectar carencias.
3. Establece un proceso para actualizar la documentación con cada lanzamiento de la API.
4. Recopila comentarios de los desarrolladores para mejorar el contenido con el tiempo.
