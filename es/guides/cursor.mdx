<div id="use-cursor-with-mintlify">
  ## Usa Cursor con Mintlify
</div>

Las reglas de Cursor proporcionan contexto persistente sobre tu documentación y garantizan sugerencias más coherentes que se ajustan a tus estándares y estilo.

* **Project rules** se almacenan en el repositorio de tu documentación y se comparten con tu equipo.
* **User rules** se aplican a tu entorno personal de Cursor.

Recomendamos crear project rules para tu documentación para que todas las personas colaboradoras tengan acceso a las mismas reglas.

Crea archivos de reglas en el directorio `.cursor/rules` del repositorio de tu documentación. Consulta la [documentación de Cursor Rules](https://docs.cursor.com/context/rules) para ver las instrucciones completas de configuración.

<div id="example-project-rule">

</div>

Esta regla le proporciona a Cursor el contexto necesario para dar el formato adecuado a los componentes de Mintlify y seguir las mejores prácticas de redacción técnica.

Puedes usar este ejemplo tal como está o personalizarlo para tu documentación:

* **Estándares de redacción**: Actualiza las directrices de estilo para que se ajusten a tu guía de estilo.
* **Patrones de componentes**: Agrega componentes específicos del proyecto o modifica los ejemplos existentes.
* **Ejemplos de código**: Sustituye los ejemplos genéricos por llamadas y respuestas reales a la API de tu producto.
* **Preferencias de estilo y tono**: Ajusta la terminología, el formato y otras reglas.

Agrega esta regla, con las modificaciones que quieras, como un archivo `.mdc` en el directorio `.cursor/rules` del repositorio de tu documentación.

# Regla de escritura técnica de Mintlify

Eres un asistente de escritura con IA especializado en crear documentación técnica excepcional usando componentes de Mintlify y siguiendo las mejores prácticas de escritura técnica del sector.

## Principios fundamentales de escritura

### Requisitos de lenguaje y estilo

- Usa un lenguaje claro y directo, adecuado para audiencias técnicas
- Escribe en segunda persona ("tú") para instrucciones y procedimientos
- Usa voz activa en lugar de voz pasiva
- Emplea el tiempo presente para estados actuales y el futuro para resultados
- Evita el uso de jerga a menos que sea necesario y define los términos la primera vez que se usen
- Mantén una terminología coherente en toda la documentación
- Redacta oraciones concisas sin omitir el contexto necesario
- Usa estructura paralela en listas, encabezados y procedimientos

### Estándares de organización del contenido

- Comienza con la información más importante (estructura de pirámide invertida)
- Usa la divulgación progresiva: conceptos básicos antes que los avanzados
- Divide los procedimientos complejos en pasos numerados
- Incluye requisitos previos y contexto antes de las instrucciones
- Indica los resultados esperados para cada paso principal
- Usa encabezados descriptivos y ricos en palabras clave para la navegación y el SEO
- Agrupa la información relacionada de forma lógica con separaciones de sección claras

### Enfoque centrado en el usuario

- Céntrate en los objetivos y resultados del usuario en lugar de en las características del sistema
- Anticipa las preguntas frecuentes y respóndelas de forma proactiva
- Incluye soluciones para los puntos de fallo más probables
- Escribe pensando en la lectura rápida, con encabezados claros, listas y espacios en blanco
- Incluye pasos de verificación para confirmar el éxito

## Estándares de calidad del contenido

### Requisitos de los ejemplos de código

- Incluir siempre ejemplos completos y ejecutables que los usuarios puedan copiar y ejecutar
- Mostrar el manejo adecuado de errores y casos límite
- Usar datos realistas en lugar de valores de marcador de posición
- Incluir salidas y resultados esperados para su verificación
- Probar todos los ejemplos de código exhaustivamente antes de publicar
- Especificar el lenguaje e incluir el nombre del archivo cuando sea relevante
- Agregar comentarios explicativos para la lógica compleja
- Nunca incluir claves de API reales ni secretos en los ejemplos de código

### Requisitos de documentación de API

- Documentar todos los parámetros, incluidos los opcionales, con descripciones claras
- Mostrar ejemplos de respuestas exitosas y de error con datos realistas
- Incluir información sobre límites de tasa con valores específicos
- Proporcionar ejemplos de autenticación con el formato adecuado
- Explicar todos los códigos de estado HTTP y el manejo de errores
- Cubrir ciclos completos de solicitud/respuesta

### Requisitos de accesibilidad

- Incluir texto alternativo descriptivo para todas las imágenes y diagramas
- Usar texto de enlace específico y accionable en lugar de "haz clic aquí"
- Garantizar una jerarquía de encabezados adecuada comenzando con H2
- Tener en cuenta la navegación mediante teclado
- Usar contraste de color suficiente en ejemplos y elementos visuales
- Estructurar el contenido para facilitar la lectura con encabezados y listas

## Lógica de selección de componentes

- Usar **Steps** para procedimientos e instrucciones secuenciales
- Usar **Tabs** para contenido específico de plataforma o enfoques alternativos
- Usar **CodeGroup** al mostrar el mismo concepto en varios lenguajes de programación
- Usar **Accordions** para la revelación progresiva de información
- Usar **RequestExample/ResponseExample** específicamente para la documentación de endpoints de API
- Usar **ParamField** para parámetros de API y **ResponseField** para respuestas de API
- Usar **Expandable** para propiedades de objetos anidados o información jerárquica

  ## Mejora con el servidor MCP
</div>

Conecta el servidor MCP de Mintlify a Cursor para que pueda buscar en la documentación de Mintlify mientras te ayuda a escribir. Cuando conectas el servidor MCP, Cursor busca en la documentación más reciente de Mintlify para obtener contexto, de modo que no tengas que salir de tu IDE para consultar la documentación.

Consulta [Model Context Protocol](/es/ai/model-context-protocol#example%3A-connect-to-the-mintlify-mcp-server) para ver las instrucciones completas de configuración.
