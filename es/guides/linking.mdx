Un uso eficaz de los enlaces crea una experiencia de documentación cohesionada que ayuda a los usuarios a descubrir contenido relacionado y a navegar de forma eficiente. Un exceso de enlaces o los enlaces rotos pueden confundir a los usuarios y hacer que tu documentación sea menos efectiva. Esta guía muestra cómo crear y mantener enlaces en toda tu documentación.

<div id="internal-links">
  ## Enlaces internos
</div>

Crea enlaces a otras páginas de tu documentación mediante rutas relativas a la raíz. Las rutas relativas a la raíz comienzan en la raíz de tu directorio de documentación y funcionan de forma consistente independientemente de la ubicación de la página que contiene el enlace.

```mdx
* [Quickstart guide](/quickstart)
* [API overview](/api-playground/overview)
* [Custom components](/customize/react-components)
```

* [Guía de inicio rápido](/es/quickstart)
* [Descripción general de la API](/es/api-playground/overview)
* [Componentes personalizados](/es/customize/react-components)

<div id="anchor-links">
  ## Enlaces de anclaje
</div>

Los enlaces de anclaje te permiten crear enlaces directos a secciones específicas de una página. Cada encabezado genera automáticamente un enlace de anclaje a partir de su texto.

<div id="link-to-headers-on-the-same-page">
  ### Enlazar a encabezados en la misma página
</div>

Haz referencia a encabezados en la página actual usando el símbolo # (almohadilla):

```mdx
[Jump to best practices](#best-practices)
```

[Ir a las prácticas recomendadas](#best-practices)

<div id="link-to-headers-on-other-pages">
  ### Vincular a encabezados de otras páginas
</div>

Combina las rutas de página con enlaces de ancla.

```mdx
* [Customize your playground](/api-playground/overview#customize-your-playground)
* [Cards properties](/components/cards#properties)
```

* [Personaliza tu Playground](/es/api-playground/overview#customize-your-playground)
* [Propiedades de Cards](/es/components/cards#properties)

<div id="how-anchor-links-are-generated">
  ### Cómo se generan los enlaces de anclaje
</div>

Los enlaces de anclaje se crean automáticamente a partir del texto de los encabezados.

* Convertir a minúsculas
* Reemplazar espacios con guiones
* Eliminar caracteres especiales
* Conservar números y letras

| Texto del encabezado | Enlace de anclaje |
|-------------|-------------|
| `## Getting Started` | `#getting-started` |
| `### API Authentication` | `#api-authentication` |
| `#### Step 1: Install` | `#step-1-install` |

<Note>
  Los encabezados con la prop `noAnchor` no generarán enlaces de anclaje. Consulta [Formatear texto](/es/create/text#disabling-anchor-links) para más información.
</Note>

<div id="link-to-api-endpoints">
  ## Enlazar a endpoints de API
</div>

Al documentar APIs, puedes enlazar a endpoints específicos desde cualquier parte de tu documentación.

Enlaza a las páginas de endpoints de API usando su ruta en la navegación.

<div id="link-to-external-pages">
  ## Enlace a páginas externas
</div>

Cuando enlaces a recursos externos, asegúrate de dejar claro que el enlace lleva fuera de tu documentación.

```mdx
Learn more about [Markdown syntax](https://www.markdownguide.org/) (external link).

See the [OpenAPI specification](https://swagger.io/specification/) in the Swagger documentation for details.
```

<div id="best-practices">
  ## Buenas prácticas
</div>

<div id="write-descriptive-link-text">
  ### Redacta texto de enlace descriptivo
</div>

Usa un texto claro y descriptivo que indique qué encontrarán las personas usuarias cuando hagan clic.

<CodeGroup>
  ```mdx Buenos ejemplos
  Consulta [Páginas ocultas](/organize/hidden-pages) para obtener más información.
  [Configura dominios personalizados](/customize/custom-domain)
  ```

  ```mdx Evita
  [Haz clic aquí](/api-playground/overview)
  [Leer más](/deploy/deployments)
  [Ver esta página](/customize/custom-domain)
  ```
</CodeGroup>

<div id="create-topic-clusters">
  ### Crea grupos de temas
</div>

Enlaza contenido relacionado para ayudar a los usuarios a encontrar información relevante.

```mdx
## Related topics

- [API authentication](/api-playground/overview#authentication)
- [Adding SDK examples](/api-playground/adding-sdk-examples)
- [Managing page visibility](/api-playground/managing-page-visibility)
```

<div id="use-contextual-links">
  ### Usa enlaces contextuales
</div>

Incorpora enlaces de forma natural en el contenido, allí donde aporten valor.

```mdx
To customize your documentation appearance, configure [themes](/customize/themes) 
and [fonts](/customize/fonts) in your settings. You can also add 
[custom scripts](/customize/custom-scripts) for advanced functionality.
```

<div id="link-to-prerequisites">
  ### Enlaza a los requisitos previos
</div>

Ayuda a los usuarios a prepararse mediante enlaces al contenido de requisitos previos:

```mdx
## Prerequisites

Before deploying your documentation, ensure you have:

- Completed the [quickstart guide](/quickstart)
- Configured your [custom domain](/customize/custom-domain)
- Set up [authentication](/deploy/authentication-setup) if needed
```

<div id="avoid-circular-links">
  ### Evita los enlaces circulares
</div>

No crees enlaces que hagan que los usuarios vayan y vengan entre las mismas páginas.

<div id="check-for-broken-links">
  ### Comprueba si hay enlaces rotos
</div>

Usa la CLI de Mintlify para detectar enlaces rotos en tu documentación.

```bash
mint broken-links
```

<div id="update-links-when-reorganizing">
  ### Actualiza los enlaces al reorganizar
</div>

Al mover o renombrar páginas:

1. Actualiza la ruta de la página en la configuración de navegación.
2. Configura redirecciones de la ruta antigua a la nueva.
3. Busca en tu documentación cualquier referencia a la ruta antigua.
4. Actualiza todos los enlaces internos para usar la nueva ruta.
5. Ejecuta `mint broken-links` para verificar que todos los enlaces funcionan.

<div id="use-redirects-for-moved-content">
  ### Usa redirecciones para el contenido que hayas movido
</div>

Cuando muevas contenido de forma permanente, añade redirecciones para evitar enlaces rotos.

```json
{
  "redirects": [
    {
      "source": "/old-path",
      "destination": "/new-path"
    }
  ]
}
```

Para más información, consulta [Redirecciones](/es/create/redirects).
