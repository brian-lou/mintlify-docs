Una base de conocimientos interna ayuda a tu equipo a encontrar respuestas y a mantener una fuente única de información fiable. Si tu equipo tiene información repartida entre distintos canales y plataformas, es posible que las personas encuentren información inexacta o no encuentren nada cuando busquen respuestas. Una base de conocimientos centralizada resuelve este problema al reunir las respuestas en un lugar accesible para todos y ofrecerle a tu equipo un espacio específico para documentar el conocimiento compartido.

Mintlify proporciona la infraestructura para bases de conocimientos a las que puede contribuir todo tu equipo.

* **Búsqueda con IA**: El [asistente](/es/ai/assistant) responde preguntas usando el contenido de tu base de conocimientos, para que las personas encuentren respuestas sin saber exactamente dónde buscar.
* **Integraciones con Slack**: Añade el asistente a [Slack](/es/ai/slack-bot) para que tu equipo pueda hacer preguntas y usar el [agente](/es/agent/slack) para capturar conocimiento de las conversaciones.
* **Contribuciones sencillas**: El [editor web](/es/editor) y el [agente](/es/agent/quickstart) permiten que cualquier persona de tu equipo actualice contenido sin necesidad de aprender Git ni Markdown.
* **Autenticación integrada**: Controla el acceso con [SSO u OAuth](/es/deploy/authentication-setup) y usa [groups](/es/deploy/authentication-setup#control-access-with-groups) para mostrar contenido diferente a distintos equipos.

<div id="prerequisites">
  ## Requisitos previos
</div>

Si aún no has creado un proyecto en Mintlify, consulta la [guía de inicio rápido](/es/quickstart) para desplegar tu sitio.

* Un sistema de autenticación (SSO o un proveedor de OAuth como Okta o Azure AD)
* Control sobre tu dominio para el alojamiento
* Acceso de administrador a tu organización de Mintlify

<div id="migrate-existing-content">
  ## Migra el contenido existente
</div>

Si estás creando una base de conocimientos desde cero, ve a [Diseña la estructura de navegación](#design-the-navigation-structure).

<div id="audit-existing-content">
  ### Revisa el contenido existente
</div>

Haz un inventario del contenido que tienes actualmente en tu base de conocimientos. Esto te ayuda a entender qué contenido necesitas migrar, planificar cómo organizarlo en tu nueva base de conocimientos, identificar cualquier vacío en el contenido y confirmar que has trasladado todo a la nueva base de conocimientos.

* **Número total de artículos**: Ayuda a estimar el esfuerzo de migración y a comprobar que no falte nada.
* **Temas y contenido**: Sirven de base para tu estructura de navegación y la organización del contenido.
* **Organización actual**: Revisa cómo está organizado actualmente tu contenido y si coincide con la estructura que quieres.
* **Tipos de contenido**: Determina los requisitos de conversión para texto, PDF, vídeos y contenido incrustado.
* **Metadatos**: Identifica qué metadatos debes conservar, como fechas, autores y etiquetas.
* **Requisitos de acceso**: Determina el mejor enfoque de autenticación para tu base de conocimientos.

<div id="export-your-existing-content">
  ### Exporta tu contenido actual
</div>

La mayoría de las plataformas de bases de conocimientos permiten exportar contenido en formatos estándar. El formato que elijas dependerá de tu plataforma actual y de tus prioridades.

* Exporta a **Markdown** para hacer la migración a Mintlify lo más sencilla posible. (recomendado)
* Exporta a **HTML** si Markdown no está disponible. Más adelante tendrás que convertir tu contenido a Markdown.
* Exporta a **JSON o CSV** si tienes metadatos estructurados que quieres conservar.

<div id="design-the-navigation-structure">
  ## Diseña la estructura de navegación
</div>

La estructura de navegación determina cómo las personas encuentran contenido en tu base de conocimientos. Puedes recrear tu estructura actual o rediseñarla para que refleje mejor cómo tu equipo organiza el contenido.

<Tip>
  La migración es un buen momento para mejorar tu estructura. Plantéate si tu organización actual realmente le funciona a tu equipo o si puedes reorganizarla para que la información sea más fácil de encontrar.
</Tip>

El archivo `docs.json` define la estructura de navegación de tu base de conocimientos. Crea este archivo en la raíz del repositorio de tu proyecto.

```json
{
  "navigation": {
    "groups": [
      {
        "group": "Finance",
        "pages": [
            "finance/overview",
            "finance/budgeting-process",
            "finance/expense-reports",
            "finance/cost-allocation"
        ]
      },
      {
        "group": "HR",
        "pages": [
            "hr/overview",
            "hr/onboarding",
            "hr/benefits",
            "hr/time-off-policy"
        ]
      },
      {
        "group": "Engineering",
        "pages": [
          "engineering/overview",
          "engineering/dev-setup",
          "engineering/deployment",
          "engineering/code-standards"
        ]
      }
    ]
  }
}
```

Consulta [Navegación](/es/organize/navigation) para obtener más información sobre cómo estructurar tu base de conocimientos.

<div id="set-up-authentication">
  ## Configura la autenticación
</div>

Determina quién necesita acceso a qué contenido de tu base de conocimientos.

Si todo el mundo debe tener acceso a toda la base de conocimientos, configura solo la [autenticación](/es/deploy/authentication-setup).

Si necesitas restringir el acceso a cierto contenido a usuarios o grupos específicos, configura la autenticación con [control de acceso basado en grupos](/es/deploy/authentication-setup#control-access-with-groups).

<div id="migrate-your-content">
  ## Migra tu contenido
</div>

Mueve el contenido exportado a una estructura de carpetas que coincida con la estructura de navegación que diseñaste. Convierte el contenido a Markdown si es necesario, agrega el Frontmatter que falte y configura los enlaces internos.

<Steps>
  <Step title="Organiza los archivos">
    Crea carpetas que coincidan con la estructura de tu `docs.json`. Por ejemplo, si tu `docs.json` tiene un grupo llamado Finance, crea una carpeta `finance/`:

    ```text
    your-project/
    ├── docs.json
    ├── finance/
    │   ├── overview.mdx
    │   ├── budgeting-process.mdx
    │   ├── expense-reports.mdx
    │   └── cost-allocation.mdx
    ├── hr/
    │   ├── overview.mdx
    │   ├── onboarding.mdx
    │   ├── benefits.mdx
    │   └── time-off-policy.mdx
    └── engineering/
        ├── overview.mdx
        ├── dev-setup.mdx
        ├── deployment.mdx
        └── code-standards.mdx
    ```

    Coloca cada artículo en la carpeta que le corresponda. La ruta del archivo debe coincidir con la ruta de tu `docs.json`. Por ejemplo, si `docs.json` hace referencia a `"finance/expense-reports"`, el archivo debe ser `finance/expense-reports.mdx` en el repositorio de tu proyecto.
  </Step>

  <Step title="Agrega Frontmatter a cada artículo">
    Cada archivo `.mdx` necesita Frontmatter al inicio con metadatos. Todas las páginas requieren un título y una descripción. Consulta [Pages](/es/organize/pages) para obtener más información sobre los metadatos de las páginas.

    ```mdx
    ---
    title: "Expense Report Process"
    description: "How to submit and track expense reports"
    ---

    Your content here...
    ```
  </Step>

  <Step title="Configura los enlaces internos">
    Enlaza las páginas usando rutas desde la raíz de tu proyecto.

    ```mdx
    Consulta la [Guía de incorporación](/hr/onboarding) para la configuración de nuevos empleados.

    Si tienes preguntas, contacta al [equipo de beneficios de RR. HH.](/hr/benefits#common-questions).
    ```
  </Step>

  <Step title="Convierte HTML y otros formatos a Markdown">
    Si exportaste tu contenido como HTML, conviértelo a Markdown. Algunas herramientas que pueden ayudarte son:

    * **Pandoc**: Herramienta de línea de comandos que convierte entre muchos formatos.
    * **CloudConvert**: Convertidor en línea compatible con HTML, DOCX, PDF y más.
    * **Extensiones de VS Code**: Busca &quot;HTML to Markdown&quot; en las extensiones.
  </Step>

  <Step title="Gestiona varios formatos de contenido">
    Si tienes archivos PDF, videos u otro contenido multimedia, decide cómo incluirlos en tu base de conocimientos.

    * **Incrusta videos**: Incrusta videos o enlaza a videos alojados.
    * **Enlaza archivos PDF**: Agrega archivos PDF al repositorio de tu proyecto y enlázalos desde las páginas correspondientes.
    * **Convierte PDF a Markdown**: Si quieres que el contenido de un PDF sea una página, convierte los PDF a Markdown.
  </Step>
</Steps>

<div id="set-up-the-assistant">
  ## Configura el asistente
</div>

El asistente se habilita automáticamente en los planes Pro y Enterprise. Permite a tu equipo hacer preguntas y obtener respuestas con fuentes citadas de tu base de conocimientos.

Configura el asistente desde tu [panel de control](https://dashboard.mintlify.com/products/assistant/settings):

* **Preguntas de ejemplo**: Agrega preguntas frecuentes como &quot;cómo envío un informe de gastos&quot; o &quot;cuál es la política de vacaciones&quot; para que las personas puedan obtener respuestas con un solo clic.
* **Sitios de búsqueda**: Incluye sitios adicionales en los que el asistente pueda buscar al responder preguntas.
* **Correo electrónico de derivación**: Configura un correo electrónico de soporte para las preguntas que el asistente no pueda responder.

<div id="add-the-assistant-to-slack">
  ### Agrega el asistente a Slack
</div>

El [bot de Slack](/es/ai/slack-bot) permite que tu equipo haga preguntas al asistente sin salir de Slack. Crea un canal en el que el bot responda a cada mensaje o permite que las personas mencionen al bot con @ en cualquier canal.

<div id="enable-team-contributions">
  ## Permite que tu equipo contribuya
</div>

Una base de conocimientos se mantiene precisa cuando todos pueden actualizarla, no solo quienes la configuraron. Mintlify ofrece tres maneras para que los miembros de tu equipo contribuyan rápidamente a tu base de conocimientos.

<div id="web-editor">
  ### Editor web
</div>

El [editor web](/es/editor) permite que cualquier persona cree y edite páginas desde su navegador. Los colaboradores pueden:

* Editar páginas visualmente o en Markdown.
* Arrastrar y soltar para reorganizar la navegación.
* Subir imágenes y contenido multimedia.
* Crear ramas y pull requests para su revisión.

Es una buena opción para especialistas en la materia que conocen el contenido, pero no se sienten cómodos con flujos de trabajo basados en código.

<div id="agent">
  ### Agente
</div>

El [agente](/es/agent/quickstart) de tu panel de control crea actualizaciones de documentación a partir de indicaciones en lenguaje natural. Describe lo que quieres cambiar y el agente crea un pull request con las actualizaciones.

Por ejemplo, un miembro del equipo podría indicar &quot;añade una sección a la página de política de gastos que explique cómo enviar recibos de comidas de más de $50&quot; y copiar en la indicación la página actual de política de gastos. El agente redactaría el contenido y abriría una PR para su revisión.

<div id="capture-knowledge-from-slack">
  ### Captura conocimiento de Slack
</div>

Los equipos comparten información valiosa en Slack que a menudo nunca llega a plasmarse en la documentación. El [agente en Slack](/es/agent/slack) puede capturar ese conocimiento y convertirlo en documentación estructurada.

Cuando alguien comparte información útil en un hilo de Slack, cualquier miembro del equipo puede mencionar a `@mintlify` con instrucciones para documentarla. El agente lee la conversación, extrae la información relevante y crea una pull request. Esto resulta útil para capturar decisiones técnicas, soluciones a problemas y explicaciones de procesos mientras el contexto aún está reciente.

Por ejemplo, si tu equipo habló en un hilo sobre cómo configurar una integración nueva, podrías responder:

> @mintlify Crea una guía para configurar la integración de Acme basada en esta conversación.

El agente usa el contexto del hilo para crear documentación que capture la información clave de la conversación.

<div id="locally">
  ### En local
</div>

Cualquier persona con acceso al repositorio de tu base de conocimientos puede trabajar en local desde su editor preferido y subir los cambios a tu repositorio.

<div id="establish-maintenance-workflows">
  ## Establece flujos de trabajo de mantenimiento
</div>

Una base de conocimientos puede deteriorarse rápidamente sin mantenimiento. Configura sistemas para mantener el contenido actualizado y ayudar a tu equipo a contribuir a la base de conocimientos.

<Steps>
  <Step title="Asigna responsables de contenido">
    Designa a una persona responsable o a un equipo pequeño para cada sección. No tienen que redactar todo el contenido, pero sí se encargan de:

    * Revisar el contenido con regularidad.
    * Detectar información desactualizada.
    * Aprobar nuevas páginas en su sección.
    * Responder cuando alguien reporte errores.
  </Step>

  <Step title="Configura ciclos de revisión y verificación de contenido">
    El contenido se desactualiza con el tiempo. Establece un calendario de revisión.

    * **Contenido crítico**: Revisar cada 30 días
    * **Contenido estándar**: Revisar cada 90 días
    * **Contenido atemporal**: Revisar una vez al año

    Al revisar, comprueba:

    * ¿Los enlaces siguen siendo válidos?
    * ¿Han cambiado los sistemas o procesos?
    * ¿Los ejemplos siguen vigentes?
    * ¿Hay nueva información que debería añadirse?
  </Step>

  <Step title="Crea pautas de contribución">
    Facilita que cualquier persona pueda mejorar la base de conocimientos. Tus pautas deben cubrir:

    * **Formato**: ¿Tienes plantillas específicas o requisitos de formato?
    * **Proceso**: ¿Cómo debe alguien proponer y enviar cambios?
    * **Revisión**: ¿Quién revisa los envíos? ¿Cuál es el plazo de respuesta?
    * **Alcance**: ¿Qué tipos de contenido se incluyen?
  </Step>

  <Step title="Supervisa las métricas de uso">
    Revisa cómo tu equipo usa la base de conocimientos para priorizar el contenido e identificar áreas de mejora. Establece una periodicidad fija para revisar las métricas de uso: mensual o trimestral son buenas opciones.

    * ¿Qué artículos reciben más visitas? Invierte en mantenerlos precisos y fáciles de leer.
    * ¿Qué artículos no reciben visitas? Considera eliminarlos o mejorar su visibilidad.
    * ¿Cuál es la tasa de rebote? Si las personas se van de inmediato, es posible que el contenido no sea útil o que la navegación deba mejorarse.
  </Step>
</Steps>

<div id="next-steps">
  ## Próximos pasos
</div>

Tu base de conocimientos está lista para publicarse. Después de desplegarla:

1. Anuncia la base de conocimientos a tu equipo.
2. Supervisa el uso y los patrones de búsqueda en tus análisis.
3. Fomenta las contribuciones cuando la gente detecte lagunas.
4. Revisa y actualiza el contenido con regularidad.

Las bases de conocimientos más exitosas evolucionan en función de cómo los equipos las usan en la práctica.
