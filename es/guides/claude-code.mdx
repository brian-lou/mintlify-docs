Claude Code es una herramienta de línea de comandos basada en agentes que puede ayudarte a mantener tu documentación. Puede escribir contenido nuevo, revisar páginas existentes y mantener la documentación al día.

Puedes hacer que Claude Code comprenda tus estándares de documentación y flujos de trabajo añadiendo un archivo `CLAUDE.md` a tu proyecto y perfeccionándolo con el tiempo.

<div id="getting-started">
  ## Primeros pasos
</div>

**Requisitos previos:**

* Una suscripción activa a Claude (Pro, Max o acceso a la API)

**Configuración:**

1. Instala Claude Code:

```bash
  npm install -g @anthropic-ai/claude-code
```

2. Ve al directorio de tu documentación.
3. (Opcional) Añade a tu proyecto el archivo `CLAUDE.md` que aparece a continuación.
4. Ejecuta `claude` para empezar.


<div id="claudemd-template">
  ## Plantilla de CLAUDE.md
</div>

Guarda un archivo `CLAUDE.md` en la raíz de tu directorio de documentación para ayudar a Claude Code a entender tu proyecto. Este archivo sirve para enseñar a Claude Code tus estándares de documentación, preferencias y flujos de trabajo. Consulta [Manage Claude&#39;s memory](https://docs.anthropic.com/en/docs/claude-code/memory) en la documentación de Anthropic para obtener más información.

Copia esta plantilla de ejemplo o ajústala según las especificaciones de tu documentación:

```mdx
# Mintlify documentation

## Relación de trabajo
- Puedes cuestionar ideas; esto puede llevar a una mejor documentación. Cita fuentes y explica tu razonamiento cuando lo hagas
- SIEMPRE pide aclaraciones en lugar de hacer suposiciones
- NUNCA mientas, adivines ni inventes nada

## Contexto del proyecto
- Formato: archivos MDX con Frontmatter YAML
- Configuración: docs.json para navegación, tema y ajustes
- Componentes: Componentes de Mintlify

## Estrategia de contenido
- Documenta lo justo para el éxito del usuario: ni demasiado ni demasiado poco
- Prioriza la precisión y la usabilidad
- Haz que el contenido sea atemporal cuando sea posible
- Busca contenido existente antes de añadir algo nuevo. Evita la duplicación a menos que se haga por una razón estratégica
- Revisa los patrones existentes para mantener la coherencia
- Empieza por hacer los cambios más pequeños y razonables

## docs.json

- Consulta el [esquema de docs.json](https://mintlify.com/docs.json) al construir el archivo docs.json y la navegación del sitio

## Requisitos de Frontmatter para las páginas
- title: Título de página claro y descriptivo
- description: Resumen conciso para SEO/navegación

## Estándares de escritura
- Voz en segunda persona ("tú")
- Requisitos previos al inicio del contenido procedimental
- Prueba todos los ejemplos de código antes de publicar
- Respeta el estilo y el formato de las páginas existentes
- Incluye casos de uso tanto básicos como avanzados
- Etiquetas de idioma en todos los bloques de código
- Texto alternativo en todas las imágenes
- Rutas relativas para los enlaces internos

## Flujo de trabajo con Git
- NUNCA uses --no-verify al hacer commits
- Pregunta cómo gestionar los cambios sin confirmar antes de empezar
- Crea una nueva rama cuando no exista una rama clara para los cambios
- Haz commits con frecuencia durante el desarrollo
- NUNCA omitas ni desactives los hooks de pre-commit

## No hacer
- Omitir el Frontmatter en ningún archivo MDX
- Usar URLs absolutas para enlaces internos
- Incluir ejemplos de código sin probar
- Hacer suposiciones: siempre pide aclaraciones
```


<div id="sample-prompts">
  ## Ejemplos de prompts
</div>

Una vez que hayas configurado Claude Code, prueba estos prompts para ver cómo puede ayudarte con tareas comunes de documentación. Puedes copiar y pegar estos ejemplos directamente o adaptarlos a tus necesidades específicas.

<div id="convert-notes-to-polished-docs">
  ### Convierte notas en documentación pulida
</div>

Convierte borradores en páginas de Markdown completas, con componentes y Frontmatter.

**Ejemplo de prompt:**

```text wrap
Convert this text into a properly formatted MDX page: [paste your text here]
```


<div id="review-docs-for-consistency">
  ### Revisa la documentación para garantizar la coherencia
</div>

Obtén sugerencias para mejorar el estilo, el formato y el uso de los componentes.

**Ejemplo de prompt:**

```text wrap
Review the files in docs/ and suggest improvements for consistency and clarity
```


<div id="update-docs-when-features-change">
  ### Actualiza la documentación cuando cambien las funcionalidades
</div>

Mantén la documentación al día a medida que tu producto evoluciona.

**Ejemplo de prompt:**

```text wrap
Nuestra API ahora requiere un parámetro de versión. Actualiza los docs para incluir version=2024-01 en todos los ejemplos
```


<div id="generate-comprehensive-code-examples">
  ### Genera ejemplos de código completos
</div>

Crea ejemplos en varios lenguajes con control de errores.

**Ejemplo de prompt:**

```text wrap
Create code examples for [your API endpoint] in JavaScript, Python, and cURL with error handling
```


<div id="extending-claude-code">
  ## Extender Claude Code
</div>

Además de interactuar manualmente con Claude Code, puedes integrarlo en tus flujos de trabajo existentes.

<div id="automation-with-github-actions">
  ### Automatización con GitHub Actions
</div>

Ejecuta Claude Code automáticamente cuando haya cambios en el código para mantener la documentación actualizada. Puedes activar revisiones de la documentación en las pull requests o actualizar ejemplos cuando se detecten cambios en la API.

<div id="multi-instance-workflows">
  ### Flujos de trabajo con múltiples instancias
</div>

Usa sesiones independientes de Claude Code para distintas tareas: una para redactar contenido nuevo y otra para la revisión y el control de calidad. Esto ayuda a mantener la coherencia y a detectar problemas que una sola sesión podría pasar por alto.

<div id="team-collaboration">
  ### Colaboración en equipo
</div>

Comparte con tu equipo tu archivo `CLAUDE.md` optimizado para garantizar criterios de documentación coherentes entre todos los colaboradores. Los equipos suelen desarrollar prompt y flujos de trabajo específicos del proyecto que pasan a formar parte de su proceso de documentación.

<div id="custom-commands">
  ### Comandos personalizados
</div>

Crea comandos slash reutilizables en `.claude/commands/` para tareas de documentación frecuentes específicas de tu proyecto o equipo.
