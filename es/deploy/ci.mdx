<Info>
  Los [planes Pro y Enterprise](https://mintlify.com/pricing?ref=docs-ci) incluyen comprobaciones de CI para repositorios de GitHub.
</Info>

Usa las comprobaciones de CI para analizar tu documentación en busca de errores y mostrar advertencias antes de publicar. Las comprobaciones de CI de Mintlify se ejecutan en pull requests dirigidas a una rama de despliegue configurada.

<div id="installation">
  ## Instalación
</div>

Para empezar, sigue los pasos de la página de [GitHub](/es/deploy/github).

<Tip>
  Solo se necesita acceso al repositorio donde se encuentra el contenido de tu documentación, por lo que se recomienda encarecidamente conceder acceso únicamente a ese repositorio.
</Tip>

## Configuración

Configura las comprobaciones de CI habilitadas para un despliegue desde la página de [Add-ons](https://dashboard.mintlify.com/products/addons) de tu panel. Activa las comprobaciones que quieras ejecutar.

Al activar las comprobaciones, puedes elegir ejecutarlas con un nivel `Warning` o `Blocking`.

* Una comprobación con nivel `Warning` nunca dará un estado de fallo, incluso si hay un error o sugerencias.
* Una comprobación con nivel `Blocking` dará un estado de fallo si hay un error o sugerencias.

<div id="available-ci-checks">
  ## Comprobaciones de CI disponibles
</div>

<div id="broken-links">
  ### Enlaces rotos
</div>

Al igual que el [verificador de enlaces del CLI](/es/installation#find-broken-links) en tu máquina local, la comprobación de CI de enlaces rotos busca automáticamente enlaces internos rotos en el contenido de tu documentación.

Para ver los resultados de esta comprobación, visita la página de resultados de las comprobaciones de GitHub para un commit específico.

<div id="vale">
  ### Vale
</div>

[Vale](https://vale.sh/) es un linter de prosa de código abierto basado en reglas que admite varios tipos de documentos, incluidos Markdown y MDX. Usa Vale para comprobar la coherencia del estilo y el tono en tu documentación.

Mintlify permite ejecutar Vale automáticamente en una comprobación de CI y mostrar los resultados como estado de la comprobación.

<div id="configuration">
  #### Configuración
</div>

Si tienes un archivo `.vale.ini` en el directorio raíz del contenido de tu despliegue, la comprobación de CI de Vale usa ese archivo de configuración y cualquier otro archivo de configuración de la `stylesPath` que hayas especificado.

Si no tienes un archivo de configuración de Vale, se carga automáticamente la configuración predeterminada.

```mdx Default vale.ini configuration expandable
# Estilos de nivel superior
StylesPath = /app/styles
MinAlertLevel = suggestion
# Etiquetas HTML inline a ignorar (code/tt para fragmentos de código, img/url para enlaces/imágenes, a para etiquetas de anclaje)
IgnoredScopes = code, tt, img, url, a
SkippedScopes = script, style, pre, figure

# Vocabularios
Vocab = Mintlify

# Paquetes
Packages = MDX

# Solo coincide con MDX
[*.mdx]
BasedOnStyles = Vale
Vale.Terms = NO # Aplica reglas de capitalización muy estrictas, mantener desactivado

# Ignorar patrones de sintaxis específicos de JSX/MDX
# `import ...`, `export ...`
# `<Component ... />`
# `<Component>...</Component>`
# `{ ... }`
TokenIgnores = (?sm)((?:import|export) .+?$), \
(?<!`)(<\w+ ?.+ ?\/>)(?!`), \
(<[A-Z]\w+>.+?<\/[A-Z]\w+>)

# Excluir JSX multilínea y llaves
# `<Component \n ... />`
BlockIgnores = (?sm)^(<\w+\n .*\s\/>)$, \
(?sm)^({.+.*})
```

Para añadir tu propio vocabulario a la configuración predeterminada, crea un directorio `styles/config/vocabularies/Mintlify` con los archivos `accept.txt` y `reject.txt`.

* `accept.txt`: Palabras que el linter Vale debe ignorar. Por ejemplo, nombres de productos o términos poco frecuentes.
* `reject.txt`: Palabras que deben marcarse como errores. Por ejemplo, jerga o palabras que no se ajustan al tono de tu documentación.

```text Example Vale file structure
/your-project
  |- docs.json
  |- .vale.ini
  |- styles/
    |- config/
      |- vocabularies/
        |- Mintlify/
          |- accept.txt
          |- reject.txt
  |- example-page.mdx
```

```text Example monorepo Vale file structure
/your-monorepo
  |- main.ts
  |- docs/
    |- docs.json
    |- .vale.ini
    |- styles/
      |- config/
      |- vocabularies/
        |- Mintlify/
          |- accept.txt
          |- reject.txt
    |- example-page.mdx
  |- test/
```

<Note>
  Por motivos de seguridad, no se admiten rutas `stylesPath` absolutas ni `stylesPath` que incluyan valores `..`.

  Usa rutas relativas e incluye `stylesPath` en tu repositorio.
</Note>

<div id="packages">
  #### Paquetes
</div>

Vale admite una variedad de [paquetes](https://vale.sh/docs/keys/packages) que pueden usarse para detectar errores de ortografía y estilo. Todos los paquetes que incluyas en tu repositorio en la ruta `stylesPath` correcta se instalan automáticamente y se usan en tu configuración de Vale.

En el caso de los paquetes que no estén incluidos en tu repositorio, puedes especificar cualquiera de los paquetes del [registro de paquetes de Vale](https://vale.sh/explorer), y se descargarán automáticamente para usarse en tu configuración de Vale.

<Note>
  Por motivos de seguridad, **no** se admite la descarga automática de paquetes que no provengan del [registro de paquetes de Vale](https://vale.sh/explorer).
</Note>

<div id="vale-with-mdx">
  #### Vale con `MDX`
</div>

<Note>
  La compatibilidad nativa con MDX requiere Vale 3.10.0 o una versión posterior. Comprueba tu versión de Vale con `vale --version`.
</Note>

Para usar los comentarios de Vale dentro del documento en archivos MDX, utiliza comentarios de estilo MDX `{/* ... */}`:

```mdx
{/* vale off */}

This text is ignored by Vale

{/* vale on */}
```

Vale reconoce y respeta automáticamente estos comentarios en archivos MDX sin necesidad de configuración adicional. Usa comentarios para omitir líneas o secciones que el linter deba ignorar.
