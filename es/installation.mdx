Usa la [CLI](https://www.npmjs.com/package/mint) para obtener una vista previa local de tu documentación mientras escribes y editas. Revisa los cambios en tiempo real antes de desplegar, prueba el aspecto y el funcionamiento de tu sitio de documentación, y detecta problemas como enlaces rotos o fallos de accesibilidad.

La CLI también incluye utilidades para mantener tu documentación, como comandos para renombrar archivos, validar especificaciones OpenAPI y migrar contenido entre formatos.

<div id="prerequisites">
  ## Requisitos previos
</div>

* [Node.js](https://nodejs.org/en) v20.17.0+ instalado (se recomiendan las versiones LTS)
* [Git](https://git-scm.com/downloads) instalado
* Tu repositorio de documentación clonado en local

<div id="clone-your-repository">
  ### Clona tu repositorio
</div>

<Steps>
  <Step title="Ubica tu repositorio">
    1. Ve a la página de [Configuración de Git](https://dashboard.mintlify.com/settings/deployment/git-settings) de tu panel de control.
    2. Anota la ubicación de tu repositorio. Tendrá uno de estos formatos:

    * `mintlify-community/docs-{org-name}-{id}` (repositorio alojado en Mintlify)
    * `your-org/your-repo` (tu propio repositorio de GitHub)
  </Step>

  <Step title="Clona tu repositorio">
    <Tabs>
      <Tab title="Tu propio repositorio">
        Reemplaza `your-org/your-repo` con los datos reales de tu repositorio que aparecen en [Configuración de Git](https://dashboard.mintlify.com/settings/deployment/git-settings).

        ```bash
        git clone https://github.com/your-org/your-repo
        cd your-repo
        ```

        <Tip>
          **Se requiere la app de GitHub.** Para habilitar los despliegues automáticos cuando subas cambios, debes instalar la app de GitHub. Consulta [GitHub](/es/deploy/github) para obtener más información.
        </Tip>
      </Tab>

      <Tab title="Repositorio alojado en Mintlify">
        Puedes clonar tu repositorio como privado o público. Los repositorios públicos son visibles para cualquier persona que acceda a la URL del repositorio. Los repositorios privados solo son visibles para las personas de tu organización.

        En la página de [Configuración de Git](https://dashboard.mintlify.com/settings/deployment/git-settings) de tu panel de control, selecciona **Clonar como privado** o **Clonar como público**.
      </Tab>
    </Tabs>
  </Step>
</Steps>

<div id="install-the-cli">
  ## Instala la CLI
</div>

Ejecuta el siguiente comando para instalar la CLI:

<CodeGroup>
  ```bash npm
  npm i -g mint
  ```

  ```bash pnpm
  pnpm add -g mint
  ```
</CodeGroup>

<div id="preview-locally">
  ## Vista previa en local
</div>

Ve al directorio de la documentación que contiene tu archivo `docs.json` y ejecuta:

```bash
mint dev
```

Tienes disponible una vista previa local de tu documentación en `http://localhost:3000`.

Como alternativa, si no quieres instalar la CLI de forma global, puedes ejecutar un script puntual:

```bash
npx mint dev
```

<div id="custom-ports">
  ### Puertos personalizados
</div>

De forma predeterminada, la CLI usa el puerto 3000. Puedes cambiarlo con la opción `--port`. Para ejecutar la CLI en el puerto 3333, por ejemplo, usa este comando:

```bash
mint dev --port 3333
```

Si intentas ejecutarlo en un puerto que ya está en uso, la CLI usa el siguiente puerto disponible:

```mdx
Port 3000 is already in use. Trying 3001 instead.
```

<div id="skip-openapi-processing">
  ## Omitir el procesamiento de OpenAPI
</div>

Si tienes muchos archivos OpenAPI, omite su procesamiento durante el desarrollo local para mejorar el rendimiento con la opción `--disable-openapi`:

```bash
mint dev --disable-openapi
```

<div id="preview-as-a-specific-group">
  ### Vista previa como un grupo específico
</div>

Si usas control de acceso basado en grupos para restringir el acceso a tu documentación, puedes previsualizarla como un grupo de autenticación específico con la opción `--groups [groupname]`.

Por ejemplo, si tienes un grupo llamado `admin`, puedes previsualizarla como miembro de ese grupo con el comando:

```bash
mint dev --groups admin
```

<div id="create-a-new-project">
  ## Crear un proyecto nuevo
</div>

Para crear un proyecto nuevo de documentación, ejecuta el siguiente comando:

```bash
mint new [directory]
```

Este comando clona el [kit de inicio](https://github.com/mintlify/starter) en el directorio que especifiques. Si no especificas ningún directorio, la herramienta de línea de comandos te pedirá que crees un subdirectorio nuevo o que sobrescribas el directorio actual.

<Warning>
  Si sobrescribes el directorio actual, se eliminarán todos los archivos existentes.
</Warning>

La herramienta de línea de comandos te pedirá un nombre para el proyecto y un [tema](/es/customize/themes) para terminar de configurarlo.

<div id="flags">
  ### Opciones
</div>

| Opción    | Descripción                                                                                       | Obligatoria |
| --------- | ------------------------------------------------------------------------------------------------- | ----------- |
| `--name`  | Establece el nombre del nuevo proyecto.                                                           | Sí          |
| `--theme` | Establece el [tema](/es/customize/themes) del nuevo proyecto.                                        | Sí          |
| `--force` | Sobrescribe el directorio actual sin pedir confirmación, incluso si contiene archivos existentes. | No          |

Al ejecutar `mint new` en entornos no interactivos, como canales de CI/CD o con agentes de IA para programar, debes proporcionar todas las opciones obligatorias (`--name` y `--theme`).

<Tip>
  La CLI detecta automáticamente los entornos no interactivos. Si faltan opciones obligatorias, muestra las instrucciones de uso en lugar de quedarse esperando entradas.
</Tip>

<div id="update-the-cli">
  ## Actualiza la CLI
</div>

Si tu vista previa local no coincide con lo que ves en la versión de producción en la web, actualiza tu CLI local:

```bash
mint update
```

Si el comando `mint update` no está disponible en tu versión local, vuelve a instalar la CLI con la versión más reciente:

<CodeGroup>
  ```bash npm
  npm i -g mint@latest
  ```

  ```bash pnpm
  pnpm add -g mint@latest
  ```
</CodeGroup>

<div id="additional-commands">
  ## Comandos adicionales
</div>

<div id="find-broken-links">
  ### Encontrar enlaces rotos
</div>

Identifica los enlaces internos rotos con el siguiente comando:

```bash
mint broken-links
```

El comando ignora los archivos que coinciden con los patrones de [.mintignore](/es/organize/mintignore). Los enlaces que apuntan a archivos ignorados se marcan como rotos.

<div id="find-accessibility-issues">
  ### Encontrar problemas de accesibilidad
</div>

Comprueba las relaciones de contraste de color y busca texto alternativo faltante en las imágenes y los videos de tu documentación con el siguiente comando:

```bash
mint a11y
```

Usa opciones para comprobar problemas específicos de accesibilidad.

```bash
# Verificar solo el texto alternativo faltante
mint a11y --skip-contrast

# Verificar solo los problemas de contraste de color
mint a11y --skip-alt-text
```

<div id="validate-documentation-build">
  ### Validar la compilación de la documentación
</div>

Valida la compilación de tu documentación en modo estricto; el proceso finalizará con un error si hay alguna advertencia o error. Usa este comando en canalizaciones de CI/CD para evitar implementar documentación con errores.

```bash
mint validate
```

Usa estas opciones para configurar el comando de validación.

* `--groups [groupname]`: Simula grupos de usuarios para la validación (útil al probar el control de acceso basado en grupos)
* `--disable-openapi`: Desactiva la generación de archivos OpenAPI durante la validación

<div id="check-openapi-spec">
  ### Comprueba la especificación OpenAPI
</div>

Comprueba si tu archivo OpenAPI tiene errores con el siguiente comando:

```bash
mint openapi-check <OpenAPI filename or URL>
```

Indica un nombre de archivo (por ejemplo, `./openapi.yaml`) o una URL (por ejemplo, `https://petstore3.swagger.io/api/v3/openapi.json`).

<div id="rename-files">
  ### Renombrar archivos
</div>

Cambia el nombre de los archivos y actualiza todas sus referencias con el siguiente comando:

```bash
mint rename <path/to/old-filename> <path/to/new-filename>
```

<div id="migrate-mdx-endpoint-pages">
  ### Migra las páginas de endpoints en MDX
</div>

Migra las páginas de endpoints en MDX a páginas generadas automáticamente a partir de tu especificación OpenAPI con el siguiente comando:

```bash
mint migrate-mdx
```

Este comando convierte páginas MDX individuales de endpoints en páginas autogeneradas definidas en tu `docs.json`, mueve el contenido de MDX a la extensión `x-mint` de tu especificación OpenAPI y actualiza tu navegación. Consulta [Migración desde MDX](/es/guides/migrating-from-mdx) para obtener información detallada.

<div id="formatting">
  ## Formato
</div>

Mientras desarrollas en local, te recomendamos usar extensiones en tu IDE para reconocer y dar formato a archivos MDX.

Si usas Cursor, Windsurf o VS Code, te recomendamos la [extensión MDX para VS Code](https://marketplace.visualstudio.com/items?itemName=unifiedjs.vscode-mdx) para el resaltado de sintaxis y [Prettier](https://marketplace.visualstudio.com/items?itemName=esbenp.prettier-vscode) para dar formato al código.

Si usas JetBrains, te recomendamos el [plugin MDX para IntelliJ IDEA](https://plugins.jetbrains.com/plugin/14944-mdx) para el resaltado de sintaxis y configurar [Prettier](https://prettier.io/docs/webstorm) para dar formato al código.

<div id="troubleshooting">
  ## Solución de problemas
</div>

<AccordionGroup>
  <Accordion title="Error: No se pudo cargar el módulo &#x22;sharp&#x22; con el entorno de ejecución darwin-arm64">
    Esto puede deberse a una versión desactualizada de Node.js. Prueba lo siguiente:

    1. Elimina la versión instalada actualmente de la CLI de mint: `npm uninstall -g mint`
    2. Actualiza a Node.js v20.17.0 o posterior.
    3. Vuelve a instalar la CLI de mint: `npm install -g mint`
  </Accordion>

  <Accordion title="Problema: aparece un error desconocido">
    **Solución**: Ve a la raíz de tu equipo y elimina la carpeta `~/.mintlify`. Después, ejecuta `mint dev` de nuevo.
  </Accordion>

  <Accordion title="Error: permiso denegado">
    Esto se debe a que no tienes los permisos necesarios para instalar paquetes de Node globalmente.

    **Solución**: Prueba a ejecutar `sudo npm i -g mint`. Se te pedirá la contraseña que usas para desbloquear tu equipo.
  </Accordion>

  <Accordion title="La vista previa local no se ve igual que mi documentación en la web">
    Esto probablemente se deba a una versión desactualizada de la CLI.

    **Solución:** Ejecuta `mint update` para obtener los cambios más recientes.
  </Accordion>

  <Accordion title="paquete mintlify vs. mint">
    Si tienes algún problema con el paquete de la CLI, primero debes ejecutar `npm ls -g`. Este comando muestra qué paquetes están instalados globalmente en tu equipo.

    Si no usas npm o no aparece en la lista de `-g`, prueba `which mint` para localizar la instalación.

    Si tienes instalado un paquete llamado `mint` y otro llamado `mintlify`, debes desinstalar `mintlify`.

    1. Desinstala el paquete antiguo:

    ```bash
      npm uninstall -g mintlify
    ```

    2. Borra la caché de npm:

    ```bash
      npm cache clean --force
    ```

    3. Vuelve a instalar el paquete nuevo:

    ```bash
    npm i -g mint
    ```
  </Accordion>

  <Accordion title="La versión del cliente muestra 'none' después de la instalación">
    Si ejecutas `mint version` y la versión del cliente se muestra como `none`, es posible que la CLI no pueda descargar la aplicación cliente debido a un firewall corporativo o a una VPN que bloquea la descarga.

    **Solución:** Pídele a tu administrador de TI que añada `releases.mintlify.com` a la lista blanca para habilitar el desarrollo local con la CLI.
  </Accordion>
</AccordionGroup>
