Usa la [CLI](https://www.npmjs.com/package/mint) para previsualizar tu documentación localmente mientras escribes y editas. Visualiza los cambios en tiempo real antes de desplegar, prueba la apariencia y funcionalidad de tu sitio de documentación y detecta problemas como enlaces rotos o problemas de accesibilidad.

La CLI también incluye utilidades para mantener tu documentación, incluyendo comandos para renombrar archivos, validar especificaciones OpenAPI y migrar contenido entre formatos.

<div id="prerequisites">
  ## Requisitos previos
</div>

* [Node.js](https://nodejs.org/en) v20.17.0+ instalado (se recomiendan las versiones LTS)
* [Git](https://git-scm.com/downloads) instalado
* Tu repositorio de documentación clonado localmente

<div id="clone-your-repository">
  ### Clona tu repositorio
</div>

<Steps>
  <Step title="Ubica tu repositorio">
    1. Ve a la página de [Git settings](https://dashboard.mintlify.com/settings/deployment/git-settings) en tu panel.
    2. Anota la ubicación de tu repositorio. Será uno de estos formatos:

    * `mintlify-community/docs-{org-name}-{id}` (repositorio alojado en Mintlify)
    * `your-org/your-repo` (tu propio repositorio de GitHub)
  </Step>

  <Step title="Clona tu repositorio">
    <Tabs>
      <Tab title="Tu propio repositorio">
        Reemplaza `your-org/your-repo` con los detalles reales de tu repositorio que aparecen en [Git settings](https://dashboard.mintlify.com/settings/deployment/git-settings).

        ```bash
        git clone https://github.com/your-org/your-repo
        cd your-repo
        ```

        <Tip>
          **Se requiere la aplicación de GitHub.** Para habilitar los despliegues automáticos cuando hagas push de cambios, debes instalar la aplicación de GitHub. Consulta [GitHub](/es/deploy/github) para obtener más información.
        </Tip>
      </Tab>

      <Tab title="Repositorio alojado en Mintlify">
        Puedes clonar tu repositorio como un repositorio privado o público. Los repositorios públicos son visibles para cualquier persona que acceda a la URL del repositorio. Los repositorios privados solo son visibles para las personas de tu organización.

        En la página de [Git settings](https://dashboard.mintlify.com/settings/deployment/git-settings) de tu panel, selecciona **Clone as private** o **Clone as public**.
      </Tab>
    </Tabs>
  </Step>
</Steps>

<div id="install-the-cli">
  ## Instalar la CLI
</div>

Ejecuta uno de los siguientes comandos para instalar la CLI:

<CodeGroup>
  ```bash npm
  npm i -g mint
  ```

  ```bash pnpm
  pnpm add -g mint
  ```
</CodeGroup>

<div id="preview-locally">
  ## Vista previa local
</div>

Ve al directorio de tu documentación que contiene el archivo `docs.json` y ejecuta:

```bash
mint dev
```

Una vista previa local de tu documentación está disponible en `http://localhost:3000`.

Si prefieres no instalar la CLI globalmente, puedes ejecutar un script de una sola ejecución:

```bash
npx mint dev
```

<div id="custom-ports">
  ### Puertos personalizados
</div>

Por defecto, la CLI utiliza el puerto 3000. Puedes cambiarlo mediante la opción `--port`. Para ejecutar la CLI en el puerto 3333, por ejemplo, usa este comando:

```bash
mint dev --port 3333
```

Si intentas utilizar un puerto que ya está en uso, la CLI usará el siguiente puerto disponible:

```mdx
Port 3000 is already in use. Trying 3001 instead.
```

<div id="skip-openapi-processing">
  ## Omitir el procesamiento de OpenAPI
</div>

Si tienes muchos archivos de OpenAPI, puedes omitir su procesamiento durante el desarrollo local para mejorar el rendimiento usando la opción `--disable-openapi`:

```bash
mint dev --disable-openapi
```

<div id="preview-as-a-specific-group">
  ### Vista previa como un grupo específico
</div>

Si utilizas control de acceso basado en grupos para restringir el acceso a tu documentación, puedes obtener una vista previa como un grupo de autenticación específico usando la opción `--groups [groupname]`.

Por ejemplo, si tienes un grupo llamado `admin`, puedes obtener una vista previa como miembro de ese grupo con el comando:

```bash
mint dev --groups admin
```

<div id="create-a-new-project">
  ## Crear un nuevo proyecto
</div>

Para crear un nuevo proyecto de documentación, ejecuta el siguiente comando:

```bash
mint new [directory]
```

Este comando clona el [starter kit](https://github.com/mintlify/starter) en el directorio que indiques. Si no especificas un directorio, la herramienta de línea de comandos (CLI) te pedirá crear un nuevo subdirectorio o sobrescribir el directorio actual.

<Warning>
  Sobrescribir el directorio actual elimina cualquier archivo existente.
</Warning>

La herramienta CLI te pedirá un nombre de proyecto y un [tema](/es/customize/themes) para finalizar la configuración de tu proyecto.

<div id="flags">
  ### Flags
</div>

| Flag | Descripción | Obligatorio |
| --- | --- | --- |
| `--name` | Establece el nombre del nuevo proyecto. | Sí |
| `--theme` | Establece el [tema](/es/customize/themes) del nuevo proyecto. | Sí |
| `--force` | Sobrescribe el directorio actual sin preguntar, incluso si contiene archivos existentes. | No |

Al ejecutar `mint new` en entornos no interactivos como pipelines de CI/CD o con agentes de programación con IA, debes proporcionar todos los flags obligatorios (`--name` y `--theme`).

<Tip>
  La CLI detecta automáticamente los entornos no interactivos. Si faltan flags obligatorios, muestra instrucciones de uso en lugar de quedarse bloqueada esperando respuestas a los prompts.
</Tip>

<div id="update-the-cli">
  ## Actualizar la CLI
</div>

Si la vista previa local no coincide con lo que ves en la versión de producción en la web, actualiza tu CLI local:

```bash
mint update
```

Si este comando `mint update` no está disponible en tu versión local, vuelve a instalar la CLI con la versión más reciente:

<CodeGroup>
  ```bash npm
  npm i -g mint@latest
  ```

  ```bash pnpm
  pnpm add -g mint@latest
  ```
</CodeGroup>

<div id="additional-commands">
  ## Comandos adicionales
</div>

<div id="find-broken-links">
  ### Buscar enlaces rotos
</div>

Identifica cualquier enlace interno roto con el siguiente comando:

```bash
mint broken-links
```

El comando ignora los archivos que coinciden con los patrones de [.mintignore](/es/organize/mintignore). Los enlaces que apuntan a archivos ignorados se marcan como rotos.

<div id="find-accessibility-issues">
  ### Detectar problemas de accesibilidad
</div>

Comprueba las relaciones de contraste de color y busca texto alternativo que falte en las imágenes y los videos de tu documentación con el siguiente comando:

```bash
mint a11y
```

Usa flags para comprobar problemas específicos de accesibilidad.

```bash
# Verificar solo el texto alternativo faltante
mint a11y --skip-contrast

# Verificar solo los problemas de contraste de color
mint a11y --skip-alt-text
```

<div id="validate-documentation-build">
  ### Validar compilación de la documentación
</div>

Valida la compilación de tu documentación en modo estricto, que finaliza con un error si hay alguna advertencia o error. Usa este comando en pipelines de CI/CD para evitar implementaciones de documentación con errores.

```bash
mint validate
```

Utiliza flags para configurar el comando de validación.

* `--groups [groupname]`: Simula grupos de usuarios para la validación (útil al probar el control de acceso basado en grupos)
* `--disable-openapi`: Desactiva la generación del archivo OpenAPI durante la validación

<div id="check-openapi-spec">
  ### Comprobar la especificación de OpenAPI
</div>

Comprueba si tu archivo de OpenAPI contiene errores con el siguiente comando:

```bash
mint openapi-check <OpenAPI filename or URL>
```

Especifica un nombre de archivo (por ejemplo, `./openapi.yaml`) o una URL (por ejemplo, `https://petstore3.swagger.io/api/v3/openapi.json`).

<div id="rename-files">
  ### Renombrar archivos
</div>

Renombra y actualiza todas las referencias a los archivos con el siguiente comando:

```bash
mint rename <path/to/old-filename> <path/to/new-filename>
```

<div id="migrate-mdx-endpoint-pages">
  ### Migrar páginas de endpoints MDX
</div>

Migra las páginas de endpoints MDX a páginas generadas automáticamente a partir de tu especificación OpenAPI con el siguiente comando:

```bash
mint migrate-mdx
```

Este comando convierte las páginas de endpoints individuales en MDX en páginas autogeneradas definidas en tu `docs.json`, mueve el contenido MDX a la extensión `x-mint` en tu especificación OpenAPI y actualiza tu menú de navegación. Consulta [Migrating from MDX](/es/guides/migrating-from-mdx) para obtener información detallada.

<div id="formatting">
  ## Formato
</div>

Al desarrollar en local, recomendamos usar extensiones en tu IDE para reconocer y dar formato a archivos MDX.

Si usas Cursor, Windsurf o VS Code, recomendamos la [extensión MDX para VS Code](https://marketplace.visualstudio.com/items?itemName=unifiedjs.vscode-mdx) para el resaltado de sintaxis y [Prettier](https://marketplace.visualstudio.com/items?itemName=esbenp.prettier-vscode) para el formateo de código.

Si usas JetBrains, recomendamos el [complemento MDX para IntelliJ IDEA](https://plugins.jetbrains.com/plugin/14944-mdx) para el resaltado de sintaxis y configurar [Prettier](https://prettier.io/docs/webstorm) para el formateo de código.

<div id="troubleshooting">
  ## Solución de problemas
</div>

<AccordionGroup>
  <Accordion title="Error: No se pudo cargar el módulo &#x22;sharp&#x22; con el runtime darwin-arm64">
    Esto puede deberse a una versión desactualizada de Node.js. Prueba lo siguiente:

    1. Elimina la versión de la CLI de mint que tienes instalada actualmente: `npm uninstall -g mint`
    2. Actualiza a Node.js v20.17.0 o superior.
    3. Vuelve a instalar la CLI de mint: `npm install -g mint`
  </Accordion>

  <Accordion title="Problema: aparece un error desconocido">
    **Solución**: Ve al directorio raíz de tu dispositivo y elimina la carpeta `~/.mintlify`. Después, ejecuta `mint dev` de nuevo.
  </Accordion>

  <Accordion title="Error: permission denied">
    Esto se debe a que no tienes los permisos necesarios para instalar paquetes de Node.js de forma global.

    **Solución**: Intenta ejecutar `sudo npm i -g mint`. Se te pedirá tu contraseña, que es la que usas para desbloquear tu computadora.
  </Accordion>

  <Accordion title="La vista previa local no se ve igual que mis documentos en la web">
    Es probable que esto se deba a una versión desactualizada de la CLI.

    **Solución:** Ejecuta `mint update` para obtener los cambios más recientes.
  </Accordion>

  <Accordion title="mintlify vs. paquete mint">
    Si tienes algún problema con el paquete de la CLI, primero deberías ejecutar `npm ls -g`. Este comando muestra qué paquetes están instalados globalmente en tu máquina.

    Si no usas npm o no lo ves en la lista con -g, prueba con `which mint` para localizar la instalación.

    Si tienes un paquete llamado `mint` y un paquete llamado `mintlify` instalados, deberías desinstalar `mintlify`.

    1. Desinstala el paquete antiguo:

    ```bash
      npm uninstall -g mintlify
    ```

    2. Limpia la caché de npm:

    ```bash
      npm cache clean --force
    ```

    3. Vuelve a instalar el paquete nuevo:

    ```bash
    npm i -g mint
    ```
  </Accordion>

  <Accordion title="La versión del cliente muestra 'none' después de la instalación">
    Si ejecutas `mint version` y la versión del cliente aparece como `none`, es posible que la CLI no pueda descargar la aplicación de cliente porque un firewall corporativo o una VPN están bloqueando la descarga.

    **Solución:** Pídele a tu administrador de TI que permita el dominio `releases.mintlify.com` para habilitar el desarrollo local con la CLI.
  </Accordion>
</AccordionGroup>
