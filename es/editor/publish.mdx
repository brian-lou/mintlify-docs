<div id="publishing-workflows">
  ## Flujos de trabajo de publicación
</div>

El editor admite dos flujos de trabajo para publicar actualizaciones de la documentación. El flujo de trabajo que uses depende de las reglas de protección de ramas de tu repositorio y de la rama en la que trabajes.

* **Crear pull requests**: Si tu repositorio tiene una regla de protección de ramas que exige pull requests antes de que los cambios puedan fusionarse en tu rama de despliegue, el editor crea un pull request cuando publicas cambios.
* **Publicar directamente**: Si tu repositorio no tiene reglas de protección de ramas, tus cambios se fusionan en la rama de despliegue y se despliegan de inmediato cuando publicas.

| Tipo de rama                                                                                                                                                                              | Protección de rama         | Flujo de trabajo de publicación                              |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------- | ------------------------------------------------------------ |
| <Tooltip headline="Rama de despliegue" tip="La rama que publica tu sitio de documentación en producción, normalmente 'main'.">Rama de despliegue</Tooltip>                                | Ninguna                    | Hace commit y despliega los cambios                          |
| Rama de despliegue                                                                                                                                                                        | Se requieren pull requests | Crea un pull request                                         |
| <Tooltip headline="Rama de funcionalidad" tip="Una rama aislada en la que trabajas en las actualizaciones antes de fusionarlas en tu rama de despliegue.">Rama de funcionalidad</Tooltip> | Ninguna                    | Fusiona los cambios en la rama de despliegue y los despliega |
| Rama de funcionalidad                                                                                                                                                                     | Se requieren pull requests | Crea un pull request                                         |

<Tip>
  Configura reglas de protección de ramas en tu proveedor de Git para exigir pull requests. Consulta [About protected branches](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches) en la documentación de GitHub o [Protected branches](https://docs.gitlab.com/user/project/repository/branches/protected/) en la documentación de GitLab.
</Tip>

<div id="save-changes">
  ## Guardar cambios
</div>

Mientras editas, el editor registra tus cambios.

* Archivos nuevos o eliminados.
* Ediciones de contenido en las páginas.
* Cambios en la estructura de navegación.
* Subidas y organización de contenido multimedia.
* Actualizaciones de configuración.

Cuando trabajas en tu rama de despliegue, tus cambios se guardan automáticamente.

Para descartar cambios, haz clic en **Deshacer cambios** junto al nombre de un archivo en el menú desplegable **Cambios**.

<div id="publish-your-changes">
  ### Publica tus cambios
</div>

Haz clic en **Publicar** en la barra de herramientas. Según tu flujo de trabajo, tus cambios se implementan de inmediato o se crea una pull request para que la combines en tu proveedor de Git. Si estás en una rama de funcionalidad, guarda tus cambios antes de publicar.

El botón **Publicar** se desactiva cuando no hay cambios pendientes o cuando ya hay una pull request abierta para la rama actual.

## Resolver conflictos

Los conflictos se producen cuando tu rama y la rama de despliegue tienen cambios incompatibles en los mismos archivos.

<div id="what-causes-conflicts">
  ### Qué causa los conflictos
</div>

Los conflictos se producen cuando:

* Tú y otro miembro del equipo editáis las mismas líneas de un archivo.
* En una rama se mueven o eliminan archivos, pero en otra se modifican.

<div id="resolve-conflicts">
  ### Resolver conflictos
</div>

El editor muestra advertencias cuando los conflictos impiden realizar operaciones como publicar o cambiar de rama. Para resolverlos, sigue las instrucciones del editor para elegir qué cambios quieres conservar.

<div id="commit-signing">
  ## Firma de commits
</div>

Firma los commits con tu cuenta de GitHub autorizándola en la [configuración de tu cuenta](https://dashboard.mintlify.com/settings/account). Si no la autorizas, la aplicación de GitHub de Mintlify firmará los commits realizados en el editor web.

Atribuir los commits a tu cuenta mantiene un registro preciso de quién hizo cambios en tu documentación.
