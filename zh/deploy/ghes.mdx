本指南将引导你在 GitHub Enterprise Server (GHES) 安装环境中设置 Mintlify GitHub App。要将 GHES 实例连接到 Mintlify，你必须在自托管环境中创建我们应用的本地版本，使其能够与我们的远程服务器通信。

如果你使用的是云托管的 GitHub 实例，请参阅 [GitHub](/zh/deploy/github) 页面了解设置说明。

<div id="prerequisites">
  ## 先决条件
</div>

* 在要安装该应用的 GitHub Enterprise Server 组织中拥有管理员权限
* 可以访问要安装该应用的组织仓库
* 具备可与我们的外部服务通信的网络连接 (请参阅下方的[网络要求](#network-requirements)部分)

<div id="network-requirements">
  ### 网络要求
</div>

<div id="outbound-connectivity">
  #### 出站网络连接
</div>

你的 GitHub Enterprise Server 必须能够访问以下目标：

* Mintlify 的 API 端点 (https://leaves.mintlify.com)
* Webhook 接收端 (端口 443)

<div id="firewall-configuration">
  #### 防火墙配置
</div>

必须放行以下出站连接：

* 来自 Mintlify 静态 IP 的连接：`54.242.90.151`
* 访问 Mintlify 服务域名的 HTTPS (端口 443)
* 对 Mintlify 服务域名进行 DNS 解析

<div id="step-1-register-the-github-app">
  ## 第 1 步：注册 GitHub App
</div>

有关详细说明，请参阅 GitHub 文档中的 [注册 GitHub App](https://docs.github.com/en/enterprise-server@3.18/apps/creating-github-apps/registering-a-github-app/registering-a-github-app)。

<Steps>
  <Step title="前往组织设置">
    1. 在 GitHub 任意页面的右上角，点击你的个人头像。
    2. 点击 **Your organizations**。
    3. 点击你想为其创建应用的组织旁边的 **设置**。
  </Step>

  <Step title="创建新的 GitHub App">
    1. 在左侧边栏中，点击 **Developer settings**。
    2. 点击 **GitHub Apps**。
    3. 点击 **New GitHub App**。
  </Step>

  <Step title="配置应用的基本信息">
    设置以下内容：

    * **GitHub App name:** `Mintlify`
    * **Description:** `与 Mintlify 服务集成`
    * **Homepage URL:** `https://mintlify.com`
    * **User authorization callback URL:** `https://your-github-server.com/` (替换为你的实际 GHES 域名)
  </Step>
</Steps>

<div id="step-2-configure-app-permissions">
  ## 第 2 步：配置应用权限
</div>

<Steps>
  <Step title="设置仓库权限">
    为该应用设置以下权限。无需任何 Organization、Account 或 Enterprise 权限：

    * **Checks:** Read and write
    * **Contents:** Read and write
    * **Deployments:** Read and write
    * **Metadata:** Read-only
    * **Pull Requests:** Read and write
  </Step>

  <Step title="订阅事件">
    选择以下 webhook 事件：

    * Installation
    * Installation Target
    * Create
    * Delete
    * Public
    * Pull Request
    * Push
    * Repository
  </Step>
</Steps>

<div id="step-3-generate-and-secure-credentials">
  ## 第 3 步：生成并妥善保管凭据
</div>

<Steps>
  <Step title="创建应用">
    点击 **Create GitHub App**。

    系统会将你重定向到该应用的设置页面。
  </Step>

  <Step title="生成私钥">
    1. 向下滚动到 **Private keys** 部分。
    2. 点击 **Generate a private key**。
    3. 下载 `.pem` 文件并妥善保管。
  </Step>

  <Step title="记录应用凭据">
    记录以下信息：

    * **App ID** (显示在设置页面顶部)
    * **Client ID** (位于 “About” 部分)
    * **Client Secret** (生成后请妥善保管)
  </Step>
</Steps>

<div id="step-4-install-the-app">
  ## 第 4 步：安装应用
</div>

<Steps>
  <Step title="进入应用安装页面">
    1. 在应用设置页面中，点击左侧边栏中的 **Install App**。
    2. 从列表中选择你的组织。
  </Step>

  <Step title="选择安装范围">
    选择以下任一项：

    * **All repositories** (可访问整个组织的所有仓库)
    * **Only select repositories** (选择特定仓库)

    <Tip>
      建议选择“Only select repositories”，将应用权限仅限于存放文档的仓库。
    </Tip>
  </Step>

  <Step title="完成安装">
    1. 点击 **Install**。
    2. 记下 URL 中的安装 ID。例如，在 `https://your-github-server.com/settings/installations/12345` 中，`12345` 就是安装 ID。
  </Step>
</Steps>

<div id="step-5-configure-webhook-url">
  ## 第 5 步：配置 Webhook URL
</div>

<Steps>
  <Step title="返回应用设置">
    1. 返回应用的设置页面。
    2. 滚动到 **Webhook** 部分。
  </Step>

  <Step title="设置 Webhook URL">
    配置以下内容：

    * **Webhook URL：** `https://leaves.mintlify.com/github-enterprise/:subdomain` (将 `:subdomain` 替换为我们提供给你的 URL)
    * **Webhook secret：** 生成一个随机字符串 (32 个字符以上) ，并妥善保存。Mintlify 也可以帮你生成并提供给你。
  </Step>
</Steps>

<div id="share-credentials-with-us">
  ## 向我们提供凭据
</div>

请通过你选择的安全信息传输方式，向我们的团队提供以下信息。

<div id="required-credentials">
  ### 必填凭据
</div>

* GitHub Enterprise Server 基础 URL：https://your-github-server.com
* App ID： (来自第 3 步)
* App client ID： (来自第 3 步)
* App client secret： (来自第 3 步)
* Installation ID： (来自第 4 步)
* 私钥：`.pem` 文件中的完整内容 (应通过安全的文件传输方式共享)
* Webhook secret： (来自第 5 步)

<div id="optional-credentials-for-troubleshooting">
  ### 用于故障排查的可选信息
</div>

* 组织名称：你的 GitHub 组织名称
* 仓库名称：安装了该应用的特定仓库
* GitHub Enterprise Server 版本：可在你的网站管理员控制面板中找到

<div id="mintlify-connection">
  ## Mintlify 连接
</div>

我们会接收您提供的凭据，并将其加密后安全存储。然后，我们会与您协作，完成以下其中一项：

* 将您的 GHES 环境与现有的 Mintlify 部署集成。
* 将您的 GHES 环境与我们为您预配的全新 Mintlify 部署集成。

在您的 GHES 环境与 Mintlify 部署集成完成后，您就可以为您的 GitHub App 启用 webhook 了。

<Note>
  webhook URL 可能会因我们的配置而发生变化。我们会测试集成，并向您提供新的 URL。
</Note>

<div id="test-the-integration">
  ## 测试集成
</div>

<Steps>
  <Step title="验证 webhook 投递">
    1. 前往 GitHub App 的设置页面。
    2. 点击 **Advanced** 标签页。
    3. 检查“Recent Deliveries”中是否有成功的 webhook 投递记录。
    4. 确认返回了 HTTP 200 响应。
  </Step>

  <Step title="测试仓库访问权限">
    1. 在已安装的仓库中创建一个测试 issue 或 pull request。
    2. 确认 Mintlify 是否做出了正确响应。
  </Step>
</Steps>

<div id="faq-and-troubleshooting">
  ## 常见问题与故障排查
</div>

<AccordionGroup>
  <Accordion title="应用安装因权限错误而失败。">
    请确保你具备：

    * 创建应用所需的站点管理员权限
    * 安装应用所需的组织所有者或管理员权限。
    * 如果安装到特定仓库，还需具备相应的仓库权限。
  </Accordion>

  <Accordion title="Webhook 未成功送达">
    * 确认 webhook URL 正确且可访问。
    * 确保你的防火墙允许出站 HTTPS 连接。
    * 检查 webhook 密钥是否与配置时设置的一致。
    * 在 GitHub App 设置的“Advanced”标签页中查看 webhook 投递日志。
  </Accordion>

  <Accordion title="我遇到了 SSL/TLS 证书错误">
    你的 GHES 可能使用自签名证书。我们的服务无法验证你服务器的证书。

    **解决方案：**确保你的 GHES 使用有效的 SSL 证书。
  </Accordion>

  <Accordion title="应用已安装，但没有响应事件。">
    * 确保 webhook 已成功送达，并且我们的服务器已返回 200 响应码进行确认。
    * 确保安装期间已授予必填权限。
  </Accordion>

  <Accordion title="我可以限制应用可访问的仓库吗？">
    可以。安装时，你可以选择“Only select repositories”并指定特定仓库。之后也可以在组织的已安装应用设置中进行修改。这是推荐的安装方式。
  </Accordion>

  <Accordion title="如何在之后更新应用权限？">
    * 以站点管理员身份进入应用设置。
    * 根据需要修改权限。
    * 修改后，应用需要由组织所有者重新批准。
    * 如有任何权限变更，请通知我们，因为这可能会影响功能。
  </Accordion>

  <Accordion title="我们的 GHES 位于企业防火墙、nginx 代理或类似环境之后。">
    你必须：

    * 在防火墙中将我们的服务域名加入白名单。
    * 确保可以通过 HTTPS 出站连接 (443 端口) 。
    * 如果不允许直接访问互联网，请配置代理。
  </Accordion>

  <Accordion title="这能在隔离网络环境中的 GHES 上运行吗？">
    不能，你的 GHES 必须能够与我们托管在云端的服务器通信。
  </Accordion>

  <Accordion title="如果我需要帮助，应该联系谁？">
    请联系你此前在 Mintlify 对接过的客户成功代表，或通过 <a href="mailto:support@mintlify.com">support@mintlify.com</a> 联系我们的支持团队，并提供：

    * 你的 GitHub Enterprise Server 版本。
    * 具体的错误信息。
    * 问题截图。
    * 网络/防火墙配置详情 (如适用) 。
  </Accordion>
</AccordionGroup>
