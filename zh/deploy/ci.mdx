<Info>
  [Pro 和 Enterprise 套餐](https://mintlify.com/pricing?ref=docs-ci)包含适用于 GitHub 仓库的 CI 检查功能。
</Info>

使用 CI 检查对文档进行 lint，提前发现错误并在部署前发出警告。Mintlify CI 检查会在针对已配置部署分支发起的拉取请求上运行。

<div id="installation">
  ## 安装
</div>

首先，请按照 [GitHub](/zh/deploy/github) 页面上的步骤进行操作。

<Tip>
  只需访问存放文档内容的仓库，因此强烈建议仅授予该仓库的访问权限。
</Tip>

## 配置

前往控制面板中的 [Add-ons](https://dashboard.mintlify.com/products/addons) 页面，配置某次部署启用的 CI 检查。启用你想要运行的检查。

启用检查时，你可以选择将其运行级别设为 `Warning` 或 `Blocking`。

* `Warning` 级别的检查即使发现错误或提出建议，也不会返回失败状态。
* `Blocking` 级别的检查如果发现错误或提出建议，则会返回失败状态。

<div id="available-ci-checks">
  ## 可用的 CI 检查
</div>

<div id="broken-links">
  ### 失效链接
</div>

与 [CLI 链接检查器](/zh/installation#find-broken-links) 在本地机器上的工作方式类似，
失效链接 CI 检查会自动扫描文档内容中的失效内部链接。

要查看此检查的结果，请访问 GitHub 上特定提交的检查结果页面。

<div id="vale">
  ### Vale
</div>

[Vale](https://vale.sh/) 是一款开源的规则式文稿检查工具，支持多种文档类型，包括 Markdown 和 MDX。使用 Vale 可检查文档在风格和语气上的一致性。

Mintlify 支持在 CI 检查中自动运行 Vale，并将结果显示为检查状态。

<div id="configuration">
  #### 配置
</div>

如果在部署的内容根目录中存在 `.vale.ini` 文件，Vale CI 检查会使用该配置文件，以及你在 `stylesPath` 中指定的所有配置文件。

如果没有 Vale 配置文件，则会自动加载默认配置。

```mdx Default vale.ini configuration expandable
# 顶级样式
StylesPath = /app/styles
MinAlertLevel = suggestion
# 要忽略的行内 HTML 标签（code/tt 用于代码片段，img/url 用于链接/图片，a 用于锚点标签）
IgnoredScopes = code, tt, img, url, a
SkippedScopes = script, style, pre, figure

# 词汇表
Vocab = Mintlify

# 包
Packages = MDX

# 仅匹配 MDX
[*.mdx]
BasedOnStyles = Vale
Vale.Terms = NO # 强制执行非常严格的大小写规则，保持关闭

# 忽略 JSX/MDX 特定语法模式
# `import ...`, `export ...`
# `<Component ... />`
# `<Component>...</Component>`
# `{ ... }`
TokenIgnores = (?sm)((?:import|export) .+?$), \
(?<!`)(<\w+ ?.+ ?\/>)(?!`), \
(<[A-Z]\w+>.+?<\/[A-Z]\w+>)

# 排除多行 JSX 和花括号
# `<Component \n ... />`
BlockIgnores = (?sm)^(<\w+\n .*\s\/>)$, \
(?sm)^({.+.*})
```

要为默认配置添加自定义词汇，请创建 `styles/config/vocabularies/Mintlify` 目录，并在其中添加 `accept.txt` 和 `reject.txt` 文件。

* `accept.txt`：Vale linter 应忽略的词语。例如，产品名称或不常见的术语。
* `reject.txt`：应标记为错误的词语。例如，行话或不符合文档语气的用词。

```text Example Vale file structure
/your-project
  |- docs.json
  |- .vale.ini
  |- styles/
    |- config/
      |- vocabularies/
        |- Mintlify/
          |- accept.txt
          |- reject.txt
  |- example-page.mdx
```

```text Example monorepo Vale file structure
/your-monorepo
  |- main.ts
  |- docs/
    |- docs.json
    |- .vale.ini
    |- styles/
      |- config/
      |- vocabularies/
        |- Mintlify/
          |- accept.txt
          |- reject.txt
    |- example-page.mdx
  |- test/
```

<Note>
  出于安全考虑，不支持使用绝对 `stylesPath`，也不支持包含 `..` 的 `stylesPath`。

  请使用相对路径，并将 `stylesPath` 包含在你的仓库中。
</Note>

<div id="packages">
  #### 包
</div>

Vale 支持多种[包](https://vale.sh/docs/keys/packages)，可用于检查拼写和文风错误。只要你在仓库中通过正确的 `stylesPath` 包含这些包，Vale 就会自动安装并在配置中使用它们。

对于未包含在仓库中的包，你可以指定 [Vale 包注册表](https://vale.sh/explorer) 中的任意包，Vale 会自动下载并在配置中使用它们。

<Note>
  出于安全原因，不支持自动下载不在 [Vale 包注册表](https://vale.sh/explorer) 中的包。
</Note>

<div id="vale-with-mdx">
  #### 在 `MDX` 中使用 Vale
</div>

<Note>
  MDX 原生支持要求 Vale 3.10.0 或更高版本。使用 `vale --version` 检查你的 Vale 版本。
</Note>

要在 MDX 文件中使用 Vale 的文档内注释，请使用 MDX 风格的注释 `{/* ... */}`：

```mdx
{/* vale off */}

This text is ignored by Vale

{/* vale on */}
```

Vale 会自动识别并处理 MDX 文件中的这些注释，无需额外配置。使用注释可跳过应被 lint 工具忽略的行或部分。
