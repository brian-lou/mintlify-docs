<Info>
  [Pro 方案](https://mintlify.com/pricing?ref=authentication)包含密码身份验证。

  [Enterprise 方案](https://mintlify.com/pricing?ref=authentication)包含所有身份验证方式。
</Info>

使用身份验证时，用户必须在访问你的文档前先登录。

当你启用身份验证时，用户必须登录才能访问任意内容。你可以将特定页面或页面组配置为公开，同时保持其他页面受保护。

<div id="configure-authentication">
  ## 配置身份验证
</div>

选择要配置的握手机制。

<Tabs>
  <Tab title="密码">
    <Info>
      密码验证仅提供访问控制，且**不**支持针对特定用户的功能，例如基于用户组的访问控制或 API playground 预填内容。
    </Info>

    ### 前提条件

    * 你的安全策略允许多个用户共享同一密码。

    ### 设置

    <Steps>
      <Step title="创建密码。">
        1. 在你的 dashboard 中，前往 [Authentication](https://dashboard.mintlify.com/products/authentication)。
        2. 启用身份验证。
        3. 在 **Password Protection** 部分输入一个安全的密码。

        输入密码后，你的网站会重新部署。部署完成后，任何访问你网站的人都必须输入该密码才能访问内容。
      </Step>

      <Step title="分发访问权限。">
        将密码和文档 URL 安全地分享给已获授权的用户。
      </Step>
    </Steps>

    ### 示例

    你将文档托管在 `docs.foo.com`，并且只需要基本的访问控制，而不需要跟踪单个用户。你希望阻止公众访问，同时让设置尽可能简单。

    在你的 dashboard 中**创建一个强密码**，然后将**登录凭据分享**给已获授权的用户。就这么简单！
  </Tab>

  <Tab title="Mintlify 控制台">
    ### 前提条件

    * 所有需要访问你文档的人都必须是你的 Mintlify 组织成员。

    ### 设置

    <Steps>
      <Step title="启用 Mintlify 控制面板身份验证。">
        1. 在控制面板中，前往 [Authentication](https://dashboard.mintlify.com/products/authentication)。
        2. 启用身份验证。
        3. 在 **Custom Authentication** 部分，点击 **Mintlify Auth**。
        4. 点击 **Enable Mintlify Auth**。

        启用 Mintlify 身份验证后，你的网站会重新部署。部署完成后，任何访问你网站的人都必须登录到你的 Mintlify 组织才能访问你的内容。
      </Step>

      <Step title="添加授权用户。">
        1. 在控制面板中，前往 [Members](https://dashboard.mintlify.com/settings/organization/members)。
        2. 将每一位需要访问你文档的人添加为成员。
        3. 根据他们的编辑权限分配合适的角色。
      </Step>
    </Steps>

    ### 示例

    你在 `docs.foo.com` 上托管文档，你的整个团队都可以访问你的控制面板。你希望将访问权限仅限制在团队成员范围内。

    在控制面板设置中**启用 Mintlify 身份验证**。

    通过确认所有团队成员在你的组织中处于活跃状态来**验证团队访问权限**。
  </Tab>

  <Tab title="OAuth 2.0">
    ### 先决条件

    * 一个支持授权码流程（Authorization Code Flow）的 OAuth 或 OIDC 服务器。
    * 能够创建可通过 OAuth 访问令牌访问的 API 端点（可选，用于启用基于用户组的访问控制）。

    ### 设置

    <Steps>
      <Step title="配置你的 OAuth 设置。">
        1. 在你的控制面板中，前往 [Authentication](https://dashboard.mintlify.com/products/authentication)。
        2. 启用身份验证。
        3. 在 **Custom Authentication** 部分，点击 **OAuth**。
        4. 配置以下字段：

        * **Authorization URL**：你的 OAuth 授权端点。
        * **Client ID**：你的 OAuth 2.0 客户端 ID。
        * **Client Secret**：你的 OAuth 2.0 客户端密钥。
        * **Scopes**（可选）：要请求的权限。复制 **完整的** scope 字符串（例如，对于 `provider.users.docs` 这样的 scope，需复制完整的 `provider.users.docs`）。如果你需要不同的访问级别，可以使用多个 scope。
        * **Additional authorization parameters**（可选）：要添加到初始授权请求中的额外查询参数。
        * **Token URL**：你的 OAuth 令牌交换端点。
        * **Info API URL**（可选）：你服务器上的端点，Mintlify 会调用它来获取用户信息。基于用户组的访问控制需要配置该字段。如果省略，OAuth 流程只会进行身份验证。
        * **Logout URL**（可选）：你的 OAuth 提供方的原生登出 URL。当用户登出时，Mintlify 会根据已配置的该 URL 校验登出重定向以确保安全。只有当重定向 URL 与配置的 `logoutUrl` 完全匹配时，重定向才会成功。如果你没有配置 Logout URL，用户将被重定向到 `/login`。Mintlify 使用 `GET` 请求重定向用户，并且不会附加查询参数，因此需要将所有参数（例如 `returnTo`）直接包含在 URL 中。
        * **Redirect URL**（可选）：用户通过认证后要被重定向到的 URL。

        5. 点击 **Save changes**。

        配置完 OAuth 设置后，你的网站会重新部署。部署完成后，任何访问你网站的人都必须先登录到你的 OAuth 提供方才能访问你的内容。
      </Step>

      <Step title="配置你的 OAuth 服务器。">
        1. 从你的 [authentication settings](https://dashboard.mintlify.com/products/authentication) 中复制 **Redirect URL**。
        2. 在你的 OAuth 服务器中，将该 Redirect URL 添加为已授权的重定向 URL。
      </Step>

      <Step title="创建你的用户信息端点（可选）。">
        为了启用基于用户组的访问控制，创建一个满足以下条件的 API 端点：

        * 能响应 `GET` 请求。
        * 接受用于认证的 `Authorization: Bearer <access_token>` 请求头。
        * 以 `User` 格式返回用户数据。更多信息参见 [User data format](#user-data-format)。

        Mintlify 会使用 OAuth 访问令牌调用此端点来获取用户信息。不会发送任何额外的查询参数。

        将此端点的 URL 添加到你的 [authentication settings](https://dashboard.mintlify.com/products/authentication) 中的 **Info API URL** 字段。
      </Step>
    </Steps>

    ### 示例

    你将文档托管在 `foo.com/docs`，并且已有一个位于 `auth.foo.com` 的 OAuth 服务器，它支持授权码流程（Authorization Code Flow）。

    在控制面板中**配置你的 OAuth 服务器详情**：

    * **Authorization URL**：`https://auth.foo.com/authorization`
    * **Client ID**：`ydybo4SD8PR73vzWWd6S0ObH`
    * **Scopes**：`['provider.users.docs']`
    * **Token URL**：`https://auth.foo.com/exchange`
    * **Info API URL**：`https://api.foo.com/docs/user-info`
    * **Logout URL**：`https://auth.foo.com/logout?returnTo=https%3A%2F%2Ffoo.com%2Fdocs`

    **在** `api.foo.com/docs/user-info` **创建一个用户信息端点**，它需要具备 `provider.users.docs` scope 的 OAuth 访问令牌，并返回：

    ```json
    {
      "groups": ["engineering", "admin"],
      "expiresAt": 1735689600,
      "apiPlaygroundInputs": {
        "header": {
          "Authorization": "Bearer user_abc123"
        }
      }
    }
    ```

    <Note>
      使用用户信息响应中的 `expiresAt` 字段来控制会话有效期。该字段是一个 Unix 时间戳（自 Unix 纪元以来经过的秒数），表示会话应在何时过期。更多详情参见 [User data format](#user-data-format)。
    </Note>

    **将你的 OAuth 服务器配置为允许重定向** 到你的回调 URL。
  </Tab>

  <Tab title="JWT">
    ### 前置条件

    * 一个可以生成并签署 JWT 的身份验证系统。
    * 一个可以创建重定向 URL 的后端服务。

    ### 设置

    <Steps>
      <Step title="生成私钥。">
        1. 在你的控制台中，前往 [Authentication](https://dashboard.mintlify.com/products/authentication)。
        2. 启用 Authentication。
        3. 在 **Custom Authentication** 部分，点击 **JWT**。
        4. 输入你现有登录流程的 URL。
        5. 点击 **Save changes**。
        6. 点击 **Generate new key**。
        7. 将密钥安全存储在后端可访问的位置。

        生成私钥后，你的网站会重新部署。部署完成后，任何访问你网站的人都必须先登录你的 JWT 身份验证系统才能访问内容。
      </Step>

      <Step title="将 Mintlify 身份验证集成到你的登录流程中。">
        修改你现有的登录流程，在用户完成身份验证后增加以下步骤：

        * 创建一个包含已通过验证用户信息的 JWT，使用 `User` 格式。更多信息参见 [User data format](#user-data-format)。
        * 使用 EdDSA 算法和你的密钥签署该 JWT。
        * 创建一个指向文档 `/login/jwt-callback` 路径的重定向 URL，并将 JWT 作为 URL hash 片段附加在后面。
      </Step>
    </Steps>

    ### 示例

    你在 `docs.foo.com` 上托管文档，现有身份验证系统位于 `foo.com`。你希望扩展登录流程，在保持文档与控制台分离的同时，为文档授予访问权限（或者你根本没有控制台）。

    在 `https://foo.com/docs-login` 创建一个登录端点，用于扩展你现有的身份验证。

    在验证用户凭据之后：

    * 按 Mintlify 的格式生成包含用户数据的 JWT。
    * 对 JWT 进行签名并重定向到 `https://docs.foo.com/login/jwt-callback#{SIGNED_JWT}`。

    <CodeGroup>
      ```ts TypeScript
      import * as jose from 'jose';
      import { Request, Response } from 'express';

      const TWO_WEEKS_IN_MS = 1000 * 60 * 60 * 24 * 7 * 2;

      const signingKey = await jose.importPKCS8(process.env.MINTLIFY_PRIVATE_KEY, 'EdDSA');

      export async function handleRequest(req: Request, res: Response) {
        const user = {
          expiresAt: Math.floor((Date.now() + TWO_WEEKS_IN_MS) / 1000), // 2 week session expiration
          groups: res.locals.user.groups,
          apiPlaygroundInputs: {
            header: {
              "Authorization": `Bearer ${res.locals.user.apiKey}`,
            },
          },
        };

        const jwt = await new jose.SignJWT(user)
          .setProtectedHeader({ alg: 'EdDSA' })
          .setExpirationTime('10 s') // 10 second JWT expiration
          .sign(signingKey);

        return res.redirect(`https://docs.foo.com/login/jwt-callback#${jwt}`);
      }
      ```

      ```python Python
      import jwt # pyjwt
      import os

      from datetime import datetime, timedelta
      from fastapi.responses import RedirectResponse

      private_key = os.getenv(MINTLIFY_JWT_PEM_SECRET_NAME, '')

      @router.get('/auth')
      async def return_mintlify_auth_status(current_user):
        jwt_token = jwt.encode(
          payload={
            'exp': int((datetime.now() + timedelta(seconds=10)).timestamp()),    # 10 second JWT expiration
            'expiresAt': int((datetime.now() + timedelta(weeks=2)).timestamp()), # 2 week session expiration
            'groups': ['admin'] if current_user.is_admin else [],
            'apiPlaygroundInputs': {
              'header': {
                'Authorization': f'Bearer {current_user.api_key}',
              },
            },
          },
          key=private_key,
          algorithm='EdDSA'
        )

        return RedirectResponse(url=f'https://docs.foo.com/login/jwt-callback#{jwt_token}', status_code=302)
      ```
    </CodeGroup>

    ### 重定向未认证用户

    当未登录用户尝试访问受保护页面时，重定向到你的登录 URL 时，会保留用户原本想访问的目标地址。

    1. 用户尝试访问受保护页面：`https://docs.foo.com/quickstart`。
    2. 重定向到你的登录 URL，并带上 redirect 查询参数：`https://foo.com/docs-login?redirect=%2Fquickstart`。
    3. 完成身份验证后，重定向到 `https://docs.foo.com/login/jwt-callback?redirect=%2Fquickstart#{SIGNED_JWT}`。
    4. 用户最终到达其最初想访问的页面。
  </Tab>
</Tabs>

<div id="make-pages-public">
  ## 公开页面
</div>

使用身份验证时，默认所有页面都需要通过身份验证才能访问。你可以在页面级或分组级使用 `public` 属性，使特定页面在无需身份验证的情况下也可访问。

<div id="individual-pages">
  ### 单个页面
</div>

要将页面设为公开，在该页面的 frontmatter 中添加 `public: true`。

```mdx Public page example
---
title: "Public page"
public: true
---
```

<div id="groups-of-pages">
  ### 页面分组
</div>

要将某个分组中的所有页面设为公开，请在 `docs.json` 的 `navigation` 对象中该分组名称下添加 `"public": true`。

```json Public group example
{
  "navigation": {
    "groups": [
      {
        "group": "Public group",
        "public": true,
        "icon": "play",
        "pages": [
          "quickstart",
          "installation",
          "settings"
        ]
      },
      {
        "group": "Private group",
        "icon": "pause",
        "pages": [
          "private-information",
          "secret-settings"
        ]
      }
    ]
  }
}
```

<div id="control-access-with-groups">
  ## 使用用户组控制访问权限
</div>

当你使用 OAuth 或 JWT 进行身份验证时，可以将特定页面的访问限制在某些用户组内。这样可以根据用户的角色或属性，让不同用户看到不同的内容。

通过在身份验证过程中传递的用户数据来管理用户组。详情见 [用户数据格式](#user-data-format)。

```json Example user info
{
  "groups": ["admin", "beta-users"],
  "expiresAt": 1735689600
}
```

在 frontmatter 中使用 `groups` 属性来指定哪些用户组可以访问特定页面。

```mdx Example page restricted to the admin group highlight={3}
---
title: "Admin dashboard"
groups: ["admin"]
---
```

用户必须至少属于列表中的一个群组才能访问该页面。如果用户在未具备所需群组的情况下尝试访问页面，他们将会看到 404 错误页面。

<div id="how-groups-interact-with-public-pages">
  ### 分组如何与公共页面交互
</div>

* 所有页面默认都需要身份验证。
* 具有 `groups` 属性的页面仅对属于这些组的已通过身份验证用户可访问。
* 没有 `groups` 属性的页面对所有已通过身份验证的用户可访问。
* 具有 `public: true` 且没有 `groups` 属性的页面对任何人都可访问。

<CodeGroup>
  ```mdx Public page
  ---
  title: "公开指南"
  public: true
  ---
  ```

  ```mdx Protected page
  ---
  title: "API 参考"
  ---
  ```

  ```mdx Protected page with groups
  ---
  title: "高级配置"
  groups: ["pro", "enterprise"]
  ---
  ```
</CodeGroup>

<div id="user-data-format">
  ## 用户数据格式
</div>

当使用 OAuth 或 JWT 认证时，你的系统会返回用户数据，用于控制会话时长、分组成员身份，以及[内容个性化](/zh/create/personalization)。

<CodeGroup>
  ```tsx Format
  type User = {
    expiresAt?: number;
    groups?: string[];
    content?: Record<string, any>;
    apiPlaygroundInputs?: {
      server?: Record<string, string>;
      header?: Record<string, unknown>;
      query?: Record<string, unknown>;
      cookie?: Record<string, unknown>;
    };
  };
  ```

  ```json Example
  {
    "expiresAt": 1735689600,
    "groups": ["admin", "beta-users"],
    "content": {
      "firstName": "Jane",
      "company": "Acme Corp"
    },
    "apiPlaygroundInputs": {
      "header": {
        "Authorization": "Bearer user_abc123"
      },
      "server": {
        "baseUrl": "https://api.foo.com"
      }
    }
  }
  ```
</CodeGroup>

<ParamField path="expiresAt" type="number">
  自 Unix 纪元以来的会话过期时间（单位为秒）。当当前时间超过该值时，用户必须重新进行认证。

  <Warning>**对于 JWT：** 这不同于 JWT 的 `exp` 声明，后者决定 JWT 何时被视为无效。出于安全考虑，请将 JWT 的 `exp` 声明设置为较短的时长（10 秒或更少）。使用 `expiresAt` 来控制实际的会话时长（从数小时到数周）。</Warning>
</ParamField>

<ParamField path="groups" type="string[]">
  用户所属的分组列表。frontmatter 中带有匹配 `groups` 的页面对该用户可访问。

  **示例**：拥有 `groups: ["admin", "engineering"]` 的用户可以访问标记为 `admin` 或 `engineering` 分组的页面。
</ParamField>

<ParamField path="content" type="Record<string, any>">
  可在 MDX 页面中通过 `user` 变量访问的自定义数据，用于[个性化内容](/zh/create/personalization#dynamic-mdx-content)。
</ParamField>

<ParamField path="apiPlaygroundInputs" type="object">
  使用用户特定的值预填 API playground 的字段。当用户通过认证后，这些值会填充到 API playground 中对应的输入字段。用户可以覆盖预填的值，他们的修改会保存在本地存储中。

  只有与当前端点的安全方案匹配的值才会被应用。

  <Expandable title="properties">
    <ParamField path="header" type="Record<string, unknown>">
      要预填的 header 值，以 header 名称作为键。
    </ParamField>

    <ParamField path="query" type="Record<string, unknown>">
      要预填的查询参数值，以参数名称作为键。
    </ParamField>

    <ParamField path="cookie" type="Record<string, unknown>">
      要预填的 cookie 值，以 cookie 名称作为键。
    </ParamField>

    <ParamField path="server" type="Record<string, string>">
      要预填的服务器变量值，以变量名称作为键。
    </ParamField>
  </Expandable>
</ParamField>
