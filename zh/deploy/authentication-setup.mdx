<div id="configure-authentication">
  ## 配置身份验证
</div>

选择要配置的握手方式。

<Tabs>
  <Tab title="密码">
    <Info>
      密码认证仅提供访问控制，**不**支持按用户区分的功能，例如基于群组的访问控制或 API 操作台预填。
    </Info>

    ### 前提条件

    * 你的安全要求允许用户之间共享密码。

    ### 设置

    <Steps>
      <Step title="创建密码。">
        1. 在控制台中，前往 [Authentication](https://dashboard.mintlify.com/products/authentication)。
        2. 启用身份验证。
        3. 在 **Password Protection** 部分输入一个高强度密码

        输入密码后，站点会重新部署。部署完成后，任何访问你站点的人都必须输入该密码才能查看内容。
      </Step>

      <Step title="分发访问权限。">
        通过安全方式将密码和文档 URL 分享给已获授权的用户。
      </Step>
    </Steps>

    ### 示例

    你的文档托管在 `docs.foo.com`，需要基本的访问控制，但无需跟踪单个用户。你希望阻止公众访问，同时保持设置简单。

    **在控制台中创建一个高强度密码**。**将凭据分享给已获授权的用户**。就是这么简单！
  </Tab>

  <Tab title="Mintlify 控制台">
    ### 前提条件

    * 所有需要访问你的文档的人员都必须是你的 Mintlify 组织成员。

    ### 设置

    <Steps>
      <Step title="启用 Mintlify 控制台身份验证。">
        1. 在控制台中，前往 [Authentication](https://dashboard.mintlify.com/products/authentication)。
        2. 启用身份验证。
        3. 在 **Custom Authentication** 部分，点击 **Mintlify Auth**。
        4. 点击 **Enable Mintlify Auth**。

        启用 Mintlify 身份验证后，站点会重新部署。部署完成后，所有访问你站点的用户都必须登录其 Mintlify 组织才能访问内容。
      </Step>

      <Step title="添加授权用户。">
        1. 在控制台中，前往 [Members](https://dashboard.mintlify.com/settings/organization/members)。
        2. 添加每位应有权访问文档的人员。
        3. 根据他们的编辑权限分配相应的角色。
      </Step>
    </Steps>

    ### 示例

    你的文档托管在 `docs.foo.com`，并且整个团队都可以访问控制台。你希望仅限团队成员访问。

    **在控制台设置中启用 Mintlify 身份验证**。

    **确认所有团队成员在你的组织中均为活跃状态，以验证团队访问权限**。
  </Tab>

  <Tab title="OAuth 2.0">
    ### 前提条件

    * 支持 Authorization Code Flow 的 OAuth 或 OIDC 服务器。
    * 能够创建可通过 OAuth 访问令牌访问的 API 端点 (可选，用于启用基于组的访问控制) 。

    ### 设置

    <Steps>
      <Step title="配置 OAuth 设置。">
        1. 在仪表板中，前往 [Authentication](https://dashboard.mintlify.com/products/authentication)。
        2. 启用身份验证。
        3. 在 **Custom Authentication** 部分中，点击 **OAuth**。
        4. 配置以下字段：

        * **Authorization URL**：你的 OAuth 端点。
        * **Client ID**：你的 OAuth 2.0 客户端 ID。
        * **Client Secret**：你的 OAuth 2.0 客户端密钥。
        * **Scopes** (可选) ：要请求的权限范围。复制**完整的** scope 字符串 (例如，对于 `provider.users.docs` 这样的 scope，请复制完整的 `provider.users.docs`) 。如果你需要不同的访问级别，可以使用多个 scope。
        * **Additional authorization parameters** (可选) ：要添加到初始授权请求中的额外查询参数。
        * **Token URL**：你的 OAuth 令牌交换端点。
        * **Info API URL** (可选) ：你服务器上的端点，Mintlify 会调用它来获取用户信息。基于组的访问控制需要此项。如果省略，OAuth 流程只会验证身份。
        * **Logout URL** (可选) ：OAuth 提供商的原生登出 URL。用户登出时，出于安全考虑，Mintlify 会根据此处配置的 URL 验证登出重定向。只有当重定向与配置的 `logoutUrl` 完全匹配时，重定向才会成功。如果你未配置登出 URL，用户会被重定向到 `/login`。Mintlify 会通过 `GET` 请求重定向用户，并且不会附加查询参数，因此请将任何参数 (例如 `returnTo`) 直接包含在 URL 中。
        * **Redirect URL** (可选) ：用户完成身份验证后重定向到的 URL。

        5. 点击 **Save changes**。

        配置好 OAuth 设置后，你的网站会重新部署。部署完成后，任何访问你网站的人都必须登录到你的 OAuth 提供商才能访问内容。
      </Step>

      <Step title="配置 OAuth 服务器。">
        1. 从你的 [authentication settings](https://dashboard.mintlify.com/products/authentication) 中复制 **Redirect URL**。
        2. 将该重定向 URL 添加为 OAuth 服务器的已授权重定向 URL。
      </Step>

      <Step title="创建用户信息端点（可选）。">
        要启用基于组的访问控制，请创建一个满足以下条件的 API 端点：

        * 响应 `GET` 请求。
        * 接受 `Authorization: Bearer <access_token>` 标头进行身份验证。
        * 以 `User` 格式返回用户数据。更多信息，请参阅[用户数据格式](#user-data-format)。

        Mintlify 会使用 OAuth 访问令牌调用此端点以获取用户信息。不会发送额外的查询参数。

        将此端点 URL 添加到你的 [authentication settings](https://dashboard.mintlify.com/products/authentication) 中的 **Info API URL** 字段。
      </Step>
    </Steps>

    ### 示例

    你的文档托管在 `foo.com/docs`，并且已有一个位于 `auth.foo.com`、支持 Authorization Code Flow 的 OAuth 服务器。

    在仪表板中**配置 OAuth 服务器详细信息**：

    * **Authorization URL**：`https://auth.foo.com/authorization`
    * **Client ID**：`ydybo4SD8PR73vzWWd6S0ObH`
    * **Scopes**：`['provider.users.docs']`
    * **Token URL**：`https://auth.foo.com/exchange`
    * **Info API URL**：`https://api.foo.com/docs/user-info`
    * **Logout URL**：`https://auth.foo.com/logout?returnTo=https%3A%2F%2Ffoo.com%2Fdocs`

    在 `api.foo.com/docs/user-info` **创建一个用户信息端点**，要求 OAuth 访问令牌具有 `provider.users.docs` scope，并返回：

    ```json
    {
      "groups": ["engineering", "admin"],
      "expiresAt": 1735689600,
      "apiPlaygroundInputs": {
        "header": {
          "Authorization": "Bearer user_abc123"
        }
      }
    }
    ```

    <Note>
      通过用户信息响应中的 `expiresAt` 字段控制会话有效期。这是一个 Unix 时间戳 (自纪元以来的秒数) ，用于指示会话应在何时过期。更多详情请参阅[用户数据格式](#user-data-format)。
    </Note>

    **将你的 OAuth 服务器配置为允许重定向到**你的回调 URL。
  </Tab>

  <Tab title="JWT">
    ### 前提条件

    * 一个能够生成并签名 JWT 的身份验证系统。
    * 一个能够创建重定向 URL 的后端服务。

    ### 设置

    <Steps>
      <Step title="生成私钥。">
        1. 在控制面板中，前往 [Authentication](https://dashboard.mintlify.com/products/authentication)。
        2. 启用身份验证。
        3. 在 **Custom Authentication** 部分，点击 **JWT**。
        4. 输入你现有登录流程的 URL。
        5. 点击 **Save changes**。
        6. 点击 **Generate new key**。
        7. 将密钥安全存储在后端可访问的位置。

        生成私钥后，站点会重新部署。部署完成后，任何访问你站点的人都必须登录到你的 JWT 身份验证系统，才能访问内容。
      </Step>

      <Step title="将 Mintlify 身份验证集成到你的登录流程中。">
        修改现有登录流程，在用户完成身份验证后加入以下步骤：

        * 创建一个 JWT，其中包含已通过身份验证的用户信息，且格式需符合 `User`。更多信息请参见[用户数据格式](#user-data-format)。
        * 使用 EdDSA 算法和你的私钥对 JWT 进行签名。
        * 创建一个重定向 URL，指向文档中的 `/login/jwt-callback` 路径，并将 JWT 作为 hash 附加到 URL 中。
      </Step>
    </Steps>

    ### 示例

    你的文档托管在 `docs.foo.com`，并且在 `foo.com` 上已有一套身份验证系统。你希望扩展登录流程，在保持文档与控制面板分离的同时授予文档访问权限 (或者你没有控制面板) 。

    在 `https://foo.com/docs-login` 创建一个登录端点，以扩展现有身份验证流程。

    验证用户凭据后：

    * 按照 Mintlify 的格式生成包含用户数据的 JWT。
    * 对 JWT 进行签名，并重定向到 `https://docs.foo.com/login/jwt-callback#{SIGNED_JWT}`。

    <CodeGroup>
      ```ts TypeScript
      import * as jose from 'jose';
      import { Request, Response } from 'express';

      const TWO_WEEKS_IN_MS = 1000 * 60 * 60 * 24 * 7 * 2;

      const signingKey = await jose.importPKCS8(process.env.MINTLIFY_PRIVATE_KEY, 'EdDSA');

      export async function handleRequest(req: Request, res: Response) {
        const user = {
          expiresAt: Math.floor((Date.now() + TWO_WEEKS_IN_MS) / 1000), // 2 周会话过期时间
          groups: res.locals.user.groups,
          apiPlaygroundInputs: {
            header: {
              "Authorization": `Bearer ${res.locals.user.apiKey}`,
            },
          },
        };

        const jwt = await new jose.SignJWT(user)
          .setProtectedHeader({ alg: 'EdDSA' })
          .setExpirationTime('10 s') // 10 秒 JWT 过期时间
          .sign(signingKey);

        return res.redirect(`https://docs.foo.com/login/jwt-callback#${jwt}`);
      }
      ```

      ```python Python
      import jwt # pyjwt
      import os

      from datetime import datetime, timedelta
      from fastapi.responses import RedirectResponse

      private_key = os.getenv(MINTLIFY_JWT_PEM_SECRET_NAME, '')

      @router.get('/auth')
      async def return_mintlify_auth_status(current_user):
        jwt_token = jwt.encode(
          payload={
            'exp': int((datetime.now() + timedelta(seconds=10)).timestamp()),    # 10 秒 JWT 过期时间
            'expiresAt': int((datetime.now() + timedelta(weeks=2)).timestamp()), # 2 周会话过期时间
            'groups': ['admin'] if current_user.is_admin else [],
            'apiPlaygroundInputs': {
              'header': {
                'Authorization': f'Bearer {current_user.api_key}',
              },
            },
          },
          key=private_key,
          algorithm='EdDSA'
        )

        return RedirectResponse(url=f'https://docs.foo.com/login/jwt-callback#{jwt_token}', status_code=302)
      ```
    </CodeGroup>

    ### 重定向未登录用户

    当未登录用户尝试访问受保护页面时，重定向到登录 URL 时会保留用户原本想访问的目标地址。

    1. 用户尝试访问受保护页面：`https://docs.foo.com/quickstart`。
    2. 重定向到你的登录 URL，并附带 redirect 查询参数：`https://foo.com/docs-login?redirect=%2Fquickstart`。
    3. 身份验证完成后，重定向到 `https://docs.foo.com/login/jwt-callback?redirect=%2Fquickstart#{SIGNED_JWT}`。
    4. 用户回到原始目标页面。
  </Tab>
</Tabs>

<div id="make-pages-public">
  ## 将页面设为公开
</div>

使用身份验证时，默认所有页面都需要登录后才能访问。你可以通过 `public` 属性，在页面级别或分组级别将特定页面设为无需身份验证即可查看。

<div id="individual-pages">
  ### 单个页面
</div>

要将页面设为公开访问，请在该页面的前置元数据中添加 `public: true`。

```mdx Public page example
---
title: "Public page"
public: true
---
```

<div id="groups-of-pages">
  ### 页面分组
</div>

要将某个分组中的所有页面设为公开，请在 `docs.json` 的 `navigation` 对象中，在该分组名称下方添加 `"public": true`。

```json Public group example
{
  "navigation": {
    "groups": [
      {
        "group": "Public group",
        "public": true,
        "icon": "play",
        "pages": [
          "quickstart",
          "installation",
          "settings"
        ]
      },
      {
        "group": "Private group",
        "icon": "pause",
        "pages": [
          "private-information",
          "secret-settings"
        ]
      }
    ]
  }
}
```

<div id="control-access-with-groups">
  ## 使用分组控制访问权限
</div>

使用 OAuth 或 JWT 身份验证时，你可以将特定页面限制为仅对某些用户分组开放。这在你希望不同用户根据其角色或属性看到不同内容时非常有用。

你可以通过身份验证期间传递的用户数据来管理分组。详情请参阅[用户数据格式](#user-data-format)。

```json Example user info
{
  "groups": ["admin", "beta-users"],
  "expiresAt": 1735689600
}
```

使用前置元数据中的 `groups` 属性，指定哪些分组可以访问特定页面。

```mdx Example page restricted to the admin group highlight={3}
---
title: "Admin dashboard"
groups: ["admin"]
---
```

用户必须属于所列分组中的至少一个，才能访问该页面。如果用户在不属于所需分组的情况下尝试访问页面，会收到 404 错误。

<div id="how-groups-interact-with-public-pages">
  ### 分组与公开页面的交互方式
</div>

* 默认情况下，所有页面都需要身份验证。
* 带有 `groups` 属性的页面仅对这些分组中的已认证用户开放。
* 不带 `groups` 属性的页面对所有已认证用户开放。
* 带有 `public: true` 且不含 `groups` 属性的页面对所有人开放。

<CodeGroup>
  ```mdx Public page
  ---
  title: "Public guide"
  public: true
  ---
  ```

  ```mdx Protected page
  ---
  title: "API reference"
  ---
  ```

  ```mdx Protected page with groups
  ---
  title: "Advanced configurations"
  groups: ["pro", "enterprise"]
  ---
  ```
</CodeGroup>

<div id="user-data-format">
  ## 用户数据格式
</div>

使用 OAuth 或 JWT 身份验证时，系统会返回用户数据，用于控制会话时长、用户所属分组以及[内容个性化](/zh/create/personalization)。

<CodeGroup>
  ```tsx Format
  type User = {
    expiresAt?: number;
    groups?: string[];
    content?: Record<string, any>;
    apiPlaygroundInputs?: {
      server?: Record<string, string>;
      header?: Record<string, unknown>;
      query?: Record<string, unknown>;
      cookie?: Record<string, unknown>;
    };
  };
  ```

  ```json Example
  {
    "expiresAt": 1735689600,
    "groups": ["admin", "beta-users"],
    "content": {
      "firstName": "Jane",
      "company": "Acme Corp"
    },
    "apiPlaygroundInputs": {
      "header": {
        "Authorization": "Bearer user_abc123"
      },
      "server": {
        "baseUrl": "https://api.foo.com"
      }
    }
  }
  ```
</CodeGroup>

<ParamField path="expiresAt" type="number">
  会话过期时间，以 Unix 时间戳秒数表示。当当前时间超过该值时，用户必须重新进行身份验证。

  <Warning>**对于 JWT：**这与 JWT 的 `exp` 声明不同，后者决定 JWT 何时失效。出于安全考虑，请将 JWT 的 `exp` 声明设置为较短时长 (10 秒或更短) 。`expiresAt` 则用于表示实际的会话时长 (数小时到数周) 。</Warning>
</ParamField>

<ParamField path="groups" type="string[]">
  用户所属分组的列表。前置元数据中 `groups` 与之匹配的页面可供该用户访问。

  **示例**：具有 `groups: ["admin", "engineering"]` 的用户可以访问标记了 `admin` 或 `engineering` 分组的页面。
</ParamField>

<ParamField path="content" type="Record<string, any>">
  自定义数据，可在 MDX 页面中通过 `user` 变量访问，用于[个性化内容](/zh/create/personalization#dynamic-mdx-content)。
</ParamField>

<ParamField path="apiPlaygroundInputs" type="object">
  使用用户特定的值预填充 API 操作台字段。用户完成身份验证后，这些值会自动填入 API 操作台中对应的输入字段。用户可以覆盖预填充值，并且这些覆盖值会持久保存在本地存储中。

  只有与当前端点安全方案匹配的值才会应用。

  <Expandable title="属性">
    <ParamField path="header" type="Record<string, unknown>">
      要预填充的请求头值，以请求头名称为键。
    </ParamField>

    <ParamField path="query" type="Record<string, unknown>">
      要预填充的查询参数值，以参数名称为键。
    </ParamField>

    <ParamField path="cookie" type="Record<string, unknown>">
      要预填充的 Cookie 值，以 Cookie 名称为键。
    </ParamField>

    <ParamField path="server" type="Record<string, string>">
      要预填充的服务器变量值，以变量名称为键。
    </ParamField>
  </Expandable>
</ParamField>
