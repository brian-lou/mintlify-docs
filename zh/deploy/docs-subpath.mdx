将文档托管在类似 `your-domain.com/docs` 这样的子路径下，把文档保留在你的主域名上，从而更容易被发现，并为用户提供一致、连贯的品牌体验。

<div id="set-up-by-hosting-provider">
  ## 由托管服务提供商进行设置
</div>

如何在 `/docs` 子路径下提供文档，取决于你所使用的托管服务提供商。选择你的托管服务提供商，并按照相应的设置说明操作。

* [Cloudflare](/zh/deploy/cloudflare)：为你的域名配置 Cloudflare Workers，使其在 `/docs` 子路径下提供文档。
* [AWS Route 53 and CloudFront](/zh/deploy/route53-cloudfront)：使用 AWS 的 Route 53 DNS 和 CloudFront CDN，将你的文档部署在 `/docs` 子路径下。
* [Vercel](/zh/deploy/vercel#host-from-docs) - 使用重写规则将你的文档部署在 `/docs` 子路径下。
* [Custom reverse proxy](/zh/deploy/reverse-proxy) - 对于其他托管平台，设置反向代理，将你的文档部署在 `/docs` 子路径下。

<div id="additional-configuration-for-strict-security-policies">
  ### 针对严格安全策略的额外配置
</div>

如果你在自定义域名上对全部流量进行代理，则可能需要在代理或防火墙规则中配置正确的 [HTTP 头](/zh/deploy/csp-configuration)，以确保文档能够正常显示。
