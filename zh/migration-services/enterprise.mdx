您可以选择我们的迁移服务，将文档迁移到 Mintlify。本指南介绍迁移流程、交付周期以及我们的质量保证方式。

<div id="what-to-expect-for-your-migration">
  ## 迁移期间您可以预期的内容
</div>

迁移是在某一时间点对您的文档进行的一次性转移，因此需要代码冻结。我们会迁移您的文档、API 参考页面、品牌素材 (徽标、颜色和字体) 以及导航结构。迁移服务还包括设计或信息架构咨询，以及落地页或自定义集成等自定义组件开发。

您的迁移包含一个用于查看进度的预发布链接，并在交付后提供 7 天的反馈期，用于处理内容、资源或品牌相关的任何问题。

<div id="migration-process">
  ## 迁移流程
</div>

迁移过程是高度协作的。我们会与您的团队密切配合，实施符合您需求的定制方案和构建！

<Steps>
  <Step title="提交迁移表单">
    提交[迁移表单](https://mintlify.typeform.com/pro-migrations)。

    提供您的文档源文件、品牌素材 (徽标、颜色代码、字体) 、OpenAPI 规范、上线日期，以及首选交付方式 (GitHub PR 或 zip 文件) 。
  </Step>

  <Step title="启动会议">
    我们会审核您提交的内容，并由迁移团队主持启动会议，带您梳理当前设置、了解现有限制，并解答您团队可能提出的任何问题。
  </Step>

  <Step title="接收范围界定和时间安排（1-2 个工作日）">
    我们会根据会议内容进行审核和分析，并在 24-48 小时内提供预计交付时间安排。我们也会标出迁移中需要进一步讨论的自定义组件或其他部分。
  </Step>

  <Step title="在迁移过程中查看进度">
    我们会启动迁移，并分享预发布链接，方便您实时跟踪进度。
  </Step>

  <Step title="接收最终交付">
    我们会根据您的偏好，通过 GitHub PR 或 zip 文件交付迁移成果。
  </Step>

  <Step title="反馈期（七个工作日）">
    提交您对内容、素材或品牌呈现的任何反馈。我们会在同一时间范围内处理所有范围内的问题。
  </Step>

  <Step title="上线支持">
    我们会提供相关文档和指导，帮助您连接代码仓库、设置重定向并配置自定义域名。
  </Step>
</Steps>

<div id="quality-assurance">
  ## 质量保证
</div>

我们与经过严格筛选的第三方供应商合作，并在交付前进行内部质量审核。以下是我们的检查内容：

<Card title="内容完整性" icon="file-check">
  * 你的源文档中的所有内容均已完成迁移。
  * 内容已使用 Mintlify 组件正确排版。
  * 导航结构符合你的规范要求。
</Card>

<Card title="视觉元素" icon="palette">
  * 图片和视频均可正常显示。
  * 自定义字体已在整个站点中统一应用。
  * 浅色和深色模式的 logo 均使用得当。
  * 配色方案在两种模式下都符合对比度要求。
</Card>

<Card title="功能性" icon="rocket">
  * 所有链接均可正常访问 (无失效链接) 。
  * 目录可正常渲染。
  * React 组件运行符合预期。
  * 不存在性能问题。
</Card>

<div id="after-your-migration">
  ## 迁移交付后
</div>

在我们完成迁移交付后，你需要完成以下步骤，才能正式发布文档：

1. [连接 GitHub 仓库并完成设置](/zh/quickstart#install-the-github-app)。
2. [根据需要设置重定向](/zh/create/redirects)。
3. [配置自定义域名](/zh/customize/custom-domain)。
4. **正式上线前先测试** - 在从旧版文档切换之前：
   * 检查预发布链接中的所有页面。
   * 测试导航和搜索功能。
   * 确认所有图片和视频都能正常加载。
   * 检查代码块是否正常渲染。
   * 分别在移动端和桌面端进行测试。
5. **上线！** 你的文档已可正式发布！

<Note>
  **需要帮助？** 我们的迁移团队可为你提供指导，协助你完成这些步骤。请通过你的专属 Slack 频道或 [support@mintlify.com](mailto:support@mintlify.com) 联系我们。
</Note>

<div id="frequently-asked-questions">
  ## 常见问题
</div>

<AccordionGroup>
  <Accordion title="迁移需要多长时间？">
    我们通常会在 2–6 周内完成迁移，具体取决于复杂程度。启动会议结束后，您将收到明确的时间安排。
  </Accordion>

  <Accordion title="交付后我可以提出修改吗？">
    可以。交付后，您有 7 天的反馈期，可对内容、资源或品牌相关设置提出修改要求。对于范围内的所有反馈，我们都会在这段时间内处理，并持续与您配合，直到您准备好正式上线。
  </Accordion>

  <Accordion title="迁移完成后，我还需要做什么？">
    迁移会转移您的内容，但您还需要：

    * 将您的文档仓库连接到 Mintlify 控制台。
    * 为旧文档 URL 设置重定向。
    * 配置自定义域名。

    对于上述每一步，我们都会提供分步文档和支持。
  </Accordion>

  <Accordion title="我可以自定义导航结构吗？">
    可以。您可以提供自定义的信息架构，我们会负责实现。如有需要且平台支持，我们也可以与您合作开发自定义组件。
  </Accordion>

  <Accordion title="如果我的文档在迁移期间发生变更，会怎样？">
    由于迁移需要代码冻结，提交后对源文档所做的任何更改都不会包含在本次迁移中。我们建议您在开始迁移前完成所有更新。

    如果无法做到这一点，我们的团队会与您协作，安排短周期冲刺来迁移特定部分，或在第一轮冲刺后预留专门时间，用于迁移期间产生的增量变更。
  </Accordion>
</AccordionGroup>
