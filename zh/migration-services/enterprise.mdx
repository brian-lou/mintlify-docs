您可以选择我们的迁移服务，将您的文档迁移至 Mintlify。本指南将介绍迁移流程、交付时间安排，以及我们的质量保障机制。

<div id="what-to-expect-for-your-migration">
  ## 迁移过程中可以预期的内容
</div>

一次迁移是在特定时间点对你的文档进行迁移，并且需要代码冻结。我们会迁移你的文档、API 参考页面、品牌元素（标志、颜色和字体）以及导航结构。迁移服务还包括设计或信息架构咨询，以及着陆页或自定义集成等自定义组件开发。

你的迁移将包含一个用于查看进度的预发布链接，以及交付后的 7 天反馈期，以便处理内容、素材或品牌方面的任何问题。

<div id="migration-process">
  ## 迁移流程
</div>

迁移流程是一个高度协作的过程。我们会与你的团队紧密合作，为你量身打造并落地自定义解决方案和实现！

<Steps>
  <Step title="提交迁移表单">
    提交[迁移表单](https://mintlify.typeform.com/pro-migrations)。

    提供你的文档来源、品牌资产（logo、色值、字体）、OpenAPI 规范、目标上线日期，以及首选交付方式（GitHub PR 或 zip 文件）。
  </Step>

  <Step title="启动会议">
    我们会审核你的提交内容，并由迁移团队组织一次启动会议，梳理你当前的配置情况、了解任何潜在限制，并解答你团队可能有的所有问题。
  </Step>

  <Step title="确认范围和时间表（1-2 个工作日）">
    我们会根据会议沟通的内容进行复盘和分析，并在 24–48 小时内提供预估的交付时间表。我们会标注出需要进一步讨论的自定义组件或迁移中的特殊部分。
  </Step>

  <Step title="在迁移过程中查看进度">
    我们开始执行迁移，并分享一个预发布环境链接，方便你实时查看进度。
  </Step>

  <Step title="接收最终交付结果">
    我们会根据你的偏好，通过 GitHub PR 或 zip 文件交付迁移结果。
  </Step>

  <Step title="反馈窗口（7 个工作日）">
    就内容、资产或品牌相关事项提交任何反馈。我们会在同一时限内处理所有范围内的问题。
  </Step>

  <Step title="上线支持">
    我们会提供文档和指导，帮助你连接仓库、设置重定向并配置自定义域名。
  </Step>
</Steps>

<div id="quality-assurance">
  ## 质量保证
</div>

我们与经过审核的第三方服务商合作，并在交付前进行内部质量审计。我们会重点检查以下内容：

<Card title="内容完整性" icon="file-check">
  * 已完成你所有源文档的迁移。
  * 内容已使用 Mintlify 组件进行正确排版和格式化。
  * 导航结构与你的规范保持一致。
</Card>

<Card title="视觉元素" icon="palette">
  * 图片和视频均能正确显示。
  * 自定义字体已在全站生效。
  * 明暗模式下分别使用了合适的徽标。
  * 两种模式下的配色方案都满足对比度要求。
</Card>

<Card title="功能性" icon="rocket">
  * 所有链接均可正常访问（无失效链接）。
  * 目录可以正常渲染。
  * React 组件按预期运行。
  * 无性能问题。
</Card>

<div id="after-your-migration">
  ## 迁移完成后
</div>

在我们完成迁移交付后，你需要完成以下步骤来发布你的文档：

1. [连接你的 GitHub 仓库并完成设置](/zh/quickstart#install-the-github-app)。
2. [按需设置重定向](/zh/create/redirects)。
3. [配置你的自定义域名](/zh/customize/custom-domain)。
4. **在正式上线前进行测试** - 在从旧文档切换过来之前：
   * 检查预发布环境中的所有页面。
   * 测试导航和搜索功能。
   * 确认所有图片和视频都能正确加载。
   * 检查代码块是否正确渲染。
   * 分别在移动端和桌面端进行测试。
5. **发布！** 你的文档已经准备好正式上线了！

<Note>
  **需要帮助吗？** 我们的迁移团队可以在这些步骤中为你提供指导。请通过你专属的 Slack 频道或 [support@mintlify.com](mailto:support@mintlify.com) 与我们联系。
</Note>

<div id="frequently-asked-questions">
  ## 常见问题解答
</div>

<AccordionGroup>
  <Accordion title="迁移通常需要多长时间？">
    我们通常会在 2–6 周内完成迁移，具体取决于复杂度。启动会议之后，你会收到一份具体的时间表。
  </Accordion>

  <Accordion title="交付之后我还能请求修改吗？">
    可以。交付后你有 7 天的反馈期，可以就内容、素材或品牌相关内容提出修改请求。我们会在同一时间范围内处理所有在约定范围内的反馈，并与你合作直到你准备好正式上线。
  </Accordion>

  <Accordion title="迁移完成后我需要做什么？">
    迁移会迁移你的内容，但你还需要：

    * 将你的文档仓库连接到 Mintlify 仪表盘。
    * 从旧的文档 URL 设置重定向。
    * 配置你的自定义域名。

    我们为上述每一步都提供详细的操作文档和支持。
  </Accordion>

  <Accordion title="我可以自定义导航结构吗？">
    可以。你可以提供自定义的信息架构，我们会为你实现。如果平台支持且有需要，我们也会和你一起进行自定义组件开发。
  </Accordion>

  <Accordion title="如果我的文档在迁移期间发生更改会怎样？">
    由于迁移需要代码冻结，在你提交之后对源文档所做的任何更改都不会被包含在内。我们建议在开始迁移之前先完成所有更新。

    如果这不现实，我们的团队会与你合作，安排短迭代来迁移特定章节，或在第一次迭代之后预留专门时间，将迁移期间产生的增量变更一并迁移。
  </Accordion>
</AccordionGroup>
