<div id="publishing-workflows">
  ## 发布工作流
</div>

编辑器支持两种发布文档更新的工作流。使用哪种工作流，取决于仓库的分支保护规则以及你当前使用的分支。

* **创建拉取请求**：如果你的仓库启用了分支保护规则，要求更改必须通过拉取请求才能合并到部署分支，那么当你发布更改时，编辑器会创建一个拉取请求。
* **直接发布**：如果你的仓库没有分支保护规则，那么当你发布时，更改会合并到部署分支并立即部署。

| 分支类型                                                                   | 分支保护   | 发布工作流         |
| ---------------------------------------------------------------------- | ------ | ------------- |
| <Tooltip headline="部署分支" tip="发布到线上文档站点的分支，通常为 'main'。">部署分支</Tooltip> | 无      | 提交并部署更改       |
| 部署分支                                                                   | 需要拉取请求 | 创建拉取请求        |
| <Tooltip headline="功能分支" tip="在合并到部署分支之前，用于处理更新的独立分支。">功能分支</Tooltip>  | 无      | 将更改合并到部署分支并部署 |
| 功能分支                                                                   | 需要拉取请求 | 创建拉取请求        |

<Tip>
  在你的 Git 提供商中配置分支保护规则，以要求通过拉取请求提交更改。请参阅 GitHub 文档中的 [About protected branches](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches) 或 GitLab 文档中的 [Protected branches](https://docs.gitlab.com/user/project/repository/branches/protected/)。
</Tip>

<div id="save-changes">
  ## 保存更改
</div>

在你编辑时，编辑器会记录你的更改。

* 新增或删除的文件。
* 页面内容编辑。
* 导航结构更改。
* 媒体上传和整理。
* 配置更新。

当你在部署分支上工作时，更改会自动保存。

要放弃更改，请点击 **Changes** 下拉菜单中文件名旁边的 **Undo changes**。

<div id="publish-your-changes">
  ### 发布更改
</div>

点击工具栏中的 **发布**。根据你的工作流程，你的更改可能会立即部署，或者系统会创建一个拉取请求，供你在 Git 提供商中合并。如果你当前在功能分支上，请先保存更改，再发布。

如果没有待发布的更改，或者当前分支的拉取请求已经打开，**发布** 按钮将被禁用。

## 解决冲突

当你的分支与部署分支对同一文件做出了不兼容的更改时，就会产生冲突。

<div id="what-causes-conflicts">
  ### 哪些情况会导致冲突
</div>

出现冲突通常是因为：

* 你和另一位团队成员修改了同一文件中的相同行。
* 文件在一个分支中被移动或删除，但在另一个分支中又被修改。

<div id="resolve-conflicts">
  ### 解决冲突
</div>

当冲突导致无法执行发布或切换分支等操作时，编辑器会显示警告。要解决冲突，请按照编辑器中的说明选择要保留的更改。

<div id="commit-signing">
  ## 提交签名
</div>

在你的[账户设置](https://dashboard.mintlify.com/settings/account)中授权 GitHub 账户后，即可使用该账户为提交签名。若未授权，Mintlify GitHub App 会为在网页编辑器中创建的提交签名。

将提交归属于你的账户，有助于准确记录是谁对文档进行了更改。
