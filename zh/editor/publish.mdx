<div id="publishing-workflows">
  ## 发布工作流
</div>

编辑器支持两种发布文档更新的工作流。你使用哪种工作流取决于代码仓库的分支保护规则以及你当前所在的分支。

* **创建 pull request**：如果你的代码仓库在部署分支上启用了分支保护规则，并要求更改在合并前必须通过 pull request，编辑器会在你发布更改时创建一个 pull request。
* **直接发布**：如果你的代码仓库没有分支保护规则，你的更改会在你发布时直接合并到部署分支并立即部署。

| 分支类型 | 分支保护 | 发布工作流 |
|-------------|-------------------|------------------------------|
| <Tooltip headline="部署分支" tip="用于发布到线上文档站点的分支，通常为「main」。">部署分支</Tooltip> | 无 | 提交并部署更改 |
| 部署分支 | 需要 pull request | 创建一个 pull request |
| <Tooltip headline="功能分支" tip="在合并到部署分支之前，你在其上进行更新工作的独立分支。">功能分支</Tooltip> | 无 | 将更改合并到部署分支并部署更改 |
| 功能分支 | 需要 pull request | 创建一个 pull request |

<Tip>
  在你的 Git 服务提供商中配置分支保护规则以要求使用 pull request。请参阅 GitHub 文档中的 [About protected branches](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches) 或 GitLab 文档中的 [Protected branches](https://docs.gitlab.com/user/project/repository/branches/protected/)。
</Tip>

<div id="save-changes">
  ## 保存更改
</div>

在你进行编辑时，编辑器会跟踪你的更改。

- 新建或删除的文件。
- 页面中的内容修改。
- 导航结构的更改。
- 媒体的上传与管理。
- 配置更新。

当你在部署分支上工作时，你的更改会自动保存。

要丢弃更改，在 **Changes** 下拉列表中文件名旁边点击 **Undo changes**。

<div id="publish-your-changes">
  ### 发布你的更改
</div>

点击工具栏中的 **Publish**。根据你的工作流，你的更改要么会立即部署，要么会创建一个 pull request，供你在 Git 托管服务中合并。如果你当前在功能分支上，请在发布前先保存你的更改。

当没有待处理的更改，或当前分支已经存在已打开的 pull request 时，**Publish** 按钮会被禁用。

## 解决冲突

当你的分支与部署分支在同一文件上存在不兼容的更改时，就会产生冲突。

<div id="what-causes-conflicts">
  ### 冲突产生的原因
</div>

发生冲突的情况包括：

- 你和另一位团队成员编辑了文件中的同一行。
- 在一个分支中某些文件被移动或删除，而在另一个分支中这些文件被修改。

<div id="resolve-conflicts">
  ### 解决冲突
</div>

当冲突导致无法执行发布、切换分支等操作时，编辑器会显示警告。要解决冲突，请按照编辑器中的指示选择要保留的更改。

<div id="commit-signing">
  ## 提交签名
</div>

在你的 [账户设置](https://dashboard.mintlify.com/settings/account) 中授权你的 GitHub 账号来签署提交。如果未授权，网页编辑器中进行的提交将由 Mintlify GitHub 应用代为签署。

将提交归属到你的账号有助于准确记录是谁更改了你的文档。
