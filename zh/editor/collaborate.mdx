通过基于分支的工作流、拉取请求和预览部署，与团队协作文档。

如果你不熟悉 Git，请参阅 [Git 概念](/zh/guides/git-concepts).

<div id="branch-based-collaboration">
  ## 基于分支的协作
</div>

使用分支可并行进行文档更新，而不会影响你的线上站点。

<div id="why-use-branches">
  ### 为什么使用分支
</div>

* **隔离改动**：在不影响线上文档的情况下进行更新。
* **发布前评审**：在更改上线前先获取团队成员的反馈。
* **并行协作**：多个团队成员可以同时在不同分支上工作。

<div id="recommended-workflow">
  ## 推荐工作流程
</div>

在合并到线上文档之前，使用拉取请求提出更改并与团队协作。这样可以确保团队在发布前完成审核，并保留清晰的更新历史。

<Steps>
  <Step title="创建拉取请求">
    准备发布更改时，请在编辑器中创建拉取请求。有关如何使用拉取请求的更多信息，请参阅<a href="/zh/editor/publish">在网页编辑器中发布更改</a>。
  </Step>

  <Step title="审核拉取请求">
    在 GitHub 或 GitLab 等 Git 托管平台中审核拉取请求。
  </Step>

  <Step title="处理反馈">
    当审核者要求修改时，按要求完成修改并保存。后续更改会自动推送到现有的拉取请求。
  </Step>

  <Step title="合并拉取请求">
    在完成所有要求的修改、获得所有必需审核者批准且自动检查全部通过后，合并拉取请求。
  </Step>
</Steps>

<div id="preview-deployments">
  ## 预览部署
</div>

预览部署会创建临时 URL，让你在更改正式上线前查看渲染后的效果。使用预览部署来收集对这些更改的反馈。

<div id="access-preview-deployments">
  ### 访问预览部署
</div>

1. 点击编辑器工具栏中的 **Share**。
2. 点击 **Preview**，在新标签页中打开预览部署。
3. 预览 URL 会显示包含所有已保存更改的文档。

<div id="share-previews">
  ### 分享预览
</div>

将预览部署 URL 分享给团队成员，以收集反馈。保存后续更改后，预览会自动更新。

<div id="preview-authentication">
  ### 预览身份验证
</div>

预览 URL 默认可公开访问。请在控制台的 [Add-ons](https://dashboard.mintlify.com/products/addons) 页面启用预览身份验证，将访问权限仅限于已通过身份验证的组织成员。

<div id="share-editor-links">
  ## 分享编辑器链接
</div>

与团队成员分享可直接打开编辑器中特定页面的链接。你可以使用编辑器链接协作更新并修改页面。

打开某个页面时，编辑器会将该页面路径保存在 URL 中。复制浏览器地址栏中的 URL，即可分享给有权访问编辑器的团队成员。

URL 格式如下：

```
https://dashboard.mintlify.com/{org}/{project}/editor/{branch}?file={filepath}
```

例如，`https://dashboard.mintlify.com/acme/docs/editor/main?file=guides/quickstart.mdx` 会在 `main` 分支中打开 `quickstart.mdx`。

任何有权访问你的 Mintlify 组织的人员，都可以通过该链接直接在编辑器中打开此文件。

<Tip>
  分享页面时，请告知对方你正在使用哪个分支，以便他们确认自己查看的是正确版本。
</Tip>
