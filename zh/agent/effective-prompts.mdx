把代理当作一位需要你引导的得力助手。为它提供清晰的指令和上下文。任务越聚焦，越容易完成，因此请将复杂项目拆分成更小的步骤。

<div id="make-prompts-specific-and-outcome-focused">
  ## 让提示词更具体，并以结果为导向
</div>

像 `@mintlify Improve the onboarding page` 这样笼统的提示词会套用通用最佳实践，但未必能按照你预期的具体方式改进内容。

试着围绕你希望用户达成的结果，或他们实际遇到的问题来编写提示词。

* `@mintlify 很多用户在安装 CLI 时遇到困难。请检查入门页面并更新文档，让用户能够轻松安装 CLI`
* `@mintlify 开发者按照我们的身份验证指南操作时总是遇到 401 错误。请检查身份验证文档，并添加更清晰的示例，说明如何正确设置 API 密钥的格式`

<div id="use-broad-prompts-for-maintenance-tasks">
  ## 对维护任务使用宽泛的提示词
</div>

对于修正错别字、更新重定向，或在整个文档中统一重命名某个功能这类常规内容维护任务，请使用宽泛的提示词。

* `@mintlify Find and fix all typos in the docs`
* `@mintlify change all unordered lists to use * instead of -`

<div id="specify-a-domain-name-for-multi-site-organizations">
  ## 为多站点组织指定域名
</div>

如果您有多个文档站点，请在消息中加入 `subdomain` 参数，以指定代理应处理哪个文档集。

要查找您的域名，请查看您想要更新的文档集对应的控制台 URL。域名是组织名称后面的最后一部分。例如，如果您的控制台 URL 是 `https://dashboard.mintlify.com/org-name/domain-name`，那么您的域名就是 `domain-name`。

使用 `@mintlify subdomain=<your-domain-name> <your-prompt>` 这一格式，指示代理处理特定的文档集。

* `@mintlify subdomain=public-docs Add a new section to the quickstart about inviting collaborators based on this PR`：指示代理仅更新 `public-docs` 站点上的 quickstart。
* `@mintlify subdomain=customer-docs Update the auth docs for the new authentication method`：指示代理仅更新 `customer-docs` 站点上的 auth 文档。
