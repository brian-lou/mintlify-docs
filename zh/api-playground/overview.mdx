API 操作台是一个交互式环境，用户可以直接测试和探索你的 API 端点。开发者无需离开文档，即可构建 API 请求、提交请求并查看响应。

请参阅[触发更新](/zh/api/update/trigger)，了解 API 操作台的实际效果。

  <img src="/images/playground/API-playground-dark.png" alt="“触发更新”端点的 API 操作台。" className="hidden dark:block" />
</Frame>

操作台会根据你的 OpenAPI 规范或 AsyncAPI 模式，为各个端点生成交互式页面。如果你修改了 API，操作台会自动更新相关页面。

我们建议根据 OpenAPI 规范生成 API 操作台。不过，在 `docs.json` 中定义基础 URL 和身份验证方式后，你也可以手动创建 API 参考页面。

<div id="get-started">
  ## 开始使用
</div>

<Steps>
  <Step title="添加 OpenAPI 规范文件。">
    <Tip>
      使用 [Swagger Editor](https://editor.swagger.io/) 或 [Mint CLI](https://www.npmjs.com/package/mint) 命令 `mint openapi-check <filename>` 验证 OpenAPI 规范文件。
    </Tip>

    ```bash {3}
    /your-project
      |- docs.json
      |- openapi.json
    ```
  </Step>

  <Step title="生成端点页面。">
    更新 `docs.json` 以引用 OpenAPI 规范。

    **如需为 OpenAPI 规范中的所有端点自动生成页面**，请为任意导航元素添加 `openapi` 属性。

    此示例会为 `openapi.json` 中定义的每个端点生成一个页面，并将这些页面归入“API reference”分组。

    ```json 生成所有端点页面
    "navigation": {
      "groups": [
        {
          "group": "API reference",
          "openapi": "openapi.json"
        }
      ]
    }
    ```

    **如仅为特定端点生成页面**，请在导航元素的 `pages` 属性中列出这些端点。

    此示例仅为 `GET /users` 和 `POST /users` 端点生成页面。要生成其他端点页面，请将更多端点添加到 `pages` 数组中。

    ```json 生成特定端点页面
    "navigation": {
      "groups": [
          {
            "group": "API reference",
            "openapi": "openapi.json",
            "pages": [
              "GET /users",
              "POST /users"
            ]
          }
      ]
    }
    ```
  </Step>
</Steps>

<div id="customize-your-playground">
  ## 自定义 API 操作台
</div>

在 `docs.json` 中定义以下属性，以自定义 API 操作台。

<ResponseField name="playground" type="object">
  API 操作台的配置。

  <Expandable title="playground" defaultOpen="True">
    <ResponseField name="display" type="&#x22;interactive&#x22; | &#x22;simple&#x22; | &#x22;none&#x22; | &#x22;auth&#x22;">
      API 操作台的显示模式。

      * `"interactive"`：显示交互式操作台。
      * `"simple"`：显示可复制的端点，不显示操作台。
      * `"none"`：不显示任何内容。
      * `"auth"`：仅向已登录用户显示交互式操作台。未登录用户或不在所需组中的用户将看不到操作台。

      默认为 `interactive`。
    </ResponseField>

    <ResponseField name="proxy" type="boolean" defaultOpen="True">
      是否通过代理服务器转发 API 请求。默认为 `true`。
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="examples" type="object">
  自动生成的 API 示例配置。

  <Expandable title="examples" defaultOpen="True">
    <ResponseField name="languages" type="array of string">
      自动生成的 API 代码示例所使用的语言。

      语言会按指定顺序显示。
    </ResponseField>

    <ResponseField name="defaults" type="&#x22;required&#x22; | &#x22;all&#x22;">
      是否在 API 示例中显示可选参数。默认为 `all`。
    </ResponseField>

    <ResponseField name="prefill" type="boolean">
      是否使用 schema 示例中的数据预填充 API 操作台。启用后，操作台会自动用 OpenAPI 规范中的示例值填充请求字段。默认为 `false`。
    </ResponseField>

    <ResponseField name="autogenerate" type="boolean">
      是否根据 API 规范为端点生成代码示例。默认为 `true`。设置为 `false` 时，API 操作台中只会显示手动编写的代码示例 (来自 OpenAPI 规范中的 `x-codeSamples` 或 MDX 中的 `<RequestExample>` 组件) 。
    </ResponseField>
  </Expandable>
</ResponseField>

<div id="example-configuration">
  ### 示例配置
</div>

此示例将 API 操作台配置为可交互模式，并提供 cURL、Python 和 JavaScript 的示例代码片段。代码片段中仅显示必填参数，操作台还会用示例值预填充请求体。

```json
{
 "api": {
   "playground": {
     "display": "interactive"
   },
   "examples": {
     "languages": ["curl", "python", "javascript"],
     "defaults": "required",
     "prefill": true
   }
 }
}
```

<div id="auth-based-playground-display">
  ### 基于身份验证的 操作台 显示
</div>

使用 `auth` 显示模式，仅向已登录用户显示交互式 操作台。当你希望用户可以公开查看 API 文档，同时仅允许登录用户访问 操作台 时，这种方式很有用。

当 `display` 设置为 `auth` 时：

* 已登录用户会看到交互式 操作台。
* 未登录用户不会看到 操作台 (等同于 `none`) 。

你还可以将 `auth` 与页面前置元数据中的 `groups` 属性结合使用，将 操作台 的访问权限限制为特定用户组。

```mdx Page with group-restricted playground
---
title: "Create user"
openapi: POST /users
playground: auth
groups: ["admin", "developer"]
public: true
---
```

在这个示例中：

* 页面是公开可见的 (任何人都可以查看文档) 。
* 只有 `admin` 或 `developer` 组中的已认证用户才能看到交互式 操作台。
* 不在这些组中的用户将看不到 操作台。

如果页面没有 `groups` 属性，所有已认证用户都可以看到交互式 操作台。

<Note>
  `auth` 显示模式要求先为你的文档配置[身份验证](/zh/deploy/authentication-setup)。
</Note>

<div id="custom-endpoint-pages">
  ### 自定义端点页面
</div>

当你需要更灵活地控制 API 文档时，可以在 OpenAPI 规范中使用 `x-mint` 扩展，或为各个端点创建单独的 MDX 页面。

这两种方式都可以让你：

* 自定义页面元数据
* 添加示例等额外内容
* 按页面控制 操作台 的行为

推荐使用 `x-mint` 扩展，这样你的所有 API 文档都可以根据 OpenAPI 规范自动生成，并集中在一个文件中维护。

如果是小型 API，或者你想按页面逐一试验修改，则更推荐使用单独的 MDX 页面。
