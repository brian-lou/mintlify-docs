<div id="add-an-asyncapi-specification-file">
  ## 添加 AsyncAPI 规范文件
</div>

要为你的 WebSocket 创建页面，你必须提供一份有效的 AsyncAPI 模式文档，格式为 JSON 或 YAML，并且符合 [AsyncAPI 3.0 规范](https://www.asyncapi.com/docs/reference/specification/v3.0.0)。

<Tip>
  使用 [AsyncAPI Studio](https://studio.asyncapi.com/) 验证你的 AsyncAPI 模式。
</Tip>

```json {3}
/your-project
  |- docs.json
  |- asyncapi.json
```

<div id="auto-populate-websockets-pages">
  ## 自动填充 WebSocket 页面
</div>

要为 AsyncAPI 模式中的所有通道自动生成页面，请在任一导航元素中添加 `asyncapi` 属性。`asyncapi` 属性可以接受以下内容：文档仓库中 AsyncAPI 模式文档的路径、托管的 AsyncAPI 文档 URL，或指向 AsyncAPI 模式文档的链接数组。

<div id="examples-with-tabs">
  ### 标签页示例
</div>

<CodeGroup>
  ```json 本地文件
  "navigation": {
    "tabs": [
      {
          "tab": "API Reference",
          "asyncapi": "/path/to/asyncapi.json"
      }
    ]
  }

  ```

  ```json 远程 URL
  "navigation": {
    "tabs": [
      {
          "tab": "API Reference",
          "asyncapi": "https://github.com/asyncapi/spec/blob/master/examples/simple-asyncapi.yml"
      }
    ]
  }
  ```

  ```json 多个文件
  "navigation": {
    "tabs": [
      {
        "tab": "API Reference",
        "asyncapi": [
          "/path/to/events.json",
          "/path/to/webhooks.json"
        ]
      }
    ]
  }
  ```
</CodeGroup>

<Note>
  当你指定多个 AsyncAPI 文件时，每个文件都会生成各自的一组通道页面。
</Note>

<div id="examples-with-groups">
  ### 分组示例
</div>

```json
"navigation": {
  "tabs": [
    {
      "tab": "AsyncAPI",
      "groups": [
        {
          "group": "Websockets",
          "asyncapi": {
            "source": "/path/to/asyncapi.json",
            "directory": "websockets"
          }
        }
      ]
    }
  ]
}
```

<Note>
  `directory` 字段为可选项。若未指定，文件将放在文档仓库的 **api-reference** 文件夹中。
</Note>

<div id="channel-page">
  ## 通道页面
</div>

如果你想更灵活地控制通道的排序，或者只引用特定通道，请创建一个在前置元数据中包含 `asyncapi` 属性的 MDX 文件。

```mdx
---
title: "Websocket Channel"
asyncapi: "/path/to/asyncapi.json channelName"
---
```
