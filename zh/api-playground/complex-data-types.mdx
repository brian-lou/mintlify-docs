当你的 API 接受多种数据格式、包含条件字段或使用继承模式时，OpenAPI 的模式组合关键字可以帮助你为这些灵活的结构编写文档。通过使用 `oneOf`、`anyOf` 和 `allOf`，你可以描述既能处理不同输入类型、又能将多个模式组合成完整数据模型的 API。

<div id="oneof-anyof-allof-keywords">
  ## `oneOf`, `anyOf`, `allOf` 关键字
</div>

对于复杂数据类型，OpenAPI 提供了用于组合 schema 的关键字：

- `allOf`：组合多个 schema（类似合并对象或基于基础 schema 进行扩展）。作用类似于 `and` 运算符。 
- `anyOf`：接受与任一给定 schema 匹配的数据。作用类似于 `or` 运算符。
- `oneOf`：仅接受与给定 schema 中恰好一个匹配的数据。作用类似于 “异或”（`exclusive-or`）运算符。

<Warning>Mintlify 会将 `oneOf` 和 `anyOf` 视为相同，因为在实际使用 API 时二者的差异很少会产生影响。</Warning>

有关这些关键字的详细规范，请参阅 [OpenAPI 文档](https://swagger.io/docs/specification/data-models/oneof-anyof-allof-not/)。

<Info>`not` 关键字目前尚不支持。</Info>

<div id="combining-schemas-with-allof">
  ### 使用 `allOf` 组合 schema
</div>

当你使用 `allOf` 时，Mintlify 会对你的 OpenAPI 文档进行一些预处理，以更易读的方式展示复杂的组合。比如，当你用 `allOf` 合并两个对象 schema 时，Mintlify 会将这两个对象的属性合并到一个对象中。当你利用 OpenAPI 中可复用的 [components](https://swagger.io/docs/specification/components/) 时，这一点会尤其有用。

```yaml
org_with_users:
  allOf:
    - $ref: '#/components/schemas/Org'
    - type: object
      properties:
        users:
          type: array
          description: 包含组织中所有用户的数组
# ...
components:
  schemas:
    Org:
      type: object
      properties:
        id:
          type: string
          description: 组织的 ID
```

    <ParamField body="users" type="object[]">

<div id="providing-options-with-oneof-and-anyof">
  ### 使用 `oneOf` 和 `anyOf` 提供选项
</div>

当你使用 `oneOf` 或 `anyOf` 时，选项会显示在带选项卡的容器中。在每个子模式中指定一个 `title` 字段，为各个选项命名。比如，下面是展示两种不同类型收货地址的方式：

```yaml
delivery_address:
  oneOf:
    - title: StreetAddress
      type: object
      properties:
        address_line_1:
          type: string
          description: 收件人的街道地址
        # ...
    - title: POBox
      type: object
      properties:
        box_number:
          type: string
          description: 邮政信箱编号
        # ...
```
