title: "管理页面可见性"
description: "控制哪些 API 端点会显示在文档导航中。"

---

对于仅供内部使用的端点、已弃用的操作、测试版功能，或应可通过直接 URL 访问但不应在站点导航中显示的端点，你可以控制哪些 OpenAPI 操作会发布为文档页面，以及它们在导航中的显示方式。

如果你的页面是根据 OpenAPI 文档自动生成的，请使用 `x-hidden` 和 `x-excluded` 扩展来管理页面可见性。

<div id="x-hidden">
  ## `x-hidden`
</div>

`x-hidden` 扩展会为某个端点创建页面，但不会在导航中显示。只有直接访问其 URL 才能打开该页面。

`x-hidden` 的常见用途包括：

* 你想编写文档，但不想突出展示的端点。
* 你会从其他内容链接到的页面。
* 面向特定用户的端点。

<div id="x-excluded">
  ## `x-excluded`
</div>

`x-excluded` 扩展会将某个端点从文档中完全排除。

`x-excluded` 的常见使用场景包括：

* 仅供内部使用的端点。
* 不希望在文档中体现的已弃用端点。
* 尚未准备好对外公开文档的 测试版功能。

<div id="implementation">
  ## 实现
</div>

在 OpenAPI 规范中，于 HTTP 方法下添加 `x-hidden` 或 `x-excluded` 扩展。

以下示例展示了如何在 OpenAPI Schema 文档中，针对端点和 webhook 路径使用这两个属性。

```json Endpoint example {11, 19}
"paths": {
  "/plants": {
    "get": {
      "description": "Returns all plants from the store",
      "parameters": { /*...*/ },
      "responses": { /*...*/ }
    }
  },
  "/hidden_plants": {
    "get": {
      "x-hidden": true,
      "description": "Returns all somewhat secret plants from the store",
      "parameters": { /*...*/ },
      "responses": { /*...*/ }
    }
  },
  "/secret_plants": {
    "get": {
      "x-excluded": true,
      "description": "Returns all top secret plants from the store (do not publish this endpoint!)",
      "parameters": { /*...*/ },
      "responses": { /*...*/ }
    }
  }
},
```

```json Webhook example {9, 15}
"webhooks": {
  "/plants_hook": {
    "post": {
      "description": "Webhook for information about a new plant added to the store",
    }
  },
  "/hidden_plants_hook": {
    "post": {
      "x-hidden": true,
      "description": "Webhook for somewhat secret information about a new plant added to the store"
    }
  },
  "/secret_plants_hook": {
    "post": {
      "x-excluded": true,
      "description": "Webhook for top secret information about a new plant added to the store (do not publish this endpoint!)"
    }
  }
}
```
