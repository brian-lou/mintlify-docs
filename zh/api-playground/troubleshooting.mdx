如果你的 API 页面未正确显示，请检查以下常见配置问题。

<AccordionGroup>
  <Accordion title="我所有的 OpenAPI 页面都完全是空白的">
    在这种情况下，很可能是 Mintlify 找不到你的 OpenAPI 文档，
    或者你的 OpenAPI 文档无效。

    在本地运行 `mint dev` 应该可以发现其中的一些问题。

    要验证你的 OpenAPI 文档是否能通过验证：

    1. 访问[这个验证器](https://editor.swagger.io/)
    2. 切换到 “Validate text” 选项卡
    3. 粘贴你的 OpenAPI 文档
    4. 点击 “Validate it!”

    如果下面出现的文本框有绿色边框，则表示你的文档已通过验证。
    这是 Mintlify 用来验证 OpenAPI 文档的同一个验证包，因此如果你的文档
    在这里通过了验证，那么很大可能问题出在其他地方。

    另外，Mintlify 不支持 OpenAPI 2.0。若你的文档使用的是该版本规范，
    就可能会遇到这个问题。你可以在 [editor.swagger.io](https://editor.swagger.io/) 中转换你的文档（在 Edit &gt; Convert to OpenAPI 3 下）：

    <Frame>
      ![Swagger Editor 的屏幕截图，其中 Edit 菜单已展开，并高亮显示了 “Convert to OpenAPI 3” 菜单项。](/images/convert-oas-3.png)
    </Frame>
  </Accordion>

  <Accordion title="我的一个 OpenAPI 页面完全是空白的">
    这通常是由于页面元数据中的 `openapi` 字段拼写错误引起的。请确保
    HTTP 方法和路径与 OpenAPI 文档中的 HTTP 方法和路径完全一致。

    下面是一个可能出现问题的示例：

    ```mdx get-user.mdx
    ---
    openapi: "GET /users/{id}/"
    ---
    ```

    ```yaml openapi.yaml
    paths:
      "/users/{id}":
        get: ...
    ```

    请注意，`openapi` 字段中的路径末尾带有斜杠，而 OpenAPI 文档中的路径则没有。

    另一个常见问题是文件名拼写错误。如果你在 `openapi` 字段中指定了某个特定的 OpenAPI 文档，请确保文件名正确。例如，如果你有两个 OpenAPI 文档 `openapi/v1.json` 和 `openapi/v2.json`，你的元数据可能如下所示：

    ```mdx api-reference/v1/users/get-user.mdx
    ---
    openapi: "v1 GET /users/{id}"
    ---
    ```
  </Accordion>

  <Accordion title="从 API Playground 发出的请求不起作用">
    如果你配置了自定义域名，那么问题可能出在你的反向代理上。默认情况下，通过 API Playground 发起的请求会首先向文档站点上 `/_mintlify/api/request` 路径发送一个 `POST` 请求。如果你的反向代理被配置为仅允许 `GET` 请求，那么所有这些请求都会失败。要解决这个问题，请将反向代理配置为允许对 `/_mintlify/api/request` 路径的 `POST` 请求。

    或者，如果你的反向代理不允许你接受 `POST` 请求，你可以在 `docs.json` 中通过 `api.playground.proxy` 设置来配置 Mintlify 直接向你的后端发送请求，具体如[设置文档](/zh/organize/settings#param-proxy)中所述。使用这种配置时，你需要在服务器上配置 CORS，因为请求将直接从用户的浏览器发出，而不是通过你的代理。
  </Accordion>

  <Accordion title="OpenAPI 导航项未生成页面">
    如果你使用的是 OpenAPI 导航配置，但页面没有生成，请检查以下常见问题：

    1. **缺少默认 OpenAPI 规范**：请确保已为该导航元素配置 `openapi` 字段：

    ```json {5}
    "navigation": {
      "groups": [
        {
          "group": "API reference",
          "openapi": "/path/to/openapi.json",
          "pages": [
            "GET /users",
            "POST /users"
          ]
        }
      ]
    }
    ```

    2. **OpenAPI 规范继承**：如果使用嵌套导航，请确保子分组继承正确的 OpenAPI 规范，或为其指定自己的规范。

    3. **验证问题**：使用 `mint openapi-check <path-to-openapi-file>` 来验证你的 OpenAPI 文档是否有效。
  </Accordion>

  <Accordion title="某些 OpenAPI 操作会显示在导航中，而其他则不会显示">
    1. **隐藏的操作**：在你的 OpenAPI 规范中标记为 `x-hidden: true` 的操作不会出现在自动生成的导航中。
    2. **无效的操作**：在 OpenAPI 规范中存在验证错误的操作可能会被跳过。请检查你的 OpenAPI 文档是否存在语法错误。
    3. **手动与自动包含**：如果你从某个 OpenAPI 规范中引用了任何端点，只有被显式引用的操作会出现在导航中，不会自动添加其他页面。这也包括在子导航元素中被引用的操作。
  </Accordion>

  <Accordion title="混合导航（OpenAPI 与 MDX 页面）无法正常工作">
    在导航中同时使用 OpenAPI 操作和常规文档页面时：

    1. **文件冲突**：同一个操作不能既有一个 `MDX` 文件，又在导航中单独配置一个条目。例如，如果你有 `get-users.mdx`，就不要在导航中再包含 `"GET /users"`。如果你确实需要一个与某个操作同名的文件，请为该端点使用 `x-mint` 扩展，让 href 指向其他位置。
    2. **路径解析**：与 OpenAPI 操作不匹配的导航条目会被视为文件路径。请确保你的 `MDX` 文件存在于预期的位置。
    3. **大小写敏感**：OpenAPI 操作匹配区分大小写。请确保导航条目中的 HTTP 方法使用大写字母。
  </Accordion>
</AccordionGroup>
