OpenAPI 是一种用于描述 API 的规范。Mintlify 支持 OpenAPI 3.0 和 3.1 文档，可自动生成交互式 API 文档并保持其最新状态。

<div id="add-an-openapi-specification-file">
  ## 添加 OpenAPI 规范文件
</div>

要使用 OpenAPI 为端点编写文档，你需要一个或多个有效的 OpenAPI 规范文件，格式为 JSON 或 YAML，并且符合 [OpenAPI specification 3.0 or 3.1](https://swagger.io/specification/)。

将 OpenAPI 规范文件添加到文档仓库中，或将其托管到可通过 URL 访问的位置。

在 `docs.json` 的 navigation 中引用任意数量的 OpenAPI 规范，即可为 API 端点创建页面。每个规范文件都会生成各自的一组端点页面。

<CodeGroup>
  ```json 单个规范
  "navigation": {
    "tabs": [
      {
        "tab": "API Reference",
        "openapi": "openapi.json"
      }
    ]
  }
  ```

  ```json 多个规范
  "navigation": {
    "tabs": [
      {
        "tab": "API Reference",
        "openapi": [
          "openapi/v1.json",
          "openapi/v2.json"
        ]
      }
    ]
  }
  ```
</CodeGroup>

<Note>
  Mintlify 支持在单个 OpenAPI 文档中使用 `$ref`，但**仅限内部引用**。不支持外部引用。
</Note>

<div id="describe-your-api">
  ### 描述你的 API
</div>

我们建议参考以下资源，了解并编写你的 OpenAPI 规范。

* 阅读 [Swagger 的 OpenAPI 指南](https://swagger.io/docs/specification/v3_0/basic-structure/)，学习 OpenAPI 语法。
* 查阅 [OpenAPI 规范的 Markdown 源文件](https://github.com/OAI/OpenAPI-Specification/blob/main/versions/)，了解最新 OpenAPI 规范的详细信息。
* 使用 [Swagger Editor](https://editor.swagger.io/) 编辑、验证和调试你的 OpenAPI 文档。
* 使用 [Mint CLI](https://www.npmjs.com/package/mint) 通过以下命令验证你的 OpenAPI 文档：`mint openapi-check <openapiFilenameOrUrl>`。

<Note>
  Swagger 的 OpenAPI 指南适用于 OpenAPI v3.0，但其中几乎所有内容同样适用于 v3.1。有关 v3.0 与 v3.1 之间差异的更多信息，请参阅 OpenAPI 博客中的 [从 OpenAPI 3.0 迁移到 3.1.0](https://www.openapis.org/blog/2021/02/16/migrating-from-openapi-3-0-to-3-1-0)。
</Note>

<div id="specify-the-base-url-for-your-api">
  ### 指定 API 的基础 URL
</div>

要启用 API 操作台，请在 OpenAPI 规范中添加 `servers` 字段，并填写 API 的基础 URL。

```json
{
  "servers": [
    {
      "url": "https://api.example.com/v1"
    }
  ]
}
```

在 OpenAPI 规范中，不同的 API 端点由各自的路径指定，例如 `/users/{id}` 或直接使用 `/`。基础 URL 决定了这些路径应追加到哪个地址。有关如何配置 `servers` 字段的更多信息，请参阅 OpenAPI 文档中的 [API Server and Base Path](https://swagger.io/docs/specification/api-host-and-base-path/)。

API 操作台会使用这些服务器 URL 来确定请求应发送到哪里。如果你指定了多个服务器，用户可以通过下拉菜单在不同服务器之间切换。如果你没有指定服务器，API 操作台会使用简单模式，因为没有基础 URL 时它无法发送请求。

如果你的 API 端点分布在不同的 URL 下，你可以针对特定路径或操作[覆盖 `servers` 字段](https://swagger.io/docs/specification/v3_0/api-host-and-base-path/#overriding-servers)。

<div id="specify-authentication">
  ### 指定身份验证
</div>

要在 API 文档和 API 操作台中启用身份验证，请在 OpenAPI 规范中配置 `securitySchemes` 和 `security` 字段。API 描述和 API 操作台会根据 OpenAPI 规范中的安全配置添加身份验证字段。

<Steps>
  <Step title="定义身份验证方式。">
    添加 `securitySchemes` 字段，定义用户如何进行身份验证。

    此示例展示了 Bearer 身份验证的配置。

    ```json
    {
      "components": {
        "securitySchemes": {
          "bearerAuth": {
            "type": "http",
            "scheme": "bearer"
          }
        }
      }
    }
    ```
  </Step>

  <Step title="将身份验证应用到端点。">
    添加 `security` 字段，以要求进行身份验证。

    ```json
    {
      "security": [
        {
          "bearerAuth": []
        }
      ]
    }
    ```
  </Step>
</Steps>

常见的身份验证类型包括：

* [API Keys](https://swagger.io/docs/specification/authentication/api-keys/)：用于基于请求头、查询参数或 Cookie 的密钥。
* [Bearer](https://swagger.io/docs/specification/authentication/bearer-authentication/)：用于 JWT 或 OAuth 令牌。
* [Basic](https://swagger.io/docs/specification/authentication/basic-authentication/)：用于用户名和密码。

如果 API 中的不同端点需要不同的身份验证方式，你可以为特定操作[覆盖 `security` 字段](https://swagger.io/docs/specification/authentication/#:~:text=you%20can%20apply%20them%20to%20the%20whole%20API%20or%20individual%20operations%20by%20adding%20the%20security%20section%20on%20the%20root%20level%20or%20operation%20level%2C%20respectively.)。

有关如何定义和应用身份验证的更多信息，请参阅 OpenAPI 文档中的 [Authentication](https://swagger.io/docs/specification/authentication/)。

<div id="customize-your-endpoint-pages">
  ## 自定义端点页面
</div>

在 OpenAPI 规范中添加 `x-mint` 扩展，自定义你的端点页面。`x-mint` 扩展可让你更灵活地控制 API 文档的生成和显示方式。

<div id="metadata">
  ### 元数据
</div>

在任意操作中添加 `x-mint: metadata`，即可覆盖自动生成的 API 页面的默认元数据。除了 `openapi` 之外，你可以使用任何可用于 MDX 前置元数据的元数据字段。

```json {7-13}
{
  "paths": {
    "/users": {
      "get": {
        "summary": "Get users",
        "description": "Retrieve a list of users",
        "x-mint": {
          "metadata": {
            "title": "List all users",
            "description": "Fetch paginated user data with filtering options",
            "og:title": "Display a list of users"
          }
        },
        "parameters": [
          {
            // 参数配置
          }
        ]
      }
    }
  }
}
```

你也可以使用 `playground` 和 `groups` 元数据字段，针对各个端点控制 API 操作台的显示：

```json {7-11}
{
  "paths": {
    "/admin/users": {
      "post": {
        "summary": "Create admin user",
        "x-mint": {
          "metadata": {
            "playground": "auth",
            "groups": ["admin"],
            "public": true
          }
        }
      }
    }
  }
}
```

此配置会使页面公开可见，同时将交互式 API 操作台仅限 `admin` 组中的已认证用户使用。

<div id="content">
  ### 内容
</div>

使用 `x-mint: content` 可在自动生成的 API 文档前添加内容。`x-mint: content` 扩展支持所有 Mintlify MDX 组件和格式。

```json {6-8}
{
  "paths": {
    "/users": {
      "post": {
        "summary": "Create user",
        "x-mint": {
          "content": "## Prerequisites\n\nThis endpoint requires admin privileges and has rate limiting.\n\n<Note>User emails must be unique across the system.</Note>"
        },
        "parameters": [
          {
            // 参数配置
          }
        ]
      }
    }
  }
}
```

<div id="href">
  ### Href
</div>

使用 `x-mint: href` 设置自动生成的端点页面 URL。指定 `x-mint: href` 后，生成的 API 页面会使用该 URL，而不是默认的自动生成 URL。

```json {6-8, 14-16}
{
  "paths": {
    "/legacy-endpoint": {
      "get": {
        "summary": "Legacy endpoint",
        "x-mint": {
          "href": "/deprecated-endpoints/legacy-endpoint"
        }
      }
    },
    "/documented-elsewhere": {
      "post": {
        "summary": "Special endpoint",
        "x-mint": {
          "href": "/guides/special-endpoint-guide"
        }
      }
    }
  }
}
```

<div id="auto-populate-api-pages">
  ## 自动生成 API 页面
</div>

在 `docs.json` 中，为任意导航元素添加 `openapi` 字段，即可自动为 OpenAPI 端点生成页面。你可以控制这些页面在导航结构中的显示位置，既可以将其作为独立的 API 章节，也可以与其他页面一同显示。

`openapi` 字段既可以填写文档仓库中的文件路径，也可以填写托管的 OpenAPI 文档 URL。

生成的端点页面默认包含以下元数据值：

* `title`：操作的 `summary` 字段 (如果存在) 。如果没有 `summary`，则根据 HTTP 方法和端点自动生成标题。
* `description`：操作的 `description` 字段 (如果存在) 。
* `version`：父锚点或标签页中的 `version` 值 (如果存在) 。
* `deprecated`：操作的 `deprecated` 字段。如果为 `true`，则会在侧边导航中的端点标题旁以及端点页面上显示“已弃用”标签。

<Tip>
  如果要将特定端点从自动生成的 API 页面中排除，请在 OpenAPI 规范中为该操作添加 [x-hidden](/zh/api-playground/managing-page-visibility#x-hidden) 属性。
</Tip>

将端点页面添加到文档中有两种方式：

1. **独立的 API 章节**：在用于独立 API 章节的导航元素中引用 OpenAPI 规范。
2. **选择性添加端点**：在导航中与其他页面一起引用特定端点。

<div id="dedicated-api-sections">
  ### 独立的 API 章节
</div>

在某个导航项中添加 `openapi` 字段，且不添加任何其他页面，即可生成独立的 API 章节。规范中的所有端点都会包含在内。

```json {5}
"navigation": {
  "tabs": [
    {
        "tab": "API Reference",
        "openapi": "https://petstore3.swagger.io/api/v3/openapi.json"
    }
  ]
}
```

要将多个 OpenAPI 规范分别整理到文档的不同部分，请在导航层级中将每个规范分配到不同的组。每个组都可以引用各自的 OpenAPI 规范。

```json {8-11, 15-18}
"navigation": {
  "tabs": [
    {
      "tab": "API Reference",
      "groups": [
        {
          "group": "Users API",
          "openapi": {
            "source": "/path/to/users-openapi.json",
            "directory": "users-api-reference"
          }
        },
        {
          "group": "Admin API",
          "openapi": {
            "source": "/path/to/admin-openapi.json",
            "directory": "admin-api-reference"
          }
        }
      ]
    }
  ]
}
```

<Note>
  `directory` 字段为可选项，用于指定生成的 API 页面在文档仓库中的存储位置。若未指定，则默认使用仓库中的 `api-reference` 目录。
</Note>

<div id="selective-endpoints">
  ### 选择特定端点
</div>

当你希望更灵活地控制端点在文档中的显示位置时，可以在导航中引用特定端点。通过这种方式，你可以为 API 端点生成页面，并将其与其他内容一起展示。你也可以用这种方式混合来自不同 OpenAPI 规范的端点。

<div id="set-a-default-openapi-spec">
  #### 设置默认 OpenAPI 规范
</div>

为某个导航项配置默认的 OpenAPI 规范，然后在 `pages` 字段中引用具体的端点。

```json {12, 15-16}
"navigation": {
  "tabs": [
    {
      "tab": "Getting started",
      "pages": [
        "quickstart",
        "installation"
      ]
    },
    {
      "tab": "API reference",
      "openapi": "/path/to/openapi.json",
      "pages": [
        "api-overview",
        "GET /users",
        "POST /users",
        "guides/authentication"
      ]
    }
  ]
}
```

任何符合 `METHOD /path` 格式的页面条目，都会使用默认的 OpenAPI 规范为该端点生成 API 页面。

<div id="openapi-spec-inheritance">
  #### OpenAPI 规范继承
</div>

OpenAPI 规范会沿导航层级向下继承。子级导航项会继承父级的 OpenAPI 规范，除非自行定义了规范。

```json {3, 7-8, 11, 13-14}
{
  "group": "API reference",
  "openapi": "/path/to/openapi-v1.json",
  "pages": [
    "overview",
    "authentication",
    "GET /users",
    "POST /users",
    {
      "group": "Orders",
      "openapi": "/path/to/openapi-v2.json",
      "pages": [
        "GET /orders",
        "POST /orders"
      ]
    }
  ]
}
```

<div id="individual-endpoints">
  #### 单个端点
</div>

通过包含文件路径，你可以在不设置默认 OpenAPI 规范的情况下引用特定端点。你也可以在同一文档章节中引用来自多个 OpenAPI 规范的端点。

```json {5-6}
"navigation": {
  "pages": [
    "introduction",
    "user-guides",
    "/path/to/users-openapi.json POST /users",
    "/path/to/orders-openapi.json GET /orders"
  ]
}
```

当你需要从不同规范中提取单个端点、只想包含部分端点，或想将端点与其他类型的文档一起展示时，这种方法会很有用。

<div id="create-mdx-pages-from-your-openapi-specification">
  ## 根据 OpenAPI 规范创建 MDX 页面
</div>

如果你想更精细地控制各个端点页面，可以根据 OpenAPI 规范创建 MDX 页面。这样，你既能继续使用自动生成的参数和响应，也能自定义页面元数据和内容，并在导航中调整页面顺序或将其排除。

你可以通过两种方式，使用单独的 MDX 页面为 OpenAPI 规范编写文档：

* 通过前置元数据中的 `openapi` 字段为端点编写文档。
* 通过前置元数据中的 `openapi-schema` 字段为数据模型编写文档。

<div id="document-endpoints">
  ### 为端点编写文档
</div>

为每个端点创建一个页面，并使用前置元数据中的 `openapi` 字段指定要显示的 OpenAPI 操作。

<CodeGroup>
  ```mdx Example
  ---
  title: "Get users"
  description: "Returns all plants from the system that the user has access to"
  openapi: "/path/to/openapi-1.json GET /users"
  deprecated: true
  version: "1.0"
  ---
  ```

  ```mdx Format
  ---
  title: "title of the page"
  description: "description of the page"
  openapi: openapi-file-path method path
  deprecated: boolean (not required)
  version: "version-string" (not required)
  ---
  ```
</CodeGroup>

方法和路径必须与您的 OpenAPI 规范完全一致。如果您有多个 OpenAPI 规范，请在引用中包含文件路径。您也可以在 `docs.json` 中引用外部 OpenAPI URL。

<div id="autogenerate-endpoint-pages">
  #### 自动生成端点页面
</div>

要根据 OpenAPI 规范自动生成 MDX 文件，请使用 Mintlify 的 [scraper](https://www.npmjs.com/package/@mintlify/scraping)。

```bash
npx @mintlify/scraping@latest openapi-file <path-to-openapi-file> -o <folder-name>
```

<Tip>
  添加 `-o` 标志以指定文件要生成到哪个文件夹。如果未指定文件夹，文件将生成到当前工作目录中。
</Tip>

<div id="document-data-models">
  ### 为数据模型编写文档
</div>

使用前置元数据中的 `openapi-schema` 字段，为 OpenAPI 规范中 `components.schemas` 定义的每个数据结构创建一个页面。

<CodeGroup>
  ```mdx Example
  ---
  openapi-schema: OrderItem
  ---
  ```

  ```mdx Format
  ---
  openapi-schema: "openapi-file-path schema-key"
  ---
  ```
</CodeGroup>

如果多个文件中存在同名 schema，请指定 OpenAPI 文件：

<CodeGroup>
  ```mdx Example
  ---
  openapi-schema: en-schema.json OrderItem
  ---
  ```

  ```mdx Format
  ---
  openapi-schema: "path-to-schema-file schema-key"
  ---
  ```
</CodeGroup>

<div id="webhooks">
  ## Webhooks
</div>

Webhooks 是由你的 API 发送的 HTTP 回调，用于在事件发生时通知外部系统。OpenAPI 3.1+ 文档支持 Webhooks。

在 OpenAPI 文档中，添加一个 `webhooks` 字段，与 `paths` 字段同级。

有关定义 Webhooks 的更多信息，请参阅 OpenAPI 文档中的 [Webhooks](https://spec.openapis.org/oas/v3.1.0#oasWebhooks)。

要为 webhook (OpenAPI 3.1+) 创建 MDX 页面，请使用 `webhook`，而不是 HTTP 方法：

```mdx
---
title: "Order updated webhook"
description: "Triggered when an order is updated"
openapi: "openapi.json webhook orderUpdated"
---
```

Webhook 名称必须与 OpenAPI 规范中 `webhooks` 字段里的键完全一致。
