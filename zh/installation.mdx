使用 [CLI](https://www.npmjs.com/package/mint) 可在编写和编辑文档时于本地预览效果。你可以在部署前实时查看更改，测试文档站点的外观和功能，并发现失效链接或无障碍问题等问题。

CLI 还提供了用于维护文档的实用工具，包括用于重命名文件、验证 OpenAPI 规范，以及在不同格式之间迁移内容的命令。

<div id="prerequisites">
  ## 前提条件
</div>

* 已安装 [Node.js](https://nodejs.org/en) v20.17.0+ (推荐使用 LTS 版本)
* 已安装 [Git](https://git-scm.com/downloads)
* 已将你的文档仓库克隆到本地

<div id="clone-your-repository">
  ### 克隆你的仓库
</div>

<Steps>
  <Step title="找到你的仓库">
    1. 前往仪表板中的 [Git settings](https://dashboard.mintlify.com/settings/deployment/git-settings) 页面。
    2. 记下你的仓库位置。格式会是以下其中一种：

    * `mintlify-community/docs-{org-name}-{id}` (Mintlify 托管的仓库)
    * `your-org/your-repo` (你自己的 GitHub 仓库)
  </Step>

  <Step title="克隆你的仓库">
    <Tabs>
      <Tab title="你自己的仓库">
        将 `your-org/your-repo` 替换为你在 [Git settings](https://dashboard.mintlify.com/settings/deployment/git-settings) 中看到的实际仓库信息。

        ```bash
        git clone https://github.com/your-org/your-repo
        cd your-repo
        ```

        <Tip>
          **需要安装 GitHub App。** 如果你想在推送更改时自动部署，就必须安装 GitHub App。更多信息请参阅 [GitHub](/zh/deploy/github)。
        </Tip>
      </Tab>

      <Tab title="Mintlify 托管的仓库">
        你可以将仓库克隆为私有仓库或公开仓库。公开仓库对任何访问该仓库 URL 的人都可见。私有仓库仅对你组织中的成员可见。

        在仪表板中的 [Git settings](https://dashboard.mintlify.com/settings/deployment/git-settings) 页面，选择 **Clone as private** 或 **Clone as public**。
      </Tab>
    </Tabs>
  </Step>
</Steps>

<div id="install-the-cli">
  ## 安装 CLI
</div>

运行以下命令安装 CLI：

<CodeGroup>
  ```bash npm
  npm i -g mint
  ```

  ```bash pnpm
  pnpm add -g mint
  ```
</CodeGroup>

<div id="preview-locally">
  ## 本地预览
</div>

进入包含 `docs.json` 文件的文档目录，然后运行：

```bash
mint dev
```

你可以在 `http://localhost:3000` 查看文档的本地预览。

或者，如果你不想全局安装 CLI，也可以运行一次性脚本：

```bash
npx mint dev
```

<div id="custom-ports">
  ### 自定义端口
</div>

默认情况下，CLI 使用 3000 端口。你可以使用 `--port` 标志来自定义端口。例如，如需让 CLI 在 3333 端口上运行，请使用以下命令：

```bash
mint dev --port 3333
```

如果你尝试在已被占用的端口上运行，CLI 会改用下一个可用端口：

```mdx
Port 3000 is already in use. Trying 3001 instead.
```

<div id="skip-openapi-processing">
  ## 跳过 OpenAPI 处理
</div>

如果你有很多 OpenAPI 文件，可以在本地开发时使用 `--disable-openapi` 标志跳过 OpenAPI 文件处理，以提升性能：

```bash
mint dev --disable-openapi
```

<div id="preview-as-a-specific-group">
  ### 以特定分组身份预览
</div>

如果你使用基于分组的访问控制来限制文档访问，可以使用 `--groups [groupname]` 标志，以特定身份验证分组的身份进行预览。

例如，如果你有一个名为 `admin` 的分组，可以使用以下命令以该分组成员的身份进行预览：

```bash
mint dev --groups admin
```

<div id="create-a-new-project">
  ## 新建项目
</div>

要新建一个文档项目，请运行以下命令：

```bash
mint new [directory]
```

此命令会将 [starter kit](https://github.com/mintlify/starter) 克隆到指定目录。如果你未指定目录，CLI 工具会提示你创建新的子目录，或覆盖当前目录。

<Warning>
  覆盖当前目录会删除其中已有的所有文件。
</Warning>

CLI 工具还会提示你输入项目名称并选择 [主题](/zh/customize/themes)，以完成项目设置。

<div id="flags">
  ### 标志
</div>

| 标志        | 说明                             | 必需 |
| --------- | ------------------------------ | -- |
| `--name`  | 设置新项目的名称。                      | 是  |
| `--theme` | 设置新项目的[主题](/zh/customize/themes)。 | 是  |
| `--force` | 即使当前目录中已有文件，也会跳过提示并直接覆盖。       | 否  |

在 CI/CD 流水线等非交互式环境中运行 `mint new`，或配合 AI 编码代理使用时，你必须提供所有必需标志 (`--name` 和 `--theme`) 。

<Tip>
  CLI 会自动检测非交互式环境。如果缺少必需标志，它会输出使用说明，而不是卡在交互提示上。
</Tip>

<div id="update-the-cli">
  ## 更新 CLI
</div>

如果你的本地预览与网页上的线上正式版显示内容不同步，请更新本地 CLI：

```bash
mint update
```

如果你的本地版本中无法使用 `mint update` 命令，请使用最新版本重新安装 CLI：

<CodeGroup>
  ```bash npm
  npm i -g mint@latest
  ```

  ```bash pnpm
  pnpm add -g mint@latest
  ```
</CodeGroup>

<div id="additional-commands">
  ## 更多命令
</div>

<div id="find-broken-links">
  ### 查找失效链接
</div>

使用以下命令查找所有失效的内部链接：

```bash
mint broken-links
```

该命令会忽略与 [.mintignore](/zh/organize/mintignore) 模式匹配的文件。指向已忽略文件的链接会被报告为失效链接。

<div id="find-accessibility-issues">
  ### 查找无障碍问题
</div>

使用以下命令测试文档中的颜色对比度，并检查图片和视频是否缺少 alt 文本：

```bash
mint a11y
```

使用标志可检查特定的无障碍问题。

```bash
# 仅检查缺失的 alt 文本
mint a11y --skip-contrast

# 仅检查颜色对比度问题
mint a11y --skip-alt-text
```

<div id="validate-documentation-build">
  ### 验证文档构建
</div>

以严格模式验证文档构建；如果存在任何警告或错误，命令会报错退出。请在 CI/CD 流水线中使用此命令，以避免部署损坏的文档。

```bash
mint validate
```

使用标志配置验证命令。

* `--groups [groupname]`：为验证模拟用户分组 (在测试基于分组的访问控制时很有用)
* `--disable-openapi`：在验证过程中禁用 OpenAPI 文件生成

<div id="check-openapi-spec">
  ### 检查 OpenAPI 规范
</div>

使用以下命令检查 OpenAPI 文件是否存在错误：

```bash
mint openapi-check <OpenAPI filename or URL>
```

传入文件名 (例如 `./openapi.yaml`) 或 URL (例如 `https://petstore3.swagger.io/api/v3/openapi.json`) 。

<div id="rename-files">
  ### 重命名文件
</div>

使用以下命令重命名文件，并更新所有相关引用：

```bash
mint rename <path/to/old-filename> <path/to/new-filename>
```

<div id="migrate-mdx-endpoint-pages">
  ### 迁移 MDX 端点页面
</div>

使用以下命令，将 MDX 端点页面迁移为基于 OpenAPI 规范自动生成的页面：

```bash
mint migrate-mdx
```

此命令会将各个 MDX 端点页面转换为你在 `docs.json` 中定义的自动生成页面，将 MDX 内容迁移到 OpenAPI 规范中的 `x-mint` 扩展，并更新你的导航。详细信息请参阅 [从 MDX 迁移](/zh/guides/migrating-from-mdx)。

<div id="formatting">
  ## 格式化
</div>

在本地开发时，我们建议在 IDE 中使用扩展，以识别并格式化 MDX 文件。

如果你使用 Cursor、Windsurf 或 VS Code，我们建议使用 [MDX VS Code extension](https://marketplace.visualstudio.com/items?itemName=unifiedjs.vscode-mdx) 实现语法高亮，并使用 [Prettier](https://marketplace.visualstudio.com/items?itemName=esbenp.prettier-vscode) 进行代码格式化。

如果你使用 JetBrains，我们建议使用 [MDX IntelliJ IDEA plugin](https://plugins.jetbrains.com/plugin/14944-mdx) 实现语法高亮，并配置 [Prettier](https://prettier.io/docs/webstorm) 进行代码格式化。

<div id="troubleshooting">
  ## 故障排查
</div>

<AccordionGroup>
  <Accordion title="错误：无法在 darwin-arm64 运行时中加载 &#x22;sharp&#x22; 模块">
    这可能是因为 Node.js 版本过旧。请尝试以下操作：

    1. 卸载当前已安装的 mint CLI：`npm uninstall -g mint`
    2. 升级到 Node.js v20.17.0 或更高版本。
    3. 重新安装 mint CLI：`npm install -g mint`
  </Accordion>

  <Accordion title="问题：遇到未知错误">
    **解决方案**：前往设备根目录并删除 `~/.mintlify` 文件夹。然后再次运行 `mint dev`。
  </Accordion>

  <Accordion title="错误：权限被拒绝">
    这是因为你没有全局安装 Node 包所需的权限。

    **解决方案**：尝试运行 `sudo npm i -g mint`。系统会提示你输入密码，即你用于解锁电脑的密码。
  </Accordion>

  <Accordion title="本地预览与网页上的文档显示不一致">
    这很可能是因为 CLI 版本过旧。

    **解决方案：**运行 `mint update` 以获取最新更改。
  </Accordion>

  <Accordion title="mintlify 与 mint 包">
    如果 CLI 包出现问题，请先运行 `npm ls -g`。此命令会显示你的机器上全局安装了哪些包。

    如果你不使用 npm，或者没有在全局列表中看到它，请尝试运行 `which mint` 来定位安装位置。

    如果你同时安装了名为 `mint` 和 `mintlify` 的包，应卸载 `mintlify`。

    1. 卸载旧包：

    ```bash
      npm uninstall -g mintlify
    ```

    2. 清除 npm 缓存：

    ```bash
      npm cache clean --force
    ```

    3. 重新安装新包：

    ```bash
    npm i -g mint
    ```
  </Accordion>

  <Accordion title="安装后客户端版本显示为 'none'">
    如果你运行 `mint version` 后客户端版本显示为 `none`，可能是因为公司防火墙或 VPN 阻止了下载，导致 CLI 无法下载客户端应用。

    **解决方案：**请联系 IT 管理员，将 `releases.mintlify.com` 加入白名单，以便通过 CLI 进行本地开发。
  </Accordion>
</AccordionGroup>
