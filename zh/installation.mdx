使用 [CLI](https://www.npmjs.com/package/mint) 在本地预览你正在编写和编辑的文档。在部署之前实时查看更改、测试文档站点的外观和功能，并发现诸如无效链接或无障碍性问题之类的错误。

CLI 还提供了用于维护文档的实用工具，包括用于重命名文件、验证 OpenAPI 规范以及在不同格式之间迁移内容的命令。

<div id="prerequisites">
  ## 前提条件
</div>

* 已安装 [Node.js](https://nodejs.org/en) v20.17.0+（建议使用 LTS 版本）
* 已安装 [Git](https://git-scm.com/downloads)
* 已将你的文档仓库克隆到本地

<div id="clone-your-repository">
  ### 克隆你的仓库
</div>

<Steps>
  <Step title="找到你的仓库">
    1. 前往控制台的 [Git settings](https://dashboard.mintlify.com/settings/deployment/git-settings) 页面。
    2. 记下你的仓库位置。格式可能为以下之一：

    * `mintlify-community/docs-{org-name}-{id}`（Mintlify 托管的仓库）
    * `your-org/your-repo`（你自己的 GitHub 仓库）
  </Step>

  <Step title="克隆你的仓库">
    <Tabs>
      <Tab title="你自己的仓库">
        将 `your-org/your-repo` 替换为你在 [Git settings](https://dashboard.mintlify.com/settings/deployment/git-settings) 中看到的实际仓库信息。

        ```bash
        git clone https://github.com/your-org/your-repo
        cd your-repo
        ```

        <Tip>
          **需要安装 GitHub App。** 若要在你推送更改时启用自动部署，必须先安装 GitHub App。更多信息请参见 [GitHub](/zh/deploy/github)。
        </Tip>
      </Tab>

      <Tab title="Mintlify 托管的仓库">
        你可以将仓库克隆为私有仓库或公共仓库。公共仓库对任何访问该仓库 URL 的人可见，私有仓库仅对你组织内的成员可见。

        在控制台的 [Git settings](https://dashboard.mintlify.com/settings/deployment/git-settings) 页面中，选择 **Clone as private** 或 **Clone as public**。
      </Tab>
    </Tabs>
  </Step>
</Steps>

<div id="install-the-cli">
  ## 安装 CLI
</div>

运行以下命令安装 CLI：

<CodeGroup>
  ```bash npm
  npm i -g mint
  ```

  ```bash pnpm
  pnpm add -g mint
  ```
</CodeGroup>

<div id="preview-locally">
  ## 本地预览
</div>

进入包含 `docs.json` 文件的文档目录，然后运行：

```bash
mint dev
```

你的文档的本地预览可以通过 `http://localhost:3000` 访问。

或者，如果你不想全局安装 CLI，可以运行一次性脚本：

```bash
npx mint dev
```

<div id="custom-ports">
  ### 自定义端口
</div>

默认情况下，CLI 使用 3000 端口。你可以使用 `--port` 参数自定义端口。比如，要让 CLI 运行在 3333 端口上，请使用以下命令：

```bash
mint dev --port 3333
```

如果你尝试在已被占用的端口上运行时，CLI 会自动使用下一个可用端口：

```mdx
Port 3000 is already in use. Trying 3001 instead.
```

<div id="skip-openapi-processing">
  ## 跳过 OpenAPI 处理
</div>

如果你有许多 OpenAPI 文件，可以在本地开发时使用 `--disable-openapi` 选项来跳过对 OpenAPI 文件的处理，从而提升性能：

```bash
mint dev --disable-openapi
```

<div id="preview-as-a-specific-group">
  ### 以特定用户组身份预览
</div>

如果你使用基于用户组的访问控制来限制对文档的访问，可以通过 `--groups [groupname]` 参数，以指定的认证用户组身份进行预览。

例如，如果你有一个名为 `admin` 的用户组，可以使用以下命令，以该用户组成员的身份进行预览：

```bash
mint dev --groups admin
```

<div id="create-a-new-project">
  ## 创建新项目
</div>

若要创建新的文档项目，请运行以下命令：

```bash
mint new [directory]
```

此命令会将 [starter kit](https://github.com/mintlify/starter) 克隆到指定目录中。若未指定目录，CLI 工具会提示你创建一个新的子目录或覆盖当前目录。

<Warning>
  覆盖当前目录会删除其中所有现有文件。
</Warning>

CLI 工具会提示你输入项目名称和 [主题](/zh/customize/themes)，以完成项目设置。

<div id="flags">
  ### 标志
</div>

| Flag | 描述 | 是否必需 |
| --- | --- | --- |
| `--name` | 指定新项目的名称。 | 是 |
| `--theme` | 指定新项目的[主题](/zh/customize/themes)。 | 是 |
| `--force` | 在不提示的情况下覆盖当前目录，即使其中包含现有文件。 | 否 |

在 CI/CD 流水线或 AI 编码助手等非交互式环境中运行 `mint new` 时，必须提供所有必需的标志（`--name` 和 `--theme`）。

<Tip>
  CLI 会自动检测非交互式环境。如果缺少必需标志，它会输出使用说明，而不会在交互提示上卡住。
</Tip>

<div id="update-the-cli">
  ## 更新 CLI
</div>

如果你的本地预览与线上生产环境中看到的内容不一致，请更新本地 CLI：

```bash
mint update
```

如果你本地安装的版本中没有 `mint update` 命令，请重新安装最新版本的 CLI：

<CodeGroup>
  ```bash npm
  npm i -g mint@latest
  ```

  ```bash pnpm
  pnpm add -g mint@latest
  ```
</CodeGroup>

<div id="additional-commands">
  ## 其他命令
</div>

<div id="find-broken-links">
  ### 查找失效链接
</div>

使用以下命令查找所有失效的内部链接：

```bash
mint broken-links
```

该命令会忽略符合 [.mintignore](/zh/organize/mintignore) 中规则的文件。指向这些被忽略文件的链接会被报告为损坏链接。

<div id="find-accessibility-issues">
  ### 查找无障碍问题
</div>

使用以下命令测试文档中的颜色对比度，并检查图像和视频是否缺少 alt 文本：

```bash
mint a11y
```

使用标志来检查特定的可访问性问题。

```bash
# 仅检查缺失的替代文本
mint a11y --skip-contrast

# 仅检查颜色对比度问题
mint a11y --skip-alt-text
```

<div id="validate-documentation-build">
  ### 验证文档构建
</div>

在严格模式下验证文档构建，如果出现任何警告或错误，命令将以错误状态退出。在 CI/CD 流水线中使用此命令，以防止部署包含问题的文档。

```bash
mint validate
```

使用标志来配置验证命令。

* `--groups [groupname]`: 在验证时模拟用户组（在测试基于用户组的访问控制时很有用）
* `--disable-openapi`: 在验证期间禁用生成 OpenAPI 文件

<div id="check-openapi-spec">
  ### 检查 OpenAPI 规范
</div>

使用以下命令检查你的 OpenAPI 文件是否有错误：

```bash
mint openapi-check <OpenAPI filename or URL>
```

传入文件名（例如 `./openapi.yaml`）或 URL（例如 `https://petstore3.swagger.io/api/v3/openapi.json`）。

<div id="rename-files">
  ### 重命名文件
</div>

使用以下命令重命名文件并更新所有文件引用：

```bash
mint rename <path/to/old-filename> <path/to/new-filename>
```

<div id="migrate-mdx-endpoint-pages">
  ### 迁移 MDX 端点页面
</div>

使用以下命令，将 MDX 端点页面迁移为从 OpenAPI 规范自动生成的页面：

```bash
mint migrate-mdx
```

此命令会将各个 MDX 端点页面转换为在 `docs.json` 中定义的自动生成的页面，将 MDX 内容移动到 OpenAPI 规范中的 `x-mint` 扩展中，并更新你的导航。有关详细信息，请参阅[从 MDX 迁移](/zh/guides/migrating-from-mdx)。

<div id="formatting">
  ## 格式化
</div>

在本地开发时，我们建议在你的 IDE 中使用扩展来识别和格式化 MDX 文件。

如果你使用 Cursor、Windsurf 或 VS Code，我们推荐使用 [MDX VS Code extension](https://marketplace.visualstudio.com/items?itemName=unifiedjs.vscode-mdx) 进行语法高亮，并使用 [Prettier](https://marketplace.visualstudio.com/items?itemName=esbenp.prettier-vscode) 进行代码格式化。

如果你使用 JetBrains，我们推荐安装 [MDX IntelliJ IDEA plugin](https://plugins.jetbrains.com/plugin/14944-mdx) 以实现语法高亮，并配置 [Prettier](https://prettier.io/docs/webstorm) 进行代码格式化。

<div id="troubleshooting">
  ## 故障排查
</div>

<AccordionGroup>
  <Accordion title="错误：无法使用 darwin-arm64 运行时加载 &#x22;sharp&#x22; 模块">
    这可能是由于 Node.js 版本过旧导致的。请尝试以下操作：

    1. 卸载当前已安装的 mint CLI：`npm uninstall -g mint`
    2. 升级到 Node.js v20.17.0 或更高版本。
    3. 重新安装 mint CLI：`npm install -g mint`
  </Accordion>

  <Accordion title="问题：遇到未知错误">
    **解决方法**：前往你的主目录并删除 `~/.mintlify` 文件夹。然后再次运行 `mint dev`。
  </Accordion>

  <Accordion title="错误：permission denied">
    这是由于缺少全局安装 Node 包所需的权限导致的。

    **解决方法**：尝试运行 `sudo npm i -g mint`。系统会提示你输入密码，即你用来解锁电脑的密码。
  </Accordion>

  <Accordion title="本地预览与网页上的文档显示效果不一致">
    这很可能是由于 CLI 版本过旧导致的。

    **解决方法：** 运行 `mint update` 以获取最新更新。
  </Accordion>

  <Accordion title="mintlify 与 mint 包的区别">
    如果你在使用 CLI 包时遇到任何问题，应首先运行 `npm ls -g`。该命令会显示你机器上全局安装了哪些包。

    如果你不使用 npm，或者在 -g 列表中没看到它，请尝试运行 `which mint` 来定位安装位置。

    如果你同时安装了名为 `mint` 和名为 `mintlify` 的包，应卸载 `mintlify`。

    1. 卸载旧包：

    ```bash
      npm uninstall -g mintlify
    ```

    2. 清理 npm 缓存：

    ```bash
      npm cache clean --force
    ```

    3. 重新安装新包：

    ```bash
    npm i -g mint
    ```
  </Accordion>

  <Accordion title="安装后客户端版本显示为 'none'">
    如果你运行 `mint version` 时，客户端版本显示为 `none`，可能是由于公司防火墙或 VPN 阻止下载，导致 CLI 无法下载客户端应用程序。

    **解决方法：** 请联系你的 IT 管理员，将 `releases.mintlify.com` 加入白名单，以便在本地使用 CLI 进行开发。
  </Accordion>
</AccordionGroup>
