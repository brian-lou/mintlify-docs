---
title: "重定向"
description: "为已移动、重命名或删除的页面配置重定向。"

---

当你更改 docs 文件夹中文件的路径时，该页面对应的 URL 路径也会随之变化。这种情况通常会发生在你重组文档或修改侧边栏标题时。

<div id="redirects">
  ## 重定向
</div>

<Note>
  重定向**不能**包含 `path#anchor` 这类 URL 锚点，也不能包含 `path?query=value` 这类查询参数。
</Note>

在 `docs.json` 文件中添加 `redirects` 字段，以配置 301 重定向。

```json
"redirects": [
  {
    "source": "/source/path",
    "destination": "/destination/path"
  }
]
```

这会将 `/source/path` 永久重定向到 `/destination/path`，这样就不会损失原始页面此前积累的任何 SEO 价值。

<div id="wildcard-redirects">
  ### 通配符重定向
</div>

要匹配通配符路径，请在参数后添加 `*`。在此示例中，`/beta/:slug*` 会匹配 `/beta/introduction`，并将其重定向到 `/v2/introduction`。

```json
"redirects": [
  {
    "source": "/beta/:slug*",
    "destination": "/v2/:slug*"
  }
]
```

<div id="partial-wildcard-redirects">
  ### 部分通配符重定向
</div>

使用部分通配符匹配以特定前缀开头的 URL 段。

```json
"redirects": [
  {
    "source": "/articles/concepts-*",
    "destination": "/collections/overview"
  }
]
```

这会匹配所有路径为 `/articles/concepts-` 的 URL，例如 `/articles/concepts-getting-started` 和 `/articles/concepts-overview`，并将它们统一重定向到 `/collections/overview`。

你也可以在目标地址中使用捕获到的通配符值进行替换。

```json
"redirects": [
  {
    "source": "/old/article-*",
    "destination": "/new/article-*"
  }
]
```

这会将 `/old/article-123` 重定向到 `/new/article-123`，同时保留前缀后捕获的值。

<div id="avoid-infinite-redirects">
  ### 避免无限重定向
</div>

为避免无限循环，请不要创建相互指回的循环重定向。

```json
"redirects": [
  {
    "source": "/docs/:slug*",
    "destination": "/help/:slug*"
  },
  {
    "source": "/help/:slug*",
    "destination": "/docs/:slug*"
  }
]
```

<div id="check-for-broken-links">
  ## 检查失效链接
</div>

使用 [CLI](/zh/installation) 查找失效链接。

```bash
mint broken-links
```
