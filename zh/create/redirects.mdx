title: "重定向"
description: "为已移动、重命名或删除的页面配置重定向。"

---

当你更改 docs 文件夹中某个文件的路径时，该页面的 URL 也会随之变化。在调整文档结构或更改侧边栏中的标题时，可能会出现这种情况。

<div id="redirects">
  ## 重定向
</div>

<Note>
  重定向 **不能** 包含 URL 锚点（如 `path#anchor`）或查询参数（如 `path?query=value`）。
</Note>

在 `docs.json` 文件中添加 `redirects` 字段以设置 301 重定向。

```json
"redirects": [
  {
    "source": "/source/path",
    "destination": "/destination/path"
  }
]
```

这会将 `/source/path` 永久重定向到 `/destination/path`，从而避免丢失原始页面以往积累的任何 SEO 权重。

<div id="wildcard-redirects">
  ### 通配符重定向
</div>

要匹配通配符路径，请在参数后使用 `*`。在此示例中，`/beta/:slug*` 会匹配 `/beta/introduction` 并重定向到 `/v2/introduction`。

```json
"redirects": [
  {
    "source": "/beta/:slug*",
    "destination": "/v2/:slug*"
  }
]
```

<div id="partial-wildcard-redirects">
  ### 部分通配符重定向
</div>

使用部分通配符来匹配以特定前缀开头的 URL 路径片段。

```json
"redirects": [
  {
    "source": "/articles/concepts-*",
    "destination": "/collections/overview"
  }
]
```

这会匹配任何具有 `/articles/concepts-` 路径的 URL，例如 `/articles/concepts-getting-started` 和 `/articles/concepts-overview`，并将它们全部重定向到 `/collections/overview`。

你也可以在目标 URL 中使用捕获到的通配符值。

```json
"redirects": [
  {
    "source": "/old/article-*",
    "destination": "/new/article-*"
  }
]
```

这会将 `/old/article-123` 重定向到 `/new/article-123`，并在新前缀之后保留被捕获的值。

<div id="avoid-infinite-redirects">
  ### 避免无限重定向
</div>

为避免出现无限循环，不要创建路径彼此相互重定向回对方的情况。

```json
"redirects": [
  {
    "source": "/docs/:slug*",
    "destination": "/help/:slug*"
  },
  {
    "source": "/help/:slug*",
    "destination": "/docs/:slug*"
  }
]
```

<div id="check-for-broken-links">
  ## 检查损坏链接
</div>

使用 [CLI](/zh/installation) 查找损坏链接。

```bash
mint broken-links
```
