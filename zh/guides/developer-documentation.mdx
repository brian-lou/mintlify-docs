开发者文档能帮助用户理解你的产品并完成集成。优质的文档可以帮助用户更充分地使用你的产品，减轻支持负担，加快采用进程，并提升开发者体验。

Mintlify 提供专为开发者文档打造的基础设施。

* **API 参考生成**：基于 OpenAPI 规范生成交互式的 [API 参考文档](/zh/api-playground/overview)，让开发者能够直接在文档中测试端点。
* **带解释的代码块**：[助手](/zh/ai/assistant) 会结合上下文解释代码示例，帮助开发者理解实现细节。
* **Git 同步**：使用 [GitHub](/zh/deploy/github) 或 [GitLab](/zh/deploy/gitlab)，让文档与你的代码库保持同步。
* **版本管理**：为多个 [版本](/zh/organize/navigation#versions)维护文档，以便仍在使用旧版本的开发者也能找到准确的信息。

<div id="prerequisites">
  ## 前提条件
</div>

如果你还没有创建 Mintlify 项目，请参阅 [Quickstart](/zh/quickstart) 以部署你的网站。

* OpenAPI 格式的 API 规范 (如果你要编写 API 文档)
* 用于存放文档的 Git 仓库
* 你的 Mintlify 组织的管理员权限

<div id="migrate-existing-documentation">
  ## 迁移现有文档
</div>

如果你要从零开始编写文档，请跳到[规划文档结构](#plan-your-documentation-structure)。

<div id="audit-existing-content">
  ### 审查现有内容
</div>

查看当前文档，了解你已经有哪些内容，以及哪些内容需要迁移。

* **API 参考文档**：是根据规范自动生成的，还是手动编写的？你记录了哪些端点？
* **Guides and tutorials**：现有哪些集成指南？它们是否还是最新的？
* **Code examples**：你使用哪些语言和框架？
* **SDK documentation**：你是否为每个 SDK 单独提供文档？
* **Changelog**：你是否维护变更日志或发布说明？
* **Metadata**：你的内容是否包含日期、作者和标签等元数据？

<div id="export-your-existing-content">
  ### 导出现有内容
</div>

* 导出为 **Markdown**，这是迁移到 Mintlify 最简单的方式。
* 导出 **OpenAPI 规范**，用于 API 参考文档内容。
* 如果无法导出为 Markdown，则导出为 **HTML**，再转换为 Markdown。

<div id="plan-your-documentation-structure">
  ## 规划文档结构
</div>

开发者文档通常包含多种内容类型。请根据用户理解您产品的方式来组织导航。

```json docs.json example
{
  "navigation": {
    "groups": [
      {
        "group": "Get Started",
        "pages": [
          "introduction",
          "quickstart",
          "authentication"
        ]
      },
      {
        "group": "Guides",
        "pages": [
          "guides/webhooks",
          "guides/error-handling",
          "guides/rate-limits",
          "guides/pagination"
        ]
      },
      {
        "group": "API Reference",
        "pages": [
          "api-reference/overview",
          "api-reference/users",
          "api-reference/orders",
          "api-reference/products"
        ]
      },
      {
        "group": "SDKs",
        "pages": [
          "sdks/javascript",
          "sdks/python",
          "sdks/go"
        ]
      }
    ]
  }
}
```

更多配置选项，请参阅 [Navigation](/zh/organize/navigation)。

<div id="set-up-your-api-reference">
  ## 设置 API 参考文档
</div>

如果你有 API，可以根据 OpenAPI 规范生成交互式参考文档。

<Steps>
  <Step title="添加 OpenAPI 规范">
    将 OpenAPI 规范文件添加到项目中。可以使用 YAML 或 JSON 格式。

    ```text
    your-project/
    ├── docs.json
    ├── openapi.yaml
    └── api-reference/
        └── overview.mdx
    ```
  </Step>

  <Step title="在 docs.json 中配置规范">
    在 `docs.json` 配置中引用 OpenAPI 文件。

    ```json Configuration example
    {
      "openapi": "openapi.yaml"
    }
    ```
  </Step>

  <Step title="将端点添加到导航">
    将端点添加到 `docs.json` 的导航中。配置选项请参阅 [OpenAPI 设置](/zh/api-playground/openapi-setup)。

    ```json Navigation example
    {
      "group": "API Reference",
      "pages": [
        "api-reference/overview",
        "api-reference/users/list-users",
        "api-reference/users/get-user",
        "api-reference/users/create-user"
      ]
    }
    ```
  </Step>
</Steps>

<div id="set-up-the-assistant">
  ## 设置助手
</div>

助手可帮助开发者查找答案并理解代码示例。你可以在[控制面板](https://dashboard.mintlify.com/products/assistant/settings)中进行配置。

* **示例问题**：添加面向开发者的问题，例如“如何对 API 请求进行身份验证？”或“向我展示如何处理 webhook。”
* **代码解释**：当开发者就特定示例提问时，助手可以结合上下文解释代码块。

<div id="set-up-versioning">
  ## 设置版本管理
</div>

如果你维护多个 API 版本，请配置版本管理，以便开发者能够找到对应版本的文档。

```json Versioning example
{
  "versions": ["v2", "v1"],
  "navigation": {
    "groups": [
      {
        "group": "API Reference",
        "version": "v2",
        "pages": ["v2/api-reference/users"]
      },
      {
        "group": "API Reference",
        "version": "v1",
        "pages": ["v1/api-reference/users"]
      }
    ]
  }
}
```

更多信息，请参阅 [Versions](/zh/organize/navigation#versions)。

<div id="connect-to-your-repository">
  ## 连接到你的仓库
</div>

安装 Mintlify 的 [GitHub App](/zh/deploy/github)，让文档与代码库保持同步，并支持协作贡献。

<Steps>
  <Step title="连接你的仓库">
    在 [dashboard](https://dashboard.mintlify.com) 中关联你的 GitHub 仓库。这样，在你推送更改时就会自动部署。
  </Step>

  <Step title="配置分支设置">
    设置生产分支，并为拉取请求启用预览部署。这样，你就可以在文档更改正式上线前先进行检查。
  </Step>
</Steps>

<Note>
  如果你使用 GitLab，请参阅 [GitLab](/zh/deploy/gitlab) 中的配置说明。
</Note>

<div id="maintain-your-documentation">
  ## 维护文档
</div>

开发者文档需要定期更新，才能确保信息准确且实用。

<Steps>
  <Step title="保持 API 参考文档为最新">
    每次发布变更时，都要更新 OpenAPI 规范。如果规范是根据代码生成的，请在发布流程中将这一步自动化。
  </Step>

  <Step title="更新代码示例">
    发布新的 SDK 版本或产品更新时，请检查代码示例。过时的示例会导致集成失败并引发支持请求。
  </Step>

  <Step title="维护变更日志">
    记录破坏性变更、新功能和弃用项。开发者依靠变更日志了解不同版本之间的变化。更多信息，请参阅 [Changelogs](/zh/create/changelogs)。
  </Step>

  <Step title="监控反馈">
    查看助手对话和搜索分析，找出文档中的缺漏。如果开发者反复询问同一主题，请完善该部分。更多信息，请参阅 [Maintenance](/zh/guides/maintenance)。
  </Step>
</Steps>

<div id="next-steps">
  ## 后续步骤
</div>

你的开发者文档已准备好上线。部署后：

1. 向开发者社区宣布文档已上线。
2. 监控搜索行为和助手对话，找出内容缺口。
3. 建立流程，在每次 API 发布时更新文档。
4. 收集开发者反馈，持续改进内容。
