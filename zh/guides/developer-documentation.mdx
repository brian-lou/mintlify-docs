开发者文档帮助人们理解并集成你的产品。高质量的文档能帮助用户更好地使用你的产品、减少支持成本、加快产品落地，并提升开发者体验。

Mintlify 提供专为开发者文档打造的基础设施。

* **API 参考生成**：从 OpenAPI 规范生成交互式 [API 参考](/zh/api-playground/overview)，让开发者可以直接在文档中测试接口。
* **带说明的代码块**：通过 [助手](/zh/ai/assistant) 在上下文中解释代码示例，帮助开发者理解实现细节。
* **Git 同步**：使用 [GitHub](/zh/deploy/github) 或 [GitLab](/zh/deploy/gitlab) 将文档与代码库保持同步。
* **版本管理**：维护多个[版本](/zh/organize/navigation#versions)的文档，使使用旧版本的开发者仍然能找到准确的信息。

<div id="prerequisites">
  ## 前置条件
</div>

如果你还没有创建 Mintlify 项目，请参阅[快速开始](/zh/quickstart)以部署你的网站。

* 你的 OpenAPI 格式的 API 规范（如果你在编写 API 文档）
* 存放文档的 Git 仓库
* 你在 Mintlify 组织中的管理员权限

<div id="migrate-existing-documentation">
  ## 迁移现有文档
</div>

如果你是从头开始编写文档，请跳至[规划文档结构](#plan-your-documentation-structure)。

<div id="audit-existing-content">
  ### 审核现有内容
</div>

检查你当前的文档，了解你已经有哪些内容，以及哪些需要迁移。

* **API reference**：是根据规范自动生成的还是手工编写的？你记录了哪些 API 端点？
* **Guides and tutorials**：现有的集成指南有哪些？它们是否仍然适用、内容是否最新？
* **Code examples**：你提供了哪些语言和框架的示例代码？
* **SDK documentation**：是否为每个 SDK 提供了单独的文档？
* **Changelog**：你是否维护变更日志或版本发布说明？
* **Metadata**：你的内容是否包含日期、作者、标签等元数据？

<div id="export-your-existing-content">
  ### 导出现有内容
</div>

* 导出为 **Markdown**，以最简单的方式迁移到 Mintlify。
* 导出 **OpenAPI 规范**，用于 API 参考文档。
* 如果无法导出为 Markdown，则先导出为 **HTML**，再转换为 Markdown。

<div id="plan-your-documentation-structure">
  ## 规划文档结构
</div>

开发者文档通常包含多种内容类型。请根据用户理解你产品的方式来设计导航结构。

```json docs.json example
{
  "navigation": {
    "groups": [
      {
        "group": "Get Started",
        "pages": [
          "introduction",
          "quickstart",
          "authentication"
        ]
      },
      {
        "group": "Guides",
        "pages": [
          "guides/webhooks",
          "guides/error-handling",
          "guides/rate-limits",
          "guides/pagination"
        ]
      },
      {
        "group": "API Reference",
        "pages": [
          "api-reference/overview",
          "api-reference/users",
          "api-reference/orders",
          "api-reference/products"
        ]
      },
      {
        "group": "SDKs",
        "pages": [
          "sdks/javascript",
          "sdks/python",
          "sdks/go"
        ]
      }
    ]
  }
}
```

如需更多配置选项，请参阅 [Navigation](/zh/organize/navigation)。

<div id="set-up-your-api-reference">
  ## 设置你的 API 参考文档
</div>

如果你有一个 API，可以根据 OpenAPI 规范生成交互式参考文档。

<Steps>
  <Step title="添加你的 OpenAPI 规范文件">
    将 OpenAPI 规范文件添加到项目中。你可以使用 YAML 或 JSON 格式。

    ```text
    your-project/
    ├── docs.json
    ├── openapi.yaml
    └── api-reference/
        └── overview.mdx
    ```
  </Step>

  <Step title="在 docs.json 中配置规范文件">
    在 `docs.json` 配置中引用你的 OpenAPI 文件。

    ```json Configuration example
    {
      "openapi": "openapi.yaml"
    }
    ```
  </Step>

  <Step title="将端点添加到导航中">
    将这些端点添加到 `docs.json` 的导航中。配置选项参见 [OpenAPI 设置](/zh/api-playground/openapi-setup)。

    ```json Navigation example
    {
      "group": "API Reference",
      "pages": [
        "api-reference/overview",
        "api-reference/users/list-users",
        "api-reference/users/get-user",
        "api-reference/users/create-user"
      ]
    }
    ```
  </Step>
</Steps>

<div id="set-up-the-assistant">
  ## 设置助手
</div>

助手可以帮助开发者查找答案并理解代码示例。你可以在 [控制台](https://dashboard.mintlify.com/products/assistant/settings) 中进行配置。

* **示例问题**：添加面向开发者的问题，例如“如何对 API 请求进行身份验证？”或“给我演示如何处理 webhook。”
* **代码讲解**：当开发者就特定示例提出问题时，助手可以结合上下文解释代码块。

<div id="set-up-versioning">
  ## 设置版本管理
</div>

如果你维护多个 API 版本，请配置版本管理，以便开发者可以找到适用于其版本的文档。

```json Versioning example
{
  "versions": ["v2", "v1"],
  "navigation": {
    "groups": [
      {
        "group": "API Reference",
        "version": "v2",
        "pages": ["v2/api-reference/users"]
      },
      {
        "group": "API Reference",
        "version": "v1",
        "pages": ["v1/api-reference/users"]
      }
    ]
  }
}
```

如需了解更多信息，请参阅[Versions](/zh/organize/navigation#versions)。

<div id="connect-to-your-repository">
  ## 连接到你的代码仓库
</div>

安装 Mintlify [GitHub App](/zh/deploy/github)，让文档与你的代码库保持同步，并方便协作贡献。

<Steps>
  <Step title="连接你的代码仓库">
    在[控制台](https://dashboard.mintlify.com)中关联你的 GitHub 仓库。这样在你推送更改时就会自动触发部署。
  </Step>

  <Step title="配置分支设置">
    设置你的生产分支，并为拉取请求（pull request）启用预览部署。这样可以在更改正式上线前先审核文档更新。
  </Step>
</Steps>

<Note>
  如果你使用 GitLab，请参阅 [GitLab](/zh/deploy/gitlab) 获取配置说明。
</Note>

<div id="maintain-your-documentation">
  ## 维护你的文档
</div>

开发者文档需要定期更新，以确保信息准确且易于使用。

<Steps>
  <Step title="保持 API 参考文档最新">
    每当你发布变更时，都要更新 OpenAPI 规范。如果规范是由代码生成的，请在发布流程中将这一过程自动化。
  </Step>

  <Step title="更新代码示例">
    在发布新的 SDK 版本或产品更新时，检查代码示例。过时的示例会导致集成失败并增加支持请求。
  </Step>

  <Step title="维护变更日志">
    记录不兼容变更、新功能和弃用内容。开发者依赖变更日志来了解不同版本之间发生了哪些变化。更多信息请参见 [Changelogs](/zh/create/changelogs)。
  </Step>

  <Step title="监控反馈">
    查看助手对话和搜索分析数据，以识别文档中的薄弱环节。如果开发者反复询问同一主题，就改进该部分内容。更多信息请参见 [Maintenance](/zh/guides/maintenance)。
  </Step>
</Steps>

<div id="next-steps">
  ## 后续步骤
</div>

你的开发者文档已经准备好发布了。部署之后：

1. 向你的开发者社区发布文档上线公告。
2. 监控搜索行为和助手对话，以发现内容空缺。
3. 为每次 API 发布建立文档更新流程。
4. 收集开发者的反馈，以便持续改进内容。
