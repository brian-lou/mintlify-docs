支持中心可以帮助客户解决问题，并查找与你的产品相关的信息。客户能够自行找到答案时，可以更快获得帮助，你的支持团队也能将精力集中在需要专业知识的复杂问题上。

Mintlify 提供支持中心所需的基础设施，可随客户规模一同扩展。

* **AI 驱动搜索**： [assistant](/zh/ai/assistant) 使用你的支持内容回答客户问题，让用户即使不知道该去哪里找或不清楚具体搜索词，也能找到答案。
* **反馈收集**：内置的 [feedback widgets](/zh/optimize/feedback) 允许客户为文章评分并报告问题，帮助你改进内容。
* **分析**：追踪哪些文章被查看、客户提出了哪些问题，以及他们在哪些地方遇到困难。
* **身份验证**：使用 [SSO 或 OAuth](/zh/deploy/authentication-setup) 基于客户的套餐或账号类型展示个性化内容。

<div id="migrate-existing-content">
  ## 迁移现有内容
</div>

如果你是从头开始创建支持中心，请跳至[规划支持中心结构](#plan-your-support-center-structure)。

<div id="audit-existing-content">
  ### 审核现有内容
</div>

检查你目前的支持资源，明确需要迁移的内容。

* **帮助文章**：你涵盖了哪些主题？哪些文章的浏览量最高？
* **常见问题解答（FAQ）**：是否有常见问题适合整理成文章？
* **支持工单**：客户反复在咨询哪些问题？这些问题应该整理成自助服务内容。
* **产品文档**：支持内容和产品文档之间是否存在重叠？

<div id="export-your-existing-content">
  ### 导出现有内容
</div>

* 导出为 **Markdown**，以最简单的方式迁移到 Mintlify。
* 如果无法导出为 Markdown，则导出为 **HTML**，然后再转换为 Markdown。
* 导出 **工单数据（ticket data）**，以识别需要编写文档的常见问题。

<div id="plan-your-support-center-structure">
  ## 规划你的支持中心结构
</div>

围绕客户遇到的问题，而不是产品功能，来组织你的支持中心。客户带着问题和目标而来，因此应让内容结构贴合他们如何看待你的产品以及他们常执行的任务。

<Tip>
  查看你的支持工单，了解客户实际在询问什么。这有助于你为内容设定优先级，并围绕真实问题来设计导航结构。
</Tip>

```json
{
  "navigation": {
    "groups": [
      {
        "group": "Get Started",
        "pages": [
          "getting-started/quick-setup",
          "getting-started/first-steps"
        ]
      },
      {
        "group": "Account",
        "pages": [
          "account/billing",
          "account/plans",
          "account/team-management",
          "account/security"
        ]
      },
      {
        "group": "Using the Product",
        "pages": [
          "product/feature-one",
          "product/feature-two",
          "product/integrations"
        ]
      },
      {
        "group": "Troubleshooting",
        "pages": [
          "troubleshooting/common-errors",
          "troubleshooting/connectivity",
          "troubleshooting/performance"
        ]
      }
    ]
  }
}
```

有关更多配置选项，请参阅 [导航](/zh/organize/navigation)。

<div id="write-effective-support-content">
  ## 撰写有效的支持内容
</div>

支持内容应帮助客户快速解决问题。每篇文章都应回答一个具体的问题或解决一个具体的问题。将相关内容划分为多个组别，而不是创建篇幅过长、信息过多的页面。

<div id="structure-articles-for-scanning">
  ### 为便于快速浏览来组织文章结构
</div>

客户在浏览支持页面时，会快速扫视以查找自己的具体问题。使用清晰的标题和简短的段落。

```mdx Example support page
---
title: "Fix login issues"
description: "Troubleshoot common problems signing in to your account"
---

## Reset your password

If you forgot your password, request a reset link from the login page.

1. Go to the login page.
2. Select **Forgot password**.
3. Enter your email address.
4. Check your inbox for the reset link.

## Clear browser cache

Old cached data can cause login problems. Clear your browser cache and try again.

## Check account status

If your account is suspended or deactivated, you'll see an error when logging in.
Contact support if you believe this is a mistake.
```

<div id="set-up-the-assistant">
  ## 设置助手
</div>

助手会基于你的支持内容来回答客户问题。可在[控制台](https://dashboard.mintlify.com/products/assistant/settings)中进行配置。

<Steps>
  <Step title="添加示例问题">
    添加客户常问的问题，例如：

    * “如何取消我的订阅？”
    * “为什么我的付款被拒绝？”
    * “如何添加团队成员？”

    示例问题会显示为快捷按钮，帮助客户一键获取解答。
  </Step>

  <Step title="设置转接邮箱">
    为助手无法解答的问题配置一个支持邮箱。这样可以确保当自助服务无法满足需求时，客户仍然能够联系到你的团队。
  </Step>

  <Step title="查看对话记录">
    定期检查助手的对话记录，以识别：

    * 助手无法回答的问题（内容缺口）
    * 不正确或不完整的回答（需改进的内容）
    * 常见问题模式（需优先处理的内容）
  </Step>
</Steps>

<div id="enable-feedback-collection">
  ## 启用反馈收集
</div>

反馈可以帮助你了解哪些页面对用户有帮助，哪些需要改进。查看[反馈](/zh/optimize/feedback)，了解用户觉得哪些页面有用、哪些页面需要改进。阅读所有评论，并根据有效反馈更新页面。

<div id="set-up-analytics">
  ## 设置分析功能
</div>

监控客户如何使用你的支持中心，以便持续改进内容。

* **热门文章**：哪些文章的浏览量最高？确保这些文章始终准确并得到良好维护。
* **搜索查询**：客户通常会搜索什么？针对那些经常被搜索却没有结果的查询创建相应内容。
* **助理对话**：助理收到哪些问题？利用这些信息识别内容空白。

<div id="restrict-content-by-customer-segment">
  ## 按客户细分限制内容访问
</div>

如果你有不同的客户层级或产品方案，可以使用基于分组的访问控制，为每一类客户展示相应的内容。

<Steps>
  <Step title="设置身份验证">
    配置[身份验证](/zh/deploy/authentication-setup)，以便在客户访问你的支持中心时识别其身份。
  </Step>

  <Step title="配置用户组">
    在用户数据中返回分组信息，根据方案类型、账号状态或其他属性来划分客户细分。详情参见 [用户数据格式](/zh/deploy/authentication-setup#user-data-format)。
  </Step>

  <Step title="按用户组为内容打标签">
    使用 frontmatter 指定每篇文章哪些用户组可以查看。

    ```mdx
    ---
    title: "Enterprise SSO setup"
    groups: ["enterprise"]
    ---
    ```
  </Step>
</Steps>

<div id="maintain-your-support-center">
  ## 维护你的支持中心
</div>

随着产品不断变化，支持内容也会逐渐过时。建立相应流程以确保内容始终准确。

<Steps>
  <Step title="配合产品发布进行更新">
    每当你发布产品变更时，及时更新受影响的支持文章。将文档更新纳入你的发布流程。
  </Step>

  <Step title="定期审查反馈">
    每周查看文章评分和客户反馈。及时处理负面反馈，它往往表明内容存在困惑或错误。
  </Step>

  <Step title="监控支持工单">
    如果客户就你的支持中心已涵盖的问题提交工单，调查自助支持为何未能奏效。文章可能难以被找到、不够清晰或信息不完整。
  </Step>

  <Step title="归档过时内容">
    删除或归档有关已弃用功能的文章。过时内容会让客户感到困惑，并降低他们对你支持中心的信任。
  </Step>
</Steps>

<div id="next-steps">
  ## 后续步骤
</div>

您的支持中心已经可以上线了。部署完成后：

1. 在您的产品和网站中添加指向支持中心的链接。
2. 监控助手对话和搜索查询，以发现内容缺口。
3. 每周查看反馈评分并改进评分较低的文章。
4. 跟踪工单量，以衡量自助服务的成效。

一个优秀的支持中心能够在降低支持成本的同时提升客户满意度。持续投入资源，打造能高效解答常见问题的内容。
