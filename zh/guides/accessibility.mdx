创建无障碍文档时，你需要优先考虑内容设计，确保无论用户以何种方式访问和使用文档，尽可能多的人都能顺畅使用你的文档。

无障碍文档能提升所有人的用户体验。你的内容会更清晰、结构更合理，也更容易浏览。

本指南提供了一些创建无障碍文档的最佳实践，但并未涵盖全部内容。你应将无障碍视为一个持续推进的过程。技术和标准会随着时间不断变化，也会带来进一步改进文档的新机会。

<div id="what-is-accessibility">
  ## 什么是无障碍？
</div>

无障碍 (有时缩写为 a11y，表示 “accessibility” 一词首尾字母之间有 11 个字母) 指的是在设计和构建网站与工具时，有意识地确保尽可能多的人都能使用它们。无论是暂时性还是永久性残障人士，都应享有同等程度的数字技术访问权。并且，面向无障碍的设计也会让所有人受益，包括通过移动设备或在低速网络环境下访问你网站的人。

无障碍文档应遵循 Web 无障碍标准，主要是 [Web Content Accessibility Guidelines (WCAG)](https://www.w3.org/WAI/WCAG22/quickref/)。这些指南有助于确保你的内容具备可感知性、可操作性、可理解性和稳健性。

<div id="getting-started-with-accessibility">
  ## 开始进行无障碍优化
</div>

提升文档的无障碍性是一个持续的过程。你不必一次性解决所有问题，而且这也不是做一次就结束的事。

如果你刚开始在文档中推行无障碍实践，可以考虑采用分阶段的方法：先从影响最大的改动着手，再在此基础上逐步完善。

<div id="first-steps">
  ### 入门步骤
</div>

以下是你现在就可以采取的三项措施，用于提升文档的无障碍体验：

1. **运行 `mint a11y`**，识别内容中的无障碍问题。
2. **为所有图片添加替代文本**。
3. **检查标题层级结构**，确保每个页面只有一个 H1，且标题按顺序递进。

<div id="plan-your-accessibility-work">
  ### 规划无障碍工作
</div>

最适合的工作流程，就是适合你团队的那一种。下面提供一种开展无障碍工作的方式：

**第一阶段：图片和结构**

* 检查所有图片是否都配有描述性的替代文本。
* 审查链接文本，替换掉“点击这里”之类的笼统表述。
* 修正文档中的标题层级问题。

**第二阶段：导航和媒体内容**

* 测试文档的键盘导航。
* 测试对屏幕阅读器的支持。
* 为嵌入的视频添加字幕和文字稿。
* 检查颜色对比度。

**第三阶段：将无障碍纳入工作流程**

* 发布新内容前运行 `mint a11y`。
* 在内容审查流程中加入无障碍检查。
* 添加交互功能时测试键盘导航。
* 确认新的外部链接和嵌入内容包含恰当的标题和说明。

从小处着手，并将无障碍纳入日常工作流程，才能更容易长期坚持。每一项改进，都能帮助更多用户顺利访问你的文档。

<div id="structure-your-content">
  ## 组织内容
</div>

结构清晰的内容更便于浏览和理解，尤其是对依靠标题在页面间跳转的屏幕阅读器用户，以及使用键盘导航的用户而言。

<div id="use-proper-heading-hierarchy">
  ### 使用正确的标题层级
</div>

每个页面都应只有一个 H1 标题，由页面前置元数据中的 `title:` 属性定义。其他标题也应按顺序使用，不要跳级。例如，不要从 H2 直接跳到 H4。

```mdx
<!-- 正确 -->
# Page title (H1)

## Main section (H2)

### Subsection (H3)

### Another subsection (H3)

## Another main section (H2)

<!-- 错误 -->
# Page title (H1)

## Main section (H2)

#### Subsection (H4)

### Another subsection (H3)
```

同一级别的标题名称应各不相同。

```mdx
<!-- 正确 -->
## Accessibility tips (H2)

### Write effective alt text (H3)

### Use proper color contrast (H3)

<!-- 错误 -->
## Accessibility tips (H2)

### Tip (H3)

### Tip (H3)
```


<div id="write-descriptive-link-text">
  ### 使用明确的链接文本
</div>

链接文本应当表意清晰，并与目标内容相关。避免使用像 &quot;点击这里&quot; 或 &quot;阅读更多&quot; 这样含糊的表达。

```mdx
<!-- 好的示例 -->
了解如何[配置导航栏](/organize/navigation)。

<!-- 链接文本与目标页面关系不明确 -->
[了解更多](/organize/navigation)。
```


<div id="keep-content-scannable">
  ### 让内容一目了然
</div>

* 拆分长段落。
* 用列表呈现步骤和选项。
* 用提示框突出关键信息。

<div id="use-proper-table-structure">
  ### 使用正确的表格结构
</div>

谨慎使用表格，仅在展示其含义依赖于行标题和列标题的表格数据时使用。

使用表格时，请添加表头，以便屏幕阅读器能够将数据与对应的列关联起来：

```mdx
| Feature | Status |
| ------- | ------ |
| Search  | Active |
| Analytics | Active |
```


<div id="write-descriptive-alt-text">
  ## 编写有描述性的替代文本
</div>

替代文本可帮助使用屏幕阅读器的用户理解图片内容，并会在图片加载失败时显示。在文档中，图片应包含能够描述图片内容并清楚说明为何要使用该图片的替代文本。即使有替代文本，你也不应仅靠图片来传达信息。请确保你的内容也说明了图片所传达的信息。

<div id="write-effective-alt-text">
  ### 编写有效的替代文本
</div>

* **具体明确**：描述图片中的内容，而不只是说明这是一张图片。
* **简明扼要**：尽量控制在一到两句话内。
* **避免冗余**：不要以 &quot;Image of&quot; 开头，因为屏幕阅读器已经知道替代文本对应的是图片。不过，如果这类上下文对理解图片很重要，你应该加入像 &quot;Screenshot of&quot; 或 &quot;Diagram of&quot; 这样的描述。

```mdx
<!-- 好的示例 -->
![Screenshot of the dashboard showing three active projects and two pending invitations](/images/dashboard.png)

<!-- 不够清晰 -->
![Dashboard screenshot](/images/dashboard.png)
```


<div id="add-alt-text-to-images">
  ### 为图片添加 替代文本
</div>

对于 Markdown 图片，请在方括号中填写 替代文本：

```mdx
![Description of the image](/path/to/image.png)
```

对于 HTML 图片，使用 `alt` 属性：

```html
<img
  src="/images/screenshot.png"
  alt="Settings panel with accessibility options enabled. The options are emphasized with an orange rectangle."
/>
```

<div id="add-titles-to-embedded-content">
  ### 为嵌入内容添加标题
</div>

iframe 和嵌入式视频需要提供描述性标题：

```html
<iframe
  src="https://www.youtube.com/embed/example"
  title="Tutorial: Setting up your first documentation site"
></iframe>
```


<div id="design-for-readability">
  ## 注重可读性设计
</div>

视觉设计上的选择会影响低视力、色盲或其他视障用户阅读文档时的可访问性。

<div id="ensure-sufficient-color-contrast">
  ### 确保足够的颜色对比度
</div>

如果你自定义了主题颜色，请确认对比度符合 WCAG 要求：

* 正文：对比度至少为 4.5:1
* 大号文本：对比度至少为 3:1
* 交互元素：对比度至少为 3:1

请同时测试浅色模式和深色模式。`mint a11y` 命令可用于检查颜色对比度。

<div id="dont-rely-on-color-alone">
  ### 不要只依赖颜色
</div>

如果你使用颜色来传达信息，也要同时配上文字标签或图标。例如，不要只用红色文字标示错误。请加入错误图标或“错误”字样。

<div id="use-clear-concise-language">
  ### 使用清晰简洁的语言
</div>

* 使用通俗易懂的表达。
* 首次使用技术术语时给出定义。
* 避免句子过长。
* 使用主动语态。

<div id="make-code-examples-accessible">
  ## 提高代码示例的无障碍性
</div>

代码块是技术文档的核心组成部分，但为了确保使用屏幕阅读器的用户能够理解其内容，需要特别注意无障碍设计。一般来说，请遵循以下准则：

* 将较长的代码示例拆分成更小、更清晰的逻辑片段。
* 为代码中的复杂逻辑添加注释。
* 考虑为复杂算法提供文字说明。
* 展示文件结构时，请使用带语言标签的代码块，而不要使用 ASCII 图示。

<div id="specify-the-programming-language">
  ### 指定编程语言
</div>

始终声明语法高亮所用的语言。这有助于屏幕阅读器向用户说明代码的上下文：

````mdx
```javascript
function getUserData(id) {
  return fetch(`/api/users/${id}`);
}
```
````


<div id="provide-context-around-code">
  ### 为代码补充上下文
</div>

为代码块提供清晰的说明：

````mdx
以下函数从 API 获取用户数据：

```javascript
function getUserData(id) {
  return fetch(`/api/users/${id}`);
}
```

该函数返回一个 Promise，解析后得到用户对象。
````


<div id="video-and-multimedia-accessibility">
  ## 视频和多媒体无障碍
</div>

视频、动画和其他多媒体内容需要提供文本替代内容，以便所有用户都能获取其中的信息。

<div id="add-captions-to-videos">
  ### 为视频添加字幕
</div>

字幕可让失聪或听障用户更方便地获取视频内容。它们也能帮助身处需要保持安静环境中的用户，以及非母语使用者：

* 为视频中所有口述内容添加字幕。
* 在字幕中加入相关的音效说明。
* 确保字幕与音频保持同步。
* 当有多人发言时，使用恰当的标点并标明说话人。

大多数视频托管平台都支持添加字幕。你可以上传字幕文件，或将自动生成的字幕作为起点，然后检查其准确性。

<div id="provide-transcripts">
  ### 提供文字稿
</div>

文字稿为访问视频内容提供了另一种方式。它们可搜索、便于引用，并且支持屏幕阅读器访问：

```mdx
<iframe
  src="https://www.youtube.com/embed/example"
  title="Tutorial: Setting up authentication"
></iframe>

<Accordion title="Video transcript">
In this tutorial, we'll walk through setting up authentication...
</Accordion>
```

将文字稿放在视频附近，或提供清晰的访问链接。

<div id="consider-alternatives-to-video-only-content">
  ### 考虑为纯视频内容提供替代方式
</div>

如果关键信息只出现在视频中：

* 以文本形式提供相同信息。
* 添加关键截图，并配上描述性的替代文本。
* 编写涵盖相同内容的文字教程。

这样可以确保无法访问视频内容的用户仍然能够完成任务。

<div id="test-your-documentation">
  ## 测试文档
</div>

定期测试有助于在用户遇到无障碍问题之前及时发现这些问题。

<div id="check-for-accessibility-issues-with-mint-a11y">
  ### 使用 `mint a11y` 检查无障碍相关问题
</div>

使用 `mint a11y` CLI 命令，自动扫描文档中的常见无障碍问题：

```bash
mint a11y
```

该命令会检查以下问题：

* 图片和视频缺少替代文本。
* 颜色对比度不足。

扫描完成后，请查看报告中的问题，并在内容中进行修复。再次运行该命令，验证修复结果。

使用标志检查特定的无障碍访问问题。

```bash
# 仅检查缺失的 替代文本
mint a11y --skip-contrast

# 仅检查颜色对比度问题
mint a11y --skip-alt-text
```

<div id="basic-keyboard-navigation-test">
  ### 基本键盘导航测试
</div>

仅使用键盘浏览你的文档：

1. 按 <kbd>Tab</kbd> 在交互元素之间向前切换。
2. 按 <kbd>Shift</kbd> + <kbd>Tab</kbd> 向后切换。
3. 按 <kbd>Enter</kbd> 激活链接和按钮。
4. 确认所有交互元素都可以通过键盘访问，并且有可见的焦点指示。

<div id="go-deeper-with-accessibility-testing">
  ### 进一步开展无障碍测试
</div>

如需进行更全面的测试：

* **屏幕阅读器**：使用 [NVDA (Windows)](https://www.nvaccess.org/) 或 [VoiceOver (Mac)](https://www.apple.com/accessibility/voiceover/) 进行测试。
* **浏览器扩展**：安装 [axe DevTools](https://www.deque.com/axe/browser-extensions/) 或 [WAVE](https://wave.webaim.org/extension/) 扫描页面中的问题。
* **WCAG 指南**：查阅 [Web Content Accessibility Guidelines](https://www.w3.org/WAI/WCAG22/quickref/)，了解详细标准。
