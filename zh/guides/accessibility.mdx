当你创建无障碍文档时，你会在内容设计上优先考虑，让尽可能多的人都能使用你的文档，而不论他们通过何种方式访问或与之交互。

无障碍文档可以改善所有人的使用体验。你的内容会更加清晰，结构更合理，也更便于浏览。

本指南提供了一些创建无障碍文档的最佳实践，但并不全面。你应当把无障碍视为一项持续的工作。技术和标准会随着时间演进，从而带来不断改进文档的新机会。

<div id="what-is-accessibility">
  ## 什么是无障碍设计？
</div>

无障碍设计（有时缩写为 a11y，指的是“accessibility”一词中首尾字母之间的 11 个字母）是指有意识地设计和构建网站和工具，使尽可能多的人都能使用它们。具有暂时或永久性障碍的人，应该享有与他人同等水平的数字技术使用权。同时，为无障碍而进行设计会让所有人受益，包括那些通过移动设备或在低速网络环境下访问你网站的人。

无障碍文档遵循网页无障碍标准，主要是 [Web Content Accessibility Guidelines (WCAG)](https://www.w3.org/WAI/WCAG22/quickref/)。这些指南有助于确保你的内容是可感知的、可操作的、可理解的且具有良好健壮性。

<div id="getting-started-with-accessibility">
  ## 无障碍入门
</div>

让你的文档满足无障碍要求是一个持续的过程。你不必一下子修复所有问题，也不可能只做一次就完事。 

如果你刚开始在文档中引入无障碍实践，可以考虑采用分阶段的方法：先从影响最大的改动入手，再在此基础上逐步完善。

<div id="first-steps">
  ### 入门步骤
</div>

以下是你现在就可以采取的三项措施，以提升文档的可访问性：

1. **运行 `mint a11y`** 来识别内容中的可访问性问题。
2. **为所有图片添加替代文本（alt 文本）**。
3. **检查你的标题层级结构**，确保每个页面只有一个 H1，且各级标题按顺序依次递增。

<div id="plan-your-accessibility-work">
  ### 规划你的无障碍工作
</div>

最好的工作流程就是最适合你团队的那一种。下面是你可以开展无障碍工作的一个思路：

**阶段 1：图片和结构**

- 检查所有图片是否具有描述性的 alt 文本。
- 审核链接文本，将诸如 “click here” 这类泛泛的短语替换掉。
- 修复整份文档中的标题层级问题。

**阶段 2：导航和媒体**

- 在你的文档中测试键盘导航。
- 测试对屏幕阅读器的兼容性。
- 为嵌入的视频添加字幕和文字稿。
- 检查颜色对比度。

**阶段 3：将其融入你的工作流程**

- 在发布新内容前运行 `mint a11y`。
- 在内容审查流程中加入无障碍检查。
- 在添加交互功能时测试键盘导航。
- 确认新的外部链接和嵌入内容包含适当的标题和描述。

从小处着手，并将无障碍融入日常工作流程，可以让这项工作更可持续。每一次改进都能帮助更多用户顺利访问你的文档。

<div id="structure-your-content">
  ## 合理组织你的内容
</div>

结构良好的内容更便于浏览和理解，尤其是对于依赖标题在页面中导航的屏幕阅读器用户，以及使用键盘进行导航的人来说。

<div id="use-proper-heading-hierarchy">
  ### 使用正确的标题层级结构
</div>

每个页面都应该只有一个 H1 标题，它由页面 frontmatter 中的 `title:` 属性定义。后续标题级别应按顺序递增，避免跳级。比如，不要从 H2 直接跳到 H4。

```mdx
<!-- 正确 -->
# Page title (H1)

## Main section (H2)

### Subsection (H3)

### Another subsection (H3)

## Another main section (H2)

<!-- 错误 -->
# Page title (H1)

## Main section (H2)

#### Subsection (H4)

### Another subsection (H3)
```

同一层级的标题应各有不同的名称。

```mdx
<!-- 正确 -->
## Accessibility tips (H2)

### Write effective alt text (H3)

### Use proper color contrast (H3)

<!-- 错误 -->
## Accessibility tips (H2)

### Tip (H3)

### Tip (H3)
```


<div id="write-descriptive-link-text">
  ### 编写描述性链接文本
</div>

链接文本应当具有明确含义，并且与目标内容紧密相关。避免使用诸如“click here”或“read more”之类含糊的短语。

```mdx
<!-- 好的示例 -->
Learn how to [configure your navigation](/organize/navigation).

<!-- 链接文本与目标页面关系不明确 -->
[Learn more](/organize/navigation).
```


<div id="keep-content-scannable">
  ### 保持内容便于快速浏览
</div>

- 拆分过长的段落。
- 使用列表来展示步骤和选项。
- 使用提示框突出重要信息。

<div id="use-proper-table-structure">
  ### 使用正确的表格结构
</div>

应尽量少用表格，仅在需要呈现其含义由行、列表头所定义的表格数据时才使用。

在使用表格时，应包含表头，以便屏幕阅读器可以将数据与正确的列关联：

```mdx
| Feature | Status |
| ------- | ------ |
| Search  | Active |
| Analytics | Active |
```


<div id="write-descriptive-alt-text">
  ## 编写具有描述性的替代文本（alt text）
</div>

替代文本（alt text）可以让使用屏幕阅读器的用户获取图像信息，并会在图像加载失败时显示。在你的文档中，图像应当包含替代文本，用来描述图像并清楚说明为何要使用该图像。即使有替代文本，你也不应仅依赖图像来传达信息。确保你的内容本身就描述了图像所要传达的信息。

<div id="write-effective-alt-text">
  ### 编写有效的替代文字（alt text）
</div>

* **要具体**：描述图像中具体呈现的内容，而不仅仅是说明这是一张图像。
* **要简洁**：控制在一到两句话之内。
* **避免冗余**：不要以 &quot;Image of&quot; 开头，因为屏幕阅读器已经知道替代文字是与图像关联的。不过，如果这些上下文对图像很重要，你可以包含诸如 &quot;Screenshot of&quot; 或 &quot;Diagram of&quot; 之类的描述。

```mdx
<!-- 好的示例 -->
![Screenshot of the dashboard showing three active projects and two pending invitations](/images/dashboard.png)

<!-- 不够清晰 -->
![Dashboard screenshot](/images/dashboard.png)
```


<div id="add-alt-text-to-images">
  ### 为图片添加替代文本（alt text）
</div>

对于 Markdown 图片，请在方括号中填写替代文本：

```mdx
![Description of the image](/path/to/image.png)
```

在 HTML 中的图片请使用 `alt` 属性：

```html
<img
  src="/images/screenshot.png"
  alt="Settings panel with accessibility options enabled. The options are emphasized with an orange rectangle."
/>
```


<div id="add-titles-to-embedded-content">
  ### 为嵌入内容添加标题
</div>

iframe 和嵌入的视频需要添加描述性标题：

```html
<iframe
  src="https://www.youtube.com/embed/example"
  title="Tutorial: Setting up your first documentation site"
></iframe>
```


<div id="design-for-readability">
  ## 为提升可读性而设计
</div>

视觉设计上的选择会影响你的文档对视力低下、色盲或其他视觉障碍用户的可访问性。

<div id="ensure-sufficient-color-contrast">
  ### 确保足够的颜色对比度
</div>

如果你自定义主题颜色，请确认对比度符合 WCAG 要求：

- 正文文本：至少 4.5:1 的对比度
- 大字号文本：至少 3:1 的对比度
- 交互元素：至少 3:1 的对比度

同时测试浅色模式和深色模式。`mint a11y` 命令可以检查颜色对比度。

<div id="dont-rely-on-color-alone">
  ### 不要仅依赖颜色
</div>

如果你使用颜色来传达信息，还应同时配合文字标签或图标。例如，不要只用红色文字标记错误，而应同时包含错误图标或“错误”字样。

<div id="use-clear-concise-language">
  ### 使用清晰、简洁的语言
</div>

- 使用通俗易懂的语言撰写。
- 在技术术语首次出现时加以定义。
- 避免将多个句子生硬连在一起。
- 使用主动语态。

<div id="make-code-examples-accessible">
  ## 提高代码示例的无障碍性
</div>

代码块是技术文档的核心组成部分，但它们需要特定的无障碍设计，才能确保使用屏幕阅读器的用户也能理解其中内容。一般来说，请遵循以下指南：

- 将较长的代码示例拆分成更小且逻辑清晰的片段。
- 在代码中为复杂逻辑添加注释。
- 考虑为复杂算法提供文字说明。
- 展示文件结构时，使用带有语言标注的实际代码块，而不是 ASCII 图。

<div id="specify-the-programming-language">
  ### 指定编程语言
</div>

务必在语法高亮中声明所使用的语言。这样可以帮助屏幕阅读器向用户说明代码的上下文：

````mdx
```javascript
function getUserData(id) {
  return fetch(`/api/users/${id}`);
}
```
````


<div id="provide-context-around-code">
  ### 为代码提供上下文
</div>

为代码块提供清晰的上下文信息：

````mdx
以下函数从 API 获取用户数据：

```javascript
function getUserData(id) {
  return fetch(`/api/users/${id}`);
}
```

这将返回一个解析为用户对象的 Promise。
````


<div id="video-and-multimedia-accessibility">
  ## 视频和多媒体无障碍设计
</div>

视频、动画和其他多媒体内容都需要提供文字替代内容，让所有用户都能获取其中的信息。

<div id="add-captions-to-videos">
  ### 为视频添加字幕
</div>

字幕让视频内容也能被失聪或听力障碍用户访问和理解。它们同样有助于身处不便播放声音环境中的用户以及非母语使用者：

- 为视频中所有口语内容添加字幕。
- 在字幕中包含相关的音效信息。
- 确保字幕与音频同步。
- 在多人讲话时使用正确的标点符号和说话人标识。

大多数视频托管平台都支持添加字幕。可以上传字幕文件，或将自动生成的字幕作为起点，然后进行检查和修正以确保准确性。

<div id="provide-transcripts">
  ### 提供文字稿
</div>

文字稿为访问视频内容提供了另一种方式。它们可被搜索、便于引用，并且可供屏幕阅读器读取：

```mdx
<iframe
  src="https://www.youtube.com/embed/example"
  title="Tutorial: Setting up authentication"
></iframe>

<Accordion title="Video transcript">
In this tutorial, we'll walk through setting up authentication...
</Accordion>
```

将文字稿放在视频旁边，或提供清晰可见的链接以供访问。


<div id="consider-alternatives-to-video-only-content">
  ### 考虑视频内容的替代方案
</div>

如果关键信息只出现在视频中：

- 提供等价的文本版本。
- 包含关键截图，并配以描述性的替代文本。
- 编写涵盖相同内容的书面教程。

这样可以确保无法访问视频内容的用户仍然能够完成他们的任务。

<div id="test-your-documentation">
  ## 测试你的文档
</div>

定期测试有助于在用户遇到这些问题之前及时发现可访问性问题。

<div id="check-for-accessibility-issues-with-mint-a11y">
  ### 使用 `mint a11y` 检查无障碍问题
</div>

使用 `mint a11y` CLI 命令自动扫描文档中的常见无障碍问题：

```bash
mint a11y
```

该命令会检查：

* 图像和视频缺少 alt 文本。
* 颜色对比度不足。

扫描完成后，查看报告的问题，并在内容中进行修复。再次运行该命令以验证修复是否生效。

使用标志（flag）来检查特定的无障碍问题。

```bash
# 仅检查缺失的替代文本
mint a11y --skip-contrast

# 仅检查颜色对比度问题
mint a11y --skip-alt-text
```


<div id="basic-keyboard-navigation-test">
  ### 基本键盘导航测试
</div>

仅使用键盘在文档中导航：

1. 按下 <kbd>Tab</kbd> 在交互元素之间向前移动。
2. 按下 <kbd>Shift</kbd> + <kbd>Tab</kbd> 向后移动。
3. 按下 <kbd>Enter</kbd> 激活链接和按钮。
4. 确认所有交互元素都可以通过键盘访问，并且在获得焦点时有清晰可见的焦点指示。

<div id="go-deeper-with-accessibility-testing">
  ### 更深入地进行无障碍测试
</div>

若要进行更全面的测试：

- **屏幕阅读器**：使用 [NVDA（Windows）](https://www.nvaccess.org/) 或 [VoiceOver（Mac）](https://www.apple.com/accessibility/voiceover/) 进行测试。
- **浏览器扩展程序**：安装 [axe DevTools](https://www.deque.com/axe/browser-extensions/) 或 [WAVE](https://wave.webaim.org/extension/) 来扫描页面并查找问题。
- **WCAG 指南**：查阅 [Web Content Accessibility Guidelines](https://www.w3.org/WAI/WCAG22/quickref/) 以了解详细标准。
