有效的链接能够打造连贯的文档体验，帮助用户发现相关内容并高效导航。链接过多或存在无效链接都会让用户感到困惑，降低文档的有效性。本指南介绍如何在整套文档中创建和维护链接。

<div id="internal-links">
  ## 内部链接
</div>

使用根相对路径链接到文档中的其他页面。根相对路径从文档目录的根开始计算，无论当前链接所在的页面位于何处，都能保持一致、可靠的行为。

```mdx
* [Quickstart guide](/quickstart)
* [API overview](/api-playground/overview)
* [Custom components](/customize/react-components)
```

* [快速入门指南](/zh/quickstart)
* [API 概览](/zh/api-playground/overview)
* [自定义组件](/zh/customize/react-components)

<div id="anchor-links">
  ## 锚点链接
</div>

锚点链接可以让你直接跳转到页面中的特定部分。每个标题都会根据其文字内容自动生成一个锚点链接。

<div id="link-to-headers-on-the-same-page">
  ### 链接到本页标题
</div>

使用 # 号引用本页中的标题：

```mdx
[Jump to best practices](#best-practices)
```

[跳至“最佳实践”](#best-practices)

<div id="link-to-headers-on-other-pages">
  ### 链接到其他页面的标题
</div>

将页面路径与锚点链接拼接在一起。

```mdx
* [Customize your playground](/api-playground/overview#customize-your-playground)
* [Cards properties](/components/cards#properties)
```

* [自定义你的 Playground](/zh/api-playground/overview#customize-your-playground)
* [卡片属性](/zh/components/cards#properties)

<div id="how-anchor-links-are-generated">
  ### 锚点链接的生成方式
</div>

锚点链接会根据标题文本自动创建。

* 转为小写
* 将空格替换为连字符
* 移除特殊字符
* 保留数字和字母

| 标题文本 | 锚点链接 |
|-------------|-------------|
| `## Getting Started` | `#getting-started` |
| `### API Authentication` | `#api-authentication` |
| `#### Step 1: Install` | `#step-1-install` |

<Note>
  带有 `noAnchor` 属性的标题不会生成锚点链接。详情参见 [格式化文本](/zh/create/text#disabling-anchor-links)。
</Note>

<div id="link-to-api-endpoints">
  ## 链接到 API 端点
</div>

在编写 API 文档时，你可以在文档中的任意位置链接到特定端点。

在导航中通过端点页面的路径来链接到相应的 API 端点页面。

<div id="link-to-external-pages">
  ## 链接到外部页面
</div>

当你链接到外部资源时，要清楚地标明该链接会跳转到文档之外的页面。

```mdx
Learn more about [Markdown syntax](https://www.markdownguide.org/) (external link).

See the [OpenAPI specification](https://swagger.io/specification/) in the Swagger documentation for details.
```

<div id="best-practices">
  ## 最佳实践
</div>

<div id="write-descriptive-link-text">
  ### 编写描述性链接文本
</div>

使用清晰、具有描述性的文本，让用户了解点击后会看到什么内容。

<CodeGroup>
  ```mdx Good examples
  有关更多信息，请参见 [Hidden pages](/organize/hidden-pages)。
  [Configure custom domains](/customize/custom-domain)
  ```

  ```mdx Avoid
  [Click here](/api-playground/overview)
  [Read more](/deploy/deployments)
  [See this page](/customize/custom-domain)
  ```
</CodeGroup>

<div id="create-topic-clusters">
  ### 创建主题集群
</div>

将相关内容互相链接起来，帮助用户发现更多相关信息。

```mdx
## Related topics

- [API authentication](/api-playground/overview#authentication)
- [Adding SDK examples](/api-playground/adding-sdk-examples)
- [Managing page visibility](/api-playground/managing-page-visibility)
```

<div id="use-contextual-links">
  ### 使用上下文链接
</div>

在内容中，在能提供实际价值的地方自然插入链接。

```mdx
To customize your documentation appearance, configure [themes](/customize/themes) 
and [fonts](/customize/fonts) in your settings. You can also add 
[custom scripts](/customize/custom-scripts) for advanced functionality.
```

<div id="link-to-prerequisites">
  ### 链接到前置内容
</div>

通过链接到前置内容来帮助用户做好准备：

```mdx
## Prerequisites

Before deploying your documentation, ensure you have:

- Completed the [quickstart guide](/quickstart)
- Configured your [custom domain](/customize/custom-domain)
- Set up [authentication](/deploy/authentication-setup) if needed
```

<div id="avoid-circular-links">
  ### 避免循环链接
</div>

不要创建让用户在同一组页面之间来回跳转的链接。

<div id="check-for-broken-links">
  ### 检查无效链接
</div>

使用 Mintlify CLI 检测文档中的无效链接。

```bash
mint broken-links
```

<div id="update-links-when-reorganizing">
  ### 在重组内容时更新链接
</div>

在移动或重命名页面时：

1. 在导航配置中更新页面路径。
2. 将旧路径设置为重定向到新路径。
3. 在文档中搜索所有对旧路径的引用。
4. 将所有内部链接更新为使用新路径。
5. 运行 `mint broken-links` 以验证所有链接是否正常。

<div id="use-redirects-for-moved-content">
  ### 对已移动的内容使用重定向
</div>

在永久移动内容时，添加重定向以避免链接失效。

```json
{
  "redirects": [
    {
      "source": "/old-path",
      "destination": "/new-path"
    }
  ]
}
```

请参阅[重定向](/zh/create/redirects)了解更多信息。
