如果你目前为 API 端点使用单独的 MDX 页面，可以迁移到基于 OpenAPI 规范自动生成页面，同时保留单页的自定义能力。这有助于减少需要维护的文件数量，并提升 API 文档的一致性。

你可以在 OpenAPI 规范中为每个端点定义元数据和内容，并按需在导航中组织这些端点。

<div id="cli-migration">
  ## CLI 迁移
</div>

`mint migrate-mdx` 命令是将 MDX 端点页面迁移为自动生成页面的推荐方式。

此命令会：

* 解析你的 `docs.json` 导航结构。
* 识别会生成 OpenAPI 端点页面的 MDX 页面。
* 从 MDX 文件中提取内容，并将其迁移到 OpenAPI 规范中的 `x-mint` 扩展。
* 更新你的 `docs.json`，使其直接引用 OpenAPI 端点，而不是 MDX 文件。
* 删除原始的 MDX 端点文件。

<Info>
  如果某个端点已经定义了 `x-mint`，同时你又有一个包含该端点内容的 MDX 页面，那么 MDX 内容会覆盖现有的 `x-mint` 设置。

  如果同一个端点对应多个内容不同的 MDX 页面，脚本会使用在 `docs.json` 中最后出现的页面内容。

  迁移工具不支持在应用更改前预览变更。
</Info>

<Steps>
  <Step title="准备 OpenAPI 规范。">
    确保你的 OpenAPI 规范有效，并且包含你想编写文档的所有端点。

    你要迁移的任何 MDX 页面都必须包含引用某个端点的 `openapi:` 前置元数据。

    <Tip>
      使用 [Swagger Editor](https://editor.swagger.io/) 或 [Mint CLI](https://www.npmjs.com/package/mint) 验证你的 OpenAPI 文件。
    </Tip>
  </Step>

  <Step title="安装 Mint CLI">
    如有需要，请安装或更新 [Mint CLI](/zh/installation)。
  </Step>

  <Step title="运行迁移命令。">
    ```bash
    mint migrate-mdx
    ```
  </Step>
</Steps>

<div id="manual-migration-steps">
  ## 手动迁移步骤
</div>

<Steps>
  <Step title="准备好你的 OpenAPI 规范。">
    确保你的 OpenAPI 规范有效，并包含你想要编写文档的所有端点。

    对于需要自定义元数据或内容的端点，请为该端点添加 `x-mint` 扩展。更多详情，请参阅 [x-mint extension](/zh/api-playground/openapi-setup#x-mint-extension)。

    对于你想要从文档中排除的端点，请为该端点添加 `x-hidden` 扩展。

    <Info>
      使用 [Swagger Editor](https://editor.swagger.io/) 或 [Mint CLI](https://www.npmjs.com/package/mint) 验证你的 OpenAPI 文件。
    </Info>
  </Step>

  <Step title="更新你的导航结构。">
    在你的 `docs.json` 中，将 MDX 页面引用替换为 OpenAPI 端点。

    ```json
    "navigation": {
      "groups": [
        {
          "group": "API Reference",
          "openapi": "/path/to/openapi.json",
          "pages": [
            "overview",
            "authentication",
            "introduction",
            "GET /health",
            "quickstart", 
            "POST /users",
            "GET /users/{id}",
            "advanced-features"
          ]
        }
      ]
    }
    ```
  </Step>

  <Step title="删除旧的 MDX 文件。">
    确认新导航可以正常工作后，删除不再需要的 MDX 端点文件。
  </Step>
</Steps>

<div id="navigation-patterns">
  ## 导航模式
</div>

你可以自定义 API 文档在导航中的展示方式。

<div id="mixed-content-navigation">
  ### 混合内容导航
</div>

将自动生成的 API 页面与其他页面组合使用：

```json
"navigation": {
  "groups": [
    {
      "group": "API Reference",
      "openapi": "openapi.json",
      "pages": [
        "api/overview",
        "GET /users",
        "POST /users", 
        "api/authentication"
      ]
    }
  ]
}
```

<div id="multiple-api-versions">
  ### 多个 API 版本
</div>

使用标签页或分组组织不同的 API 版本：

```json
"navigation": {
  "tabs": [
    {
      "tab": "API v1",
      "openapi": "specs/v1.json"
    },
    {
      "tab": "API v2", 
      "openapi": "specs/v2.json"
    }
  ]
}
```

<div id="when-to-use-individual-mdx-pages">
  ## 何时使用单独的 MDX 页面
</div>

如果你有以下需求，可以考虑保留单独的 MDX 页面：

* 需要为每个端点编写大量自定义内容，例如 React 组件或较长的示例。
* 需要独特的页面布局。
* 想为特定端点采用实验性的文档编写方式。

对于大多数场景，使用 OpenAPI 导航在可维护性和一致性方面更有优势。
