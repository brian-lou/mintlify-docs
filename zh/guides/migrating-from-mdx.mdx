---
title: "将 MDX API 页面迁移到 OpenAPI 导航"
sidebarTitle: "从 MDX 迁移到 OAS"
description: "迁移到基于 OpenAPI 的自动生成并配合灵活导航。"
keywords: ["API migration", "mint migrate-mdx", "OpenAPI migration", "x-mint extension"]
---

如果你目前为每个 API 端点使用单独的 MDX 页面，可以迁移为根据 OpenAPI 规范自动生成页面，同时仍然保留对单个页面进行自定义的能力。这样可以帮助你减少需要维护的文件数量，并提升 API 文档的一致性。

你可以在 OpenAPI 规范中为每个端点定义元数据和内容，并在导航中按需组织这些端点。

<div id="cli-migration">
  ## CLI 迁移
</div>

`mint migrate-mdx` 命令是从 MDX 端点页面迁移到自动生成页面的推荐方式。

该命令会：

* 解析你的 `docs.json` 导航结构。
* 识别出会生成 OpenAPI 端点页面的 MDX 页面。
* 从 MDX 文件中提取内容，并将其移动到 OpenAPI 规范中的 `x-mint` 扩展里。
* 更新你的 `docs.json`，使其直接引用 OpenAPI 端点，而不是 MDX 文件。
* 删除原始的 MDX 端点文件。

<Info>
  如果你已经为某个端点定义了 `x-mint`，并且还为该端点提供了带内容的 MDX 页面，那么 MDX 内容将会覆盖已有的 `x-mint` 设置。

  如果你为同一个端点创建了多个内容不同的 MDX 页面，脚本将使用在 `docs.json` 中出现位置最靠后的那个页面的内容。

  迁移工具不支持在应用更改之前预览更改。
</Info>

<Steps>
  <Step title="准备你的 OpenAPI 规范。">
    确保你的 OpenAPI 规范是有效的，并且包含你想要记录的所有端点。

    任何你想迁移的 MDX 页面，其 frontmatter 中都必须包含用于引用某个端点的 `openapi:` 字段。

    <Tip>
      使用 [Swagger Editor](https://editor.swagger.io/) 或 [Mint CLI](https://www.npmjs.com/package/mint) 验证你的 OpenAPI 文件。
    </Tip>
  </Step>

  <Step title="安装 Mint CLI">
    如有需要，安装或更新 [Mint CLI](/zh/installation)。
  </Step>

  <Step title="运行迁移命令。">
    ```bash
    mint migrate-mdx
    ```
  </Step>
</Steps>

<div id="manual-migration-steps">
  ## 手动迁移步骤
</div>

<Steps>
  <Step title="准备你的 OpenAPI 规范。">
    确保你的 OpenAPI 规范有效，并且包含你希望在文档中覆盖的所有端点。

    对于任何你想自定义元数据或内容的端点，在该端点上添加 `x-mint` 扩展。更多详情请参见 [x-mint 扩展](/zh/api-playground/openapi-setup#x-mint-extension)。

    对于任何你想从文档中排除的端点，在该端点上添加 `x-hidden` 扩展。

    <Info>
      使用 [Swagger Editor](https://editor.swagger.io/) 或 [Mint CLI](https://www.npmjs.com/package/mint) 验证你的 OpenAPI 文件。
    </Info>
  </Step>

  <Step title="更新你的导航结构。">
    在 `docs.json` 中，将 MDX 页面引用替换为 OpenAPI 端点。

    ```json
    "navigation": {
      "groups": [
        {
          "group": "API Reference",
          "openapi": "/path/to/openapi.json",
          "pages": [
            "overview",
            "authentication",
            "introduction",
            "GET /health",
            "quickstart", 
            "POST /users",
            "GET /users/{id}",
            "advanced-features"
          ]
        }
      ]
    }
    ```
  </Step>

  <Step title="删除旧的 MDX 文件。">
    在确认新导航正常工作之后，删除那些不再需要的 MDX 端点文件。
  </Step>
</Steps>

<div id="navigation-patterns">
  ## 导航模式
</div>

你可以自定义导航中 API 文档的显示方式。

<div id="mixed-content-navigation">
  ### 混合式导航
</div>

将自动生成的 API 页面与其他页面组合在一起：

```json
"navigation": {
  "groups": [
    {
      "group": "API Reference",
      "openapi": "openapi.json",
      "pages": [
        "api/overview",
        "GET /users",
        "POST /users", 
        "api/authentication"
      ]
    }
  ]
}
```

<div id="multiple-api-versions">
  ### 多个 API 版本
</div>

通过选项卡或分组来组织不同的 API 版本：

```json
"navigation": {
  "tabs": [
    {
      "tab": "API v1",
      "openapi": "specs/v1.json"
    },
    {
      "tab": "API v2", 
      "openapi": "specs/v2.json"
    }
  ]
}
```

<div id="when-to-use-individual-mdx-pages">
  ## 何时使用独立 MDX 页面
</div>

在以下情况下，可以考虑保留独立的 MDX 页面：

* 每个端点需要大量自定义内容，例如 React 组件或较长的示例。
* 需要独特的页面布局。
* 需要针对特定端点采用实验性的文档编写方式。

对于大多数用例，在可维护性和一致性方面，OpenAPI 导航是更好的选择。
