`docs.json` 中的 [navigation](/zh/organize/settings#param-navigation) 属性用于控制文档的结构和信息层级。

通过合理配置导航，你可以更好地组织内容，让用户快速找到所需信息。

在导航的根级别选择一种主要的组织方式。选定后，你可以在其中嵌套其他导航元素。

<div id="pages">
  ## 页面
</div>

页面是最基本的导航组件。每个页面都是文档仓库中的一个 MDX 文件。

<img className="block dark:hidden pointer-events-none" src="/images/navigation/pages-light.png" alt="页面装饰图。" />

<img className="hidden dark:block pointer-events-none" src="/images/navigation/pages-dark.png" alt="页面装饰图。" />

在 `navigation` 对象中，`pages` 是一个数组，其中每一项都必须指向某个[页面文件](/zh/organize/pages)的路径。

```json
{
  "navigation": {
    "pages": [
      "settings",
      "pages",
      "navigation",
      "themes",
      "custom-domain"
    ]
  }
}
```

<div id="groups">
  ## 分组
</div>

使用分组将侧边栏导航整理为不同的区块。分组可以相互嵌套、添加标签，并配上图标。

<img className="block dark:hidden pointer-events-none" src="/images/navigation/groups-light.png" alt="分组的装饰性图示。" />

<img className="hidden dark:block pointer-events-none" src="/images/navigation/groups-dark.png" alt="分组的装饰性图示。" />

在 `navigation` 对象中，`groups` 是一个数组，其中每一项都是一个对象，必须包含 `group` 和 `pages` 字段。`icon`、`tag` 和 `expanded` 字段为可选项。

```json
{
  "navigation": {
    "groups": [
      {
        "group": "Getting started",
        "icon": "play",
        "pages": [
          "quickstart",
          {
            "group": "Editing",
            "expanded": false,
            "icon": "pencil",
            "pages": [
              "installation",
              "editor"
            ]
          }
        ]
      },
      {
        "group": "Writing content",
        "icon": "notebook-text",
        "tag": "NEW",
        "pages": [
          "writing-content/page",
          "writing-content/text"
        ]
      }
    ]
  }
}
```

<div id="default-expanded-state">
  ### 默认展开状态
</div>

使用 `expanded` 属性来控制导航侧边栏中嵌套分组的默认展开状态。

* `expanded: true`：分组默认展开。
* `expanded: false` 或省略：分组默认折叠。

<Note>
  `expanded` 属性仅影响嵌套分组，也就是分组中的分组。顶层分组始终处于展开状态，且无法折叠。
</Note>

```json
{
  "group": "Getting started",
  "pages": [
    "quickstart",
    {
      "group": "Advanced",
      "expanded": false,
      "pages": ["installation", "configuration"]
    }
  ]
}
```

<div id="tabs">
  ## 标签页
</div>

标签页会通过独立的 URL 路径将文档划分为不同部分。它还会在文档顶部生成一条水平导航栏，方便用户在各个部分之间切换。

<img className="block dark:hidden pointer-events-none" src="/images/navigation/tabs-light.png" alt="标签页导航的装饰性图示。" />

<img className="hidden dark:block pointer-events-none" src="/images/navigation/tabs-dark.png" alt="标签页导航的装饰性图示。" />

在 `navigation` 对象中，`tabs` 是一个数组，其中每一项都是一个对象，必须包含 `tab` 字段，也可以包含其他导航字段，例如分组、页面、图标或指向外部页面的链接。

```json
{
  "navigation": {
    "tabs": [
      {
        "tab": "API reference",
        "icon": "square-terminal",
        "pages": [
          "api-reference/get",
          "api-reference/post",
          "api-reference/delete"
        ]
      },
      {
        "tab": "SDKs",
        "icon": "code",
        "pages": [
          "sdk/fetch",
          "sdk/create",
          "sdk/delete"
        ]
      },
      {
        "tab": "Blog",
        "icon": "newspaper",
        "href": "https://external-link.com/blog"
      }
    ]
  }
}
```

<div id="menus">
  ### 菜单
</div>

菜单可为标签页添加下拉导航项。使用菜单可帮助用户直接跳转到标签页中的特定页面。

在 `navigation` 对象中，`menu` 是一个数组，其中每个条目都是一个对象，必须包含 `item` 字段，还可以包含其他导航字段，例如分组、页面、图标或外部页面链接。

菜单项只能包含分组、页面和外部链接。

```json
{
  "navigation": {
    "tabs": [
      {
        "tab": "Developer tools",
        "icon": "square-terminal",
        "menu": [
          {
            "item": "API reference",
            "icon": "rocket",
            "groups": [
              {
                "group": "Core endpoints",
                "icon": "square-terminal",
                "pages": [
                  "api-reference/get",
                  "api-reference/post",
                  "api-reference/delete"
                ]
              }
            ]
          },
          {
            "item": "SDKs",
            "icon": "code",
            "description": "SDK 用于与 API 交互。",
            "pages": [
              "sdk/fetch",
              "sdk/create",
              "sdk/delete"
            ]
          }
        ]
      }
    ]
  }
}
```

<div id="anchors">
  ## 锚点
</div>

锚点会在侧边栏顶部添加固定显示的导航项。你可以使用锚点为内容分区、快速访问外部资源，或创建醒目的行动号召。

<img className="block dark:hidden pointer-events-none" src="/images/navigation/anchors-light.png" alt="锚点导航的装饰性图示。" />

<img className="hidden dark:block pointer-events-none" src="/images/navigation/anchors-dark.png" alt="锚点导航的装饰性图示。" />

在 `navigation` 对象中，`anchors` 是一个数组，其中每一项都是一个对象，必须包含 `anchor` 字段，也可以包含其他导航字段，例如分组、页面、图标或外部页面链接。

```json
{
  "navigation": {
    "anchors": [
      {
        "anchor": "Documentation",
        "icon": "book-open",
        "pages": [
          "quickstart",
          "development",
          "navigation"
        ]
      },
      {
        "anchor": "API reference",
        "icon": "square-terminal",
        "pages": [
          "api-reference/get",
          "api-reference/post",
          "api-reference/delete"
        ]
      },
      {
        "anchor": "Blog",
        "href": "https://external-link.com/blog"
      }
    ]
  }
}
```

<div id="global-anchors">
  ### 全局锚点
</div>

对于需要显示在所有页面上的链接，无论用户当前查看的是 navigation 中的哪个部分，都应使用全局锚点。全局锚点特别适合链接到文档外部的资源 (例如博客、社区论坛或支持门户) ，也适合为重要的内部页面 (例如变更日志或状态页面) 提供统一的访问入口。

全局锚点既支持外部 URL，也支持指向文档内页面的相对路径。

```json
{
  "navigation": {
    "global":  {
      "anchors": [
        {
          "anchor": "Changelog",
          "icon": "list",
          "href": "/changelog"
        },
        {
          "anchor": "Blog",
          "icon": "pencil",
          "href": "https://mintlify.com/blog"
        }
      ]
    },
    "tabs": /*...*/
  }
}
```

  ## 下拉菜单

下拉菜单位于侧边栏导航顶部的可展开菜单中。下拉菜单中的每一项都会指向文档中的某个部分。

在 `navigation` 对象中，`dropdowns` 是一个数组，其中每一项都是一个对象，必须包含 `dropdown` 字段，还可以包含其他导航字段，例如分组、页面、图标或外部页面链接。

```json

  "navigation": {
    "dropdowns": [
      {
        "dropdown": "Documentation",

        "pages": [
          "quickstart",
          "development",
          "navigation"
        ]
      },

        "dropdown": "API reference",
        "icon": "square-terminal",
        "pages": [
          "api-reference/get",
          "api-reference/post",
          "api-reference/delete"
        ]

      {
```

在 `navigation` 对象中，`products` 是一个数组，其中每一项都是一个对象，必须包含 `product` 字段，也可以包含其他导航字段，例如分组、页面、图标或外部页面链接。

```json
            ]
          },
          {
            "group": "Endpoints",
            "pages": [
              "core-api/users",
              "core-api/orders"
            ]
          }
        ]
      },
      {
        "product": "Analytics Platform",
        "description": "Analytics Platform description",
        "icon": "chart-bar",

          "analytics/overview",
          "analytics/dashboard",
```

<div id="openapi">
  ## OpenAPI
</div>

将 OpenAPI 规范直接集成到文档的导航结构中，即可自动生成 API 文档。你可以创建专门的 API 章节，也可以将端点页面放入其他导航组件中。

你可以在导航层级的任意级别设置默认的 OpenAPI 规范。除非子元素定义了自己的规范，否则它们都会继承该规范。

<Note>
  当你为某个导航元素 (例如 锚点、标签页 或 分组) 添加 `openapi` 属性但未指定任何页面时，Mintlify 会自动为 OpenAPI 规范中定义的 **所有端点** 生成页面。

  若要控制显示哪些端点，请在 `pages` 数组中明确列出所需端点。
</Note>

如需详细了解如何在文档中引用 OpenAPI 端点，请参阅 [OpenAPI 设置](/zh/api-playground/openapi-setup)。

```json
{
  "navigation": {
    "groups": [
      {
        "group": "API reference",
        "openapi": "/path/to/openapi-v1.json",
        "pages": [
          "overview",
          "authentication",
          "GET /users",
          "POST /users",
          {
            "group": "Products",
            "openapi": "/path/to/openapi-v2.json",
            "pages": [
              "GET /products",
              "POST /products"
            ]
          }
        ]
      }
    ]
  }
}
```

<div id="versions">
  ## 版本
</div>

将导航划分为不同版本。你可以通过下拉菜单选择版本。

<img className="block dark:hidden pointer-events-none" src="/images/navigation/versions-light.png" alt="版本切换器的装饰性图示。" />

<img className="hidden dark:block pointer-events-none" src="/images/navigation/versions-dark.png" alt="版本切换器的装饰性图示。" />

在 `navigation` 对象中，`versions` 是一个数组，其中的每一项都是一个对象，必须包含 `version` 字段，也可以包含其他任意导航字段。

```json
{
  "navigation": {
    "versions": [
      {
        "version": "1.0.0",
        "groups": [
          {
            "group": "Getting started",
            "pages": ["v1/overview", "v1/quickstart", "v1/development"]
          }
        ]
      },
      {
        "version": "2.0.0",
        "groups": [
          {
            "group": "Getting started",
            "pages": ["v2/overview", "v2/quickstart", "v2/development"]
          }
        ]
      }
    ]
  }
}
```

<div id="nesting">
  ## 嵌套
</div>

导航元素之间可以相互嵌套，以创建更复杂的层级结构。你必须设置一个根级父导航元素，例如标签页、分组或下拉菜单。然后，你可以在主要导航模式中嵌套其他类型的导航元素。

在导航层级的每一层中，每个导航元素只能包含一种类型的子元素。例如，标签页可以包含锚点，而锚点可以包含分组；但标签页不能在同一层级同时包含锚点和分组。

  ```json 带标签页的版本化文档
            {
              "tab": "API Reference",
              "pages": ["v1/api/overview"]
            }
          ]
        }
      ]
    }
  }
  ```
</CodeGroup>

<div id="breadcrumbs">
  ## 面包屑导航
</div>

面包屑导航会在页面顶部显示完整的导航路径。有些主题默认启用了面包屑导航，有些则默认未启用。你可以通过 `docs.json` 中的 `styling` 属性控制是否在站点中启用面包屑导航。

<CodeGroup>
  ```json 显示完整面包屑导航
  "styling": {
    "eyebrows": "breadcrumbs"
  }
  ```

  ```json 仅显示父级章节
  "styling": {
    "eyebrows": "section"
  }
  ```
</CodeGroup>

<div id="interaction-configuration">
  ## 交互配置
</div>

使用 `docs.json` 中的 `interaction` 属性，控制用户与导航元素的交互方式。

<div id="enable-auto-navigation-for-groups">
  ### 为分组启用自动导航
</div>

当用户展开某个导航分组时，某些主题会自动跳转到该分组中的第一页。你可以使用 `drilldown` 选项覆盖主题的默认行为。

* 设为 `true`，在选中导航分组时强制自动跳转到第一页。
* 设为 `false`，可阻止跳转，选中时仅展开或折叠该分组。
* 保持未设置，则使用主题的默认行为。

<CodeGroup>
  ```json 强制导航
  "interaction": {
    "drilldown": true  // 当用户展开某个分组时，强制跳转到第一页
  }
  ```

  ```json 阻止导航
  "interaction": {
    "drilldown": false // 永不跳转，仅展开或折叠该分组
  }
  ```
</CodeGroup>
