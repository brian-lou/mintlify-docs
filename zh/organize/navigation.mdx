`docs.json` 中的 [navigation](/zh/organize/settings#param-navigation) 属性用于控制文档的结构和信息层级。

通过合理配置导航，你可以组织内容，让用户准确找到他们所需的信息。

在导航的根级别选择一种主要的组织方式。确定主要方式后，你可以在其下嵌套其他导航元素。

<div id="pages">
  ## 页面
</div>

页面是最基本的导航组件。每个页面都是文档仓库中的一个 MDX 文件。

<img className="block dark:hidden pointer-events-none" src="/images/navigation/pages-light.png" alt="页面的装饰性图形。" />

<img className="hidden dark:block pointer-events-none" src="/images/navigation/pages-dark.png" alt="页面的装饰性图形。" />

在 `navigation` 对象中，`pages` 是一个数组，其中的每一项都必须指向一个[页面文件](/zh/organize/pages)的路径。

```json
{
  "navigation": {
    "pages": [
      "settings",
      "pages",
      "navigation",
      "themes",
      "custom-domain"
    ]
  }
}
```

<div id="groups">
  ## 分组
</div>

使用分组将侧边栏导航组织成不同的部分。分组可以相互嵌套、添加标签，并搭配图标进行展示。

<img className="block dark:hidden pointer-events-none" src="/images/navigation/groups-light.png" alt="装饰性分组图形。" />

<img className="hidden dark:block pointer-events-none" src="/images/navigation/groups-dark.png" alt="装饰性分组图形。" />

在 `navigation` 对象中，`groups` 是一个数组，其中每个条目都是一个对象，并且需要包含 `group` 字段和 `pages` 字段。`icon`、`tag` 和 `expanded` 字段是可选的。

```json
{
  "navigation": {
    "groups": [
      {
        "group": "Getting started",
        "icon": "play",
        "pages": [
          "quickstart",
          {
            "group": "Editing",
            "expanded": false,
            "icon": "pencil",
            "pages": [
              "installation",
              "editor"
            ]
          }
        ]
      },
      {
        "group": "Writing content",
        "icon": "notebook-text",
        "tag": "NEW",
        "pages": [
          "writing-content/page",
          "writing-content/text"
        ]
      }
    ]
  }
}
```

<div id="default-expanded-state">
  ### 默认展开状态
</div>

使用 `expanded` 属性来控制导航侧边栏中嵌套分组的默认状态。

* `expanded: true`：分组默认展开。
* `expanded: false` 或省略：分组默认折叠。

<Note>
  `expanded` 属性仅影响嵌套分组——也就是分组中的分组。顶层分组始终展开，无法折叠。
</Note>

```json
{
  "group": "Getting started",
  "pages": [
    "quickstart",
    {
      "group": "Advanced",
      "expanded": false,
      "pages": ["installation", "configuration"]
    }
  ]
}
```

<div id="tabs">
  ## 选项卡
</div>

选项卡会为文档创建具有独立 URL 路径的不同部分，并在文档顶部生成一条水平导航栏，方便用户在各个部分之间切换。

<img className="block dark:hidden pointer-events-none" src="/images/navigation/tabs-light.png" alt="装饰性选项卡导航图形。" />

<img className="hidden dark:block pointer-events-none" src="/images/navigation/tabs-dark.png" alt="装饰性选项卡导航图形。" />

在 `navigation` 对象中，`tabs` 是一个数组，每个元素都是一个对象，必须包含一个 `tab` 字段，并且可以包含其他导航配置项，例如分组、页面、图标或指向外部页面的链接。

```json
{
  "navigation": {
    "tabs": [
      {
        "tab": "API reference",
        "icon": "square-terminal",
        "pages": [
          "api-reference/get",
          "api-reference/post",
          "api-reference/delete"
        ]
      },
      {
        "tab": "SDKs",
        "icon": "code",
        "pages": [
          "sdk/fetch",
          "sdk/create",
          "sdk/delete"
        ]
      },
      {
        "tab": "Blog",
        "icon": "newspaper",
        "href": "https://external-link.com/blog"
      }
    ]
  }
}
```

<div id="menus">
  ### 菜单
</div>

菜单为选项卡添加下拉导航项。使用菜单可以帮助用户直接进入该选项卡中的特定页面。

在 `navigation` 对象中，`menu` 是一个数组，其中的每一项都是一个对象。每个对象都需要包含一个 `item` 字段，并且可以包含其他导航字段，例如分组、页面、图标或指向外部页面的链接。

菜单项只能包含分组、页面和外部链接。

```json
{
  "navigation": {
    "tabs": [
      {
        "tab": "Developer tools",
        "icon": "square-terminal",
        "menu": [
          {
            "item": "API reference",
            "icon": "rocket",
            "groups": [
              {
                "group": "Core endpoints",
                "icon": "square-terminal",
                "pages": [
                  "api-reference/get",
                  "api-reference/post",
                  "api-reference/delete"
                ]
              }
            ]
          },
          {
            "item": "SDKs",
            "icon": "code",
            "description": "SDKs are used to interact with the API.",
            "pages": [
              "sdk/fetch",
              "sdk/create",
              "sdk/delete"
            ]
          }
        ]
      }
    ]
  }
}
```

<div id="anchors">
  ## 锚点
</div>

锚点会在侧边栏顶部添加常驻的导航项。可以使用锚点来划分内容结构、提供快速访问外部资源的入口，或创建醒目的操作入口。

<img className="block dark:hidden pointer-events-none" src="/images/navigation/anchors-light.png" alt="锚点导航的装饰性图像。" />

<img className="hidden dark:block pointer-events-none" src="/images/navigation/anchors-dark.png" alt="锚点导航的装饰性图像。" />

在 `navigation` 对象中，`anchors` 是一个数组，其中每一项都是一个对象，该对象必须包含一个 `anchor` 字段，并且可以包含其他导航字段，例如分组、页面、图标或指向外部页面的链接。

```json
{
  "navigation": {
    "anchors": [
      {
        "anchor": "Documentation",
        "icon": "book-open",
        "pages": [
          "quickstart",
          "development",
          "navigation"
        ]
      },
      {
        "anchor": "API reference",
        "icon": "square-terminal",
        "pages": [
          "api-reference/get",
          "api-reference/post",
          "api-reference/delete"
        ]
      },
      {
        "anchor": "Blog",
        "href": "https://external-link.com/blog"
      }
    ]
  }
}
```

<div id="global-anchors">
  ### 全局锚点
</div>

对于需要在所有页面上显示的链接，请使用全局锚点，不论用户正在浏览导航的哪一部分。全局锚点在链接到文档之外的资源（例如博客、社区论坛或支持门户），或为重要的内部页面（例如更新日志或状态页）提供一致的访问入口时尤其有用。

全局锚点同时支持外部 URL 和指向文档内页面的相对路径。

```json
{
  "navigation": {
    "global":  {
      "anchors": [
        {
          "anchor": "Changelog",
          "icon": "list",
          "href": "/changelog"
        },
        {
          "anchor": "Blog",
          "icon": "pencil",
          "href": "https://mintlify.com/blog"
        }
      ]
    },
    "tabs": /*...*/
  }
}
```

<div id="dropdowns">
  ## 下拉菜单
</div>

下拉菜单位于侧边栏导航顶部的可展开菜单中。下拉菜单中的每一项都会指向文档的某个部分。

<img className="block dark:hidden pointer-events-none" src="/images/navigation/dropdowns-light.png" alt="装饰性下拉导航图形。" />

<img className="hidden dark:block pointer-events-none" src="/images/navigation/dropdowns-dark.png" alt="装饰性下拉导航图形。" />

在 `navigation` 对象中，`dropdowns` 是一个数组，其中每个元素都是一个对象，该对象必须包含一个 `dropdown` 字段，并且可以包含其他导航配置字段，例如分组、页面、图标或指向外部页面的链接。

```json
{
  "navigation": {
    "dropdowns": [
      {
        "dropdown": "Documentation",
        "icon": "book-open",
        "pages": [
          "quickstart",
          "development",
          "navigation"
        ]
      },
      {
        "dropdown": "API reference",
        "icon": "square-terminal",
        "pages": [
          "api-reference/get",
          "api-reference/post",
          "api-reference/delete"
        ]
      },
      {
        "dropdown": "Blog",
        "href": "https://external-link.com/blog"
      }
    ]
  }
}
```

“产品”会在导航中创建一个专用区域，用于组织与特定产品相关的文档。你可以使用“产品”来区分文档中的不同产品、服务或重要功能集。

在 `navigation` 对象中，`products` 是一个数组，其中每个条目都是一个对象，该对象必须包含一个 `product` 字段，并且可以包含其他导航字段，例如 groups、pages、icons 或指向外部页面的链接。

```json
            ]
          },
          {
            "group": "Endpoints",
            "pages": [
              "core-api/users",
              "core-api/orders"
            ]
          }
        ]

      {
        "product": "Analytics Platform",
```

<div id="openapi">
  ## OpenAPI
</div>

将 OpenAPI 规范直接集成到你的导航结构中，以自动生成 API 文档。你可以创建专门的 API 部分，或将端点页面放入其他导航组件中。

在导航层级中的任意层级设置默认的 OpenAPI 规范。子元素会继承该规范，除非它们定义了自己的规范。

<Note>
  当你将 `openapi` 属性添加到一个导航元素（例如锚点、选项卡或分组），且未指定任何页面时，Mintlify 会自动为 OpenAPI 规范中定义的 **所有端点** 生成页面。

  若要控制显示哪些端点，请在 `pages` 数组中显式列出需要的端点。
</Note>

有关在文档中引用 OpenAPI 端点的更多信息，请参见 [OpenAPI 设置](/zh/api-playground/openapi-setup)。

```json
{
  "navigation": {
    "groups": [
      {
        "group": "API reference",
        "openapi": "/path/to/openapi-v1.json",
        "pages": [
          "overview",
          "authentication",
          "GET /users",
          "POST /users",
          {
            "group": "Products",
            "openapi": "/path/to/openapi-v2.json",
            "pages": [
              "GET /products",
              "POST /products"
            ]
          }
        ]
      }
    ]
  }
}
```

<div id="versions">
  ## 版本
</div>

将导航划分为不同版本。版本可以从下拉菜单中选择。

<img className="block dark:hidden pointer-events-none" src="/images/navigation/versions-light.png" alt="版本切换器的装饰性图形。" />

在 `navigation` 对象中，`versions` 是一个数组，其中每一项都是一个对象，该对象必须包含一个 `version` 字段，并且可以包含任意其他导航字段。

```json
{
  "navigation": {
    "versions": [
      {
        "version": "1.0.0",
        "groups": [
          {
            "group": "Getting started",
            "pages": ["v1/overview", "v1/quickstart", "v1/development"]
          }
        ]
      },
      {
        "version": "2.0.0",
        "groups": [
          {
            "group": "Getting started",
            "pages": ["v2/overview", "v2/quickstart", "v2/development"]
          }
        ]
      }
    ]
  }
}
```

<div id="nesting">
  ## 嵌套
</div>

导航元素可以相互嵌套，以创建复杂的层级结构。你必须有一个根级的父导航元素，例如选项卡（tab）、分组（group）或下拉菜单（dropdown）。在你的主导航模式中，可以嵌套其他类型的导航元素。

在导航层级的每一层中，每个导航元素只能包含一种类型的子元素。比如，一个选项卡可以包含带有分组的链接（anchor），但一个选项卡不能在同一层级同时包含链接和分组。

  ```json 带选项卡的多版本文档
            }
          ]
        }
      ]
    }
  }
  ```
</CodeGroup>

<div id="breadcrumbs">
  ## 面包屑导航
</div>

面包屑导航会在页面顶部显示完整的导航路径。有些主题默认启用面包屑导航，有些则不会。你可以通过在 `docs.json` 中使用 `styling` 属性来控制站点是否启用面包屑导航。

<CodeGroup>
  ```json 显示完整面包屑导航
  "styling": {
    "eyebrows": "breadcrumbs"
  }
  ```

  ```json 仅显示父级章节
  "styling": {
    "eyebrows": "section"
  }
  ```
</CodeGroup>

<div id="interaction-configuration">
  ## 交互配置
</div>

使用 `docs.json` 中的 `interaction` 属性来控制用户与导航元素的交互方式。

<div id="enable-auto-navigation-for-groups">
  ### 为导航分组启用自动导航
</div>

当用户展开导航分组时，一些主题会自动跳转到该分组中的第一个页面。你可以使用 `drilldown` 选项覆盖主题的默认行为。

* 设置为 `true`，在选择导航分组时强制自动跳转到第一个页面。
* 设置为 `false`，在选择分组时阻止跳转，只展开或折叠该分组。
* 保持未设置则使用主题的默认行为。

<CodeGroup>
  ```json Force navigation
  "interaction": {
    "drilldown": true  // 当用户展开导航分组时强制跳转到第一个页面
  }
  ```

  ```json Prevent navigation
  "interaction": {
    "drilldown": false // 从不跳转，只展开或折叠该分组
  }
  ```
</CodeGroup>
