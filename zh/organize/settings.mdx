`docs.json` 文件可将一组 Markdown 文件转换为一个可浏览、可自定义的文档站点。这个必需的配置文件可控制样式、导航、集成等。你可以把它视作文档的蓝图。

`docs.json` 中的设置会全局应用于所有页面。

<div id="setting-up-your-docsjson">
  ## 设置你的 `docs.json`
</div>

开始时，你只需指定 `theme`、`name`、`colors.primary` 和 `navigation`。其他字段都是可选的，可以随着文档需求的增加再逐步添加。

为了获得最佳编辑体验，请在 `docs.json` 文件顶部添加 schema 引用。这样可以在大多数代码编辑器中启用自动补全、验证和实用的工具提示：

```json
{
  "$schema": "https://mintlify.com/docs.json",
  "theme": "mint",
  "name": "Your Docs",
  "colors": {
    "primary": "#ff0000"
  },
  "navigation": {
    // 你的导航结构
  }
  // 其余配置项
}
```

<div id="customization">
  ### 自定义
</div>

<ResponseField name="theme" required>
  站点的布局主题。

  可选值如下：`mint`、`maple`、`palm`、`willow`、`linden`、`almond`、`aspen`。

  更多信息，请参阅 [Themes](/zh/customize/themes)。
</ResponseField>

<ResponseField name="name" type="string" required>
  你的项目、组织或产品的名称。
</ResponseField>

<ResponseField name="colors" type="object" required>
  文档使用的颜色。不同主题对颜色的应用方式有所不同。如果你只提供主色，则会将其应用到所有颜色元素。

  <Expandable title="颜色">
    <ResponseField name="primary" type="string matching ^#([a-fA-F0-9]{6}|[a-fA-F0-9]{3})$" required>
      文档的主色。通常在浅色模式下用于强调，具体会因主题而略有差异。

      必须是以 `#` 开头的十六进制颜色代码。
    </ResponseField>

    <ResponseField name="light" type="string matching ^#([a-fA-F0-9]{6}|[a-fA-F0-9]{3})$">
      在深色模式下用于强调的颜色。

      必须是以 `#` 开头的十六进制颜色代码。
    </ResponseField>

    <ResponseField name="dark" type="string matching ^#([a-fA-F0-9]{6}|[a-fA-F0-9]{3})$">
      在浅色和深色模式下用于按钮和悬停状态的颜色，具体会因主题而略有差异。

      必须是以 `#` 开头的十六进制颜色代码。
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="description" type="string">
  用于 SEO 和 AI 索引的站点描述。
</ResponseField>

<ResponseField name="logo" type="string or object">
  为浅色和深色模式设置 徽标。

  <Expandable title="徽标">
    <ResponseField name="light" type="string" required>
      指向浅色模式 徽标 文件的路径。请包含文件扩展名。示例：`/logo.png`
    </ResponseField>

    <ResponseField name="dark" type="string" required>
      指向深色模式 徽标 文件的路径。请包含文件扩展名。示例：`/logo-dark.png`
    </ResponseField>

    <ResponseField name="href" type="string (uri)">
      点击 徽标 时跳转到的 URL。如果未提供，徽标 默认链接到你的主页。示例：`https://mintlify.com`
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="favicon" type="string or object">
  favicon 文件的路径，包含文件扩展名。系统会自动调整为合适的 favicon 尺寸。可以使用单个文件，也可以分别为浅色和深色模式提供文件。示例：`/favicon.png`

  <Expandable title="Favicon">
    <ResponseField name="light" type="string" required>
      浅色模式 favicon 文件的路径。请包含文件扩展名。示例：`/favicon.png`
    </ResponseField>

    <ResponseField name="dark" type="string" required>
      深色模式 favicon 文件的路径。请包含文件扩展名。示例：`/favicon-dark.png`
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="thumbnails" type="object">
  用于社交媒体和页面预览的缩略图自定义设置。

  <Expandable title="缩略图">
    <ResponseField name="appearance" type="&#x22;light&#x22; | &#x22;dark&#x22;">
      缩略图的视觉主题。如果未指定，缩略图将使用站点在 `colors` 字段中定义的配色方案。
    </ResponseField>

    <ResponseField name="background" type="string">
      缩略图的背景图片。可以是相对路径或绝对 URL。
    </ResponseField>

    <ResponseField name="fonts" type="object">
      缩略图的字体配置。仅支持 Google Fonts 的字体家族名称。

      <Expandable title="字体">
        <ResponseField name="family" type="string" required>
          字体家族名称，例如 &quot;Open Sans&quot; 或 &quot;Playfair Display&quot;。支持 [Google Fonts](https://fonts.google.com) 的字体家族名称。
        </ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="styling" type="object">
  视觉样式配置。

  <Expandable title="样式">
    <ResponseField name="eyebrows" type="&#x22;section&#x22; | &#x22;breadcrumbs&#x22;">
      页面眉题的显示样式。选择 `section` 显示章节名称，选择 `breadcrumbs` 显示完整导航路径。默认为 `section`。
    </ResponseField>

    <ResponseField name="latex" type="boolean">
      控制是否包含 LaTeX 样式表，并覆盖自动检测结果。默认情况下，Mintlify 会自动检测内容中是否使用了 LaTeX，并加载所需的样式表。

      * 设置为 `true`：当自动检测无法识别你的数学公式时，强制加载 LaTeX 样式表。
      * 设置为 `false`：如果你不使用数学公式，但内容触发了误检，则禁止加载 LaTeX 样式表以提升性能。
    </ResponseField>

    <ResponseField name="codeblocks" type="&#x22;system&#x22; | &#x22;dark&#x22; | string | object">
      代码块主题配置。默认为 `"system"`。

      **简单配置：**

      * `"system"`：匹配当前站点模式 (浅色或深色)
      * `"dark"`：始终使用深色模式

      **自定义主题配置：**

      * 使用字符串为所有代码块指定同一个 [Shiki 主题](https://shiki.style/themes)
      * 使用对象分别为浅色和深色模式指定不同的 [Shiki 主题](https://shiki.style/themes)

      <ResponseField name="theme" type="string">
        同时用于浅色和深色模式的单个 Shiki 主题名称。

        ```json
        "styling": {
          "codeblocks": {
            "theme": "dracula"
          }
        }
        ```
      </ResponseField>

      <ResponseField name="theme" type="object">
        分别用于浅色和深色模式的主题。

        <Expandable title="theme">
          <ResponseField name="light" type="string" required>
            用于浅色模式的 Shiki 主题名称。
          </ResponseField>

          <ResponseField name="dark" type="string" required>
            用于深色模式的 Shiki 主题名称。
          </ResponseField>

          ```json
          "styling": {
            "codeblocks": {
              "theme": {
                "light": "github-light",
                "dark": "github-dark"
              }
            }
          }
          ```
        </Expandable>
      </ResponseField>

      <ResponseField name="languages" type="object">
        代码块的自定义语言配置。

        <Expandable title="languages">
          <ResponseField name="custom" type="array of string">
            指向描述自定义 Shiki 语言的 JSON 文件路径。使用此项可为 Shiki 默认语言集中未包含的语言添加语法高亮。

            JSON 文件必须遵循 Shiki 使用的 [TextMate 语法格式](https://macromates.com/manual/en/language_grammars)。

            ```json
            "styling": {
              "codeblocks": {
                "languages": {
                  "custom": ["/languages/my-custom-language.json"]
                }
              }
            }
            ```
          </ResponseField>
        </Expandable>
      </ResponseField>
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="icons" type="object">
  图标库设置。

  <Expandable title="Icons">
    <ResponseField name="library" type="&#x22;fontawesome&#x22; | &#x22;lucide&#x22;" required>
      整个文档站点使用的图标库。默认为 `fontawesome`。

      一个项目只能使用一个图标库。文档中的所有图标名称都必须来自同一个图标库。

      <Note>
        无论图标库设置如何，你都可以为任意单个图标指定外部托管图标的 URL，或指定项目内图标文件的路径。
      </Note>
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="fonts" type="object">

    <ResponseField name="format" type="&#x22;woff&#x22; | &#x22;woff2&#x22;">

        </ResponseField>

        <ResponseField name="weight" type="number">
          字重，例如 400、700。可变字体支持更精确的字重值，例如 550。
        </ResponseField>

        <ResponseField name="source" type="string (uri)">
          可填写以下任一项：

  </Expandable>

          链接目标。必须是有效的外部 URL。对于 `github` 类型，必须是 GitHub 仓库 URL；对于 `discord` 类型，必须是 Discord 邀请 URL。

        <ResponseField name="href" type="string (uri)" required>
          按钮目标。必须是外部 URL。如果 `type` 为 `github`，则必须是 GitHub 仓库 URL；如果 `type` 为 `discord`，则必须是 Discord 邀请 URL。

<div id="upgrading-from-mintjson">
  ## 从 `mint.json` 升级
</div>

如果你的文档项目使用已弃用的 `mint.json` 文件，请按以下步骤升级到 `docs.json`。

<Steps>
  <Step title="安装或更新 CLI">
    如果你还没有安装 [CLI](/zh/installation)，请先安装：

    <CodeGroup>
      ```bash npm
      npm i -g mint
      ```

      ```bash yarn
      yarn global add mint
      ```

      ```bash pnpm
      pnpm add -g mint
      ```
    </CodeGroup>

    如果你已经安装了 CLI，请确保它是最新版本：

    ```bash
    mint update
    ```
  </Step>

  <Step title="创建 docs.json 文件">
    在你的文档仓库中，运行：

    ```bash
    mint upgrade
    ```

    此命令会根据现有的 `mint.json` 生成一个 `docs.json` 文件。请检查生成的文件，确保所有配置都正确。
  </Step>

  <Step title="删除 mint.json 文件">
    确认 `docs.json` 配置无误后，你就可以安全地删除旧的 `mint.json` 文件。
  </Step>
</Steps>
