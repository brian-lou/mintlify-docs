`docs.json` 文件可以让你将一组 Markdown 文件转换成一个可导航、可定制的文档站点。这个必需的配置文件控制站点的样式、导航、集成等各个方面。你可以把它看作是整个文档站点的蓝图。

`docs.json` 中的设置会全局生效，适用于所有页面。

<div id="setting-up-your-docsjson">
  ## 配置你的 `docs.json`
</div>

开始使用时，你只需要指定 `theme`、`name`、`colors.primary` 和 `navigation`。其他字段是可选的，可以在文档需求增加时再逐步添加。

为了获得最佳的编辑体验，请在 `docs.json` 文件的顶部加入 schema 参考。这将在大多数代码编辑器中启用自动补全、验证以及实用的悬浮提示信息：

```json
{
  "$schema": "https://mintlify.com/docs.json",
  "theme": "mint",
  "name": "Your Docs",
  "colors": {
    "primary": "#ff0000"
  },
  "navigation": {
    // 您的导航结构
  }
  // 其余配置项
}
```

  ### 自定义
</div>

<ResponseField name="theme" required>
  你的网站布局主题。

  以下选项之一：`mint`, `maple`, `palm`, `willow`, `linden`, `almond`, `aspen`。

  更多信息请参阅 [Themes](/zh/customize/themes)。
</ResponseField>

<ResponseField name="name" type="string" required>
  你的项目、组织或产品的名称。
</ResponseField>

<ResponseField name="colors" type="object" required>
  你的文档中使用的颜色。不同主题会以不同方式使用这些颜色。如果你只提供一种主色，它会应用到所有与颜色相关的元素上。

  <Expandable title="颜色">
    <ResponseField name="primary" type="string matching ^#([a-fA-F0-9]{6}|[a-fA-F0-9]{3})$" required>
      文档的主色。通常用于浅色模式下的重点突出，具体效果会因主题而异。

      必须是以 `#` 开头的十六进制颜色值。
    </ResponseField>

    <ResponseField name="light" type="string matching ^#([a-fA-F0-9]{6}|[a-fA-F0-9]{3})$">
      在深色模式中用于强调显示的颜色。

      必须是以 `#` 开头的十六进制颜色值。
    </ResponseField>

    <ResponseField name="dark" type="string matching ^#([a-fA-F0-9]{6}|[a-fA-F0-9]{3})$">
      在浅色和深色模式中用于按钮和悬停状态的颜色，具体效果会因主题而异。

      必须是以 `#` 开头的十六进制颜色值。
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="description" type="string">
  你的网站描述，用于 SEO 和 AI 索引。
</ResponseField>

<ResponseField name="logo" type="string or object">
  为浅色和深色模式设置你的 logo。

  <Expandable title="Logo">
    <ResponseField name="light" type="string" required>
      指向浅色模式 logo 文件的路径。请包含文件扩展名。例如：`/logo.png`
    </ResponseField>

    <ResponseField name="dark" type="string" required>
      指向深色模式 logo 文件的路径。请包含文件扩展名。例如：`/logo-dark.png`
    </ResponseField>

    <ResponseField name="href" type="string (uri)">
      点击 logo 时要跳转到的 URL。如果未提供，logo 将链接到你的网站首页。例如：`https://mintlify.com`
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="favicon" type="string or object">

  <Expandable title="Favicon">
    <ResponseField name="light" type="string" required>
      指向浅色模式 favicon 文件的路径。请包含文件扩展名。例如：`/favicon.png`

    <ResponseField name="dark" type="string" required>
      指向深色模式 favicon 文件的路径。请包含文件扩展名。例如：`/favicon-dark.png`
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="thumbnails" type="object">

  </Expandable>

<ResponseField name="styling" type="object">
  视觉样式配置。

  <Expandable title="样式">
    <ResponseField name="eyebrows" type="&#x22;section&#x22; | &#x22;breadcrumbs&#x22;">
      页面 eyebrow 的样式。选择 `section` 显示所属章节名称，或选择 `breadcrumbs` 显示完整导航路径。默认值为 `section`。
    </ResponseField>

    <ResponseField name="latex" type="boolean">
      控制是否包含 LaTeX 样式表，并覆盖自动检测。默认情况下，Mintlify 会自动检测内容中的 LaTeX 使用情况，并加载所需的样式表。

      * 设为 `true`：当自动检测未能识别你的数学表达式时，强制加载 LaTeX 样式表。
      * 设为 `false`：如果你不使用数学表达式，但内容触发了误报检测，可以阻止加载 LaTeX 样式表以提升性能。
    </ResponseField>

    <ResponseField name="codeblocks" type="&#x22;system&#x22; | &#x22;dark&#x22; | string | object">
      代码块主题配置。默认值为 `"system"`。

      **简单配置：**

      * `"system"`：匹配当前站点模式（浅色或深色）
      * `"dark"`：始终使用深色模式

      **自定义主题配置：**

      * 使用字符串为所有代码块指定单个 [Shiki 主题](https://shiki.style/themes)
      * 使用对象为浅色和深色模式分别指定不同的 [Shiki 主题](https://shiki.style/themes)

      <ResponseField name="theme" type="string">
        同时用于浅色和深色模式的单个 Shiki 主题名称。

        ```json
        "styling": {
          "codeblocks": {
            "theme": "dracula"
          }
        }
        ```
      </ResponseField>

      <ResponseField name="theme" type="object">
        分别为浅色和深色模式设置不同的主题。

        <Expandable title="theme">
          <ResponseField name="light" type="string" required>
            浅色模式使用的 Shiki 主题名称。
          </ResponseField>

          <ResponseField name="dark" type="string" required>
            深色模式使用的 Shiki 主题名称。
          </ResponseField>

          ```json
          "styling": {
            "codeblocks": {
              "theme": {
                "light": "github-light",
                "dark": "github-dark"
              }
            }
          }
          ```
        </Expandable>
      </ResponseField>

      <ResponseField name="languages" type="object">
        代码块的自定义语言配置。

        <Expandable title="languages">
          <ResponseField name="custom" type="array of string">
            指向描述自定义 Shiki 语言的 JSON 文件的路径。使用此项可以为 Shiki 默认集合中未包含的语言添加语法高亮。

            JSON 文件必须遵循 Shiki 使用的 [TextMate 语法格式](https://macromates.com/manual/en/language_grammars)。

            ```json
            "styling": {
              "codeblocks": {
                "languages": {
                  "custom": ["/languages/my-custom-language.json"]
                }
              }
            }
            ```
          </ResponseField>
        </Expandable>
      </ResponseField>
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="icons" type="object">
  图标库设置。

  <Expandable title="图标">
    <ResponseField name="library" type="&#x22;fontawesome&#x22; | &#x22;lucide&#x22;" required>

</ResponseField>

        </ResponseField>

        <ResponseField name="href" type="string (uri)" required>
          按钮目标。必须是外部 URL。如果 `type` 为 `github`，则必须是 GitHub 仓库 URL。如果 `type` 为 `discord`，则必须是 Discord 邀请 URL。

<div id="upgrading-from-mintjson">
  ## 从 `mint.json` 升级
</div>

如果你的文档项目使用的是已弃用的 `mint.json` 文件，请按照以下步骤升级到 `docs.json`。

<Steps>
  <Step title="安装或更新 CLI">
    如果你还没有安装 [CLI](/zh/installation)，请现在安装：

    <CodeGroup>
      ```bash npm
      npm i -g mint
      ```

      ```bash yarn
      yarn global add mint
      ```

      ```bash pnpm
      pnpm add -g mint
      ```
    </CodeGroup>

    如果你已经安装了 CLI，请确保它是最新版本：

    ```bash
    mint update
    ```
  </Step>

  <Step title="创建 docs.json 文件">
    在你的文档仓库中运行：

    ```bash
    mint upgrade
    ```

    此命令会基于现有的 `mint.json` 创建一个 `docs.json` 文件。请检查生成的文件，确保所有设置都正确。
  </Step>

  <Step title="删除 mint.json 文件">
    在确认你的 `docs.json` 配置无误之后，你就可以安全地删除旧的 `mint.json` 文件。
  </Step>
</Steps>
